1. Visão geral do Dashboard Bancário

Este dashboard bancário foi desenvolvido a partir de um arquivo contábil que contém os dados necessários para a análise financeira.

O projeto implementa um processo completo de tratamento de dados, desde o arquivo contábil de origem até a visualização no Power BI e a integração de um modelo de Machine Learning desenvolvido para realizar previsões.

Foi dada especial atenção à qualidade dos dados. O arquivo contábil apresentava várias anomalias que exigiam uma etapa de limpeza dos dados, identificação de valores ausentes e valores discrepantes, além de transformações adaptadas à estrutura dos dados.

2. Fonte de dados — Arquivo contábil

A fonte inicial do projeto é um arquivo contábil que contém os dados utilizados para construir as análises bancárias.

Antes da integração ao processo ETL, a estrutura do arquivo foi analisada com o objetivo de identificar os diferentes problemas de qualidade dos dados que poderiam afetar as análises e os modelos preditivos.

Problemas encontrados

  • Valores ausentes
  • Valores discrepantes
  • Inconsistências nos dados
  • Formatos de dados que exigem transformação
  • Estrutura das colunas que exige adaptação

3. Limpeza e transformação com Python

Python é utilizado para preparar os dados antes de sua integração ao processo ETL.

Esta etapa permite analisar a qualidade do arquivo contábil, identificar anomalias e transformar os dados para obter uma estrutura que possa ser utilizada nas etapas seguintes.

3.1 Identificação de valores ausentes

Os dados são analisados para identificar campos incompletos ou ausentes. O tratamento é realizado de acordo com a natureza dos dados e sua importância para a análise.

3.2 Identificação de valores discrepantes

Valores incomuns também são identificados para evitar que afetem os indicadores do dashboard ou os resultados do Machine Learning.

3.3 Transformação dos dados

Após a identificação dos problemas, os dados são transformados para atender à estrutura necessária para sua integração à Staging Area e ao Data Warehouse.

3.4 Objetivo da preparação dos dados com Python

O objetivo desta etapa é produzir dados limpos, consistentes e estruturados que possam ser utilizados tanto para a análise de business intelligence quanto para a modelagem preditiva.

7. Machine Learning — Previsão

Após a preparação e análise dos dados, um componente de Machine Learning é integrado ao projeto.

O modelo utiliza os dados preparados para produzir um valor preditivo com base nas variáveis de entrada.

7.1 Variáveis utilizadas

O script de previsão em Python recebe duas variáveis de entrada:

  • ca_tnd — receita em TND
  • ca_eur — receita em EUR

7.2 Carregamento do modelo

O modelo de Machine Learning previamente treinado é salvo em um arquivo chamado EXPORT.pkl.

O script Python carrega esse modelo utilizando a biblioteca pickle.

7.3 Arquivo Python — ca.py 

 
import sys 
import json 
import pickle 
import os 
 
mode = sys.argv[1] 
ca_tnd = float(sys.argv[2]) 
ca_eur = float(sys.argv[3]) 
 
BASE_DIR = os.path.dirname(os.path.abspath(**file**)) 
model_path = os.path.join(BASE_DIR, "EXPORT.pkl") 
 
model = pickle.load(open(model_path, "rb")) 
 
prediction = model.predict([[ca_tnd, ca_eur]]) 
 
result = { 
"mode": mode, 
"ca_tnd": ca_tnd, 
"ca_eur": ca_eur, 
"prediction": float(prediction[0]) 
} 
 
print(json.dumps(result))

7.4 Explicação do arquivo ca.py

  1. Importação das bibliotecas: Python utiliza sys, json, pickle e os para gerenciar os parâmetros, o modelo e a comunicação.
  2. Recuperação dos parâmetros: os valores mode, ca_tnd e ca_eur são recuperados dos argumentos enviados ao script.
  3. Conversão numérica: os valores de receita são convertidos em números decimais utilizando float().
  4. Localização do modelo: os.path é utilizado para construir o caminho para o arquivo EXPORT.pkl.
  5. Carregamento do modelo: pickle.load() restaura o modelo de Machine Learning treinado.
  6. Previsão: model.predict() recebe as duas variáveis ca_tnd e ca_eur e gera a previsão.
  7. Criação da resposta: o resultado é organizado em um objeto Python contendo o modo, os valores de entrada e a previsão.
  8. Comunicação JSON: json.dumps() converte o resultado em JSON para que possa ser recuperado pelo Node.js.

8. Integração do Python com Node.js

Node.js atua como intermediário entre a aplicação e o script Python.

O módulo child_process e a função spawn() permitem que o Node.js execute o programa Python e recupere seu resultado.

8.1 Serviço CaService.js 

 
const { spawn } = require("child_process"); 
 
function runPython(file, args = []) { 
 
return new Promise((resolve, reject) => { 
 
const py = spawn("python", ["-u", file, ...args]); 
 
let output = ""; 
 
py.stdout.on("data", (data) => { 
  output += data.toString(); 
}); 
 
py.stderr.on("data", (err) => { 
  console.error(err.toString()); 
}); 
 
py.on("close", (code) => { 
 
  if (code !== 0) { 
    return reject("Python error code " + code); 
  } 
 
  try { 
    resolve(JSON.parse(output.trim())); 
  } catch (e) { 
    reject("JSON parse error"); 
  } 
 
}); 
 
}); 
 
} 
 
module.exports = runPython;

8.2 Funcionamento do serviço

  1. Node.js recebe o caminho do arquivo Python.
  2. Os parâmetros necessários são enviados ao script.
  3. spawn() inicia o processo Python.
  4. Node.js recupera os dados produzidos por stdout.
  5. Os erros do Python são recuperados usando stderr.
  6. O resultado JSON é analisado utilizando JSON.parse().
  7. O resultado final é retornado ao controlador Express.

9. API Node.js / Express

O Express disponibiliza uma rota de API que permite à aplicação enviar os dados necessários ao sistema de previsão.

9.1 Rota CARoute.js 

 
const express = require("express"); 
const router = express.Router(); 
const path = require("path"); 
const runPython = require("../service/CaService"); 
 
router.use(express.json()); 
 
router.post("/", async (req, res) => { 
 
try { 
 
const { mode, ca_tnd, ca_eur } = req.body; 
 
console.log("REQUEST BODY:", req.body); 
 
if (ca_tnd == null || ca_eur == null) { 
 
  return res.status(400).json({ 
    error: "ca_tnd and ca_eur are required" 
  }); 
 
} 
 
const result = await runPython( 
  path.join(__dirname, "../../python/ca.py"), 
  [ 
    mode || "export", 
    String(ca_tnd), 
    String(ca_eur) 
  ] 
); 
 
return res.status(200).json(result); 
 
} catch (error) { 
 
console.error("SERVER ERROR:", error); 
 
return res.status(500).json({ 
  error: error.toString() 
}); 
 
} 
 
}); 
 
module.exports = router;

9.2 Explicação da rota

A rota utiliza o método POST para receber os dados enviados pela aplicação.

O servidor então recupera mode, ca_tnd e ca_eur de req.body.

Uma validação verifica se os dois valores de receita obrigatórios estão presentes.

Em seguida, o serviço runPython() é chamado para executar ca.py com os parâmetros recebidos.

Finalmente, o resultado da previsão é retornado ao cliente como uma resposta JSON.

10. Servidor Express

O arquivo principal do servidor inicializa o Express, permite o recebimento de dados JSON e registra a rota de previsão. 

 
const express = require("express"); 
 
const app = express(); 
 
app.use(express.json()); 
 
const CARoute = require("./routes/CARoute"); 
 
app.use("/CA", CARoute); 
 
app.listen(3000, () => { 
 
console.log("SERVER STARTED"); 
 
});
