Prediction System Private Universities

Integration of a Machine Learning model developed with Python, Pandas, Scikit-learn and SVR into a Node.js / Express Web application designed for the analysis of private university institutions.

Start Documentation
01

General System Overview

This system implements a Machine Learning architecture designed for analysis and prediction in the context of private universities. The objective is to build a model capable of studying a relationship between the duration of a university event or activity and a graduate success indicator. In this example, the data contains two main variables: graduate_success_rate, which represents the graduate success rate, and event_duration, which represents the duration of the event. The model is developed using Python and the Scikit-learn library. The algorithm used is SVR, which stands for Support Vector Regression, configured with a linear kernel. Once trained, the model is saved in the EDUCATION_model.pkl file using Joblib. This allows the model to be reused later without having to retrain it. The Node.js backend then uses the native child_process module to launch a Python script. The spawn() function allows the Python script to be executed as an external process. Node.js then retrieves the program's standard output through stdout. The result produced by Python is interpreted as JSON using JSON.parse(). Finally, Express exposes a GET /plot route that allows the frontend to retrieve the data prepared by Python. The complete architecture therefore consists of Python being responsible for data processing and Machine Learning, while Node.js and Express handle communication with the Web application and dashboard.

Machine Learning Model Training

The first Python script is dedicated to creating and training the prediction model. The program begins by importing Pandas, SVR from Scikit-learn, and Joblib. Pandas is used to build a DataFrame containing the data used for training. In this example, the DataFrame contains the graduate success rate and the duration of events. The variable X represents the features used as input for the model. Here, the model uses event_duration. The variable y represents the target variable, meaning graduate_success_rate. The SVR model is then created using SVR(kernel='linear'). Choosing a linear kernel means that the model looks for a linear-type relationship between the input variable and the value to be predicted. The fit(X, y) method trains the model using the available data. Once training is complete, the model is saved in EDUCATION_model.pkl using joblib.dump(). The resulting file can then be used by another Python script to perform predictions without retraining the model.

Importing the Libraries 

import pandas as pd

from sklearn.svm import SVR

import joblib

Pandas is used to create and manipulate data in the form of a DataFrame. SVR provides the Support Vector Regression algorithm. Joblib allows the trained model object to be saved to a file so that it can be reused later.

Creating the Data 

data = {

    'graduate_success_rate': [85, 85, 90],

    'event_duration': [2, 2, 2]

}

The data dictionary contains the information used for training. The graduate_success_rate column represents the graduate success rate, while event_duration represents the duration of the event. In a real project, this data could come from a database, a CSV file, an API, or a data collection system.

Creating the DataFrame 

df = pd.DataFrame(data)

The pd.DataFrame() function transforms the Python dictionary into a Pandas table. The DataFrame then makes it easier to select the columns used to train the model.

Separating the Variables 

X = df[['event_duration']]

y = df['graduate_success_rate']

The variable X contains the model's input feature. In this example, this is the duration of the event. The variable y contains the value that the model must learn to predict: the graduate success rate. This separation follows the classic principle of supervised learning.

03

SVR Algorithm

The algorithm selected for this project is SVR, or Support Vector Regression. It is a Machine Learning method used to solve regression problems, meaning situations where the objective is to predict a numerical value. Unlike a simple traditional linear regression, SVR is based on the Support Vector Machine principle and aims to build a function that respects a certain margin around the observations. In the code, the model is created with SVR(kernel='linear'). The kernel='linear' parameter indicates that the model uses a linear relationship between the variables. The fit(X, y) method then allows the model to learn the relationship between event duration and success rate. Choosing SVR can be useful when implementing a regression approach capable of generalizing from the available observations. In a real project, the model should naturally be trained on a sufficiently large dataset and evaluated using suitable metrics before being used for decision-making purposes.

Creating the Model 

model = SVR(kernel='linear')

This instruction creates an SVR model with a linear kernel. At this stage, the model is still empty: it must be trained using the available data.

Training 

model.fit(X, y)

The fit() method starts the learning process. X contains the explanatory variables and y contains the target variable. The model analyzes the relationships present in the data so that it can later produce predictions for new observations.

Principle: University Data → X = Event Duration → y = Success Rate → SVR → Training → Trained Model
04

Saving the Model with Joblib

After training, it is not necessary to keep all training data in the Web backend. The trained model can be saved as a file. In this project, the Joblib library is used to perform this operation. The instruction joblib.dump(model, 'EDUCATION_model.pkl') saves the model object in a file called EDUCATION_model.pkl. This file represents the trained Machine Learning model. It can then be loaded by another Python script to produce predictions. This separation between model training and model usage is important in a professional architecture. Training can be performed periodically, while the Web application can simply use the latest validated version of the model. 

joblib.dump(
    model,
    'EDUCATION_model.pkl'
)

joblib.dump() takes two parameters here: the first corresponds to the trained model object and the second corresponds to the name of the saved file. The PKL file can then be loaded with Joblib in a prediction script.

Result: Trained SVR Model → Joblib → EDUCATION_model.pkl → Model Reuse

Data Preparation with Pandas and JSON

In the complete system, Python can also prepare data intended to be displayed in a chart or dashboard. Pandas is particularly suitable for this task because it makes it easy to manipulate data in rows and columns. After creating a DataFrame, the to_dict(orient="records") method can transform rows into a list of Python dictionaries. This structure is then placed inside a result object. The json library can finally convert this Python object into a JSON string using json.dumps(). JSON is a particularly suitable exchange format between Python and Node.js. Node.js can therefore receive a structure that is easy to interpret in JavaScript. The frontend can then use the received information to build charts representing, for example, the relationship between event duration and graduate success rate.

Creating the DataFrame 

data = {

    "x": [1, 2, 3],

    "y": [10, 20, 30]

}

df = pd.DataFrame(data)

The dictionary contains two sets of values. Pandas transforms them into two columns in the DataFrame. This structure makes it easier to prepare the data before sending it to Node.js.

Converting to Records 

result = {

    "rows":
        df.to_dict(
            orient="records"
        )

}

The orient="records" option asks Pandas to represent each row as a dictionary. The result can therefore take the form of a list of JavaScript objects after JSON conversion.

Generating JSON 

print(
    json.dumps(result)
)

json.dumps() transforms the Python object into a JSON string. The print() instruction then sends this string to stdout, where Node.js can retrieve it.

06

Node.js Service and Communication with Python

The file fac.js acts as a bridge between the Node.js backend and the Python scripts. It uses the native Node.js child_process module, particularly the spawn() function. This function allows an external process to be launched, in this case the Python program. The runPython(scriptName) function receives the name of the Python script to execute and automatically builds its path using path.join(). The Python process is then launched using spawn("python", [scriptPath]). During execution, Node.js listens to stdout to retrieve the data produced by Python and stderr to retrieve possible errors. When Python finishes, the close event is triggered. Node.js then checks the exit code. If the code is different from zero, the Promise is rejected with the error message. If the execution is successful, Node.js attempts to transform the Python output into a JavaScript object using JSON.parse(). This step is essential when Python returns structured data in JSON format. The service therefore becomes an interface between the Python ecosystem, specialized in Data Science, and the Node.js backend, specialized in Web communication.

Importing the Modules 

const { spawn } =
require("child_process");

const path =
require("path");

child_process allows Python to be launched from Node.js. The path module is used to build a reliable file path.

runPython() Function 

function runPython(scriptName) {

    return new Promise(
        (resolve, reject) => {

            ...

        }
    );

}

The function returns a Promise because the Python process runs asynchronously. The Promise will be resolved when the script finishes successfully or rejected if an error occurs.

Building the Python Path 

const scriptPath = path.join(
    __dirname,
    "..",
    "..",
    "python",
    scriptName
);

__dirname represents the directory of the current JavaScript file. The different elements are then combined using path.join() to locate the Python script.

Executing Python 

const py = spawn(
    "python",
    [scriptPath]
);

Node.js launches the Python program and passes it the script path. This technique allows the Python environment to be used directly from the JavaScript backend.

Retrieving stdout 

py.stdout.on("data", (data) => {

    output += data.toString();

});

Python writes its result using print(). Node.js retrieves this result through stdout. The toString() method converts the received data into text and the += operator is used to reconstruct the complete output.

Handling stderr 

py.stderr.on("data", (data) => {

    error += data.toString();

});

Error messages generated by Python are retrieved using stderr. This allows Node.js to identify possible problems encountered during execution.

JSON Transformation 

try {

    resolve(
        JSON.parse(output)
    );

} catch (e) {

    reject(output);

}

When Python returns a JSON string, JSON.parse() transforms it into a JavaScript object. Node.js can then directly manipulate the data and send it to Express. If the output is not valid JSON, the catch block intercepts the error and rejects the Promise with the received output.

07

Express System Route

The Express router represents the API layer that allows the frontend to access the data produced by Python. The file first imports Express and then creates a router using express.Router(). The fac.js service is then imported so that the runPython() function can be used. The GET /plot route is the entry point used to retrieve the data intended for visualization. When this route receives a request, it calls await runPython("plot.py"). The Node.js service then launches the Python script plot.py. Python prepares the data, generates the structures required for the chart if necessary, and returns them in JSON format. Node.js receives the result and Express places it inside the data property. Finally, the server returns a JSON response containing a confirmation message and the data. The frontend can then retrieve the response and use the values to build a chart or populate a dashboard dedicated to private universities.

Creating the Router 

const express =
require("express");

const router =
express.Router();

Express is imported and an independent router is created. This organization makes it possible to separate routes related to private universities from the other application routes.

Importing the Service 

const { runPython } =
require("../service/fac");

The router retrieves the runPython() function from the Node.js service. It can therefore trigger the Python script when a request arrives.

GET /plot Route 

router.get(
    "/plot",
    async (req, res) => {

        ...

    }
);

The route uses the GET HTTP method. The async keyword allows the use of await to wait for the Python execution to finish.

Calling the Python Script 

const result =
    await runPython(
        "plot.py"
    );

Express asks the Node.js service to execute specifically the plot.py file. The JSON result produced by Python is stored in the result variable.

API Response 

res.json({

    message: "OK",

    data: result

});

Express returns a JSON response containing a confirmation message and the data produced by Python. The frontend can then directly use the data property.

Error Handling 

catch (err) {

            err.toString()

}

The catch block handles errors coming from the Python service or from process execution. The server then returns HTTP status 500 to indicate an internal server error.

Complete System Architecture

The complete architecture is based on a separation of responsibilities between the Machine Learning layer and the Web application layer. The process starts with data related to private universities. This data can be prepared using Pandas and then used to train an SVR model. The model learns a relationship between the explanatory variables and the graduate success rate. Node.js retrieves this output through stdout and then uses JSON.parse() to transform the JSON string into a JavaScript object. Express then returns the data to the frontend. This architecture therefore allows Python to remain responsible for Data Science and Machine Learning processing while Node.js and Express expose the results to the frontend.

Concrete Example of the System Workflow

To understand the complete workflow, imagine that the frontend wants to retrieve the data required to display a chart about private universities. The frontend sends an HTTP GET /plot request to the Express API. The route receives the request and calls runPython("plot.py"). The Node.js service automatically builds the Python file path and launches the process using spawn(). The Python script then prepares the data with Pandas. If the data needs to be transformed into a structure that can be used by JavaScript, Pandas uses to_dict(orient="records"). The resulting object is then converted into a JSON string using json.dumps(). Python uses print() to send this string to stdout. Node.js retrieves the output with py.stdout.on("data", ...). When the Python process finishes, Node.js checks the exit code. If everything has executed correctly, the JSON string is converted into a JavaScript object using JSON.parse(). Express then places this object in the data property of the response. The frontend receives the data and can use it to build a chart representing the prediction results or information related to private universities.
