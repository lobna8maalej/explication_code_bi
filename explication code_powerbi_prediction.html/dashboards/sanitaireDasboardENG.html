🏥 SANITAIRE Analytics Dashboard — Technical Documentation

This documentation explains in detail how the CasaDashboard.jsx component works, its connection with sanitaireSlice.js, its CasaDashboard.css file, as well as the use of Redux Toolkit, Axios, Recharts, and Power BI.

The component provides an analytics interface that displays a Power BI report, retrieves healthcare data from the Redux store, and represents the values and prediction as a bar chart.

1. General Project Overview

The CasaDashboard.jsx component represents the main Dashboard interface dedicated to SANITAIRE data.

It uses React to build the interface, Redux Toolkit to retrieve and manage global data, Axios to communicate with the backend, and Recharts to create a BarChart.

The Dashboard also contains a Power BI report embedded directly into the page using an iframe element.

CasaDashboard.jsx ↓ useEffect() ↓ dispatch(fetchSanitaireData()) ↓ sanitaireSlice.js ↓ Axios ↓ GET /sanitaire ↓ Backend ↓ Redux Store ↓ data / loading / error ↓ CasaDashboard.jsx ↓ Information + BarChart ↓ CasaDashboard.css ↓ Final Interface

extraReducers manages the different stages of the asynchronous action created with createAsyncThunk.

Three main states are managed:

fetchSanitaireData.pending ↓ Request in progress fetchSanitaireData.fulfilled ↓ Request successful fetchSanitaireData.rejected ↓ Request failed

28. pending State

.addCase(fetchSanitaireData.pending, (state) => {

state.loading = true;

state.error = null;

})

pending means that the request is currently in progress.

Redux then sets: 

state.loading = true;

and resets the error: 

state.error = null;

In React, this allows the following message to be displayed: 

Loading...

29. fulfilled State

.addCase(fetchSanitaireData.fulfilled, (state, action) => {

state.loading = false;

state.data = action.payload;

})

fulfilled means that the request was successful.

Loading is then completed: 

state.loading = false;

The received data is then stored in: 

state.data = action.payload;

action.payload corresponds to the value returned by: 

return response.data.data;

30. rejected State

.addCase(fetchSanitaireData.rejected, (state, action) => {

state.loading = false;

state.error = action.payload;

})

rejected is triggered when data retrieval fails.

Loading is stopped: 

state.loading = false;

The error is then stored: 

state.error = action.payload;

The React component can then display this error.

69. What CasaDashboard.jsx Actually Does

The CasaDashboard.jsx component mainly acts as a presentation and orchestration layer.

The component then retrieves the result using:

Finally, it uses the data to display the model, prediction, chart, and Power BI report.

The CasaDashboard.jsx component therefore constitutes the main interface of the SANITAIRE Dashboard.

It triggers data retrieval using dispatch(fetchSanitaireData()) and retrieves the Redux state using: 

useSelector((state) => state.sanitaire)

The sanitaireSlice.js file is responsible for the data retrieval logic. It uses createAsyncThunk and Axios to send a GET request to: 

http://localhost:3000/sanitaire

The slice then manages the three request states: pending, fulfilled, and rejected.

When the data is available, it is stored in state.sanitaire.data. The component then retrieves the model, values, and prediction.

The values are then transformed into chartData in order to build a BarChart using Recharts.
