# 47 — Gerenciamento de Dados Imobiliários com Redux Toolkit e React

Nesta parte do projeto, foi desenvolvido um sistema de gerenciamento de dados imobiliários utilizando várias tecnologias frontend complementares, incluindo React, Redux Toolkit, Axios, Chart.js e Power BI.

O principal objetivo dessa funcionalidade é permitir que o usuário visualize um dashboard imobiliário contendo um relatório do Power BI, um gráfico que representa os preços dos imóveis e uma funcionalidade que permite inserir dados imobiliários no backend.

A arquitetura é baseada em uma separação clara entre o gerenciamento dos dados e a visualização. O Redux Toolkit é utilizado para centralizar o estado relacionado à inserção de dados imobiliários, enquanto o React é responsável pela interface do usuário e pelas interações.

O Axios gerencia a comunicação HTTP entre o frontend e o backend Node.js/Express. Quando o usuário clica no botão "Insert data", a função handleInsert() prepara um array contendo vários imóveis e, em seguida, executa a ação Redux insertImmobilier().

Essa ação é criada com createAsyncThunk() e envia uma solicitação HTTP POST para http://localhost:3000/insert.

O backend recebe os dados e os processa. O Redux Toolkit gerencia automaticamente os diferentes estados da operação assíncrona por meio de pending, fulfilled e rejected.

Quando a inserção começa, a propriedade loading passa a ser true. Quando a inserção é realizada com sucesso, o Redux recupera o status, a mensagem e a quantidade de linhas processadas retornadas pelo backend.

Em caso de erro, a mensagem correspondente é armazenada em error. O componente React utiliza então useSelector() para recuperar essas informações do store do Redux e exibir o resultado para o usuário.

Ao mesmo tempo, o Chart.js é utilizado para representar graficamente os preços de dois imóveis, uma casa e um apartamento, enquanto um iframe permite integrar um relatório do Power BI diretamente na interface.

Essa arquitetura combina, portanto, Business Intelligence com Power BI, visualização gráfica com Chart.js, gerenciamento de estado com Redux Toolkit e comunicação com o backend por meio do Axios em uma única página.

# 48 — Importação do Redux Toolkit e Axios

O arquivo Redux começa importando duas funcionalidades essenciais do Redux Toolkit: createSlice e createAsyncThunk.

O createSlice é utilizado para criar uma parte específica do store do Redux dedicada ao gerenciamento dos dados imobiliários.

Ele permite definir o nome do slice, seu estado inicial e a lógica associada às diferentes ações.

O createAsyncThunk é utilizado para criar uma ação assíncrona capaz de executar uma operação que requer tempo, como uma solicitação HTTP para um servidor backend.

O código também importa o Axios utilizando import axios from "axios".

Axios é uma biblioteca JavaScript utilizada para enviar solicitações HTTP. Neste projeto, o Axios é utilizado para enviar dados imobiliários do frontend React para o backend Node.js/Express.

A combinação do Redux Toolkit e do Axios permite, portanto, criar uma comunicação organizada entre a interface do usuário e a API backend.

# 49 — Criação da Ação Assíncrona insertImmobilier

A principal ação do arquivo Redux é insertImmobilier. Ela é criada utilizando createAsyncThunk().

O primeiro parâmetro, "immobilier/insertImmobilier", corresponde ao tipo da ação Redux e permite identificar essa operação dentro da aplicação.

O segundo parâmetro é uma função assíncrona que recebe os dados imobiliários na variável data.

A função utiliza então um bloco try/catch para tratar corretamente uma comunicação bem-sucedida ou com falha com o servidor.

Dentro do bloco try, o Axios utiliza axios.post("http://localhost:3000/insert", data) para enviar uma solicitação HTTP POST para o backend.

A variável data contém as informações imobiliárias preparadas no componente React.

Quando o servidor responde, a resposta é armazenada na variável res.

res.data contém as informações retornadas pelo backend. Esse valor é então retornado utilizando return res.data.

Ele se torna automaticamente o payload da ação fulfilled quando a operação é bem-sucedida.

No bloco catch, se o Axios encontrar um erro, o código utiliza rejectWithValue() para transmitir o erro ao reducer do Redux.

A expressão err.response.data permite que a aplicação recupere as informações de erro enviadas pelo backend.

Essa organização permite gerenciar corretamente a comunicação entre o frontend e o backend.

# 50 — Criação do Slice Imobiliário

O código cria então o slice do Redux utilizando createSlice().

O slice é denominado "immobilier" por meio da propriedade name.

Ele representa uma parte do store global dedicada à funcionalidade imobiliária.

O estado inicial contém várias propriedades: status, message, rows, loading e error.

A propriedade status é inicialmente definida como null e será utilizada para receber o status retornado pelo backend após a inserção.

A propriedade message contém inicialmente uma string vazia e será utilizada para exibir a mensagem retornada pelo servidor.

A propriedade rows é inicializada com zero e representa a quantidade de linhas processadas ou inseridas.

A propriedade loading é inicialmente definida como false, o que significa que nenhuma operação de inserção está em andamento quando a aplicação inicia.

Finalmente, error é inicializado como null para que um possível erro possa ser armazenado.

Portanto, o slice centraliza todas as informações necessárias para acompanhar a operação de inserção.

# 51 — Gerenciamento do Estado Pending

Quando o usuário clica no botão de inserção, a ação insertImmobilier é enviada ao Redux utilizando dispatch().

O Redux Toolkit ativa automaticamente o estado pending no início da operação assíncrona.

O código .addCase(insertImmobilier.pending, (state) => { ... }) define o que deve acontecer enquanto a operação está sendo carregada.

A propriedade state.loading é então definida como true.

Isso informa à interface React que uma inserção está atualmente em andamento.

O código também define state.error = null, removendo um erro anterior antes de iniciar uma nova operação.

No componente React, o valor de loading é utilizado para desativar temporariamente o botão e alterar seu texto.

Portanto, durante a inserção, o usuário vê "Inserting..." em vez de "Insert data".

Essa lógica também impede que o usuário clique várias vezes no botão durante a mesma operação.

# 52 — Gerenciamento do Estado Fulfilled

Quando a solicitação POST para o backend é bem-sucedida, o Redux Toolkit ativa automaticamente o estado fulfilled.

O código recupera então as informações retornadas pelo servidor por meio de action.payload.

A primeira instrução é state.loading = false, indicando que a inserção foi concluída.

Em seguida, o código recupera o status retornado pelo backend por meio de state.status = action.payload.status.

A mensagem retornada pelo servidor é armazenada em state.message = action.payload.message.

Finalmente, a quantidade de linhas processadas é armazenada utilizando state.rows = action.payload.rows.

Graças a essa lógica, o frontend pode exibir com precisão o resultado da operação.

Por exemplo, se o backend retornar um status de sucesso, uma mensagem confirmando a inserção e a quantidade de linhas inseridas, essas informações ficam disponíveis no store do Redux.

O React então as recupera utilizando useSelector() para exibi-las ao usuário.

# 53 — Gerenciamento do Estado Rejected

Quando a solicitação do Axios falha, o Redux Toolkit ativa o estado rejected.

Essa situação pode ocorrer se o servidor backend estiver parado, se o endereço da API estiver incorreto, se ocorrer um erro no servidor ou se outro erro impedir a inserção.

Nessa situação, o código define state.loading novamente como false, porque a operação terminou mesmo tendo falhado.

O erro é então recuperado utilizando action.payload.message e armazenado em state.error.

O componente React pode então exibir esse erro na interface utilizando a condição {error && ...}.

Esse gerenciamento permite, portanto, informar claramente ao usuário quando uma inserção não pode ser concluída.

Todo o ciclo da operação assíncrona é gerenciado pelo Redux Toolkit: pending no início, fulfilled em caso de sucesso e rejected em caso de erro.

# 54 — Exportação do Reducer

No final do arquivo Redux, o código utiliza export default immobilierSlice.reducer.

Essa instrução exporta o reducer criado pelo createSlice().

Esse reducer deverá posteriormente ser adicionado ao store principal do Redux da aplicação.

Depois de registrado no store, ele ficará disponível para o componente React por meio de useSelector(), e as ações poderão ser executadas utilizando useDispatch().

Essa organização permite, portanto, centralizar toda a lógica de estado relacionada à inserção de dados imobiliários no slice immobilier.

# 55 — Importação das Funcionalidades do React

O componente ImmobilierDashboard começa importando o React, assim como as ferramentas necessárias do Redux.

O useDispatch permite que o componente envie ações para o Redux, enquanto o useSelector permite recuperar dados do store.

O componente também importa a ação insertImmobilier do arquivo Redux immobilierSlice.

Essa ação será utilizada quando o usuário clicar no botão de inserção.

O arquivo CSS ImmobilierDashboard.css também é importado para separar a lógica de apresentação da lógica JavaScript.

# 56 — Importação e Configuração do Chart.js

O componente também utiliza a biblioteca Chart.js com o componente React Bar fornecido por react-chartjs-2.

Essa biblioteca permite representar os dados imobiliários em forma de gráfico.

Vários elementos do Chart.js são importados: CategoryScale para o eixo que contém as categorias, LinearScale para o eixo numérico, BarElement para as barras do gráfico, Title para o gerenciamento do título, Tooltip para exibir informações ao passar o cursor e Legend para a legenda.

Esses elementos são registrados posteriormente utilizando ChartJS.register().

Essa etapa é necessária para que o Chart.js possa utilizar corretamente esses componentes no gráfico.

# 57 — Criação do Componente ImmobilierDashboard

A função ImmobilierDashboard() representa a página principal do dashboard imobiliário.

Ela combina várias funcionalidades: exibição do relatório do Power BI, do gráfico de preços imobiliários, do botão de inserção e dos resultados retornados pelo backend.

O componente atua, portanto, como a camada de apresentação.

Ele recebe informações do Redux e as transforma em elementos visíveis na interface.

O usuário pode, portanto, visualizar as informações imobiliárias e iniciar uma operação de inserção sem precisar se comunicar diretamente com a API backend.

# 58 — Uso do useDispatch

O código utiliza const dispatch = useDispatch() para obter a função utilizada para enviar ações do Redux.

Essa função é então utilizada em handleInsert() por meio da instrução dispatch(insertImmobilier(data)).

Isso significa que o React prepara os dados e, em seguida, solicita ao Redux que execute a ação assíncrona de inserção.

O componente não realiza diretamente a solicitação do Axios. A comunicação com o backend é centralizada no slice do Redux.

Essa separação torna o código mais organizado e facilita a manutenção da aplicação.

# 59 — Recuperação do Estado com useSelector

O componente recupera então as informações do slice imobiliário utilizando useSelector().

A instrução const { status, message, rows, loading, error } = useSelector((state) => state.immobilier) extrai várias propriedades do store do Redux.

status contém o status da operação, message contém a mensagem retornada pelo backend, rows contém a quantidade de linhas processadas, loading indica se a inserção está em andamento e error contém um possível erro.

Graças ao useSelector(), o componente React recebe automaticamente as informações atualizadas sempre que esses valores mudam no Redux e pode atualizar a interface de acordo.

# 60 — Criação da Função handleInsert

A função handleInsert() é executada quando o usuário clica no botão "Insert data".

Ela começa criando uma constante chamada data.

Essa constante contém um array com dois objetos que representam dois imóveis.

O primeiro objeto corresponde a uma House com uma área de 120 m², um preço de 200000 e uma fonte chamada AROUS.

O segundo objeto corresponde a um Apartment com uma área de 80 m², um preço de 150000 e uma fonte chamada GEMMA.

Cada objeto também possui um identificador idImmobilier.

Depois de preparar esse array, a função chama dispatch(insertImmobilier(data)).

O Redux recebe os dados e inicia o processo assíncrono. O Axios então envia os dados para o backend por meio da solicitação POST definida no slice.

Essa função representa, portanto, o ponto de partida de toda a operação de inserção a partir da interface do usuário.

A propriedade datasets contém as séries de dados do gráfico.

# 63 — Exibição do Estado de Carregamento

O componente utiliza a propriedade loading para determinar se a inserção está atualmente em andamento.

O botão possui a propriedade disabled={loading}.

Quando loading é true, o botão é desativado para evitar múltiplas inserções simultâneas.

Seu texto também muda por meio de uma expressão condicional: {loading ? "Insertion..." : "Insert data"}.

Isso permite que o usuário compreenda imediatamente que a operação está em andamento.

Quando o Redux passa para o estado fulfilled ou rejected, loading volta a ser false e o botão fica disponível novamente.

Essa lógica simples melhora a experiência do usuário e permite acompanhar visualmente o processamento da solicitação.

# 64 — Exibição do Resultado da Inserção

Após uma inserção bem-sucedida, o componente verifica se status existe utilizando a condição {status && (...)}.

Se essa condição for verdadeira, um parágrafo com a classe CSS success é exibido.

Seu conteúdo combina a mensagem retornada pelo backend com a quantidade de linhas processadas.

A expressão {message} ({rows} rows) permite exibir informações como a mensagem de sucesso acompanhada pela quantidade de linhas inseridas.

Os valores exibidos não são escritos diretamente dentro do componente: eles vêm do backend, são armazenados no Redux e posteriormente recuperados pelo React utilizando useSelector().

Essa sequência mostra claramente o fluxo das informações desde o servidor até a interface do usuário.

# 65 — Exibição de Erros

O componente também permite exibir erros utilizando {error && (...)}.

Se existir um erro no estado do Redux, um parágrafo com a classe error é exibido e contém o valor da variável error.

Essas informações vêm do bloco catch do thunk do Redux.

Quando ocorre um erro, rejectWithValue() transmite as informações para o reducer rejected, que as armazena em state.error.

O React então recupera esse valor utilizando useSelector().

O usuário pode, portanto, ser informado diretamente na interface quando um erro impede a inserção dos dados imobiliários.

# 68 — Comunicação Completa entre React, Redux, Axios e Backend

O processo completo começa quando o usuário abre o Real Estate Dashboard.

O React exibe o componente ImmobilierDashboard juntamente com o relatório do Power BI e o gráfico do Chart.js.

Quando o usuário clica no botão "Insert data", a função handleInsert() cria o array contendo as informações imobiliárias.

Em seguida, ela chama dispatch(insertImmobilier(data)).

O Redux Toolkit ativa então o estado pending e a propriedade loading passa a ser true.

O thunk insertImmobilier utiliza o Axios para enviar uma solicitação HTTP POST para /insert.

O backend recebe os dados, processa-os e retorna uma resposta.

Se a resposta for bem-sucedida, o Redux ativa fulfilled, desativa o carregamento e armazena o status, a mensagem e a quantidade de linhas no store.

Se ocorrer um erro, o Redux ativa rejected e armazena a mensagem de erro.

Graças ao useSelector(), o React recupera automaticamente os novos valores e atualiza a interface.

O botão retorna ao seu estado normal e o resultado ou erro é exibido.

Essa comunicação forma, portanto, uma cadeia completa entre o usuário, React, Redux Toolkit, Axios, o backend e, finalmente, o retorno das informações para a interface.

# 72 — Ciclo Completo de Inserção de Dados

O ciclo começa quando o usuário clica no botão "Insert data".

A função handleInsert() prepara dois objetos imobiliários e os agrupa em um array.

O array é então passado para insertImmobilier(data) utilizando dispatch().

O Redux Toolkit ativa o estado pending, que ativa o indicador de carregamento e desativa o botão.

O thunk utiliza então o Axios para enviar os dados para a API backend por meio de uma solicitação POST.

O servidor recebe os dados e os processa.

Se a operação for bem-sucedida, a resposta do servidor se torna o payload de fulfilled.

O Redux recupera então o status, a mensagem e a quantidade de linhas.

O carregamento é desativado e a mensagem de sucesso fica visível na interface.

Se a operação falhar, o bloco catch transmite o erro para o Redux utilizando rejectWithValue().

O reducer rejected armazena esse erro e o React o exibe para o usuário.

O ciclo completo permite, portanto, acompanhar com precisão o estado da operação desde o início até o resultado final.
