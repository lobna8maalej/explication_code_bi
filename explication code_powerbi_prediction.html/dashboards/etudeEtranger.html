01

Présentation générale du système

Ce système met en place une architecture de prédiction Machine Learning destinée à une application Web liée au domaine des études à l'étranger. L'objectif est de permettre à une application développée avec Node.js et Express d'utiliser un modèle Machine Learning entraîné en Python. Le fonctionnement est séparé en plusieurs parties afin de rendre l'application organisée, modulaire et facilement évolutive. La première partie correspond au modèle Machine Learning sauvegardé dans le fichier eduworld.pkl. Ce fichier contient un modèle déjà entraîné qui peut être chargé par Python afin de produire une prédiction sans devoir refaire l'entraînement à chaque requête. La deuxième partie correspond au script Python predict.py. Ce script constitue le moteur de prédiction. Il récupère les valeurs envoyées comme arguments depuis Node.js, les convertit en nombres avec float(), vérifie que le nombre de variables correspond exactement au nombre de caractéristiques attendu par le modèle, transforme les données en tableau NumPy puis appelle la méthode predict() du modèle chargé. Le résultat est ensuite envoyé vers la sortie standard grâce à print(). Une autre partie du projet utilise également Pandas pour construire et manipuler des données tabulaires. Le DataFrame créé avec Pandas peut être converti en objets JSON afin de faciliter leur utilisation par une application Web. La troisième partie correspond au service Node.js etudeEtranger. Ce service utilise le module natif child_process et particulièrement la fonction spawn() pour lancer le programme Python depuis Node.js. Les valeurs sont transmises au script Python sous forme d'arguments de ligne de commande. Node.js écoute ensuite stdout pour récupérer le résultat de Python et stderr pour récupérer les éventuelles erreurs. Enfin, une route Express appelée /dashboard utilise ce service plusieurs fois avec différents modes de prédiction. Les résultats sont regroupés dans un tableau puis retournés au frontend sous forme d'un objet JSON. L'architecture complète permet donc de connecter un modèle Machine Learning Python à une application Web moderne et de centraliser plusieurs prédictions dans un dashboard.

Service Node.js et communication avec Python

Le fichier de service etudeEtranger.js permet à Node.js de communiquer avec le programme Python. Cette communication est réalisée grâce au module natif child_process. Node.js possède la capacité de lancer des programmes externes, et spawn() permet ici de créer un processus Python indépendant. La fonction runPrediction(values) retourne une Promise car l'exécution de Python est asynchrone. Le chemin du script Python est construit avec path.join(). Ensuite, spawn("python", ...) lance Python et lui transmet le chemin du fichier ainsi que les valeurs reçues. La méthode split(",") transforme une chaîne comme "10,20,30" en tableau ["10", "20", "30"]. L'opérateur ... permet ensuite de transmettre chaque valeur comme argument séparé au programme Python. Pendant l'exécution, Node.js écoute stdout afin de récupérer la prédiction retournée par Python. Il écoute également stderr afin de récupérer les éventuels messages d'erreur. Lorsque Python termine, l'événement close est déclenché. Node.js vérifie alors le code de sortie. Si le code est différent de zéro, la Promise est rejetée. Sinon, le résultat est nettoyé avec trim() puis retourné avec resolve(). Cette fonction constitue donc la passerelle technique entre l'application JavaScript et le modèle Machine Learning Python.

Route Express du Dashboard

Le routeur Express constitue la couche API qui permet au frontend ou au dashboard de demander plusieurs prédictions. Le fichier commence par importer Express puis crée un routeur avec express.Router(). Le service etudeEtranger est ensuite importé afin de pouvoir appeler la fonction runPrediction(). Le frontend peut alors récupérer toutes les prédictions en une seule requête et les afficher dans un dashboard sous forme de cartes, graphiques, indicateurs ou tableaux.

Architecture complète du système

L'architecture globale repose sur une séparation claire entre le Machine Learning et l'application Web. Le processus commence au niveau du dashboard ou du frontend. Celui-ci demande les informations nécessaires via une requête HTTP vers l'API Express. La route /dashboard reçoit cette requête et prépare la liste des différents modes de prédiction. Pour chaque mode, Express appelle la fonction runPrediction() du service Node.js. Cette fonction utilise child_process.spawn() afin de lancer le script Python. Les variables sont transmises à Python sous forme d'arguments de ligne de commande. Le script Python charge alors eduworld.pkl avec Pickle. Les variables reçues sont converties en nombres et le nombre de features est vérifié grâce à model.n_features_in_. Les données validées sont transformées en tableau NumPy puis envoyées au modèle avec model.predict(). Python produit ensuite le résultat avec print(). Node.js récupère cette valeur via stdout et la retourne à la route Express. Express convertit chaque prédiction en nombre et construit le tableau final results. Une réponse JSON contenant toutes les prédictions est finalement envoyée au frontend. Le dashboard peut alors utiliser ces données pour afficher différents indicateurs de performance, graphiques ou statistiques. Cette architecture permet donc de conserver Python pour la partie Data Science et Machine Learning tout en utilisant Node.js et Express pour la partie Web et API.
