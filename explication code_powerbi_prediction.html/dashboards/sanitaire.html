01

Présentation générale du système

Le système Sanitaire constitue une architecture Web intégrant un modèle de Machine Learning afin de produire automatiquement une prédiction à partir de variables numériques. L'objectif de cette architecture est de séparer clairement la partie Intelligence Artificielle de la partie application Web. Le modèle Machine Learning est développé et entraîné en Python puis sauvegardé dans un fichier appelé CASA.pkl. Ce fichier contient le modèle déjà entraîné et permet de réutiliser les connaissances apprises sans devoir effectuer à nouveau la phase d'entraînement à chaque prédiction. Le script Python sanitaire.py représente le moteur de prédiction. Il charge le modèle avec la bibliothèque joblib, récupère les valeurs envoyées par Node.js, les convertit en nombres avec float(), construit un tableau NumPy puis utilise la méthode predict() du modèle pour obtenir la prédiction. Le résultat est ensuite transformé en objet JSON afin de pouvoir être récupéré facilement par le backend Node.js. Du côté JavaScript, le service sanitaireService.js utilise le module natif child_process et la fonction spawn() pour lancer le programme Python depuis Node.js. Le service transmet le type de modèle ainsi que les valeurs numériques comme arguments du processus Python. Node.js récupère ensuite la sortie standard stdout produite par Python et recherche la ligne contenant le résultat JSON. Cette ligne est ensuite analysée avec JSON.parse(). Le routeur Express sanitaireRoute.js expose ensuite une API permettant au frontend de demander une prédiction. Dans l'exemple fourni, la route appelle le service avec le modèle identifié par "1" et les valeurs 10 et 20. Le résultat est ensuite retourné au frontend sous forme JSON avec une propriété message et une propriété data. Enfin, le projet contient également un module de connexion MySQL permettant d'établir une connexion avec la base de données POWERBI_PREDICTION. L'ensemble forme donc une architecture dans laquelle Python assure le traitement Machine Learning, Node.js assure l'exécution et la communication avec Python, Express fournit l'API Web et MySQL peut assurer la persistance des données.

02

Script Python de prédiction

Le fichier sanitaire.py constitue le cœur du traitement Machine Learning. Son rôle principal est de charger le modèle CASA.pkl, de récupérer les variables transmises par Node.js, de préparer ces données sous forme numérique et d'exécuter la prédiction. Le script commence par importer plusieurs bibliothèques. La fonction load provenant de joblib permet de recharger le modèle Machine Learning sauvegardé. La bibliothèque NumPy permet de construire le tableau numérique transmis au modèle. Le module sys permet d'accéder aux arguments envoyés par Node.js et le module os permet de construire un chemin fiable vers le fichier du modèle. Enfin, json permet de convertir le résultat de la prédiction en format JSON. Le programme détermine d'abord le dossier contenant le script avec os.path.dirname(__file__). Le chemin du fichier CASA.pkl est ensuite construit avec os.path.join(). Le modèle est chargé grâce à load(). Le script récupère ensuite les arguments à partir de sys.argv[2:]. Le deuxième élément et les suivants correspondent aux valeurs numériques, car le premier argument après le script représente ici le type de modèle. Les valeurs sont converties en nombres décimaux avec map(float, ...). Elles sont ensuite placées dans un tableau NumPy avec np.array([values]). Cette structure correspond au format attendu par les modèles Machine Learning de type Scikit-learn. Le script affiche également plusieurs informations de debug : les valeurs reçues, la forme du tableau et le nombre de caractéristiques attendues par le modèle grâce à model.n_features_in_. Ces informations permettent de contrôler que les données transmises par Node.js correspondent bien à la structure utilisée lors de l'entraînement. La méthode model.predict(X) effectue ensuite la prédiction. Enfin, le script construit un objet JSON contenant le nom du modèle, la prédiction et les valeurs utilisées. Cet objet est envoyé avec print(), ce qui permet à Node.js de le récupérer grâce à stdout.

03

Modèle Machine Learning CASA

Le fichier CASA.pkl représente le modèle Machine Learning utilisé par le système Sanitaire. Contrairement à un programme Python qui devrait entraîner le modèle à chaque exécution, le fichier PKL contient directement le modèle déjà entraîné. Le script Python n'a donc qu'à charger cet objet avec Joblib puis à lui fournir les nouvelles données à prédire. Cette séparation entre entraînement et prédiction est importante dans une architecture professionnelle car l'entraînement peut être effectué périodiquement sur un jeu de données complet tandis que le modèle sauvegardé peut être utilisé ensuite par l'application Web. La propriété model.n_features_in_ permet également de connaître le nombre de variables attendues par le modèle. Dans le code fourni, Node.js transmet par exemple deux valeurs : 10 et 20. Le modèle doit donc être compatible avec cette structure d'entrée. Si le nombre de variables envoyées ne correspond pas au nombre attendu par le modèle, une erreur de dimension peut se produire. Les informations affichées par le mode debug permettent justement de contrôler cette correspondance.

Fonctionnement du modèle : Données d'entrée → Tableau NumPy → CASA.pkl → predict() → Valeur prédite

Service Node.js et communication avec Python

Le fichier sanitaireService.js joue le rôle de passerelle entre Node.js et Python. Node.js ne réalise pas directement la prédiction Machine Learning ; il lance le programme Python grâce au module natif child_process. La fonction runPlotPython() retourne une Promise, ce qui permet de gérer l'exécution asynchrone du processus Python. La fonction reçoit deux paramètres : modelType et values. Le paramètre modelType représente le type de modèle à utiliser, tandis que values contient les variables numériques. La fonction spawn() lance ensuite Python avec le chemin du script sanitaire.py. Le tableau transmis à spawn contient le chemin du programme Python, le type du modèle et toutes les valeurs converties en chaînes grâce à values.map(String). Python reçoit donc les données sous forme d'arguments de ligne de commande. Node.js écoute ensuite l'événement data de stdout afin de récupérer progressivement la sortie du programme Python. Comme Python affiche également des informations de debug avant le JSON, le service ne tente pas de parser immédiatement toute la sortie. Lorsque le processus se termine, le code utilise split("\n") pour séparer les lignes, map(l => l.trim()) pour supprimer les espaces inutiles, puis filter(l => l.startsWith("{")) pour rechercher les lignes qui commencent par une accolade et qui correspondent donc potentiellement au JSON final. La méthode pop() récupère ensuite la dernière ligne JSON trouvée. Enfin, JSON.parse() transforme la chaîne JSON en objet JavaScript. Cet objet peut alors être retourné à la route Express. Cette technique permet donc à Node.js de récupérer proprement le résultat Python même lorsque le script produit également des informations de debug.

Route Express et API Sanitaire

Le fichier sanitaireRoute.js constitue la couche API du système. Express est importé puis un routeur est créé avec express.Router(). Le service sanitaireService est ensuite importé afin que la route puisse déclencher le programme Python. La route GET / est déclarée comme une fonction asynchrone grâce au mot-clé async. Lorsqu'une requête est reçue, la route appelle runPlotPython("1", [10, 20]). Le premier argument représente le type du modèle et le tableau contient les variables numériques. La route utilise await afin d'attendre que Python termine son exécution. Lorsque le service retourne l'objet JSON, Express construit une réponse contenant message: "OK" et data: result. Cette réponse peut ensuite être consommée par le frontend. Si une erreur se produit pendant l'exécution Python ou lors de l'analyse JSON, le bloc catch intercepte l'erreur et retourne un statut HTTP 500. Cette architecture permet donc au frontend de ne pas communiquer directement avec Python. Le frontend communique uniquement avec l'API Express, tandis qu'Express utilise le service Node.js pour lancer le modèle Python.

Architecture complète du système

L'architecture complète repose sur une communication en plusieurs niveaux. Le processus commence au niveau du frontend ou du dashboard, qui envoie une requête HTTP vers l'API Express. Express reçoit la requête sur la route Sanitaire et appelle la fonction runPlotPython() du service Node.js. Cette fonction utilise spawn() pour créer un processus Python indépendant. Python reçoit le type du modèle et les variables numériques. Le script sanitaire.py charge alors CASA.pkl grâce à Joblib. Les variables reçues sont converties en nombres puis transformées en tableau NumPy. Le modèle applique ensuite la méthode predict() afin de calculer la prédiction. Python construit un objet JSON contenant le nom du modèle, la prédiction et les valeurs d'entrée. Node.js récupère la sortie Python grâce à stdout. Comme le script affiche également des informations de debug, le service recherche la dernière ligne commençant par une accolade afin d'identifier le JSON final. JSON.parse() transforme ensuite cette chaîne en objet JavaScript. Le résultat est retourné à Express, qui construit la réponse HTTP destinée au frontend. Parallèlement, le module MySQL permet au backend d'établir une connexion avec la base POWERBI_PREDICTION. Cette base peut être utilisée pour stocker les données nécessaires au fonctionnement de l'application ou pour conserver les résultats générés par le système. L'ensemble forme donc une architecture séparant les responsabilités : le frontend s'occupe de la visualisation, Express de l'API, Node.js de l'orchestration, Python du Machine Learning, Joblib du chargement du modèle, NumPy de la préparation des données et MySQL de la persistance.

Explication à donner lors de la présentation

Lors d'une présentation professionnelle, ce système peut être présenté comme une architecture d'intelligence artificielle intégrée à une application Web du domaine sanitaire. Le modèle Machine Learning est préalablement entraîné puis sauvegardé dans CASA.pkl. Lorsqu'une prédiction est demandée, Node.js utilise le module child_process et la fonction spawn() afin de lancer le script Python. Python récupère les variables, les transforme en données numériques et les prépare avec NumPy. Le modèle CASA est ensuite chargé avec Joblib et la méthode predict() permet de calculer le résultat. Python retourne ensuite le résultat au format JSON. Node.js récupère cette réponse via stdout et la transforme en objet JavaScript grâce à JSON.parse(). Express expose ensuite le résultat à travers une API REST. Le frontend peut donc appeler l'API et afficher les prédictions dans un dashboard. MySQL complète l'architecture en fournissant une solution de stockage des données. L'intérêt de cette approche est de séparer clairement les responsabilités : Python est spécialisé dans le Machine Learning, Node.js orchestre l'exécution, Express gère les requêtes HTTP, JSON assure l'échange des résultats et MySQL assure la persistance. Cette organisation rend le système plus modulaire et permet d'ajouter ultérieurement d'autres modèles, d'autres variables ou de nouvelles fonctionnalités au dashboard.
