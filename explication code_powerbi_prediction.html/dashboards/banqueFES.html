📊 Documentación del Frontend

React • Redux Toolkit • Axios • Power BI • Recharts

1 — Descripción general del sistema Frontend

En esta parte del proyecto, desarrollamos el Frontend de la aplicación utilizando React y Redux Toolkit con el fin de gestionar la visualización del dashboard bancario, comunicarnos con el Backend y recuperar automáticamente el resultado de una predicción. El Frontend actúa como una interfaz entre el usuario y el sistema de procesamiento de datos. El usuario accede a una página llamada Banque que muestra un dashboard de Power BI, así como un resultado de predicción generado por el Backend. Para organizar correctamente la comunicación entre los diferentes componentes, utilizamos Redux Toolkit. Redux permite centralizar y gestionar el estado de la aplicación, mientras que createAsyncThunk se utiliza para gestionar una operación asíncrona, en nuestro caso el envío de una solicitud HTTP al Backend. Para realizar esta comunicación HTTP, utilizamos Axios. Cuando se carga el componente React, la función useEffect() activa automáticamente la acción Redux createBanquePrediction enviando los valores x1: 10 y x2: 2. Redux envía entonces una solicitud POST a http://localhost:3000/banque. El Backend recibe estos datos, realiza el procesamiento o la predicción y devuelve una respuesta. Esta respuesta se almacena posteriormente en el store de Redux mediante el estado predictionData. El componente React recupera entonces los datos utilizando useSelector() y actualiza automáticamente la interfaz. El sistema también gestiona tres situaciones importantes: la carga mediante loading, el éxito mediante fulfilled y el error mediante rejected. Cuando la predicción está disponible, el componente muestra su valor en una tarjeta de resultado y también crea un gráfico con Recharts para comparar los valores X1, X2 y la predicción. Al mismo tiempo, un informe de Power BI se integra en la página utilizando un elemento HTML iframe. Por lo tanto, tenemos una arquitectura Frontend en la que React gestiona la interfaz de usuario, Redux Toolkit administra el estado y las operaciones asíncronas, Axios gestiona la comunicación con el Backend, Power BI muestra el dashboard de apoyo a la toma de decisiones y Recharts representa gráficamente el resultado de la predicción.

2 — Redux Toolkit y gestión del estado

El primer archivo corresponde al Redux Slice dedicado a la predicción bancaria. Redux Toolkit se utiliza para simplificar la gestión global del estado de la aplicación. La primera línea import { createSlice, createAsyncThunk } from "@reduxjs/toolkit"; nos permite importar dos funcionalidades importantes. createSlice se utiliza para crear una parte del store de Redux llamada aquí banque, mientras que createAsyncThunk se utiliza para crear una acción asíncrona destinada a comunicarse con el Backend. La línea import axios from "axios"; importa Axios, una biblioteca utilizada para realizar solicitudes HTTP. En nuestra aplicación, Axios se utiliza para enviar los datos de predicción al servidor. El principio consiste, por tanto, en separar la lógica de comunicación con el Backend de la lógica de visualización del componente React. Esto hace que la aplicación esté mejor organizada y sea más fácil de mantener. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

3 — Función createAsyncThunk

La función createBanquePrediction se crea con createAsyncThunk. Su función es realizar una operación asíncrona que envía datos al Backend. El primer argumento "banque/create" representa el nombre de la acción Redux. El segundo argumento es una función asíncrona que recibe los datos en el parámetro data. La función utiliza entonces axios.post() para enviar una solicitud HTTP POST a http://localhost:3000/banque. La palabra data representa los datos enviados por el componente React. En nuestro ejemplo, estos datos están compuestos por x1: 10 y x2: 2. Por lo tanto, el servidor recibe estos dos valores y puede utilizarlos para realizar la predicción. La palabra clave await permite esperar la respuesta del servidor antes de continuar la ejecución. Una vez recibida la respuesta, res.data se utiliza para recuperar únicamente los datos devueltos por el Backend. La función devuelve entonces estos datos mediante return res.data. Redux Toolkit pasará automáticamente esta respuesta al reducer correspondiente al estado fulfilled. Si se produce un error durante la solicitud de Axios, la instrucción catch intercepta el error. Utilizamos entonces rejectWithValue() para transmitir el error al reducer de Redux. La expresión err.response?.data permite recuperar el mensaje enviado por el servidor cuando existe una respuesta. El símbolo ?. corresponde al encadenamiento opcional y evita un error si response no existe. Si no hay información de error disponible por parte del servidor, se utiliza el mensaje "Erreur serveur". Esta función actúa, por tanto, como puente entre el Frontend Redux y el Backend. 

export const createBanquePrediction = createAsyncThunk(
  "banque/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/banque",
        data
      );

      return res.data;

    } catch (err) {

      return rejectWithValue(
        err.response?.data || "Erreur serveur"
      );

    }
  }
);

4 — Creación de banqueSlice y estado inicial

Después de crear la acción asíncrona, creamos el banqueSlice utilizando createSlice(). Este Slice representa la parte del store de Redux dedicada a la funcionalidad bancaria. La propiedad name: "banque" proporciona un nombre a esta parte del estado. La propiedad initialState define el estado inicial de esta funcionalidad. Tenemos tres elementos principales de información. El primero es predictionData: null, lo que significa que todavía no hay ninguna predicción disponible al iniciar la aplicación. El segundo es loading: false, que indica que ninguna solicitud está actualmente en curso en el momento inicial. El tercero es error: null, que indica que todavía no se ha producido ningún error. Esta organización permite que el componente React conozca con precisión en qué situación se encuentra la solicitud: espera, carga, éxito o error. 

const banqueSlice = createSlice({
  name: "banque",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

5 — Gestión del estado pending

Cuando se ejecuta createBanquePrediction y comienza la solicitud al Backend, Redux Toolkit activa automáticamente el estado pending. El código .addCase(createBanquePrediction.pending, (state) => { ... }) define lo que debe suceder durante la carga. Establecemos entonces state.loading = true. El componente React puede saber de esta manera que hay una solicitud en curso y mostrar el mensaje Loading prediction.... También restablecemos state.error = null para eliminar un posible error anterior. Esta gestión permite disponer de una interfaz dinámica e informar al usuario de que el sistema está recuperando actualmente la predicción. 

.addCase(createBanquePrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

6 — Gestión del estado fulfilled

Cuando la solicitud de Axios termina correctamente y el Backend devuelve una respuesta válida, Redux Toolkit activa el estado fulfilled. El código .addCase(createBanquePrediction.fulfilled, (state, action) => { ... }) recupera entonces la respuesta del servidor en action.payload. Establecemos state.loading = false porque la solicitud ha terminado. A continuación, state.predictionData = action.payload almacena el resultado de la predicción en el store de Redux. Estos datos quedan entonces disponibles para los componentes React que utilizan useSelector(). El proceso es, por tanto, muy importante: el Backend produce el resultado, Redux lo almacena en su estado global y React recupera automáticamente este nuevo valor para actualizar la visualización. 

.addCase(createBanquePrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

7 — Gestión del estado rejected

Si la solicitud falla, por ejemplo si el Backend está detenido, si la URL es incorrecta o si el servidor devuelve un error, Redux Toolkit activa el estado rejected. El código .addCase(createBanquePrediction.rejected, (state, action) => { ... }) gestiona esta situación. Establecemos state.loading = false porque la solicitud ha terminado aunque haya fallado. A continuación, state.error = action.payload recupera el mensaje de error enviado mediante rejectWithValue(). El componente React puede entonces leer este estado y mostrar un mensaje de error al usuario. Esta organización evita que el usuario se quede sin información cuando falla la comunicación con el servidor. 

.addCase(createBanquePrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

8 — Ciclo completo de Redux

El funcionamiento completo de Redux Toolkit puede resumirse de la siguiente manera: el componente React ejecuta dispatch(createBanquePrediction(...)). Redux Toolkit inicia entonces la acción asíncrona. En cuanto comienza la solicitud, se activa el estado pending y loading pasa a true. Axios envía entonces los datos al Backend. Si el Backend devuelve correctamente la predicción, se activa el estado fulfilled y el resultado se almacena en predictionData. Si la solicitud falla, se activa el estado rejected y el error se almacena en error. React observa los cambios en el store mediante useSelector() y actualiza automáticamente la interfaz. Esta arquitectura permite, por tanto, gestionar correctamente las operaciones asíncronas sin colocar toda la lógica directamente dentro del componente React.

Flujo de datos:

React → dispatch() → Redux Toolkit → createAsyncThunk → Axios → Backend → Predicción → Redux Store → useSelector() → Interfaz React

9 — Componente React Banque

El segundo archivo corresponde al componente React llamado Banque. Su función es construir la interfaz de usuario del dashboard bancario y recuperar los datos de predicción almacenados en Redux. La primera línea import React, { useEffect } from "react"; importa React así como el Hook useEffect. A continuación, useDispatch y useSelector se importan desde react-redux. useDispatch() permite al componente enviar una acción Redux, mientras que useSelector() le permite leer información del store de Redux. El archivo CSS Banque.css también se importa para gestionar los estilos de la página. Finalmente, se importan varios componentes de Recharts para construir el gráfico: BarChart, Bar, XAxis, YAxis, Tooltip, CartesianGrid, ResponsiveContainer y Legend. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { createBanquePrediction } from "../redux/banqueSlice";
import "./Banque.css";

10 — useDispatch

En el componente Banque, utilizamos const dispatch = useDispatch(). El Hook useDispatch() proporciona la función dispatch, que se utiliza para enviar acciones a Redux. Mediante esta función, el componente React puede solicitar a Redux que ejecute la predicción bancaria. Sin dispatch, el componente no podría activar directamente nuestra acción createBanquePrediction. El papel de dispatch es, por tanto, transmitir una acción desde el componente React hacia el sistema Redux. 

const dispatch = useDispatch();

11 — useSelector y recuperación del estado Redux

El Hook useSelector() permite al componente React recuperar los datos almacenados en el store de Redux. En nuestro código, recuperamos tres elementos de información. El primero es predictionData, que contiene el resultado devuelto por el Backend. El segundo es loading, que indica si la solicitud está en curso. El tercero es error, que puede contener un mensaje de error. La expresión state.banque?.predictionData significa que buscamos la propiedad predictionData dentro de la parte banque del store. El símbolo ?. evita un error si el objeto banque no existe temporalmente. Gracias a useSelector(), cuando Redux modifica esta información, React detecta el cambio y actualiza automáticamente el componente. 

const predictionData = useSelector(
  (state) => state.banque?.predictionData
);

const loading = useSelector(
  (state) => state.banque?.loading
);

const error = useSelector(
  (state) => state.banque?.error
);

12 — useEffect y lanzamiento automático de la predicción

El Hook useEffect() se utiliza para ejecutar automáticamente una operación cuando se carga el componente. En nuestro código, utilizamos dispatch(createBanquePrediction({ x1: 10, x2: 2 })). Esto significa que cuando se muestra la página Banque, el componente envía automáticamente una acción Redux para solicitar una predicción al Backend. Los valores enviados son x1: 10 y x2: 2. El array de dependencias contiene dispatch. En este contexto, el efecto se ejecuta cuando el componente se monta. Este enfoque permite lanzar automáticamente la predicción sin necesidad de que el usuario haga clic en un botón. El proceso es entonces: visualización del componente, ejecución de useEffect(), llamada a dispatch(), lanzamiento de createBanquePrediction, solicitud Axios al Backend, recepción de la respuesta y actualización de Redux. 

useEffect(() => {
  dispatch(
    createBanquePrediction({
      x1: 10,
      x2: 2,
    })
  );
}, [dispatch]);

13 — Preparación de los datos del gráfico

Después de recuperar el resultado desde Redux, el componente crea una nueva variable llamada chartData. Esta variable está destinada a Recharts. La expresión condicional predictionData ? [...] : [] significa que si existe una predicción, creamos un array que contiene los datos del gráfico. En caso contrario, creamos un array vacío. El objeto contiene una propiedad name con el valor "Banque", seguida de los valores X1, X2 y Prediction. Para X1, utilizamos predictionData.x1 || 0. Esto significa que si existe el valor X1, se utiliza; de lo contrario, se utiliza el valor 0. El mismo principio se aplica a X2 y a la predicción. Este paso transforma los datos recibidos del Backend en una estructura que puede ser utilizada directamente por el gráfico de Recharts. 

const chartData = predictionData
  ? [
      {
        name: "Banque",
        X1: predictionData.x1 || 0,
        X2: predictionData.x2 || 0,
        Prediction:
          predictionData.prediction || 0,
      },
    ]
  : [];

14 — Integración del Dashboard de Power BI

El componente React también integra un informe de Power BI utilizando un elemento HTML iframe. El objetivo es mostrar un dashboard de apoyo a la toma de decisiones creado con Power BI directamente dentro de nuestra aplicación Web. La clase powerbi-frame permite aplicar el estilo definido en Banque.css. La propiedad title="BANQUE" proporciona un título al elemento integrado. La propiedad src contiene la dirección del informe de Power BI publicado. La propiedad frameBorder="0" elimina el borde del iframe y allowFullScreen permite la visualización en pantalla completa. Esta integración permite, por tanto, reunir dos dimensiones del proyecto en la misma página: por un lado, el dashboard de apoyo a la toma de decisiones de Power BI y, por otro, la predicción generada dinámicamente por el Backend y mostrada por React. 

<div className="powerbi-container">

  <iframe
    className="powerbi-frame"
    title="BANQUE"
    src="https://app.powerbi.com/view?..."
    frameBorder="0"
    allowFullScreen
  />

</div>

15 — Visualización del estado de carga

El componente utiliza la variable loading de Redux para informar al usuario cuando una predicción está en curso. La condición {loading && (...)} significa que el párrafo se muestra únicamente cuando loading es true. El mensaje mostrado es Loading prediction.... Esto corresponde al estado pending definido en el Redux Slice. Existe, por tanto, una relación directa entre el Backend, Redux y la interfaz: cuando comienza la solicitud, Redux activa loading y React muestra el mensaje de carga. 

{loading && (
  <p className="loading">
    Loading prediction...
  </p>
)}

16 — Visualización de errores

El componente también contempla la posibilidad de que se produzca un error. La condición {error && (...)} significa que el mensaje de error se muestra únicamente cuando existe un error en el store de Redux. Este error puede proceder de Axios, del Backend o de un problema de comunicación con el servidor. El valor de error se almacenó en Redux cuando se activó el estado rejected. React recupera entonces este valor utilizando useSelector() y lo muestra al usuario en un párrafo con la clase CSS error. 

{error && (
  <p className="error">
    {error}
  </p>
)}

17 — Estado de espera

El componente también contempla una situación en la que no hay ninguna predicción disponible y ninguna solicitud está actualmente en curso. La condición !loading && !error && !predictionData comprueba tres elementos: la carga ha terminado, no existe ningún error y todavía no hay datos de predicción disponibles. En esta situación, la aplicación muestra el mensaje Waiting for prediction result.... Esto permite gestionar correctamente el estado inicial de la página antes de recibir el resultado de la predicción. 

{!loading &&
  !error &&
  !predictionData && (
    <p className="waiting">
      ⏳ Waiting for prediction result...
    </p>
)}

18 — Visualización del resultado de la predicción

Cuando existe predictionData, el componente muestra una tarjeta que contiene el resultado de la predicción. La condición {predictionData && (...)} renderiza esta parte de la interfaz únicamente cuando los datos están disponibles. El título 📌 Result indica claramente al usuario que se trata del resultado producido por el modelo. El valor mostrado utiliza predictionData.prediction?.toFixed(2). La propiedad prediction corresponde al resultado enviado por el Backend. La función toFixed(2) muestra el número con dos dígitos después del punto decimal. El símbolo ?. comprueba que la propiedad existe antes de llamar al método. Esta tarjeta representa, por tanto, la parte principal de la visualización del resultado predictivo. 

{predictionData && (
  <div className="prediction-card">

    <h2 className="prediction-title">
      📌 Result
    </h2>

    <div className="prediction-value">
      {predictionData.prediction?.toFixed(2)}
    </div>

  </div>
)}

19 — Creación del gráfico con Recharts

Después de mostrar el valor numérico, el componente crea un gráfico utilizando la biblioteca Recharts. El objetivo es representar visualmente los valores X1, X2 y Prediction. El componente ResponsiveContainer permite que el gráfico se adapte automáticamente al ancho disponible. La propiedad width="100%" indica que el gráfico utiliza todo el ancho de su contenedor y height={350} define una altura de 350 píxeles. El componente BarChart recibe los datos mediante data={chartData}. El componente CartesianGrid muestra una cuadrícula que facilita la lectura del gráfico. XAxis define el eje horizontal y utiliza dataKey="name" para mostrar el nombre de la categoría, aquí Banque. YAxis representa el eje vertical que contiene los valores numéricos. Tooltip muestra información cuando el usuario coloca el cursor sobre una barra. Legend muestra la leyenda de las diferentes series. Finalmente, tres componentes Bar representan respectivamente X1, X2 y Prediction. Cada barra utiliza una clave de datos diferente mediante dataKey. El gráfico proporciona, por tanto, una representación visual y comparativa de los datos utilizados para la predicción y del resultado obtenido. 

<ResponsiveContainer

  height={350}

  <BarChart data={chartData}>

    <XAxis dataKey="name" />

    <YAxis />

    <Tooltip />

    <Legend />

    <Bar
      dataKey="X1"
      fill="#2196F3"
      name="X1"
    />

    <Bar
      dataKey="X2"
      fill="#FFC107"
      name="X2"
    />

    <Bar
      dataKey="Prediction"

</ResponsiveContainer>

20 — Arquitectura completa del Frontend

Los dos archivos de Redux y React trabajan juntos siguiendo una arquitectura organizada. El componente Banque representa la parte visual. Cuando se carga, useEffect() llama a dispatch() con la acción createBanquePrediction. Esta acción está definida en banqueSlice.js utilizando createAsyncThunk. Redux Toolkit inicia entonces una solicitud Axios al Backend con los valores X1 y X2. Durante esta comunicación, Redux entra en el estado pending y la variable loading pasa a ser true. Cuando el Backend devuelve una respuesta correcta, Redux entra en el estado fulfilled y coloca la respuesta en predictionData. El componente React recupera estos datos utilizando useSelector(). React detecta automáticamente el cambio de estado y actualiza la interfaz. El resultado se muestra entonces en la tarjeta de predicción y los datos se preparan en chartData para construir el gráfico de Recharts. Si se produce un error durante la comunicación, Redux entra en el estado rejected, almacena el error en error y React muestra el mensaje correspondiente. Al mismo tiempo, el iframe de Power BI muestra el dashboard de apoyo a la toma de decisiones. Tenemos, por tanto, una separación clara entre presentación, gestión del estado, comunicación con el servidor y visualización de datos.

21 — Función de Redux y función de React

En esta arquitectura, React y Redux tienen responsabilidades diferentes pero complementarias. React es principalmente responsable de la interfaz de usuario: construye la página, muestra el dashboard de Power BI, muestra el resultado de la predicción y crea el gráfico. Redux Toolkit es responsable de la gestión del estado y de la comunicación con el Backend. El Redux Slice contiene la información predictionData, loading y error. createAsyncThunk gestiona la operación asíncrona y Axios se comunica con el servidor. React utiliza posteriormente useSelector() para leer el estado de Redux y useDispatch() para enviar acciones. Esta separación hace que el código sea más limpio porque la lógica de recuperación de datos no está completamente mezclada con el código de visualización. React se concentra principalmente en presentar la información, mientras que Redux organiza su flujo y su estado dentro de la aplicación.

22 — Gestión de los tres estados de la solicitud

Un elemento importante de esta arquitectura es la gestión de los tres estados generados automáticamente por createAsyncThunk. El primer estado es pending: corresponde al momento en que la solicitud está en curso y permite mostrar un indicador de carga. El segundo estado es fulfilled: corresponde a una solicitud exitosa y permite almacenar la respuesta en predictionData. El tercer estado es rejected: corresponde a una solicitud fallida y permite almacenar el problema en error. Gracias a estos tres estados, la interfaz React puede reaccionar automáticamente a los cambios en la comunicación con el Backend. El usuario sabe, por tanto, si el sistema está funcionando, si la predicción está disponible o si se ha producido un error.

pending → Solicitud en curso → loading = true

fulfilled → Solicitud exitosa → predictionData = result

rejected → Solicitud fallida → error = message

23 — Conclusión

Para concluir, estos dos archivos constituyen una parte esencial del Frontend de nuestra aplicación de predicción bancaria. El archivo Redux utiliza Redux Toolkit para centralizar el estado de la funcionalidad bancaria y gestionar la comunicación asíncrona con el Backend mediante createAsyncThunk y Axios. El estado inicial contiene la información necesaria para conocer el resultado de la predicción, el estado de carga y los posibles errores. Los tres estados pending, fulfilled y rejected permiten gestionar automáticamente las diferentes etapas de la solicitud. El componente React Banque utiliza posteriormente useDispatch() para activar la acción Redux y useSelector() para recuperar información del store. El Hook useEffect() permite lanzar automáticamente la predicción cuando se carga el componente. Una vez recibido el resultado, React muestra el valor de la predicción en una tarjeta y utiliza Recharts para crear una representación gráfica que compara X1, X2 y la predicción. El componente también integra un dashboard de Power BI mediante un iframe con el objetivo de reunir el análisis de apoyo a la toma de decisiones y el análisis predictivo en una misma interfaz. La arquitectura final se basa, por tanto, en la comunicación entre React, Redux Toolkit, Axios, el Backend, el modelo de predicción, Power BI y Recharts. Esta organización permite construir una aplicación Frontend dinámica y estructurada capaz de presentar al usuario tanto datos de apoyo a la toma de decisiones como resultados predictivos.

Para presentar esta parte ante un jurado, podemos explicar que el Frontend de la aplicación está desarrollado con React y que Redux Toolkit se utiliza para gestionar el estado y la comunicación con el Backend. En el archivo Redux, creé una acción asíncrona con createAsyncThunk. Esta acción utiliza Axios para enviar los valores X1 y X2 al Backend mediante una solicitud POST. Redux Toolkit gestiona automáticamente tres estados: pending cuando la solicitud está en curso, fulfilled cuando la respuesta se recibe correctamente y rejected cuando se produce un error. El resultado devuelto por el Backend se almacena en predictionData. En el componente React Banque, utilizo useDispatch para activar la acción y useSelector para recuperar los datos desde Redux. Con useEffect, la predicción se lanza automáticamente cuando se carga la página. Cuando llega la respuesta, React muestra el resultado en una tarjeta y utiliza Recharts para representar gráficamente X1, X2 y la predicción. También integré un dashboard de Power BI mediante un iframe para mostrar resultados de apoyo a la toma de decisiones en la misma interfaz. El objetivo es, por tanto, combinar Business Intelligence con Power BI y Machine Learning con predicción dentro de una sola aplicación, utilizando Redux para organizar el flujo de datos entre el Frontend y el Backend.
