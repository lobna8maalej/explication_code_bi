📊 Explicação detalhada do Dashboard de CA

React • Redux Toolkit • Axios • API • Power BI • Recharts

1. Visão geral do sistema frontend

Nesta parte do projeto, desenvolvemos uma interface frontend dedicada à previsão de receita, denominada CA Dashboard. Essa interface é construída com React e utiliza várias tecnologias complementares para se comunicar com o backend, gerenciar os dados de forma centralizada, exibir os resultados da previsão e representar os dados graficamente. O funcionamento geral é baseado na comunicação entre o componente React, Redux Toolkit, Axios e a API do backend. O componente React não gerencia diretamente toda a lógica de comunicação com o servidor. Ele utiliza Redux para disparar uma ação assíncrona que envia os dados ao backend. Axios é utilizado para realizar a requisição HTTP para a URL http://localhost:3000/CA. O backend recebe os dados de receita em TND e EUR, assim como o modo de previsão. Ele realiza o processamento necessário e retorna um resultado que contém, principalmente, a previsão. O Redux recebe essa resposta e a armazena no estado global. O componente React utiliza então useSelector para recuperar os dados do Redux e exibir o resultado na tela. O componente também utiliza useEffect para iniciar automaticamente a previsão quando a página é carregada. Finalmente, a biblioteca Recharts transforma os dados recebidos em um gráfico para comparar a receita real com o valor previsto. Ao mesmo tempo, um relatório do Power BI é integrado à página por meio de um elemento iframe. Dessa forma, obtemos uma arquitetura frontend completa que combina visualização de BI, previsão por Machine Learning, gerenciamento de estado com Redux, comunicação com o backend e representação gráfica dos resultados.

2. Importação do Redux Toolkit

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

Esta instrução importa duas funções importantes do Redux Toolkit. A função createAsyncThunk é utilizada para criar uma operação assíncrona, especialmente para realizar uma requisição HTTP ao backend. No nosso projeto, essa função é utilizada para enviar os dados de receita para a API e obter o resultado da previsão. A função createSlice é utilizada para criar uma parte do store do Redux dedicada à receita. Essa parte é chamada de slice. O slice contém o nome dessa parte do estado, seu estado inicial e a lógica utilizada para modificar esse estado quando a requisição está pendente, é concluída com sucesso ou falha. Portanto, o uso do Redux Toolkit simplifica consideravelmente o gerenciamento do estado global da aplicação.

3. Importação do Axios

import axios from "axios";

Axios é uma biblioteca JavaScript utilizada para realizar requisições HTTP. Em nossa aplicação, Axios atua como intermediário entre o frontend React e o backend Node.js. Quando queremos iniciar uma previsão, o frontend precisa enviar os dados para o servidor. Axios nos permite realizar essa operação por meio do método axios.post(). O servidor recebe os dados enviados pelo React, realiza o processamento da previsão e retorna uma resposta JSON. Axios recupera essa resposta para que posteriormente ela possa ser armazenada no Redux e exibida no componente React. Portanto, o uso do Axios facilita a comunicação entre as diferentes partes da aplicação.

4. Criação da operação assíncrona com createAsyncThunk

export const createPrediction = createAsyncThunk(
  "ca/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/CA",
        data
      );

      return res.data;

    } catch (err) {
      return rejectWithValue(
        err.response?.data || "Server error"
      );
    }
  }
);

Esta parte representa a principal ligação entre o Redux e o backend. Criamos uma função chamada createPrediction utilizando createAsyncThunk. O primeiro parâmetro, "ca/create", representa o tipo da ação do Redux. O segundo parâmetro é uma função assíncrona que recebe os dados na variável data. Essa função utiliza Axios para enviar uma requisição HTTP POST para http://localhost:3000/CA. O método POST é utilizado porque estamos enviando informações ao servidor para que ele possa realizar uma previsão. A variável data contém os parâmetros necessários para a previsão. No nosso caso, contém principalmente mode, ca_tnd e ca_eur. A palavra-chave await aguarda a resposta do servidor antes de continuar a execução. Quando o servidor responde corretamente, a resposta é armazenada em res e res.data contém os dados JSON retornados pelo backend. A instrução return res.data então envia esses dados para o Redux. Se ocorrer um erro durante a requisição, a execução entra no bloco catch. A função rejectWithValue() permite então enviar uma mensagem de erro para o Redux. A expressão err.response?.data recupera a mensagem retornada pelo servidor quando ela existe. Se não houver uma resposta utilizável, a mensagem "Server error" será utilizada. Essa estrutura permite gerenciar corretamente as duas situações possíveis: uma previsão bem-sucedida ou um erro durante a comunicação com o backend.

5. Criação do caSlice

const caSlice = createSlice({
  name: "ca",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

Esta parte cria o slice do Redux dedicado à receita. A propriedade name: "ca" identifica essa parte do store do Redux. Portanto, a aplicação possui um espaço de estado específico dedicado aos dados de CA. A propriedade initialState define o estado inicial do sistema. predictionData é inicializado como null porque nenhuma previsão foi recebida ainda. loading é inicializado como false porque não existe nenhuma requisição sendo executada no início. Finalmente, error é inicializado como null porque inicialmente não existe nenhum erro. A propriedade reducers está vazia no nosso caso porque não precisamos criar ações síncronas tradicionais. O gerenciamento da nossa ação assíncrona createPrediction é realizado em extraReducers. Isso permite que o Redux reaja automaticamente aos diferentes estados da requisição assíncrona.

6. Estado pending: requisição em andamento

.addCase(createPrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

Quando a requisição de previsão começa, o Redux ativa automaticamente o estado pending. Isso significa que a requisição está sendo executada naquele momento. Nessa situação, definimos state.loading = true. Essa informação permite que o componente React saiba que deve exibir uma mensagem indicando que a previsão está sendo carregada. Também redefinimos state.error = null para remover um possível erro de uma requisição anterior. Dessa forma, o sistema consegue manter informações claras sobre o estado atual da comunicação com o backend.

7. Estado fulfilled: previsão bem-sucedida

.addCase(createPrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

Quando o backend responde corretamente, o Redux ativa o estado fulfilled. Isso significa que a requisição assíncrona foi concluída com sucesso. Então definimos state.loading = false porque o carregamento terminou. Em seguida, armazenamos o resultado retornado pelo servidor em state.predictionData. A propriedade action.payload contém os dados retornados por return res.data no thunk. O Redux armazena assim o resultado da previsão em seu estado global. O componente React pode então recuperar essas informações por meio de useSelector.

8. Estado rejected: erro na previsão

.addCase(createPrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

Se a requisição falhar, o Redux ativa automaticamente o estado rejected. Nessa situação, state.loading passa a ser false porque a requisição terminou, mesmo que tenha terminado com um erro. A mensagem de erro enviada por meio de rejectWithValue() é então armazenada em state.error. O componente React pode recuperar esse erro e exibi-lo ao usuário. O gerenciamento dos três estados pending, fulfilled e rejected permite construir uma interface dinâmica que indica claramente se a previsão está em andamento, foi concluída ou encontrou um erro.

9. Exportação do reducer do Redux

export default caSlice.reducer;

Esta instrução exporta o reducer criado pelo caSlice. O reducer representa a lógica que permite ao Redux modificar o estado de CA de acordo com as diferentes ações recebidas. Posteriormente, ele pode ser integrado ao store do Redux da aplicação. Graças a essa exportação, o componente React pode acessar indiretamente os dados armazenados na parte ca do store.

11. useDispatch e useSelector

Esses dois hooks permitem que o componente React se conecte ao Redux. useDispatch() permite enviar uma ação para o Redux. Portanto, podemos considerar dispatch como o mecanismo que permite ao componente enviar uma instrução para o Redux, enquanto useSelector permite ao componente ler os dados armazenados pelo Redux.

16. Recuperação dos dados com useSelector

const predictionData =
  useSelector((state) => state.ca?.predictionData);

const loading =
  useSelector((state) => state.ca?.loading);

const error =
  useSelector((state) => state.ca?.error);

Essas três instruções permitem que o componente React recupere as informações armazenadas no Redux. A primeira recupera predictionData, que é o resultado da previsão retornado pelo backend. A segunda recupera loading, que indica se a requisição está atualmente em andamento. A terceira recupera error, que pode conter um erro. A notação state.ca significa que estamos acessando a parte do store correspondente ao slice de CA. O operador ?. é o operador de encadeamento opcional, que ajuda a evitar determinados erros quando um valor intermediário não existe.

17. Início automático da previsão com useEffect

useEffect(() => {
  dispatch(
    createPrediction({
      mode: "export",
      ca_tnd: 50000,
      ca_eur: 10000,
    })
  );
}, [dispatch]);

Esta parte é essencial para o funcionamento automático do Dashboard. O hook useEffect permite executar uma operação depois que o componente foi renderizado. Quando a página de CA é carregada, o componente chama dispatch() e ativa createPrediction(). Em seguida, enviamos três dados para o backend: mode: "export", ca_tnd: 50000 e ca_eur: 10000. Esses dados representam os valores utilizados pelo modelo de previsão. O Redux passa essas informações para o thunk, o thunk utiliza Axios para enviar uma requisição POST ao backend e o backend realiza a previsão. O array [dispatch] indica as dependências do useEffect. Nesse caso, o efeito é executado quando o componente é montado e caso a referência de dispatch seja alterada.

O processo completo começa quando o usuário abre o CA Dashboard. O React carrega o componente CA e o hook useEffect inicia automaticamente a ação createPrediction. 30. Gerenciamento dos três estados da requisição

Uma das vantagens importantes do Redux Toolkit neste projeto é o gerenciamento automático dos diferentes estados da operação assíncrona. Quando a requisição começa, o estado pending é ativado e loading passa a ser true. O frontend exibe então a mensagem de carregamento. Quando o backend retorna corretamente a previsão, o estado fulfilled é ativado, loading passa a ser false e o resultado é armazenado em predictionData. O React pode então exibir o cartão de resultado e o gráfico. Se ocorrer um erro durante a requisição, o estado rejected é ativado, loading passa a ser false e a mensagem de erro é armazenada em error. O componente React exibe então esse erro. Dessa forma, obtemos um gerenciamento claro de todo o ciclo de vida da requisição.

31. Arquitetura frontend utilizada

A arquitetura utilizada nessa funcionalidade separa claramente as responsabilidades. O componente React CA.jsx é responsável pela interface e pela visualização. O arquivo caSlice.js é responsável pelo gerenciamento do estado do Redux e pela comunicação assíncrona com a API. Axios é responsável por enviar a requisição HTTP. O backend Node.js é responsável por processar a requisição e gerar a previsão. Recharts é responsável pela visualização gráfica do resultado e o Power BI fornece uma visualização adicional para apoiar a tomada de decisões. Essa separação torna o projeto mais organizado e facilita a manutenção e a evolução da aplicação.

32. Diferença entre Redux e React neste código

Nessa arquitetura, React e Redux possuem responsabilidades diferentes, mas complementares. React é utilizado principalmente para construir a interface do usuário: exibe o título, o relatório do Power BI, a mensagem de carregamento, o resultado e o gráfico. Redux é utilizado para gerenciar o estado da previsão: armazena os dados recebidos do backend, indica se uma requisição está em andamento e armazena possíveis erros. useDispatch permite que o React solicite ao Redux que inicie uma operação e useSelector permite que o React recupere os dados armazenados pelo Redux. Essa separação evita que toda a lógica de comunicação com o servidor seja misturada diretamente com a interface.

33. Relação entre Power BI e a previsão por Machine Learning

O CA Dashboard reúne dois tipos de funcionalidades complementares. Por um lado, o Power BI fornece indicadores e visualizações para apoiar a tomada de decisões com base nos dados do projeto. Por outro lado, a parte React e Redux permite que a aplicação chame o backend para obter uma previsão por meio de Machine Learning. O resultado dessa previsão é posteriormente apresentado de forma numérica e gráfica utilizando Recharts. A vantagem dessa arquitetura é, portanto, combinar Business Intelligence e análise preditiva dentro da mesma interface. O Power BI permite compreender os dados históricos e os indicadores, enquanto o modelo de previsão permite obter uma estimativa baseada nos dados enviados ao backend.

34. Resumo do funcionamento

Em resumo, quando o usuário abre o CA Dashboard, o React carrega o componente CA. O hook useEffect inicia automaticamente uma ação do Redux chamada createPrediction. Essa ação é criada com createAsyncThunk e utiliza Axios para enviar uma requisição POST ao backend em http://localhost:3000/CA. Os dados enviados são o modo export, a receita em TND de 50000 e a receita em EUR de 10000. Durante a execução, o Redux entra no estado pending e o React exibe a mensagem de carregamento. Quando o servidor retorna o resultado, o Redux entra no estado fulfilled e armazena a resposta em predictionData. O React recupera essas informações por meio de useSelector, exibe o valor previsto com duas casas decimais e prepara os dados necessários para o gráfico. O Recharts então exibe duas barras que permitem comparar a receita real com a previsão. Ao mesmo tempo, o Power BI é exibido dentro de um iframe para fornecer uma visualização adicional de apoio à tomada de decisões. Se ocorrer um erro, o Redux entra no estado rejected e o React exibe a mensagem de erro. Portanto, o sistema forma uma cadeia completa entre a interface React, Redux Toolkit, Axios, o backend Node.js, o modelo de previsão, Recharts e Power BI.

Nesta parte do meu projeto, desenvolvi um Dashboard dedicado à previsão de receitas utilizando React e Redux Toolkit. Utilizo Redux para gerenciar o estado dos dados de previsão e evitar colocar toda a lógica diretamente dentro do componente React. Criei um slice chamado caSlice que contém três elementos principais de informação: predictionData para armazenar o resultado, loading para determinar se a requisição está em andamento e error para gerenciar os erros. Também utilizo createAsyncThunk para realizar uma operação assíncrona. Essa operação utiliza Axios para enviar uma requisição POST ao meu backend em /CA. Quando a página de CA é carregada, useEffect ativa automaticamente essa ação com os dados de receita em TND e EUR, assim como o modo de processamento. O Redux Toolkit gerencia automaticamente três estados: pending quando a requisição está em andamento, fulfilled quando a previsão é recebida corretamente e rejected quando ocorre um erro. No componente React, utilizo useSelector para recuperar os dados armazenados no Redux e useDispatch para enviar a ação de previsão. Quando a previsão está disponível, eu a exibo em um cartão com duas casas decimais. Também utilizo Recharts para criar um gráfico de barras que compara a receita real com o valor previsto. Finalmente, integro um relatório do Power BI na mesma página utilizando um iframe. Portanto, essa arquitetura combina React para a interface, Redux Toolkit para o gerenciamento do estado, Axios para a comunicação com o backend, Machine Learning para a previsão, Recharts para a visualização e Power BI para a análise e apoio à tomada de decisões. O objetivo é fornecer uma única interface que permita aos usuários consultar dados de BI e resultados preditivos de maneira clara e interativa.

36. Conclusão

Este código frontend implementa, portanto, uma arquitetura completa para utilizar um modelo de previsão a partir de uma aplicação React. O Redux Toolkit atua como gerenciador de estado e controla o ciclo de vida da requisição por meio dos estados pending, fulfilled e rejected. Axios gerencia a comunicação com o backend Node.js. O React utiliza useEffect para ativar automaticamente a previsão, useDispatch para enviar a ação do Redux e useSelector para recuperar os resultados. O Recharts posteriormente transforma os dados em uma representação gráfica que permite comparar os valores reais e as previsões. Finalmente, o Power BI complementa o Dashboard com visualizações de apoio à tomada de decisões. Essa organização separa claramente a interface, o gerenciamento do estado, a comunicação com o servidor, a previsão e a visualização dos dados. Portanto, fornece uma arquitetura frontend estruturada e adequada para uma aplicação de Business Intelligence que integra Machine Learning.
