# 109 — Présentation du Dashboard Etude

Le Dashboard Etude à l'étranger constitue une interface frontend développée avec React permettant d'afficher et d'analyser des données relatives aux études à l'étranger. Cette fonctionnalité utilise plusieurs technologies complémentaires : React pour construire l'interface utilisateur, Redux Toolkit pour centraliser et gérer l'état des données, Axios pour communiquer avec le backend, Recharts pour représenter graphiquement les données, et Power BI pour intégrer un rapport de Business Intelligence directement dans la page. Contrairement à un formulaire de saisie classique, le Dashboard Etude récupère automatiquement les données depuis le backend lorsque le composant est chargé. L'utilisateur peut donc consulter directement les informations disponibles, les valeurs associées aux différents modes d'étude et les valeurs de prédiction. Le dashboard combine ainsi plusieurs niveaux de visualisation : le rapport Power BI, la liste des données récupérées, et le graphique comparatif généré avec Recharts.

L'utilisateur n'a donc pas besoin de cliquer sur un bouton pour déclencher la récupération des données.

# 132 — Création du fichier etudeSlice.js

La gestion des données est centralisée dans le fichier etudeSlice.js. Ce fichier utilise Redux Toolkit et Axios : 


import { createSlice, createAsyncThunk }
from "@reduxjs/toolkit";

import axios from "axios";

createAsyncThunk permet de créer une action asynchrone. createSlice permet de créer la partie du store dédiée aux données Etude. Axios permet quant à lui de communiquer avec le backend.

# 133 — Création de fetchEtudeData

L'action asynchrone principale est : 


export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        ...
    }
);

fetchEtudeData est responsable de récupérer les données Etude. Le premier paramètre : "etude/fetchEtudeData" représente le type Redux de l'action. Le symbole _ indique qu'aucun argument particulier n'est nécessaire pour lancer cette action. Le paramètre thunkAPI fournit des outils Redux Toolkit permettant notamment de gérer les erreurs.

# 134 — Requête Axios vers le backend

À l'intérieur du thunk, Axios envoie une requête GET : 


const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

La méthode GET permet au frontend de demander les données au serveur. L'endpoint utilisé est : /etude/dashboard. Le backend reçoit donc la requête et retourne les données nécessaires au dashboard. Le mot-clé await permet d'attendre la réponse du serveur avant de continuer l'exécution.

# 135 — Retour des données du backend

Après la réponse Axios, le code utilise : 


return response.data.data;

response contient la réponse complète fournie par Axios. response.data correspond au corps de la réponse HTTP. Enfin, response.data.data récupère le tableau de données contenu dans la propriété data de la réponse backend. Cette valeur devient ensuite le payload de l'action Redux lorsque celle-ci réussit.

# 136 — Gestion des erreurs Axios

Le thunk contient également un bloc try/catch : 


try {

    const response = await axios.get(
        "http://localhost:3000/etude/dashboard"
    );

    return response.data.data;

} catch (error) {

    return thunkAPI.rejectWithValue(
        error.message
    );

}

Si la requête réussit, les données sont retournées. Si une erreur se produit, le programme passe dans le bloc catch. L'instruction : rejectWithValue(error.message) transmet le message d'erreur au reducer rejected. Cette approche permet au composant React d'afficher ensuite le problème à l'utilisateur.

# 137 — Création du slice Etude

Le slice Redux est créé avec : 


const etudeSlice = createSlice({

    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    ...
});

La propriété name identifie le slice sous le nom etude. L'initialState définit les valeurs initiales du state. items commence avec un tableau vide car aucune donnée n'a encore été récupérée. loading commence à false car aucune requête n'est en cours au démarrage. error commence à null puisqu'aucune erreur n'existe initialement.

# 138 — Etat pending

Lorsque fetchEtudeData() commence, Redux Toolkit déclenche automatiquement l'état pending : 


.addCase(
    fetchEtudeData.pending,
    (state) => {

        state.loading = true;
        state.error = null;

    }
)

loading devient true. Le composant React peut alors afficher le message Loading.... L'erreur précédente est également supprimée avec state.error = null. Le système est donc prêt à recevoir une nouvelle réponse du backend.

# 139 — Etat fulfilled

Lorsque la requête réussit, Redux Toolkit déclenche l'état fulfilled : 


.addCase(
    fetchEtudeData.fulfilled,
    (state, action) => {

        state.loading = false;

        state.items = action.payload;

    }
)

loading redevient false puisque la requête est terminée. Les données retournées par le thunk sont disponibles dans action.payload. Elles sont ensuite enregistrées dans : state.items. Le composant React reçoit alors automatiquement les nouvelles données grâce à useSelector().

# 140 — Etat rejected

Lorsque la requête échoue, Redux Toolkit déclenche l'état rejected : 


.addCase(
    fetchEtudeData.rejected,
    (state, action) => {

        state.loading = false;

        state.error = action.payload;

    }
)

loading est remis à false car la requête est terminée. Le message d'erreur transmis par rejectWithValue() est récupéré avec action.payload. Il est ensuite stocké dans : state.error. React peut alors afficher cette erreur dans l'interface.

# 141 — Exportation du reducer

À la fin du fichier Redux, le reducer est exporté : 


export default etudeSlice.reducer;

Ce reducer doit ensuite être enregistré dans le store Redux principal. Une fois enregistré, le composant React peut accéder au state avec : 


useSelector(state => state.etude);

Le lien entre le store Redux et le composant EtudeDashboard est ainsi établi.

# 142 — Cycle Redux complet

Le fonctionnement de Redux Toolkit repose sur trois états principaux :

⏳ Pending

La requête commence. loading = true.

✅ Fulfilled

La requête réussit. Les données sont stockées dans items.

❌ Rejected

La requête échoue. L'erreur est stockée dans error.

# 143 — Parcours complet des données

Le parcours complet commence lorsque l'utilisateur ouvre la page Etude Dashboard. React charge le composant EtudeDashboard. Le hook useEffect() est ensuite exécuté. Il déclenche : dispatch(fetchEtudeData()). Redux Toolkit passe alors dans l'état pending. Le thunk utilise Axios pour envoyer une requête GET vers : http://localhost:3000/etude/dashboard. Le backend traite la requête et retourne une réponse JSON. Si la réponse réussit, le thunk retourne response.data.data. Redux déclenche ensuite fulfilled et enregistre les données dans state.items. React récupère ces données avec useSelector(). Les données sont ensuite transformées en chartData. Recharts utilise finalement ce tableau pour construire le graphique.

Axios est responsable de la communication HTTP entre le frontend et le backend. Dans cette fonctionnalité, Axios utilise une requête GET : http://localhost:3000/etude/dashboard. # 148 — Rôle de Recharts

Recharts est utilisé pour transformer les données récupérées en représentation graphique. Les données sont préparées dans chartData. Cette bibliothèque permet donc de transformer les données numériques en une visualisation facilement compréhensible.

# 149 — Rôle de Power BI

Power BI apporte la dimension Business Intelligence au Dashboard Etude. Le rapport est intégré directement dans React grâce à une iframe. Cette intégration permet de combiner deux approches complémentaires. Power BI fournit des visualisations et analyses décisionnelles avancées. React fournit quant à lui une interface personnalisée capable de récupérer les données du backend, d'afficher les prédictions et de produire des graphiques supplémentaires avec Recharts. Le dashboard devient ainsi une interface hybride combinant développement web, analyse de données et Business Intelligence.

# 150 — Architecture complète

L'architecture de cette fonctionnalité peut être résumée en plusieurs couches. Le frontend React contient le composant EtudeDashboard. Le slice Redux contient la logique de récupération des données. createAsyncThunk orchestre l'opération asynchrone. Axios communique avec l'API. Le backend Node.js / Express traite la requête et retourne les données. Redux stocke ensuite les résultats. React récupère les données avec useSelector(). Les données sont transformées en chartData. Recharts produit la visualisation graphique. En parallèle, Power BI fournit le rapport décisionnel intégré. Cette séparation des responsabilités rend l'application plus organisée, évolutive et maintenable.

Le Dashboard Etude à l'étranger représente une fonctionnalité complète combinant développement frontend, gestion d'état, communication backend, visualisation des données, prédiction et Business Intelligence.
