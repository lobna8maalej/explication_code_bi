Sistema de predicción INFO

Integración de varios modelos de Machine Learning desarrollados en Python dentro de una aplicación Web Node.js / Express para generar simultáneamente predicciones para INFO2, INFO3 y GoMyCode.

01

Presentación general del sistema

El sistema de predicción INFO constituye una arquitectura Web que permite integrar varios modelos de Machine Learning desarrollados en Python dentro de una aplicación Node.js y Express. El objetivo principal de esta arquitectura es recibir un conjunto de valores numéricos desde la aplicación Web, transmitir estos datos a Python y utilizar tres modelos diferentes de Machine Learning para generar simultáneamente tres predicciones correspondientes a los modelos INFO2, INFO3 y GoMyCode. Los modelos se entrenan previamente y se guardan en archivos .pkl. El archivo INFO2.pkl corresponde al primer modelo, INFO3.pkl al segundo modelo y gomycode.pkl al tercer modelo. El script Python info.py constituye el motor de predicción. Primero busca los archivos de los modelos en el mismo directorio que el script utilizando os.path y posteriormente carga cada modelo mediante la biblioteca Python pickle. Después de cargar los modelos, el script recupera los datos enviados por Node.js mediante sys.argv. Estos datos se envían en forma de una cadena JSON. Python utiliza entonces json.loads() para convertir esta cadena en una estructura Python, mientras que NumPy transforma los valores en una matriz numérica bidimensional. Esta etapa es importante porque los modelos de Scikit-learn generalmente esperan una matriz que contenga observaciones y características. El programa también verifica que los datos no contengan valores NaN para evitar errores durante la predicción. A continuación, los tres modelos se utilizan mediante el método predict(). El resultado de cada modelo se convierte en un número decimal y se agrupa en un objeto JSON que contiene info2_pred, info3_pred y gomycode_pred. El resultado JSON se envía a Node.js mediante stdout. En el lado JavaScript, el archivo infoService.js utiliza el módulo child_process y su función spawn() para ejecutar el script Python. Los valores recibidos desde el frontend se convierten en JSON mediante JSON.stringify() y se transmiten al programa Python como argumento. Node.js recupera posteriormente la salida estándar de Python en la variable output. Esta salida se analiza mediante JSON.parse() para reconstruir el objeto JavaScript que contiene las tres predicciones. El archivo infoRoute.js expone después una ruta HTTP POST /predict. Esta ruta recupera la propiedad values del cuerpo de la solicitud, verifica que sea un array y después llama a runInfoPrediction(). Finalmente, el resultado se devuelve al frontend mediante una respuesta JSON que contiene una propiedad success y una propiedad data. Por último, el archivo principal del servidor inicializa Express, activa CORS, activa el procesamiento JSON mediante express.json(), registra el router con el prefijo /info y ejecuta el servidor en el puerto 3000. La arquitectura completa permite, por tanto, que el frontend envíe datos a Node.js, que Node.js se comunique con Python, que Python ejecute varios modelos de Machine Learning y que los resultados sean devueltos en formato JSON al dashboard.

02

Script Python de predicción

El archivo info.py representa el motor de Machine Learning del sistema. Su función es cargar los tres modelos guardados, recuperar los datos enviados por Node.js, preparar estos datos en formato numérico y realizar las tres predicciones. El script comienza importando las bibliotecas necesarias. os permite gestionar las rutas de archivos, pickle permite cargar los modelos de Machine Learning guardados, json permite intercambiar datos estructurados entre JavaScript y Python, sys permite recuperar los argumentos enviados por Node.js y NumPy permite construir el array numérico enviado a los modelos. El programa determina posteriormente el directorio del script mediante os.path.dirname(os.path.abspath(__file__)). Este método permite obtener una ruta absoluta fiable, independientemente del directorio desde el cual se ejecute Python. El diccionario files asocia posteriormente cada identificador lógico con su archivo de modelo. El bucle for recorre estos archivos, construye su ruta completa mediante os.path.join(), comprueba su existencia mediante os.path.exists() y los abre mediante pickle.load(). Los modelos cargados se almacenan en el diccionario models. Esta organización permite gestionar varios modelos dentro de una misma estructura y facilita su utilización durante la fase de predicción.

Importación de bibliotecas 

import os
import pickle
import json
import sys
import numpy as np

Estas bibliotecas permiten realizar las diferentes operaciones del script. os gestiona las rutas y archivos, pickle carga nuevamente los modelos Machine Learning guardados, json permite la comunicación estructurada con Node.js, sys recupera los argumentos de la línea de comandos y NumPy prepara los datos numéricos en forma de matriz.

Determinación del directorio 

BASE_DIR = os.path.dirname(
    os.path.abspath(__file__)
)

Esta instrucción permite obtener la ruta absoluta del directorio donde se encuentra info.py. Esto garantiza que los archivos de los modelos puedan localizarse correctamente incluso si Node.js ejecuta Python desde otro directorio.

03

Carga de los tres modelos de Machine Learning

El sistema utiliza tres modelos diferentes de Machine Learning. El diccionario files contiene las correspondencias entre los nombres utilizados en el código y los archivos físicos de los modelos presentes en el directorio Python. El modelo INFO2.pkl está asociado al identificador info2. El modelo INFO3.pkl está asociado al identificador info3. El modelo gomycode.pkl está asociado al identificador gomycode. El bucle recorre cada elemento del diccionario. Para cada modelo, el programa construye su ruta completa y comprueba primero que el archivo exista. Si el archivo no existe, el programa genera una excepción indicando exactamente la ruta que falta. Si el archivo existe, se abre en modo binario mediante open(..., "rb") y pickle.load() vuelve a cargar el objeto de Machine Learning. El modelo cargado se almacena posteriormente en models[key]. Al finalizar este bucle, los tres modelos están disponibles en memoria y pueden utilizarse de manera independiente para realizar las predicciones. 

models = {}

files = {
    "info2": "INFO2.pkl",
    "info3": "INFO3.pkl",
    "gomycode": "gomycode.pkl"
}

Carga de los modelos 

for key, file in files.items():

    path = os.path.join(
        BASE_DIR,
        file
    )

    if not os.path.exists(path):
        raise Exception(
            f"Missing model file: {path}"
        )

    with open(path, "rb") as f:
        models[key] = pickle.load(f)

Recepción y preparación de los datos

Después de cargar los modelos, el script comprueba que se hayan transmitido datos desde Node.js. La condición if len(sys.argv) < 2 permite comprobar la presencia de un argumento adicional. Si no existe ningún argumento, el programa detiene su ejecución e indica que faltan los datos procedentes de Node.js. Cuando los datos están disponibles, se recuperan mediante sys.argv[1]. Node.js transmite un array JavaScript convertido en una cadena JSON. Python utiliza entonces json.loads() para convertir esta cadena JSON en una estructura Python. Después, np.array([ ... ], dtype=float) transforma los valores en números decimales y añade una dimensión adicional para obtener una matriz bidimensional. Este paso es especialmente importante para Scikit-learn, ya que los modelos esperan normalmente una entrada con formato de matriz [número_de_observaciones, número_de_features]. El programa realiza posteriormente una comprobación con np.isnan(input_data).any(). Esta instrucción permite detectar valores numéricos inválidos o ausentes. Si se detecta un valor NaN, se genera una excepción para evitar que el modelo realice una predicción utilizando datos incorrectos. 

if len(sys.argv) < 2:
    raise Exception(
        "Missing input data from Node.js"
    )

input_data = np.array(
    [json.loads(sys.argv[1])],
    dtype=float
)

if np.isnan(input_data).any():
    raise Exception(
        f"Invalid input received: {input_data}"
    )
Preparación: JSON → Python → NumPy → Matriz 2D → Modelos ML
05

Ejecución de las tres predicciones

Una vez preparados los datos, el programa ejecuta los tres modelos de Machine Learning. El diccionario result contiene tres propiedades. La primera propiedad, info2_pred, llama al modelo almacenado en models["info2"] utilizando el método predict(input_data). La segunda propiedad utiliza models["info3"] y produce info3_pred. Finalmente, la tercera utiliza models["gomycode"] y produce gomycode_pred. La notación [0] permite obtener la primera predicción devuelta por el modelo, ya que una predicción de Scikit-learn generalmente se devuelve en forma de array. La función float() convierte posteriormente el resultado en un número Python estándar para facilitar su serialización en JSON. El programa puede producir tres resultados diferentes a partir del mismo conjunto de variables de entrada. Esto permite al dashboard comparar las predicciones de los diferentes modelos y mostrarlas simultáneamente al usuario. 

result = {

    "info2_pred":
        float(
            models["info2"]
            .predict(input_data)[0]
        ),

    "info3_pred":
        float(
            models["info3"]
            .predict(input_data)[0]
        ),

    "gomycode_pred":
        float(
            models["gomycode"]
            .predict(input_data)[0]
        )
}

Resultado JSON y gestión de errores

Después de ejecutar los modelos, el programa también muestra información de seguimiento en stderr. Esta separación es importante porque los mensajes de depuración no se envían a la salida estándar utilizada para el JSON. El programa muestra primero un título indicando el inicio de los resultados y después recorre el diccionario result para mostrar cada predicción con cuatro cifras decimales. A continuación, la respuesta destinada a Node.js se genera mediante json.dumps(result) y se muestra mediante print(). De esta manera, Node.js puede recuperar directamente la cadena JSON. Toda la parte de predicción se encuentra dentro de un bloque try. Si se produce un error durante la ejecución de un modelo, el programa entra en el bloque except. Entonces crea un objeto JSON que contiene una propiedad error con el mensaje de la excepción. Finalmente, sys.exit(1) indica al proceso Node.js que el programa Python terminó con un error. 

print(json.dumps(result))

Servicio Node.js y comunicación con Python

El archivo infoService.js constituye el intermediario entre la aplicación Node.js y el script Python. Su función es recibir los valores procedentes de la ruta Express, ejecutar el programa Python y recuperar los resultados de las predicciones. El módulo child_process proporciona la función spawn(), que permite a Node.js crear un proceso externo. El módulo path permite construir la ruta hacia info.py. La función runInfoPrediction(values) devuelve una Promise, lo que permite que la ruta Express utilice await y espere hasta que finalice la ejecución de Python. Los valores recibidos se convierten en una cadena JSON mediante JSON.stringify(values). Este paso permite transmitir un array JavaScript completo a Python como un único argumento. La función spawn() ejecuta posteriormente Python con la ruta del script y la cadena JSON. Node.js escucha stdout para recuperar la respuesta generada por Python. Los datos recibidos se agregan progresivamente a la variable output. Paralelamente, stderr recupera posibles mensajes de error o información de depuración. Cuando el proceso Python finaliza, el evento close proporciona el código de salida. Si este código es diferente de cero, el servicio considera que Python encontró un error y rechaza la Promise. Si la ejecución es correcta, Node.js utiliza JSON.parse(output) para transformar el resultado JSON de Python en un objeto JavaScript. El objeto obtenido se transmite entonces a la ruta Express mediante resolve(result).

Conversión de los datos a JSON 

const inputJson =
    JSON.stringify(values);

JSON.stringify() transforma el array JavaScript en una cadena JSON. Esta cadena puede transmitirse como argumento al programa Python.

Ejecución de Python 

const py = spawn("python", [
    pyPath,
    inputJson
]);

Esta instrucción ejecuta el programa Python y le transmite los datos de entrada. Node.js actúa así como puente entre la API Web y el motor de Machine Learning.

Recuperación de stdout 

py.stdout.on("data", (data) => {
    output += data.toString();
});

La salida estándar del programa Python se recupera progresivamente y se almacena en output. Esta variable contiene finalmente el JSON generado por info.py.

Conversión del JSON 

const result = JSON.parse(output);

resolve(result);

JSON.parse() transforma la cadena producida por Python en un objeto JavaScript. Node.js puede entonces transmitir este objeto a Express.

08

Ruta Express de predicción

El archivo infoRoute.js define el endpoint que permite al frontend solicitar una predicción. Express se importa y se crea un router mediante express.Router(). A continuación se importa el servicio runInfoPrediction() para permitir que la ruta ejecute el modelo Python. La ruta utiliza el método HTTP POST con el camino /predict. Cuando llega una solicitud, el programa recupera values desde req.body. Una primera validación comprueba que esta variable exista y que sea un array mediante Array.isArray(values). Si los datos son incorrectos, la API devuelve inmediatamente un estado 400 con el mensaje Invalid input. Cuando los datos son válidos, la ruta llama a await runInfoPrediction(values). El servidor espera entonces a que termine el proceso Python y recupera las tres predicciones. Express devuelve posteriormente una respuesta JSON que contiene success: true y data: result. Si se produce un error en cualquier etapa, el bloque catch captura el error y devuelve una respuesta HTTP 500. Esta ruta constituye, por tanto, el punto de comunicación entre el frontend y el sistema de Machine Learning.

Endpoint

POST /info/predict

Validación de los datos 

const { values } = req.body;

if (!values || !Array.isArray(values)) {

}

res.json({

El frontend recibe así una estructura JSON que contiene los resultados de los tres modelos. Puede utilizar esta información para mostrar tarjetas KPI, gráficos, tablas comparativas u otras visualizaciones dentro del dashboard.

09

Servidor Express principal

El archivo principal inicializa la aplicación Web Node.js. Se importa el framework Express y se crea una instancia de la aplicación mediante express(). El middleware cors() se activa para permitir la comunicación entre el frontend y el backend cuando se ejecutan en diferentes orígenes. El middleware express.json() permite al servidor procesar solicitudes que contienen datos JSON en su cuerpo. El puerto utilizado por el servidor es 3000. A continuación, se registra el router infoRoute mediante app.use("/info", ...). Esto significa que todas las rutas definidas en el router estarán disponibles utilizando el prefijo /info. Como el router contiene una ruta POST /predict, el endpoint final es POST /info/predict. Finalmente, app.listen() inicia el servidor y muestra un mensaje en la consola. El backend queda así disponible para el frontend y puede recibir los datos necesarios para realizar las predicciones. 

const express = require("express");
const cors = require("cors");

const app = express();

app.use(cors());
app.use(express.json());

const PORT = 3000;

app.use(
    "/info",
    require("./Routes/infoRoute")
);

app.listen(PORT, () => {

    console.log(
        `Server running on http://localhost:${PORT}`
    );

});

Arquitectura completa

La arquitectura completa del sistema funciona mediante una cadena de comunicación claramente separada. Todo comienza con el frontend o dashboard, que prepara las variables necesarias y las envía a la API Express mediante una solicitud HTTP POST. Express recibe esta solicitud en /info/predict y recupera el array values desde req.body. Después de la validación, Express llama al servicio runInfoPrediction(). El servicio Node.js transforma los valores en JSON mediante JSON.stringify() y utiliza spawn() para ejecutar el programa info.py. Python recibe entonces los valores mediante sys.argv. El script comprueba la presencia de los datos, los convierte desde JSON utilizando json.loads() y crea una matriz NumPy bidimensional. Los tres modelos INFO2.pkl, INFO3.pkl y gomycode.pkl se cargan al iniciar el script mediante pickle.load(). Cada modelo recibe posteriormente la misma matriz de entrada y utiliza predict() para calcular su propia predicción. Los tres resultados se agrupan en un objeto JSON. Python escribe este resultado en stdout. Node.js recupera esta salida y utiliza JSON.parse() para convertir el JSON en un objeto JavaScript. Posteriormente devuelve este objeto al router Express. Express construye finalmente la respuesta HTTP que contiene success: true y data. El frontend puede utilizar entonces las tres predicciones para mostrarlas en su interfaz. Esta arquitectura presenta la ventaja de separar claramente las responsabilidades: el frontend se encarga de la presentación, Express gestiona la API, Node.js coordina la comunicación, Python ejecuta el Machine Learning, NumPy prepara los datos y los archivos PKL contienen los modelos entrenados.

Función de las tecnologías

Cada tecnología utilizada en esta arquitectura tiene una función específica. Python constituye el entorno de ejecución del Machine Learning. Pickle permite guardar y cargar nuevamente los modelos entrenados desde los archivos PKL. NumPy prepara los datos numéricos en una estructura compatible con Scikit-learn. JSON proporciona el formato de intercambio de datos entre Node.js y Python. El módulo sys permite transmitir parámetros al script Python. Node.js constituye el backend JavaScript y coordina el sistema. child_process proporciona spawn(), que permite ejecutar Python. Express permite crear la API REST y gestionar las rutas HTTP. CORS permite la comunicación entre el frontend y el backend. Finalmente, los archivos INFO2.pkl, INFO3.pkl y gomycode.pkl contienen los modelos de Machine Learning previamente entrenados. La combinación de estas tecnologías permite transformar un modelo de Data Science en un servicio que puede ser utilizado desde una aplicación Web.

Ejemplo de comunicación con la API

Para utilizar el sistema, el frontend debe enviar una solicitud POST a /info/predict. El cuerpo de la solicitud debe contener una propiedad values que incluya un array numérico. Por ejemplo, una solicitud puede enviar varias variables en forma de array. Express recupera este array mediante req.body, comprueba su validez y después lo transmite al servicio Node.js. El servicio convierte posteriormente este array en JSON y lo envía al programa Python. Python transforma el JSON en un array NumPy y transmite este array a los tres modelos. Finalmente, los tres resultados se agrupan en una respuesta JSON.

Conclusión

El sistema INFO representa una integración completa entre Machine Learning y desarrollo Web. Tres modelos entrenados se guardan en los archivos INFO2.pkl, INFO3.pkl y gomycode.pkl. El script Python info.py carga estos modelos mediante Pickle, recupera los datos enviados por Node.js, los transforma en un array NumPy y ejecuta las tres predicciones utilizando el método predict(). Los resultados se agrupan posteriormente en un objeto JSON y se transmiten a Node.js mediante stdout. El servicio infoService.js utiliza child_process y spawn() para ejecutar Python y recuperar los resultados. Express proporciona posteriormente la API REST mediante el endpoint POST /info/predict. El frontend puede comunicarse únicamente con la API sin necesidad de ejecutar Python directamente. Esta arquitectura permite separar claramente las diferentes responsabilidades manteniendo una comunicación sencilla basada en JSON. El funcionamiento global puede resumirse mediante la siguiente cadena: Datos → Express → Node.js → spawn() → Python → NumPy → INFO2/INFO3/GoMyCode → predict() → JSON → Node.js → Express → Dashboard . Esta organización hace que el sistema sea modular, comprensible y escalable, y permite integrar varios modelos de Data Science en una aplicación Web destinada al análisis y a la toma de decisiones.
