Présentation générale du système

Le système présenté dans cette documentation constitue une architecture complète permettant d'intégrer un modèle de Machine Learning développé avec Python et XGBoost dans une application Web basée sur Node.js et Express. L'objectif principal est de recevoir depuis le frontend un ensemble de caractéristiques numériques, de transmettre ces données au programme Python, de les préparer correctement, puis d'utiliser un modèle XGBoost afin de calculer une prédiction ainsi qu'un niveau de confiance associé à cette prédiction. Le système utilise un fichier model.pkl permettant de sauvegarder le modèle Machine Learning. Lorsque ce fichier n'existe pas encore, le programme Python crée automatiquement un jeu de données synthétique avec la fonction make_classification(), sépare les données en données d'entraînement et de test avec train_test_split(), crée un modèle XGBClassifier, entraîne ce modèle avec fit() puis sauvegarde le modèle dans le fichier model.pkl grâce à pickle. Lorsque le fichier existe déjà, le programme ne réentraîne pas le modèle et passe directement à la phase de prédiction. Il recharge alors le modèle avec pickle.load(), lit les données JSON transmises par Node.js à travers stdin, vérifie la présence du champ features, contrôle que celui-ci est bien une liste et vérifie que cette liste contient exactement 20 caractéristiques. Les valeurs sont ensuite converties en nombres flottants et placées dans un tableau NumPy à deux dimensions. Le modèle XGBoost utilise ensuite predict_proba() afin de calculer les probabilités associées aux trois classes. La fonction np.argmax() permet de sélectionner la classe ayant la probabilité la plus élevée et np.max() permet de récupérer la probabilité maximale afin de calculer la confiance du modèle. Python retourne ensuite un objet JSON contenant la prédiction, la confiance et le pourcentage de confiance. Du côté Node.js, le module child_process et la fonction spawn() permettent de lancer le script Python comme processus externe. Node.js écrit les données JSON dans stdin du processus Python et récupère le résultat dans stdout. Le service JavaScript convertit ensuite la réponse JSON en objet JavaScript avec JSON.parse(). Express expose enfin une route HTTP POST /predict qui reçoit les caractéristiques depuis le frontend, appelle le service de prédiction et retourne directement le résultat au client. Le serveur Express active également CORS pour autoriser les requêtes provenant du frontend exécuté sur http://localhost:5173 et utilise express.json() pour analyser automatiquement les requêtes JSON. L'architecture complète permet ainsi de séparer clairement le frontend, l'API Express, le service Node.js et le moteur Machine Learning Python.

NumPy permet de transformer les valeurs reçues en tableau numérique compatible avec le modèle. os permet de manipuler les chemins de fichiers et de vérifier l'existence de model.pkl. traceback est utilisé pour récupérer des informations détaillées lorsqu'une exception se produit. xgboost fournit XGBClassifier, le modèle de classification utilisé dans cette application. Création automatique du modèle

Une particularité importante de ce système est sa capacité à créer automatiquement le modèle lorsqu'il n'existe pas encore. La condition if not os.path.exists(MODEL_PATH) vérifie si le fichier model.pkl est absent. Si le fichier n'existe pas, le programme entre dans une phase d'entraînement. Cette logique permet d'éviter de dépendre d'un modèle déjà présent lors du premier lancement. Le programme affiche d'abord un message de suivi dans stderr afin de signaler que le modèle est en cours de création. La fonction make_classification() génère ensuite un jeu de données synthétique comprenant 200 observations et 20 caractéristiques. Parmi ces caractéristiques, 10 sont informatives et aucune caractéristique redondante n'est générée. Le système utilise trois classes différentes et random_state=42 permet d'obtenir une génération reproductible. Les données sont ensuite divisées en deux parties avec train_test_split(). 80 % des données sont utilisées pour l'entraînement et 20 % pour le test grâce à test_size=0.2. Le modèle XGBClassifier est ensuite créé avec une configuration adaptée à une classification multiclasse. L'option objective="multi:softprob" indique que le modèle doit produire des probabilités pour les différentes classes. Le paramètre num_class=3 indique que le problème contient trois classes. Le paramètre eval_metric="mlogloss" définit la métrique utilisée pour évaluer la perte de classification multiclasse. Le modèle est ensuite entraîné avec model.fit(X_train, y_train). Après l'entraînement, le modèle complet est sauvegardé dans model.pkl avec pickle.dump(). Une réponse JSON indiquant que le modèle a été entraîné et sauvegardé est alors envoyée. Enfin, sys.exit(0) arrête proprement le programme puisque le lancement initial avait uniquement pour objectif de créer le modèle. 

if not os.path.exists(MODEL_PATH):

    X, y = make_classification(
        n_samples=200,
        n_features=20,
        n_informative=10,
        n_redundant=0,
        n_classes=3,
        random_state=42
    )

X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,

)

La séparation permet donc d'utiliser une partie des données pour apprendre les relations entre les caractéristiques et les classes et de conserver une autre partie pour tester le comportement du modèle. Dans ce script, les variables X_test et y_test sont préparées mais aucune métrique de test n'est calculée explicitement. L'objectif principal du code est ici de créer et sauvegarder le modèle afin qu'il puisse ensuite être utilisé par le système de prédiction. 

model = xgb.XGBClassifier(
    objective="multi:softprob",
    num_class=3,
    eval_metric="mlogloss"
)

model.fit(X_train, y_train)

Chargement du modèle existant

Lorsque le fichier model.pkl existe déjà, la phase de création du modèle n'est pas exécutée. Le programme passe directement à la phase de prédiction. Il ouvre le fichier en mode binaire avec open(MODEL_PATH, "rb") puis recharge l'objet Machine Learning grâce à pickle.load(). Cette approche permet de réutiliser le modèle déjà entraîné sans devoir recommencer l'apprentissage à chaque requête. C'est une séparation importante entre la phase d'entraînement et la phase d'utilisation du modèle. 

with open(MODEL_PATH, "rb") as f:
    model = pickle.load(f)

Réception et validation des données

Pour la phase de prédiction, le programme Python utilise sys.stdin.read() afin de lire les données envoyées par Node.js. Contrairement à une communication utilisant sys.argv, les données sont ici transmises directement dans le flux d'entrée standard du processus Python. La méthode strip() permet de supprimer les espaces et retours à la ligne inutiles. Le programme vérifie ensuite que des données ont bien été reçues. Si la chaîne est vide, une exception No JSON data received est générée. Lorsque les données sont présentes, json.loads() transforme la chaîne JSON en objet Python. Le programme vérifie ensuite que l'objet contient bien une propriété features. Cette propriété représente le tableau des caractéristiques utilisées pour la prédiction. Une deuxième validation vérifie que features est réellement une liste. Enfin, le programme vérifie que cette liste contient exactement 20 valeurs. Cette vérification est essentielle car le modèle a été entraîné avec 20 caractéristiques. Une différence entre le nombre de variables d'entrée et le nombre de variables attendu par le modèle provoquerait une erreur lors de la prédiction. 

raw = sys.stdin.read().strip()

if not raw:
    raise ValueError(
        "No JSON data received"
    )

data = json.loads(raw)

if "features" not in data:
    raise ValueError(
        "features field missing"
    )

features = data["features"]

if not isinstance(features, list):
    raise ValueError(
        "features must be a list"
    )

if len(features) != 20:
    raise ValueError(
        f"Expected 20 features but received {len(features)}"
    )
⚠️ Le modèle attend exactement 20 features pour effectuer une prédiction.

Conversion des caractéristiques avec NumPy

Après validation, les caractéristiques sont converties en valeurs numériques avec NumPy. Chaque valeur est transformée en float, puis l'ensemble est placé dans une liste imbriquée afin de créer une matrice contenant une seule observation et 20 caractéristiques. Le type np.float32 est utilisé pour obtenir un tableau numérique compatible avec le modèle XGBoost. Cette étape permet de passer d'une liste JSON reçue par l'API à une structure matricielle directement exploitable par l'algorithme Machine Learning. 

features = np.array(
    [[float(x) for x in features]],
    dtype=np.float32
)

Calcul de la prédiction et de la confiance

Une fois les données converties en matrice NumPy, le modèle XGBoost est prêt à effectuer la prédiction. Le programme utilise model.predict_proba(features) plutôt que simplement model.predict(). Cette méthode est particulièrement intéressante car elle retourne les probabilités associées aux différentes classes. Dans ce système, trois classes sont définies. L'expression [0] permet de récupérer le tableau de probabilités correspondant à l'unique observation envoyée au modèle. La fonction np.argmax(probabilities) recherche ensuite l'indice de la probabilité la plus élevée. Cet indice représente la classe prédite par le modèle. La fonction np.max(probabilities) récupère la valeur de probabilité maximale. Cette valeur représente ici le niveau de confiance associé à la classe sélectionnée. Le programme convertit cette valeur en nombre Python standard avec float(), puis calcule également un pourcentage en multipliant la confiance par 100. La fonction round() permet de limiter le nombre de chiffres affichés. Le résultat final contient donc trois informations principales : la classe prédite, la confiance sous forme décimale et la confiance sous forme de pourcentage. 

probabilities = model.predict_proba(
    features
)[0]

prediction = int(
    np.argmax(probabilities)
)

confidence = float(
    np.max(probabilities)
)

Construction de la réponse 

print(json.dumps({
    "success": True,
    "prediction": prediction,
    "confidence": round(confidence, 4),
    "percentage": round(
        confidence * 100,
        2
    )
}))

Gestion des erreurs Python

L'ensemble de la phase de prédiction est placé dans un bloc try. Cette organisation permet d'intercepter les erreurs pouvant survenir pendant le chargement du modèle, la lecture des données, la conversion numérique ou l'exécution de la prédiction. Lorsqu'une exception se produit, le bloc except construit une réponse JSON contenant success: false, le message de l'erreur et le résultat de traceback.format_exc(). Le traceback fournit des informations détaillées sur l'endroit où l'erreur s'est produite, ce qui facilite le développement et le débogage. Le programme termine ensuite le processus avec sys.exit(1). Le code de sortie différent de zéro indique à Node.js qu'une erreur est survenue. 

except Exception as e:

Service Node.js et communication avec Python

Le fichier predictService.js constitue la couche intermédiaire entre Express et le programme Python. Il utilise le module natif child_process de Node.js ainsi que spawn() afin de créer un processus Python indépendant. La fonction predict(features) retourne une Promise, ce qui permet à la route Express d'attendre proprement le résultat avec await. Le chemin du script Python est construit avec path.resolve(). Cette méthode permet d'obtenir un chemin absolu vers model_service.py. Le processus Python est ensuite lancé avec spawn("python", [pythonPath]). Node.js crée deux variables, result et error, destinées respectivement à recevoir la sortie standard et les messages d'erreur. L'événement python.stdout.on("data") récupère les données envoyées par Python dans stdout et les ajoute progressivement à la variable result. En parallèle, python.stderr.on("data") récupère les messages de diagnostic envoyés par Python. Cette séparation permet de conserver le résultat JSON propre dans stdout tout en affichant les informations de debug dans stderr. L'événement python.on("error") permet de détecter une erreur lors du lancement du processus Python. Enfin, lorsque Python termine son exécution, l'événement close est appelé. Le service vérifie alors que la sortie n'est pas vide, puis utilise JSON.parse(result) afin de transformer le JSON Python en objet JavaScript. Si l'analyse réussit, la Promise est résolue avec resolve(parsedResult). Si une erreur JSON se produit, la Promise est rejetée avec un message détaillé. 

const { spawn } = require("child_process");
const path = require("path");

const predict = (features) => {

    return new Promise((resolve, reject) => {

        const pythonPath = path.resolve(
            __dirname,
            "../../python/model_service.py"
        );

        const python = spawn(
            "python",
            [pythonPath]
        );

    });

};

Envoi des données vers Python 

python.stdin.write(
    JSON.stringify({
        features: features
    })
);

python.stdin.end();

Ici, Node.js convertit les caractéristiques en JSON grâce à JSON.stringify(), puis écrit cette chaîne dans le flux d'entrée standard du processus Python avec stdin.write(). La fonction stdin.end() indique que Node.js a terminé l'envoi des données. Python peut alors lire l'intégralité du contenu avec sys.stdin.read().

Récupération du résultat Python 

python.stdout.on("data", (data) => {
    result += data.toString();
});

Python écrit son résultat JSON dans stdout. Node.js récupère ce résultat progressivement et le stocke dans la variable result.

Conversion JSON 

const parsedResult = JSON.parse(result);

resolve(parsedResult);

JSON.parse() transforme la chaîne JSON reçue depuis Python en objet JavaScript exploitable par Express.

Route Express de prédiction

Le fichier predictRoutes.js définit l'endpoint HTTP permettant au frontend d'accéder au système de prédiction. Express crée un routeur avec express.Router(), puis le service predict est importé depuis predictService. La route utilise la méthode HTTP POST avec le chemin /. Comme ce routeur est ensuite monté dans le serveur principal avec le préfixe /predict, l'endpoint final accessible au frontend devient POST /predict. Lorsqu'une requête arrive, le serveur affiche le corps reçu dans la console avec console.log. Le tableau features est ensuite récupéré depuis req.body.features et transmis à la fonction predict(). Comme cette fonction retourne une Promise, la route utilise await pour attendre le résultat Python. Une fois le résultat disponible, Express l'envoie directement au frontend avec res.json(). Si une erreur survient pendant la communication avec Python ou pendant le traitement, le bloc catch intercepte l'erreur et renvoie un statut HTTP 500 accompagné d'un objet JSON indiquant que l'opération a échoué.

POST /predict 
router.post("/", async (req, res) => {

    console.log("BODY:", req.body);

    try {

        const result =
            await predict(req.body.features);

        res.json(result);

    } catch (error) {

        console.error(error);

        res.status(500).json({
            success: false,
            error: error.toString()
        });

    }

});

Serveur Express principal

Le fichier principal du backend initialise le serveur Express. La bibliothèque express est importée afin de créer l'application et la bibliothèque cors est utilisée pour autoriser les communications provenant du frontend. Le middleware cors() est configuré avec l'origine http://localhost:5173, ce qui correspond à l'adresse du frontend pendant le développement. Le middleware express.json() est ensuite activé afin qu'Express puisse automatiquement analyser les requêtes contenant des données JSON. Le port est défini avec process.env.PORT || 3000. Cela signifie que si une variable d'environnement PORT existe, elle sera utilisée ; sinon, le serveur utilisera le port 3000. Le routeur predictRoutes est ensuite importé et enregistré avec le préfixe /predict. Enfin, app.listen() démarre le serveur et affiche dans la console le port utilisé. 

const express = require("express");

    "/predict",
    predictRoutes

app.listen(PORT, () => {

        `Server running on port ${PORT}`

Architecture complète du système

L'architecture complète repose sur une séparation claire entre l'interface utilisateur, l'API Web, le service Node.js et le moteur Machine Learning. Tout commence avec le frontend qui collecte ou génère les 20 caractéristiques nécessaires à la prédiction. Le frontend envoie ensuite une requête POST vers /predict. Express reçoit cette requête grâce au routeur predictRoutes. La route récupère req.body.features puis appelle le service predict(). Ce service utilise child_process.spawn() pour lancer le script Python. Node.js transmet les caractéristiques au processus Python en utilisant stdin. Python lit ces données avec sys.stdin.read(), les convertit depuis JSON et vérifie qu'elles contiennent exactement 20 features. Les valeurs sont transformées en matrice NumPy puis transmises au modèle XGBoost chargé depuis model.pkl. Le modèle utilise predict_proba() pour calculer les probabilités des trois classes. Python identifie la classe ayant la probabilité maximale avec np.argmax() et calcule la confiance correspondante avec np.max(). Le résultat est sérialisé en JSON et écrit dans stdout. Node.js récupère cette sortie, la transforme avec JSON.parse() puis transmet l'objet obtenu à Express. Express renvoie enfin la réponse JSON au frontend. Le dashboard peut alors afficher la classe prédite, le niveau de confiance et le pourcentage associé. Cette organisation permet donc au frontend de communiquer uniquement avec une API Web sans avoir besoin d'exécuter directement Python ou XGBoost.

Explication à donner lors de la présentation

🎤 Exemple d'explication orale

« Dans cette partie de mon projet, j'ai intégré un modèle de Machine Learning XGBoost dans une application Web développée avec Node.js et Express.

Le modèle est utilisé pour effectuer une classification en trois classes. Il travaille avec 20 caractéristiques en entrée. Le modèle est sauvegardé dans un fichier model.pkl afin de pouvoir être réutilisé sans devoir être entraîné à chaque prédiction.

Lors du premier lancement, si le fichier model.pkl n'existe pas, mon script Python génère automatiquement des données synthétiques avec make_classification(). Les données sont ensuite séparées avec train_test_split() et un modèle XGBClassifier est entraîné avec fit().

Une fois l'entraînement terminé, le modèle est sauvegardé avec pickle.dump(). Lors des exécutions suivantes, le modèle est simplement chargé avec pickle.load().

Pour effectuer une prédiction, le frontend envoie les 20 caractéristiques à mon API Express avec une requête POST vers /predict.

Node.js récupère les données et utilise le module child_process avec la fonction spawn() pour lancer le script Python.

Les données sont envoyées à Python dans stdin au format JSON. Python lit ces données avec sys.stdin.read(), vérifie qu'il y a bien 20 caractéristiques et les convertit en tableau NumPy.

Ensuite, le modèle XGBoost utilise predict_proba() pour calculer les probabilités des trois classes. Je récupère la classe ayant la probabilité maximale avec np.argmax() et je récupère le niveau de confiance avec np.max().

Python retourne ensuite un résultat JSON contenant la prédiction, la confiance et le pourcentage de confiance.

Node.js récupère cette réponse grâce à stdout puis utilise JSON.parse() pour transformer la réponse Python en objet JavaScript.

Enfin, Express retourne ce résultat au frontend afin que le dashboard puisse afficher la classe prédite et le niveau de confiance.

L'intérêt de cette architecture est de séparer clairement les responsabilités : le frontend s'occupe de l'interface, Express de l'API, Node.js de l'orchestration, Python et XGBoost du Machine Learning, NumPy de la préparation des données et Pickle de la sauvegarde du modèle.

Cette architecture permet donc d'intégrer un modèle Machine Learning Python dans une application Web JavaScript tout en gardant une communication claire entre les différentes couches du système. »

Conclusion

Le système présenté constitue une intégration complète entre Machine Learning et développement Web. Le modèle XGBoost est entraîné lors du premier lancement lorsque le fichier model.pkl est absent, puis sauvegardé avec Pickle afin d'être réutilisé lors des prédictions suivantes. Le programme Python vérifie les données reçues, contrôle la présence des 20 features, convertit les valeurs en matrice NumPy et utilise predict_proba() pour obtenir les probabilités des trois classes. La classe ayant la probabilité maximale est sélectionnée comme prédiction et cette probabilité est utilisée comme niveau de confiance. Node.js assure ensuite la communication avec Python grâce au module child_process et à la fonction spawn(). Les données sont envoyées par stdin et les résultats sont récupérés par stdout. Express expose une API REST avec l'endpoint POST /predict afin de permettre au frontend d'utiliser le modèle sans communiquer directement avec Python. L'ensemble peut être résumé par la chaîne suivante : Frontend → Express → predictService → spawn() → stdin → Python → NumPy → XGBoost → predict_proba() → JSON → stdout → Node.js → Express → Dashboard. Cette architecture permet ainsi de transformer un modèle Machine Learning développé en Python en un service accessible depuis une application Web moderne.
