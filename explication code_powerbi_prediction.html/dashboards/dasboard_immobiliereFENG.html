🏠 Real Estate Dashboard — Code Explanation

Technical documentation explaining how Redux Toolkit, Axios, React, Chart.js and Power BI work.

# 47 — Real Estate Data Management with Redux Toolkit and React

In this part of the project, a real estate data management system has been developed using several complementary frontend technologies, including React, Redux Toolkit, Axios, Chart.js and Power BI. The main objective of this functionality is to allow the user to display a real estate dashboard containing a Power BI report, a chart representing real estate prices and a feature allowing real estate data to be inserted into the backend. The architecture is based on a clear separation between data management and data display. Redux Toolkit is used to centralize the state related to real estate data insertion, while React is responsible for the user interface and interactions. Axios handles HTTP communication between the frontend and the Node.js/Express backend. When a user clicks the "Insert data" button, the handleInsert() function prepares an array containing several real estate properties and then triggers the Redux action insertImmobilier(). This action is created with createAsyncThunk() and sends an HTTP POST request to http://localhost:3000/insert. The backend then receives the data and processes it. Redux Toolkit automatically manages the different states of the asynchronous operation with pending, fulfilled and rejected. When the insertion starts, the loading property becomes true. When the insertion succeeds, Redux retrieves the status, message and number of processed rows returned by the backend. In case of an error, the corresponding message is stored in error. The React component then uses useSelector() to retrieve this information from the Redux store and display the result to the user. At the same time, Chart.js is used to graphically display the prices of two real estate properties, a house and an apartment, while an iframe allows a Power BI report to be integrated directly into the interface. This architecture therefore combines Business Intelligence with Power BI, graphical visualization with Chart.js, state management with Redux Toolkit and backend communication through Axios on the same page.

# 48 — Importing Redux Toolkit and Axios

The Redux file begins by importing two essential Redux Toolkit features: createSlice and createAsyncThunk. createSlice is used to create a specific part of the Redux store dedicated to managing real estate data. It allows the developer to define the slice name, its initial state and the logic associated with different actions. createAsyncThunk is used to create an asynchronous action capable of performing an operation that requires time, such as an HTTP request to a backend server. The code also imports Axios with import axios from "axios". Axios is a JavaScript library used to send HTTP requests. In this project, Axios is used to send real estate data from the React frontend to the Node.js/Express backend. The combination of Redux Toolkit and Axios therefore makes it possible to create organized communication between the user interface and the backend API.

# 49 — Creating the insertImmobilier Asynchronous Action

The main action in the Redux file is insertImmobilier. It is created using createAsyncThunk(). The first parameter, "immobilier/insertImmobilier", corresponds to the Redux action type and allows this operation to be identified within the application. The second parameter is an asynchronous function that receives the real estate data in the data variable. The function then uses a try/catch block to properly handle successful or failed communication with the server. Inside the try block, Axios uses axios.post("http://localhost:3000/insert", data) to send an HTTP POST request to the backend. The data variable contains the real estate information prepared in the React component. When the server responds, the response is stored in the res variable. res.data contains the information returned by the backend. This value is then returned by the function with return res.data. It automatically becomes the payload of the fulfilled action when the operation succeeds. In the catch block, if Axios encounters an error, the code uses rejectWithValue() to transmit the error to the Redux reducer. The expression err.response.data allows the application to retrieve the error information sent by the backend. This organization therefore makes it possible to properly manage communication between the frontend and backend.

# 50 — Creating the Real Estate Slice

The code then creates the Redux slice using createSlice(). The slice is named "immobilier" through the name property. It represents a part of the global store dedicated to the real estate functionality. The initial state contains several properties: status, message, rows, loading and error. The status property is initially set to null and will be used to receive the status returned by the backend after the insertion. message initially contains an empty string and will be used to display the message returned by the server. rows is initialized to zero and represents the number of processed or inserted rows. The loading property is initially set to false, which means that no insertion operation is in progress when the application starts. Finally, error is initialized to null so that a possible error can be stored. The slice therefore centralizes all the information necessary to monitor the insertion operation.

# 51 — Managing the Pending State

When the user clicks the insertion button, the insertImmobilier action is sent to Redux using dispatch(). Redux Toolkit automatically triggers the pending state at the beginning of the asynchronous operation. The code .addCase(insertImmobilier.pending, (state) => { ... }) defines what should happen while the operation is loading. The state.loading property is then set to true. This indicates to the React interface that an insertion is currently in progress. The code also sets state.error = null, which removes a previous error before starting a new operation. In the React component, the loading value is used to temporarily disable the button and change its text. Thus, during the insertion, the user sees "Inserting..." instead of "Insert data". This logic also prevents the user from clicking the button multiple times during the same operation.

# 52 — Managing the Fulfilled State

When the POST request to the backend succeeds, Redux Toolkit automatically triggers the fulfilled state. The code then retrieves the information returned by the server through action.payload. The first instruction is state.loading = false, which indicates that the insertion is complete. The code then retrieves the status returned by the backend with state.status = action.payload.status. The message returned by the server is stored in state.message = action.payload.message. Finally, the number of processed rows is stored with state.rows = action.payload.rows. Thanks to this logic, the frontend can accurately display the result of the operation. For example, if the backend returns a success status, a message confirming the insertion and the number of inserted rows, this information becomes available in the Redux store. React then retrieves it using useSelector() to display it to the user.

# 53 — Managing the Rejected State

When the Axios request fails, Redux Toolkit triggers the rejected state. This situation may occur if the backend server is stopped, if the API address is incorrect, if a server error occurs or if another error prevents the insertion. In this situation, the code sets state.loading back to false, because the operation is finished even though it failed. The error is then retrieved with action.payload.message and stored in state.error. The React component can then display this error in the interface using the condition {error && ...}. This handling therefore allows the user to be clearly informed when an insertion cannot be performed. The entire asynchronous operation cycle is handled by Redux Toolkit: pending at the start, fulfilled in case of success and rejected in case of an error.

# 54 — Exporting the Reducer

At the end of the Redux file, the code uses export default immobilierSlice.reducer. This instruction exports the reducer created by createSlice(). This reducer must then be added to the application's main Redux store. Once registered in the store, it becomes accessible to the React component through useSelector(), and actions can be triggered through useDispatch(). This organization therefore makes it possible to centralize all state logic related to the insertion of real estate data in the immobilier slice.

# 55 — Importing React Features

The ImmobilierDashboard component begins by importing React as well as the required Redux tools. useDispatch allows the component to send actions to Redux, while useSelector allows it to retrieve data from the store. The component also imports the insertImmobilier action from the Redux file immobilierSlice. This action will be used when the user clicks the insertion button. The CSS file ImmobilierDashboard.css is also imported in order to separate presentation logic from JavaScript logic.

# 56 — Importing and Configuring Chart.js

The component also uses the Chart.js library with the React Bar component provided by react-chartjs-2. This library makes it possible to represent real estate data as a chart. Several Chart.js elements are imported: CategoryScale for the axis containing the categories, LinearScale for the numerical axis, BarElement for the chart bars, Title for title management, Tooltip for displaying information when hovering and Legend for the legend. These elements are then registered using ChartJS.register(). This step is necessary so that Chart.js can correctly use these components in the chart. The project can therefore create a bar chart displaying the prices associated with different types of real estate properties.

# 57 — Creating the ImmobilierDashboard Component

The ImmobilierDashboard() function represents the main page of the real estate dashboard. It combines several features: displaying the Power BI report, the real estate price chart, the insertion button and the display of results returned by the backend. The component therefore acts as the presentation layer. It receives information from Redux and transforms it into visible elements in the interface. The user can therefore view the real estate information and launch an insertion operation without having to communicate directly with the backend API.

# 58 — Using useDispatch

The code uses const dispatch = useDispatch() to obtain the function used to send Redux actions. This function is later used in handleInsert() with the instruction dispatch(insertImmobilier(data)). This means that React prepares the data and then asks Redux to execute the asynchronous insertion action. The component does not directly perform the Axios request. Communication with the backend is centralized in the Redux slice. This separation makes the code more organized and facilitates application maintenance.

# 59 — Retrieving State with useSelector

The component then retrieves the information from the real estate slice using useSelector(). The instruction const { status, message, rows, loading, error } = useSelector((state) => state.immobilier) extracts several properties from the Redux store. status contains the status of the operation, message contains the message returned by the backend, rows contains the number of processed rows, loading indicates whether the insertion is in progress and error contains a possible error. Thanks to useSelector(), the React component is automatically informed when these values change in Redux and can update the interface accordingly.

# 60 — Creating the handleInsert Function

The handleInsert() function is executed when the user clicks the "Insert data" button. It begins by creating a constant called data. This constant contains an array of two objects representing two real estate properties. The first object corresponds to a House with an area of 120 m², a price of 200000 and a source called AROUS. The second object corresponds to an Apartment with an area of 80 m², a price of 150000 and a source called GEMMA. Each object also has an idImmobilier identifier. After preparing this array, the function calls dispatch(insertImmobilier(data)). Redux therefore receives the data and triggers the asynchronous process. Axios then sends the data to the backend through the POST request defined in the slice. This function therefore represents the starting point of the entire insertion operation from the user interface.

# 61 — Preparing the Chart Data

The chart is prepared using the chartData constant. This constant contains the information required by Chart.js to build the bar chart. The labels property contains the categories displayed on the horizontal axis: House and Apartment. The datasets property contains the chart data series. A series called Real Estate Price is defined and contains the values 200000 and 150000. These values correspond to the prices of the house and apartment defined previously in the example data. The chart can therefore visually compare the prices of the two types of real estate properties.

# 62 — Integrating the Power BI Dashboard

The component also integrates a Power BI report using an iframe element. The iframe receives a published Power BI URL through its src property. This makes it possible to display the Power BI report directly inside the React page. The iframe-card class controls its appearance through the CSS file. The title property identifies the embedded content and allowFullScreen enables full-screen display when this feature is available. This integration makes it possible to combine Power BI business intelligence analysis with interactive features developed directly in React. The real estate dashboard can therefore display both Power BI visualizations and dynamic processing performed on the frontend.

# 63 — Displaying the Loading State

The component uses the loading property to determine whether the insertion is currently in progress. The button has the property disabled={loading}. When loading is true, the button is disabled to prevent multiple simultaneous insertions. Its text also changes through a conditional expression: {loading ? "Insertion..." : "Insert data"}. The user can therefore immediately understand that the operation is in progress. When Redux moves to the fulfilled or rejected state, loading becomes false again and the button becomes available. This small piece of logic improves the user experience and makes it possible to visually follow the request processing.

# 64 — Displaying the Insertion Result

After a successful insertion, the component checks whether status exists using the condition {status && (...)}. If this condition is true, a paragraph with the CSS class success is displayed. Its content combines the message returned by the backend and the number of processed rows. The expression {message} ({rows} rows) therefore displays information such as the success message accompanied by the number of inserted rows. The displayed values are not written directly inside the component: they come from the backend, have been stored in Redux and are then retrieved by React using useSelector(). This chain clearly shows the path of information from the server to the user interface.

# 65 — Displaying Errors

The component also provides error display using {error && (...)}. If an error is present in the Redux state, a paragraph with the error class is displayed with the content of the error variable. This information comes from the catch block of the Redux thunk. When an error occurs, rejectWithValue() passes the information to the rejected reducer, which stores it in state.error. React then retrieves this value using useSelector(). The user can therefore be directly informed in the interface when an error prevents the insertion of real estate data.

# 66 — Displaying the Chart with Chart.js

The chart is displayed using the Bar component provided by react-chartjs-2. The instruction <Bar data={chartData} /> passes the previously prepared data to Chart.js. Chart.js then uses the labels to display the categories and the dataset values to build the bars. In this case, the chart represents the prices of two real estate categories: House and Apartment. The dataset also contains a backgroundColor property that defines the colors used for the bars. The chart therefore provides a simple visual representation that makes it possible to quickly compare the prices of different types of properties. This visualization complements the information displayed in the Power BI dashboard.

# 67 — Overall Interface Organization

The main interface is contained in a div with the immobilier-container class. It first contains the title 🏠 Real Estate Dashboard, followed by a section dedicated to the Power BI report. Then, a chart-box section contains the Chart.js chart. Finally, a prediction-card section contains the results title, the insertion button and the success or error messages. This organization makes it possible to visually separate the different dashboard features. The CSS file ImmobilierDashboard.css can then define the width, spacing, borders, shadows, colors and layout of each of these areas without mixing presentation with JavaScript logic.

# 68 — Complete Communication Between React, Redux, Axios and Backend

The complete process begins when the user opens the Real Estate Dashboard. React displays the ImmobilierDashboard component along with the Power BI report and the Chart.js chart. When the user clicks the "Insert data" button, the handleInsert() function creates the array containing the real estate information. It then calls dispatch(insertImmobilier(data)). Redux Toolkit then triggers the pending state and the loading property becomes true. The insertImmobilier thunk uses Axios to send an HTTP POST request to /insert. The backend receives the data, processes it and returns a response. If the response is successful, Redux triggers fulfilled, disables loading and stores the status, message and number of rows in the store. If an error occurs, Redux triggers rejected and stores the error message. Thanks to useSelector(), React automatically retrieves the new values and updates the interface. The button returns to its normal state and the result or error is displayed. This communication therefore forms a complete chain between the user, React, Redux Toolkit, Axios, the backend and finally the return of information to the interface.

# 72 — Complete Data Insertion Cycle

The cycle begins when the user clicks the "Insert data" button. The handleInsert() function prepares two real estate objects and groups them into an array. The array is then passed to insertImmobilier(data) using dispatch(). Redux Toolkit triggers the pending state, which activates the loading indicator and disables the button. The thunk then uses Axios to send the data to the backend API through a POST request. The server receives the data and processes it. If the operation succeeds, the server response becomes the payload of fulfilled. Redux then retrieves the status, message and number of rows. Loading is disabled and the success message becomes visible in the interface. If the operation fails, the catch block passes the error to Redux through rejectWithValue(). The rejected reducer stores this error and React displays it to the user. The complete cycle therefore makes it possible to accurately monitor the operation state from its launch to its final result.
