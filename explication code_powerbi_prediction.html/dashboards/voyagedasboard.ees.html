✈️ Voyage ML Dashboard — Documentación técnica

Esta documentación explica en detalle el funcionamiento del componente VoyageDashboard.jsx, del archivo voyageSlice.js, la comunicación con el backend mediante Axios, la gestión del estado con Redux Toolkit, la visualización con Recharts, así como la integración de Power BI y del sistema de Machine Learning.

Introducción

El Dashboard Voyage permite enviar automáticamente datos relacionados con los precios de un viaje al backend.

Los datos enviados al backend son:

  • prix_concurrent_2 = 1900
  • prix_concurrent_agence2 = 2000
  • prix_extra = 50

La solicitud se envía utilizando el método HTTP POST a: 

http://localhost:3000/voyage

El backend procesa los datos y devuelve una respuesta JSON que contiene, entre otros elementos, una predicción.

Redux Toolkit recupera esta respuesta y la almacena en el estado del módulo voyage.

El valor de la predicción se utiliza posteriormente para construir un gráfico de barras con Recharts.

Paralelamente, un informe de Power BI se integra directamente en el Dashboard mediante un iframe.

1. Presentación general del proyecto

El componente VoyageDashboard.jsx representa la interfaz React del Dashboard dedicado al análisis y la predicción de datos de viajes.

Su objetivo es enviar automáticamente varias variables relacionadas con los precios de un viaje al backend.

El backend procesa posteriormente estos datos de acuerdo con la lógica definida en el sistema de Machine Learning.

El resultado devuelto por el backend es recuperado por Redux Toolkit.

El Dashboard muestra después la predicción y un gráfico que permite comparar un valor real con el valor predicho.

}

22. Gestión de errores 

catch (error) {
return thunkAPI.rejectWithValue(
    error.response?.data?.error ||
    error.message
);
}

Si la solicitud falla, se ejecuta el bloque catch.

rejectWithValue() permite enviar un mensaje de error personalizado al Redux Store.

23. Optional Chaining en la gestión de errores 

error.response?.data?.error

El operador ?. permite acceder a una propiedad únicamente cuando el objeto anterior existe.

Esto evita un error si error.response no existe.

Si el mensaje del backend no está disponible, el código utiliza: 

error.message
