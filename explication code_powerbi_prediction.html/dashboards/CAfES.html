📊 Explicación detallada del Dashboard de CA

React • Redux Toolkit • Axios • API • Power BI • Recharts

1. Descripción general del sistema frontend

En esta parte del proyecto, desarrollamos una interfaz frontend dedicada a la predicción de ingresos, denominada CA Dashboard. Esta interfaz está construida con React y utiliza varias tecnologías complementarias para comunicarse con el backend, gestionar los datos de forma centralizada, mostrar los resultados de la predicción y representar los datos gráficamente. El funcionamiento general se basa en la comunicación entre el componente React, Redux Toolkit, Axios y la API del backend. El componente React no gestiona directamente toda la lógica de comunicación con el servidor. Utiliza Redux para activar una acción asíncrona que envía los datos al backend. Axios se utiliza para realizar la solicitud HTTP a la URL http://localhost:3000/CA. El backend recibe los datos de ingresos en TND y EUR, así como el modo de predicción. Realiza el procesamiento necesario y devuelve un resultado que contiene, en particular, la predicción. Redux recibe esta respuesta y la almacena en el estado global. El componente React utiliza entonces useSelector para recuperar los datos de Redux y mostrar el resultado en pantalla. El componente también utiliza useEffect para iniciar automáticamente la predicción cuando se carga la página. Finalmente, la biblioteca Recharts transforma los datos recibidos en un gráfico para comparar los ingresos reales con el valor predicho. Al mismo tiempo, un informe de Power BI se integra en la página mediante un elemento iframe. De esta manera, obtenemos una arquitectura frontend completa que combina visualización de BI, predicción mediante Machine Learning, gestión del estado con Redux, comunicación con el backend y representación gráfica de los resultados.

2. Importación de Redux Toolkit

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

Esta instrucción importa dos funciones importantes de Redux Toolkit. La función createAsyncThunk se utiliza para crear una operación asíncrona, especialmente para realizar una solicitud HTTP al backend. En nuestro proyecto, esta función se utiliza para enviar los datos de ingresos a la API y obtener el resultado de la predicción. La función createSlice se utiliza para crear una parte del store de Redux dedicada a los ingresos. Esta parte se denomina slice. El slice contiene el nombre de esta parte del estado, su estado inicial y la lógica utilizada para modificar este estado cuando la solicitud está pendiente, tiene éxito o falla. Por lo tanto, el uso de Redux Toolkit simplifica considerablemente la gestión del estado global de la aplicación.

3. Importación de Axios

import axios from "axios";

Axios es una biblioteca de JavaScript utilizada para realizar solicitudes HTTP. En nuestra aplicación, Axios actúa como intermediario entre el frontend React y el backend Node.js. Cuando queremos iniciar una predicción, el frontend debe enviar los datos al servidor. Axios nos permite realizar esta operación mediante el método axios.post(). El servidor recibe los datos enviados por React, realiza el procesamiento de la predicción y devuelve una respuesta JSON. Axios recupera esta respuesta para que posteriormente pueda almacenarse en Redux y mostrarse en el componente React. Por lo tanto, el uso de Axios facilita la comunicación entre las diferentes partes de la aplicación.

4. Creación de la operación asíncrona con createAsyncThunk

export const createPrediction = createAsyncThunk(
  "ca/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/CA",
        data
      );

      return res.data;

    } catch (err) {
      return rejectWithValue(
        err.response?.data || "Server error"
      );
    }
  }
);

Esta parte representa el vínculo principal entre Redux y el backend. Creamos una función llamada createPrediction utilizando createAsyncThunk. El primer parámetro, "ca/create", representa el tipo de acción de Redux. El segundo parámetro es una función asíncrona que recibe los datos en la variable data. Esta función utiliza Axios para enviar una solicitud HTTP POST a http://localhost:3000/CA. El método POST se utiliza porque estamos enviando información al servidor para que pueda realizar una predicción. La variable data contiene los parámetros necesarios para la predicción. En nuestro caso, contiene principalmente mode, ca_tnd y ca_eur. La palabra clave await espera la respuesta del servidor antes de continuar la ejecución. Cuando el servidor responde correctamente, la respuesta se almacena en res y res.data contiene los datos JSON devueltos por el backend. La instrucción return res.data pasa entonces estos datos a Redux. Si se produce un error durante la solicitud, la ejecución entra en el bloque catch. La función rejectWithValue() permite entonces enviar un mensaje de error a Redux. La expresión err.response?.data recupera el mensaje devuelto por el servidor cuando existe. Si no hay una respuesta utilizable, se utiliza el mensaje "Server error". Esta estructura permite gestionar correctamente las dos situaciones posibles: una predicción exitosa o un error durante la comunicación con el backend.

5. Creación de caSlice

const caSlice = createSlice({
  name: "ca",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

Esta parte crea el slice de Redux dedicado a los ingresos. La propiedad name: "ca" identifica esta parte del store de Redux. Por lo tanto, la aplicación tiene un espacio de estado específico dedicado a los datos de CA. La propiedad initialState define el estado inicial del sistema. predictionData se inicializa en null porque todavía no se ha recibido ninguna predicción. loading se inicializa en false porque no hay ninguna solicitud ejecutándose al inicio. Finalmente, error se inicializa en null porque inicialmente no existe ningún error. La propiedad reducers está vacía en nuestro caso porque no necesitamos crear acciones síncronas tradicionales. La gestión de nuestra acción asíncrona createPrediction se realiza en extraReducers. Esto permite que Redux reaccione automáticamente a los diferentes estados de la solicitud asíncrona.

6. Estado pending: solicitud en progreso

.addCase(createPrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

Cuando comienza la solicitud de predicción, Redux activa automáticamente el estado pending. Esto significa que la solicitud se está ejecutando actualmente. En esta situación, establecemos state.loading = true. Esta información permite al componente React saber que debe mostrar un mensaje indicando que la predicción está cargándose. También restablecemos state.error = null para eliminar un posible error de una solicitud anterior. De esta manera, el sistema puede mantener información clara sobre el estado actual de la comunicación con el backend.

7. Estado fulfilled: predicción exitosa

.addCase(createPrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

Cuando el backend responde correctamente, Redux activa el estado fulfilled. Esto significa que la solicitud asíncrona se ha completado correctamente. Entonces establecemos state.loading = false porque la carga ha finalizado. A continuación, almacenamos el resultado devuelto por el servidor en state.predictionData. La propiedad action.payload contiene los datos devueltos por return res.data en el thunk. Redux almacena así el resultado de la predicción en su estado global. El componente React puede entonces recuperar esta información mediante useSelector.

8. Estado rejected: error de predicción

.addCase(createPrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

Si la solicitud falla, Redux activa automáticamente el estado rejected. En esta situación, state.loading pasa a ser false porque la solicitud ha terminado, aunque haya terminado con un error. El mensaje de error enviado mediante rejectWithValue() se almacena entonces en state.error. El componente React puede recuperar este error y mostrarlo al usuario. La gestión de los tres estados pending, fulfilled y rejected permite construir una interfaz dinámica que indica claramente si la predicción está en progreso, se ha completado o ha encontrado un error.

9. Exportación del reducer de Redux

export default caSlice.reducer;

Esta instrucción exporta el reducer creado por caSlice. El reducer representa la lógica que permite a Redux modificar el estado de CA según las diferentes acciones recibidas. Posteriormente puede integrarse en el store de Redux de la aplicación. Gracias a esta exportación, el componente React puede acceder indirectamente a los datos almacenados en la parte ca del store.

17. Inicio automático de la predicción con useEffect

useEffect(() => {
  dispatch(
    createPrediction({
      mode: "export",
      ca_tnd: 50000,
      ca_eur: 10000,
    })
  );
}, [dispatch]);

Esta parte es esencial para el funcionamiento automático del Dashboard. El hook useEffect permite ejecutar una operación después de que el componente se haya renderizado. Cuando se carga la página de CA, el componente llama a dispatch() y activa createPrediction(). A continuación, enviamos tres datos al backend: mode: "export", ca_tnd: 50000 y ca_eur: 10000. Estos datos representan los valores utilizados por el modelo de predicción. Redux pasa esta información al thunk, el thunk utiliza Axios para enviar una solicitud POST al backend y el backend realiza la predicción. El array [dispatch] indica las dependencias de useEffect. En este caso, el efecto se ejecuta cuando el componente se monta y si la referencia a dispatch cambia.

30. Gestión de los tres estados de la solicitud

Una de las ventajas importantes de Redux Toolkit en este proyecto es la gestión automática de los diferentes estados de la operación asíncrona. Cuando comienza la solicitud, se activa el estado pending y loading pasa a ser true. El frontend muestra entonces el mensaje de carga. Cuando el backend devuelve correctamente la predicción, se activa el estado fulfilled, loading pasa a ser false y el resultado se almacena en predictionData. React puede entonces mostrar la tarjeta de resultado y el gráfico. Si se produce un error durante la solicitud, se activa el estado rejected, loading pasa a ser false y el mensaje de error se almacena en error. El componente React muestra entonces este error. De esta manera obtenemos una gestión clara de todo el ciclo de vida de la solicitud.

32. Diferencia entre Redux y React en este código

En esta arquitectura, React y Redux tienen responsabilidades diferentes pero complementarias. React se utiliza principalmente para construir la interfaz de usuario: muestra el título, el informe de Power BI, el mensaje de carga, el resultado y el gráfico. Redux se utiliza para gestionar el estado de la predicción: almacena los datos recibidos del backend, indica si una solicitud está en progreso y almacena los posibles errores. useDispatch permite a React solicitar a Redux que inicie una operación y useSelector permite a React recuperar los datos almacenados por Redux. Esta separación evita que toda la lógica de comunicación con el servidor se mezcle directamente con la interfaz.

34. Resumen del funcionamiento

En resumen, cuando el usuario abre el CA Dashboard, React carga el componente CA. El hook useEffect inicia automáticamente una acción de Redux llamada createPrediction. Esta acción se crea con createAsyncThunk y utiliza Axios para enviar una solicitud POST al backend en http://localhost:3000/CA. Los datos enviados son el modo export, los ingresos en TND de 50000 y los ingresos en EUR de 10000. Durante la ejecución, Redux entra en el estado pending y React muestra el mensaje de carga. Cuando el servidor devuelve el resultado, Redux entra en el estado fulfilled y almacena la respuesta en predictionData. React recupera esta información mediante useSelector, muestra el valor predicho con dos decimales y prepara los datos necesarios para el gráfico. Recharts muestra entonces dos barras que permiten comparar los ingresos reales con la predicción. Al mismo tiempo, Power BI se muestra dentro de un iframe para proporcionar una visualización adicional de apoyo a la toma de decisiones. Si se produce un error, Redux entra en el estado rejected y React muestra el mensaje de error. Por lo tanto, el sistema forma una cadena completa entre la interfaz React, Redux Toolkit, Axios, el backend Node.js, el modelo de predicción, Recharts y Power BI.

Utilizo Redux para gestionar el estado de los datos de predicción y evitar colocar toda la lógica directamente dentro del componente React. Creé un slice llamado caSlice que contiene tres elementos principales de información: predictionData para almacenar el resultado, loading para determinar si la solicitud está en progreso y error para gestionar los errores. También utilizo createAsyncThunk para realizar una operación asíncrona. Esta operación utiliza Axios para enviar una solicitud POST a mi backend en /CA. Cuando se carga la página de CA, useEffect activa automáticamente esta acción con los datos de ingresos en TND y EUR, así como el modo de procesamiento. Redux Toolkit gestiona automáticamente tres estados: pending cuando la solicitud está en progreso, fulfilled cuando la predicción se recibe correctamente y rejected cuando se produce un error. En el componente React, utilizo useSelector para recuperar los datos almacenados en Redux y useDispatch para enviar la acción de predicción. Cuando la predicción está disponible, la muestro en una tarjeta con dos decimales. También utilizo Recharts para crear un gráfico de barras que compara los ingresos reales con el valor predicho. Finalmente, integro un informe de Power BI en la misma página utilizando un iframe. Por lo tanto, esta arquitectura combina React para la interfaz, Redux Toolkit para la gestión del estado, Axios para la comunicación con el backend, Machine Learning para la predicción, Recharts para la visualización y Power BI para el análisis y apoyo a la toma de decisiones. El objetivo es proporcionar una única interfaz que permita a los usuarios consultar datos de BI y resultados predictivos de una manera clara e interactiva.

36. Conclusión

Este código frontend implementa, por tanto, una arquitectura completa para utilizar un modelo de predicción desde una aplicación React. Redux Toolkit actúa como gestor del estado y controla el ciclo de vida de la solicitud mediante los estados pending, fulfilled y rejected. Axios gestiona la comunicación con el backend Node.js. React utiliza useEffect para activar automáticamente la predicción, useDispatch para enviar la acción de Redux y useSelector para recuperar los resultados. Recharts transforma posteriormente los datos en una representación gráfica que permite comparar los valores reales y las predicciones. Finalmente, Power BI complementa el Dashboard con visualizaciones de apoyo a la toma de decisiones. Esta organización separa claramente la interfaz, la gestión del estado, la comunicación con el servidor, la predicción y la visualización de datos. Por lo tanto, proporciona una arquitectura frontend estructurada y adecuada para una aplicación de Business Intelligence que integra Machine Learning.
