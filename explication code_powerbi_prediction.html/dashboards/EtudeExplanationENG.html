🌍 Study Abroad Dashboard — Code Explanation

Technical documentation explaining how React, Redux Toolkit, Axios, Recharts and Power BI work together to retrieve, display and visualize data related to studying abroad.

# 109 — Study Abroad Dashboard Overview

The Study Abroad Dashboard is a frontend interface developed with React that allows users to display and analyze data related to studying abroad. This functionality uses several complementary technologies: React to build the user interface, Redux Toolkit to centralize and manage the application state, Axios to communicate with the backend, Recharts to represent data graphically, and Power BI to integrate a Business Intelligence report directly into the page. Unlike a traditional data-entry form, the Study Dashboard automatically retrieves data from the backend when the component is loaded. The user can therefore directly access the available information, the values associated with the different study modes and the prediction values. The dashboard therefore combines several levels of visualization: the Power BI report, the list of retrieved data, and the comparison chart generated with Recharts.

# 110 — Importing React and useEffect

The EtudeDashboard.jsx file begins by importing React and the useEffect hook: 


import React, { useEffect } from "react";

React is used to create the user interface component. The useEffect hook allows an operation to be executed after the component has been rendered. In this dashboard, useEffect plays an important role because it automatically starts data retrieval when the page is loaded. The user therefore does not need to click a button to trigger the data retrieval.

# 111 — Importing useDispatch and useSelector

The component then imports two hooks from react-redux: 


import { useDispatch, useSelector } from "react-redux";

useDispatch() allows the React component to send an action to Redux. In our application, it will be used to trigger the asynchronous action fetchEtudeData(). useSelector(), on the other hand, allows the component to read information stored in the Redux store. The component can therefore retrieve: items for the data, loading to determine the loading state, and error to retrieve a possible error. These two hooks therefore establish communication between the React component and the Redux store.

# 112 — Importing fetchEtudeData

The component then imports the asynchronous action fetchEtudeData from the Redux file: 


import { fetchEtudeData } from "../redux/etudeSlice";

This function is defined in the etudeSlice.js file. It is created using createAsyncThunk() and its purpose is to contact the backend in order to retrieve the Study Dashboard data. The React component therefore does not perform the Axios request directly. The server communication logic is centralized inside the Redux slice. This separation makes the architecture clearer and easier to maintain.

# 113 — Importing Recharts Components

The dashboard also uses the Recharts library: 


import {
  BarChart,
  Bar,
  XAxis,
  YAxis,
  Tooltip,
  CartesianGrid,
  Legend,
  ResponsiveContainer
} from "recharts";

Each component has a specific responsibility. BarChart represents the general structure of the chart as a bar chart. Bar represents a data series. XAxis represents the horizontal axis. YAxis represents the vertical axis. Tooltip displays information when the user hovers over a bar. CartesianGrid adds a grid to improve the readability of the chart. Legend displays the legend of the series. Finally, ResponsiveContainer allows the chart to automatically adapt to the available width.

# 114 — Importing the CSS File

The file also imports its CSS file: 


import "./EtudeDashboard.css";

This organization separates the JavaScript logic from the visual presentation. The JSX file contains the structure and behavior of the dashboard, while EtudeDashboard.css contains the rules used to control colors, dimensions, spacing, borders, cards and responsiveness. This separation improves readability and makes future interface modifications easier.

# 115 — Creating the EtudeDashboard Component

The main component is defined with: 


export default function EtudeDashboard() {

EtudeDashboard represents the complete page dedicated to study abroad data. It contains several elements: data retrieval, the Power BI report, loading information, error messages, the data list, and the Recharts graph. The component therefore represents the presentation layer of the functionality.

# 116 — Initializing useDispatch

The code uses: 


const dispatch = useDispatch();

This instruction retrieves the dispatch function provided by Redux. It allows the component to send an action to the store. In our case, this function will be used to trigger: 


dispatch(fetchEtudeData());

This instruction therefore asks Redux to execute the asynchronous action responsible for retrieving the Study data.

# 117 — Retrieving the Study State with useSelector

The component then retrieves the data from the Redux store: 


const { items, loading, error } =
    useSelector(state => state.etude);

useSelector() provides access to the etude section of the Redux store. Three properties are extracted. items contains the data retrieved from the backend. loading indicates whether the request is currently in progress. error contains a possible error. When Redux modifies one of these values, React is automatically notified of the change and the component is re-rendered so that the interface can be updated.

# 118 — Automatic Data Retrieval with useEffect

The dashboard uses the useEffect hook: 


useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

This logic automatically triggers data retrieval after the component has been loaded. When the user opens the Study Dashboard, React executes the useEffect. It calls: dispatch(fetchEtudeData()). Redux Toolkit then starts the asynchronous action cycle. The backend is subsequently contacted through Axios. The dependency array contains dispatch in order to follow the dependency management rules of the hook.

# 119 — Transforming Data for Recharts

The data received from Redux is transformed so that it is compatible with Recharts: 


const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

The map() method iterates through each element of the items array. For each element, a new object is created. The name property receives item.mode. It represents the study mode and will be used as a category on the horizontal axis. The Value property receives item.value. It represents the actual value associated with the study mode. Finally, the Prediction property receives item.prediction. The ?? operator allows the value 0 to be used when the prediction value is missing or is null.

The component also provides error display:

# 132 — Creating the etudeSlice.js File

Data management is centralized in the etudeSlice.js file. This file uses Redux Toolkit and Axios: 


import { createSlice, createAsyncThunk }
from "@reduxjs/toolkit";

import axios from "axios";

createAsyncThunk allows an asynchronous action to be created. createSlice creates the part of the store dedicated to the Study data. Axios is responsible for communicating with the backend.

# 133 — Creating fetchEtudeData

The main asynchronous action is: 


export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        ...
    }
);

fetchEtudeData is responsible for retrieving the Study data. The first parameter: "etude/fetchEtudeData" represents the Redux action type. The _ symbol indicates that no specific argument is required to launch this action. The thunkAPI parameter provides Redux Toolkit tools that can be used, in particular, to handle errors.

# 134 — Axios Request to the Backend

Inside the thunk, Axios sends a GET request: 


const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

The GET method allows the frontend to request data from the server. The endpoint used is: /etude/dashboard. The backend therefore receives the request and returns the data required by the dashboard. The await keyword allows the program to wait for the server response before continuing execution.

# 135 — Returning Data from the Backend

After the Axios response, the code uses: 


return response.data.data;

response contains the complete response provided by Axios. response.data corresponds to the body of the HTTP response. Finally, response.data.data retrieves the data array contained in the data property of the backend response. This value then becomes the payload of the Redux action when it succeeds.

# 136 — Handling Axios Errors

The thunk also contains a try/catch block: 


try {

    const response = await axios.get(
        "http://localhost:3000/etude/dashboard"
    );

    return response.data.data;

} catch (error) {

    return thunkAPI.rejectWithValue(
        error.message
    );

}

If the request succeeds, the data is returned. If an error occurs, the program enters the catch block. The instruction: rejectWithValue(error.message) sends the error message to the rejected reducer. This approach allows the React component to display the problem to the user.

# 137 — Creating the Study Slice

The Redux slice is created with: 


const etudeSlice = createSlice({

    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    ...
});

The name property identifies the slice under the name etude. The initialState defines the initial state values. items starts with an empty array because no data has been retrieved yet. loading starts as false because no request is running at startup. error starts as null because there is initially no error.

# 138 — Pending State

When fetchEtudeData() starts, Redux Toolkit automatically triggers the pending state: 


.addCase(
    fetchEtudeData.pending,
    (state) => {

        state.loading = true;
        state.error = null;

    }
)

loading becomes true. The React component can then display the Loading... message. The previous error is also cleared with state.error = null. The system is therefore ready to receive a new response from the backend.

# 139 — Fulfilled State

When the request succeeds, Redux Toolkit triggers the fulfilled state: 


.addCase(
    fetchEtudeData.fulfilled,
    (state, action) => {

        state.loading = false;

        state.items = action.payload;

    }
)

loading becomes false because the request is complete. The data returned by the thunk is available in action.payload. It is then stored in: state.items. The React component automatically receives the new data through useSelector().

# 140 — Rejected State

When the request fails, Redux Toolkit triggers the rejected state: 


.addCase(
    fetchEtudeData.rejected,
    (state, action) => {

        state.loading = false;

        state.error = action.payload;

    }
)

loading is set back to false because the request is complete. The error message transmitted by rejectWithValue() is retrieved through action.payload. It is then stored in: state.error. React can then display this error in the interface.

# 141 — Exporting the Reducer

At the end of the Redux file, the reducer is exported: 


export default etudeSlice.reducer;

This reducer must then be registered in the main Redux store. Once registered, the React component can access the state using: 


useSelector(state => state.etude);

The connection between the Redux store and the EtudeDashboard component is therefore established.

# 142 — Complete Redux Cycle

The Redux Toolkit workflow is based on three main states:

⏳ Pending

The request starts. loading = true.

✅ Fulfilled

The request succeeds. The data is stored in items.

❌ Rejected

The request fails. The error is stored in error.

# 143 — Complete Data Flow

The complete process starts when the user opens the Study Dashboard page. React loads the EtudeDashboard component. The useEffect() hook is then executed. It triggers: dispatch(fetchEtudeData()). Redux Toolkit then enters the pending state. The thunk uses Axios to send a GET request to: http://localhost:3000/etude/dashboard. The backend processes the request and returns a JSON response. If the response succeeds, the thunk returns response.data.data. Redux then triggers fulfilled and stores the data in state.items. React retrieves this data using useSelector(). The data is then transformed into chartData. Finally, Recharts uses this array to build the chart.

# 145 — Role of React

React represents the user interface layer. It is responsible for displaying the Dashboard, the title, the data list, loading and error messages, as well as the chart. React also automatically reacts to changes in the Redux state. When items is updated, the component is re-rendered and the new data automatically appears in the interface.

# 146 — Role of Redux Toolkit

Redux Toolkit centralizes the management of the Study data. The etude slice contains: items, loading, and error. It also manages the different states of the asynchronous action: pending, fulfilled, and rejected. This organization avoids placing all the backend communication logic directly inside the React component.

# 147 — Role of Axios

Axios is responsible for HTTP communication between the frontend and the backend. In this functionality, Axios uses a GET request: http://localhost:3000/etude/dashboard. It then receives the response from the server. The Redux thunk retrieves the data using: response.data.data. Axios therefore acts as the communication bridge between the React/Redux application and the backend API.

# 148 — Role of Recharts

Recharts is used to transform the retrieved data into a graphical representation. The data is prepared inside chartData. Recharts then uses: BarChart, Bar, XAxis, YAxis, Tooltip, Legend, and ResponsiveContainer. This library therefore makes it possible to transform numerical data into an easily understandable visualization.

# 149 — Role of Power BI

Power BI brings the Business Intelligence dimension to the Study Dashboard. The report is integrated directly into React using an iframe. This integration makes it possible to combine two complementary approaches. Power BI provides advanced visualizations and decision-making analysis. React, on the other hand, provides a customized interface capable of retrieving data from the backend, displaying predictions and producing additional charts with Recharts. The dashboard therefore becomes a hybrid interface combining web development, data analysis and Business Intelligence.

# 150 — Complete Architecture

The architecture of this functionality can be summarized in several layers. The React frontend contains the EtudeDashboard component. The Redux slice contains the data retrieval logic. createAsyncThunk orchestrates the asynchronous operation. Axios communicates with the API. The Node.js / Express backend processes the request and returns the data. Redux then stores the results. React retrieves the data using useSelector(). The data is transformed into chartData. Recharts produces the graphical visualization. At the same time, Power BI provides the integrated decision-making report. This separation of responsibilities makes the application more organized, scalable and maintainable.

# 151 — Conclusion

The Study Abroad Dashboard represents a complete functionality combining frontend development, state management, backend communication, data visualization, prediction and Business Intelligence. React builds the user interface. useEffect automatically triggers data retrieval. Redux Toolkit centralizes the state and manages the asynchronous cycle. createAsyncThunk facilitates the creation of the data retrieval action. Axios communicates with the backend through an HTTP GET request. Node.js / Express provides the data requested by the frontend. Recharts transforms the data into a graphical visualization. Finally, Power BI adds a Business Intelligence layer directly integrated into the application. The entire system therefore forms a modern architecture capable of connecting backend data, Redux state management, the React interface, prediction, graphical visualization and Power BI decision-making analysis.
