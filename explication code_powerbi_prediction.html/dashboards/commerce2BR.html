Sistema de Previsão Commerce

Integração de modelos de Machine Learning SVR treinados em Python, salvos como arquivos PKL e utilizados por meio de uma API Node.js / Express.

01

Visão Geral

Este módulo implementa uma arquitetura de previsão desenvolvida para o setor de comércio e permite comparar ou estimar resultados para duas marcas: Carrefour e Aziza. A arquitetura utiliza várias tecnologias que se comunicam entre si. A primeira parte é desenvolvida em Python e utiliza a biblioteca Scikit-learn juntamente com o algoritmo SVR, ou Support Vector Regression. Dois modelos independentes de Machine Learning são treinados utilizando as mesmas variáveis de entrada X, mas com dois conjuntos diferentes de valores-alvo: um conjunto para Carrefour e outro para Aziza. Após o treinamento, os modelos são serializados utilizando a biblioteca pickle e salvos como arquivos carrefour.pkl e aziza.pkl. A segunda parte do sistema corresponde ao script Python responsável por receber os dados do Node.js. Esse script lê um objeto JSON enviado por meio da entrada padrão, identifica o modelo solicitado, carrega o arquivo PKL correspondente, recupera as variáveis x1 e x2 e, em seguida, utiliza o método predict() do modelo SVR para produzir uma previsão. A terceira parte é desenvolvida em Node.js. O backend utiliza o módulo nativo child_process para executar o Python a partir do Node.js. A função runCommerce() prepara o caminho para o interpretador Python, localiza o script de previsão, inicia o processo Python e envia os dados para ele em formato JSON. O resultado produzido pelo Python é recuperado por meio do stdout, convertido de JSON para um objeto JavaScript e então retornado ao backend. Finalmente, o Express disponibiliza uma API REST com uma rota de teste /train e uma rota POST /predict. O frontend ou dashboard pode, portanto, enviar o nome do modelo juntamente com as variáveis de entrada e receber automaticamente a previsão calculada pelo modelo real de Machine Learning.

02

Treinamento dos Modelos SVR

A primeira etapa do sistema consiste na criação dos modelos de Machine Learning. O código Python importa SVR de sklearn.svm. SVR significa Support Vector Regression e é uma versão do método Support Vector Machines adaptada para problemas de regressão. Diferentemente de uma fórmula matemática simples programada manualmente, o modelo SVR é treinado utilizando dados de entrada e valores-alvo. Neste projeto, o array X contém quatro observações e duas variáveis para cada observação. A primeira observação contém os valores 10 e 1, a segunda 20 e 2, a terceira 30 e 3 e a quarta 40 e 4. Essas duas variáveis representam as características utilizadas pelo modelo para aprender a relação com a variável-alvo. Para Carrefour, o array y_carrefour contém os valores 120, 240, 360 e 480. Um primeiro objeto SVR() é criado e o método fit() é chamado com X e y_carrefour. O modelo aprende, portanto, uma relação entre as duas variáveis de entrada e os valores-alvo do Carrefour. O modelo é então salvo no arquivo carrefour.pkl. O mesmo princípio é aplicado ao Aziza. O array y_aziza contém os valores 100, 200, 300 e 400. Um segundo modelo SVR é criado, treinado utilizando as mesmas variáveis X, mas com os valores-alvo do Aziza, e então salvo como aziza.pkl. Dessa forma, obtemos dois modelos independentes capazes de produzir previsões diferentes a partir das mesmas variáveis de entrada.

Importando o SVR 

from sklearn.svm import SVR

Esta instrução importa a classe SVR do módulo sklearn.svm. Ela permite criar um modelo de regressão baseado em Support Vector Machines. O modelo pode então ser treinado utilizando o método fit() e utilizado para produzir previsões com predict().

Importando o Pickle 

import pickle

A biblioteca pickle é utilizada para serializar o modelo treinado. Após o treinamento, o modelo SVR existe como um objeto Python na memória. O Pickle permite transformar esse objeto em um arquivo para que ele possa ser salvo e carregado posteriormente sem precisar treinar o modelo a cada previsão.

Gerenciamento do Caminho do Projeto 

BASE_DIR = os.path.dirname(
    os.path.abspath(__file__)
)

Esta parte determina automaticamente a pasta onde o script Python está localizado. os.path.abspath(__file__) recupera o caminho absoluto do arquivo atual, enquanto os.path.dirname() recupera a pasta que contém esse arquivo. Esse método é particularmente útil para construir caminhos confiáveis para os arquivos PKL.

Dados Comuns 

X = [
    [10, 1],
    [20, 2],
    [30, 3],
    [40, 4]
]

O array X representa os dados de entrada do Machine Learning. Cada linha corresponde a uma observação e contém duas variáveis. O modelo recebe, portanto, duas características para cada previsão. Por exemplo, a primeira observação consiste em 10 e 1. Esses dois valores serão enviados ao modelo SVR para que ele possa calcular uma estimativa.

Dados do Carrefour 

y_carrefour = [
    120,
    240,
    360,
    480
]

O array y_carrefour representa a variável-alvo utilizada para treinar o modelo do Carrefour. Cada valor corresponde a uma observação do array X. O modelo deve, portanto, aprender a relação entre as duas variáveis de entrada e esses quatro valores-alvo.

Criando e Treinando o Modelo Carrefour 

carrefour_model = SVR()

carrefour_model.fit(
    X,
    y_carrefour
)

SVR() cria uma nova instância do modelo Support Vector Regression. O método fit() inicia então o processo de aprendizado. O primeiro argumento corresponde às variáveis de entrada X e o segundo corresponde aos valores-alvo y_carrefour. O modelo analisa os dados fornecidos para aprender uma relação que poderá ser utilizada posteriormente para produzir previsões para novos valores.

Salvando o Modelo Carrefour 

carrefour_path = os.path.join(
    BASE_DIR,
    "carrefour.pkl"

with open(
    carrefour_path,
    "wb"

    pickle.dump(
        carrefour_model,
        f

O caminho para o arquivo carrefour.pkl é construído utilizando os.path.join(). O arquivo é então aberto utilizando o modo wb, que significa escrita binária. A função pickle.dump() serializa o objeto carrefour_model e o salva no arquivo. O modelo treinado pode, portanto, ser reutilizado posteriormente sem precisar ser treinado novamente.

O modelo Aziza utiliza exatamente as mesmas variáveis de entrada X, mas possui uma variável-alvo diferente. O array y_aziza contém os valores 100, 200, 300 e 400. Um novo objeto SVR() é criado e depois treinado com X e y_aziza. Essa separação permite construir dois modelos distintos. O modelo Carrefour aprende as relações presentes nos dados do Carrefour, enquanto o modelo Aziza aprende as relações presentes nos dados do Aziza.

03

Script de Previsão em Python

Após o treinamento e salvamento dos modelos, um segundo script Python é utilizado para realizar as previsões. Seu papel é particularmente importante porque atua como uma ponte entre o Node.js e os modelos de Machine Learning em Python. O script importa sys, json, pickle e os. Ele começa lendo os dados enviados pelo Node.js utilizando sys.stdin.read(). Esses dados são enviados em formato JSON e convertidos em um objeto Python utilizando json.loads(). O script então recupera o nome do modelo utilizando data.get("model", "carrefour"). Se nenhum modelo for informado, Carrefour se torna o modelo padrão. Um dicionário file_map é então utilizado para associar o nome lógico do modelo ao arquivo PKL correspondente. Se o nome recebido não existir nesse dicionário, o programa gera um erro. Quando o modelo é válido, o caminho do arquivo PKL é construído automaticamente e o arquivo é aberto em modo binário. pickle.load() então recarrega o modelo SVR treinado. Uma verificação de segurança utiliza hasattr(model, "predict") para verificar se o objeto carregado realmente possui um método de previsão. As variáveis x1 e x2 são então recuperadas dos dados recebidos e convertidas em números decimais utilizando float(). Finalmente, o modelo é chamado com model.predict([[x1, x2]]). A lista dupla é necessária porque o Scikit-learn geralmente espera uma estrutura que represente uma ou mais observações com suas características. O resultado é recuperado e convertido para float. Finalmente, o script produz um objeto JSON contendo success, o nome do modelo e a previsão. Se ocorrer um erro em qualquer etapa, o bloco except também retorna JSON, mas com success: false e a mensagem de erro.

Lendo os Dados do Node.js 

data = json.loads(
    sys.stdin.read()
)

sys.stdin.read() permite que o script Python leia os dados enviados pelo processo Node.js. Como o Node.js envia as informações em formato JSON, json.loads() transforma essa string JSON em um dicionário Python que pode ser utilizado pelo programa.

Seleção do Modelo 

model_name = data.get(
    "model",
    "carrefour"
).lower()

Esta instrução recupera o nome do modelo solicitado. O método get() utiliza Carrefour como valor padrão caso a propriedade model não seja fornecida. O método lower() converte o texto para letras minúsculas a fim de evitar determinados problemas relacionados a letras maiúsculas.

Mapeamento do Modelo / Arquivo PKL 

file_map = {
    "carrefour": "carrefour.pkl",
    "aziza": "aziza.pkl"
}

O dicionário file_map associa o nome enviado pelo frontend ao arquivo físico que contém o modelo. Se model = carrefour, o programa carrega carrefour.pkl. Se model = aziza, ele carrega aziza.pkl. Essa organização evita construir diretamente um nome de arquivo a partir de uma entrada do usuário que não tenha sido controlada.

Carregando o Modelo 

with open(
    model_path,
    "rb"
) as f:

    model = pickle.load(f)

O arquivo PKL é aberto utilizando o modo rb, que significa leitura binária. pickle.load() reconstrói o objeto Python salvo anteriormente. O modelo SVR treinado é, portanto, restaurado na memória e pode ser imediatamente utilizado para realizar uma previsão.

Validação do Modelo 

if not hasattr(
    model,
    "predict"
):

    raise Exception(
        "Invalid ML model loaded"
    )

Essa validação garante que o objeto carregado realmente possui um método predict(). Como o sistema espera um modelo de Machine Learning capaz de produzir uma previsão, essa verificação impede que o processo continue com um objeto incompatível.

Recuperando as Variáveis 

x1 = float(
    data["x1"]
)

x2 = float(
    data["x2"]
)

As duas variáveis enviadas pelo Node.js são recuperadas do objeto JSON. A função float() converte os valores em números decimais para que possam ser utilizados corretamente pelo modelo SVR.

Produzindo a Previsão 

prediction = model.predict(
    [[x1, x2]]
)[0]

Esta instrução representa a principal etapa de Machine Learning. O modelo SVR recebe as duas variáveis de entrada e utiliza os parâmetros aprendidos durante o treinamento para calcular uma previsão. O método predict() retorna um array contendo o resultado. O índice [0] recupera a primeira previsão.

Resposta JSON 

print(json.dumps({
    "success": True,
    "model": model_name,
    "prediction": float(prediction)
}))

O resultado é convertido para JSON utilizando json.dumps(). Esse formato é essencial porque o Node.js pode recuperar facilmente a resposta a partir da saída padrão do processo Python e depois convertê-la em um objeto JavaScript. Em caso de sucesso, a resposta contém o status, o nome do modelo e o valor previsto.

Serviço Node.js e Comunicação com Python

O arquivo de serviço server.js atua como gateway entre o backend Node.js e o programa Python. O módulo child_process fornecido pelo Node.js permite executar um processo externo. Aqui, a função spawn() é utilizada para iniciar o interpretador Python. A função runCommerce() retorna uma Promise, permitindo que a rota Express utilize await e aguarde a conclusão do processamento Python. O serviço primeiro constrói o caminho para o interpretador Python localizado no ambiente virtual .venv. Em seguida, constrói o caminho para o script commerce2.py. Antes de iniciar o Python, o código utiliza fs.existsSync() para verificar se o interpretador e o script realmente existem. Essa etapa é particularmente útil para diagnosticar erros de caminho. Quando os dois arquivos estão disponíveis, spawn() inicia o Python com o script de previsão. O Node.js então envia os dados ao processo Python utilizando python.stdin.write(). Os dados são convertidos para JSON utilizando JSON.stringify(). O Python lê esses dados utilizando sys.stdin.read(). Durante a execução, o Node.js monitora o stdout para recuperar o resultado produzido pelo Python e também monitora stderr para recuperar possíveis mensagens de erro. Quando o Python termina, o evento close é acionado. O código então verifica o código de saída do processo. Se o código for diferente de zero, significa que o processo Python terminou com um erro. Se o resultado estiver vazio, outro erro é retornado. Finalmente, se o Python produziu uma resposta, JSON.parse() transforma o texto JSON em um objeto JavaScript. Esse objeto é então retornado utilizando resolve(). O serviço fornece, portanto, uma comunicação real entre o ambiente JavaScript e o modelo de Machine Learning em Python.

Importando os Módulos do Node.js 

const { spawn } =
require("child_process");

const path =
require("path");

const fs =
require("fs");

child_process permite executar o Python a partir do Node.js. path permite construir caminhos de arquivos compatíveis com o sistema operacional. fs é utilizado principalmente para verificar a existência dos arquivos.

Criando a Promise 

function runCommerce(inputData) {

    return new Promise(
        (resolve, reject) => {

        ...
    });

}

A função retorna uma Promise porque a execução do Python é uma operação assíncrona. O Node.js precisa iniciar o Python, aguardar seu resultado e depois retornar esse resultado para a rota Express.

Localizando o Python 

const pythonPath = path.resolve(
    __dirname,
    "../../.venv/Scripts/python.exe"
);

Esta instrução constrói o caminho absoluto para o interpretador Python utilizado pelo projeto. Aqui, o programa utiliza a instalação Python localizada no ambiente virtual .venv. Isso permite utilizar exatamente o ambiente no qual as bibliotecas necessárias, especialmente Scikit-learn, estão instaladas.

Localizando o Script Python 

const scriptPath = path.resolve(
    __dirname,
    "../../python/commerce2.py"
);

O caminho para o script Python de previsão também é construído como um caminho absoluto. Dessa forma, o Node.js sabe exatamente qual arquivo deve executar.

Verificação dos Arquivos 

fs.existsSync(pythonPath)

fs.existsSync(scriptPath)

Essas verificações permitem detectar rapidamente se o Python ou o script não podem ser encontrados. Em um projeto real, isso facilita bastante o diagnóstico quando um caminho está incorreto ou quando um arquivo foi movido.

Iniciando o Python 

const python = spawn(
    pythonPath,
    [scriptPath]
);

spawn() inicia o interpretador Python e passa para ele o caminho do script commerce2.py. O Node.js passa então a ter um processo filho com o qual pode se comunicar por meio de stdin, stdout e stderr.

Enviando Dados para o Python 

python.stdin.write(
    JSON.stringify(inputData)
);

python.stdin.end();

Os dados recebidos pelo Node.js são convertidos em uma string JSON e enviados para a entrada padrão do processo Python. stdin.end() indica que o Node.js terminou de enviar os dados. O Python pode então ler todo o conteúdo utilizando sys.stdin.read().

Recuperando o Resultado do Python 

python.stdout.on(
    "data",
    (data) => {

        result += data.toString();

    }
);

O Node.js monitora os dados enviados pelo Python através do stdout. Os blocos recebidos são convertidos em texto e adicionados à variável result. Quando o Python termina, essa variável contém a resposta JSON.

Tratamento de Erros do Python 

python.stderr.on(
    "data",
    (data) => {

        error += data.toString();

    }
);

stderr é utilizado para recuperar mensagens de erro produzidas pelo Python. Isso permite que o backend determine a causa de um possível problema.

Conversão JSON 

const parsedResult =
    JSON.parse(
        result.trim()
    );

resolve(
    parsedResult
);

O Python retorna uma string JSON. O Node.js utiliza JSON.parse() para transformar essa string em um objeto JavaScript. O objeto resultante é então retornado para a rota utilizando resolve().

Rota de Previsão do Express

O arquivo serverRoutes.js define os endpoints acessíveis pelo frontend. Ele cria um router Express utilizando express.Router() e depois importa o serviço runCommerce(). Uma primeira rota GET chamada /train serve como rota de teste. Ela não realiza realmente o treinamento dos modelos; apenas retorna uma mensagem indicando que Carrefour e Aziza estão prontos. O treinamento real é realizado pelo script Python de criação dos modelos. A segunda rota, POST /predict, é a principal rota de previsão. Ela recupera as informações enviadas em req.body, incluindo o nome do modelo, x1 e x2. Uma validação verifica se x1 e x2 estão presentes. Se algum valor estiver ausente, a API retorna uma resposta HTTP 400. Quando os dados são válidos, a rota chama runCommerce() com as informações recebidas. O serviço Node.js então inicia o script Python, carrega o modelo PKL correspondente e calcula a previsão. Assim que a resposta é recebida, o Express a retorna diretamente ao cliente utilizando res.status(200).json(result). O frontend pode, portanto, chamar essa API e receber diretamente o resultado do modelo de Machine Learning.

Criando o Router 

const express =
require("express");

const router =
express.Router();

Esta parte importa o Express e depois cria um router independente. Isso permite organizar os endpoints em um arquivo separado do servidor principal.

Importando o Serviço 

const serverService =
require("../service/server");

const runCommerce =
serverService.runCommerce;

O router recupera a função runCommerce() do serviço. Essa função será chamada sempre que uma solicitação de previsão for recebida.

Rota de Teste 

router.get(
    "/train",
    (req, res) => {

    return res.status(200).json({

        success: true,

        message:
            "Carrefour + Aziza ready"

    });

});

Essa rota permite verificar rapidamente se o router funciona e se o backend responde corretamente. Ela retorna um status HTTP 200 juntamente com uma mensagem indicando que os dois modelos estão disponíveis.

Rota POST /predict 

router.post(
    "/predict",
    async (req, res) => {

        ...
    }
);

Essa rota recebe os dados necessários para realizar uma previsão. Como utiliza POST, as informações são enviadas no corpo da solicitação HTTP em formato JSON.

Recuperando os Dados 

const {
    model,
    x1,
    x2
} = req.body || {};

As três principais informações são recuperadas da solicitação: o modelo a ser utilizado e as duas variáveis de entrada. O modelo pode ser carrefour ou aziza.

Validação 

if (
    x1 === undefined ||
    x1 === null ||
    x2 === undefined ||
    x2 === null
) {

    return res.status(400).json({

        success: false,

        error:
            "x1 and x2 required"

    });

}

Essa validação impede que o backend chame o Python quando as variáveis necessárias não são fornecidas. Nesse caso, o servidor retorna um erro HTTP 400 indicando que x1 e x2 são obrigatórios.

Chamando o Serviço Python 

const result =
    await runCommerce({

        model,
        x1,
        x2

    });

Essa instrução cria a ligação entre a rota Express e o serviço Node.js. Graças ao await, a rota aguarda o processo Python concluir o cálculo antes de continuar.

Resposta Final 

return res.status(200).json(
    result
);

Depois que o Python retorna o resultado, o Express o envia ao cliente em formato JSON. O frontend recebe, portanto, a previsão calculada pelo modelo SVR real.

Servidor Principal Node.js / Express

O arquivo principal do backend inicializa a aplicação Express e conecta as rotas de previsão. O Express é importado e uma instância da aplicação é criada utilizando express(). O middleware express.json() é habilitado para que o servidor possa receber e interpretar dados JSON enviados pelo frontend. O arquivo serverRoutes é então importado e montado utilizando o prefixo /server. Isso significa que todas as rotas definidas em serverRoutes ficam acessíveis a partir desse caminho base. Portanto, a rota router.post("/predict") torna-se o endpoint completo POST /server/predict. O servidor também contém uma rota raiz GET / que retorna { status: "OK" }. Essa rota pode ser utilizada como um Health Check para verificar se o backend foi iniciado corretamente. Finalmente, app.listen(3000) inicia o servidor na porta 3000. O backend pode então receber solicitações do frontend e executar previsões em Python.

const express =

O Express é importado e, em seguida, uma instância da aplicação é criada. Essa instância representa o servidor HTTP que receberá as solicitações.

Esse middleware permite que o Express compreenda solicitações cujo corpo contém dados JSON. Ele é essencial aqui porque o frontend envia o modelo e as variáveis x1 e x2 em formato JSON.

const serverRoutes =
require("./routes/serverRoutes");

app.use(

O servidor importa o router que contém os endpoints de previsão e o monta sob o prefixo /server. A rota /predict torna-se, portanto, /server/predict.

O servidor fica escutando na porta 3000. Todas as solicitações enviadas para essa porta podem ser processadas pelo Express.

Arquitetura Completa do Sistema

A arquitetura completa é baseada na comunicação entre várias etapas. Tudo começa no frontend ou dashboard, que contém os dados necessários para a previsão. Ele envia uma solicitação HTTP POST para o endpoint /server/predict. O Express recebe a solicitação e recupera as propriedades model, x1 e x2. Após a validação, a rota chama o serviço runCommerce(). Esse serviço utiliza o módulo child_process do Node.js para iniciar o programa Python. O Node.js envia os dados ao programa Python em formato JSON através do stdin. O script Python lê os dados, identifica o modelo solicitado e seleciona o arquivo PKL correspondente utilizando o dicionário file_map. O modelo SVR é então recarregado utilizando pickle.load(). As variáveis x1 e x2 são recuperadas e passadas ao modelo utilizando predict(). O modelo produz um valor previsto. O Python então converte esse valor para JSON e o escreve no stdout. O Node.js recupera o conteúdo do stdout, interpreta o JSON utilizando JSON.parse() e retorna o resultado para a rota Express. Finalmente, o Express envia a resposta JSON ao frontend. Essa arquitetura permite utilizar um modelo real de Machine Learning desenvolvido em Python enquanto mantém um backend Web moderno baseado em Node.js e Express.

Papel das Tecnologias

Cada tecnologia utilizada nesta arquitetura possui uma responsabilidade específica. Python e Scikit-learn são utilizados na parte de Machine Learning. SVR é o algoritmo de regressão utilizado para aprender a relação entre as variáveis de entrada e os valores-alvo. Pickle permite salvar os modelos treinados e recarregá-los durante as previsões. Node.js é o ambiente de execução do backend JavaScript. Express é utilizado para criar a API REST e tratar as solicitações HTTP. O módulo child_process permite que o Node.js execute o Python e se comunique com ele. JSON é o formato de troca de dados entre os dois ambientes. Finalmente, o frontend ou dashboard utiliza a API para enviar as variáveis de entrada e exibir o resultado da previsão.

Para entender como o sistema funciona na prática, imagine que um usuário seleciona o modelo Carrefour e fornece os valores x1 = 30 e x2 = 3. O frontend então envia uma solicitação POST para /server/predict com um objeto JSON contendo o modelo e as duas variáveis. O Express recebe a solicitação e verifica se x1 e x2 estão presentes. A rota então chama runCommerce(). O Node.js inicia o script Python commerce2.py utilizando spawn() e envia os dados JSON para ele. O Python lê o JSON, identifica carrefour como o modelo solicitado, seleciona carrefour.pkl e então recarrega o modelo SVR utilizando pickle.load(). Os valores 30 e 3 são então passados para model.predict([[30, 3]]). O modelo utiliza os parâmetros aprendidos durante o treinamento para produzir uma estimativa. O Python então converte o resultado para JSON e o escreve no stdout. O Node.js recupera esse resultado, utiliza JSON.parse() para convertê-lo em um objeto JavaScript e depois o envia ao Express. Finalmente, o Express retorna esse resultado ao frontend. O dashboard pode então exibir o valor previsto ao usuário. Se o modelo solicitado fosse aziza, o mesmo fluxo seria utilizado, mas o script carregaria aziza.pkl e utilizaria o modelo SVR treinado com os dados do Aziza.

Conclusão

Este sistema representa uma arquitetura completa de Machine Learning integrada a uma aplicação Web. Os dados são utilizados para treinar dois modelos SVR independentes, e os modelos treinados são então salvos em arquivos PKL. Um script Python especializado posteriormente recarrega o modelo solicitado e produz uma previsão com base nas variáveis recebidas. O Node.js atua como gateway entre a aplicação Web e o Python através do módulo child_process e da função spawn(). O Express fornece os endpoints HTTP que permitem ao frontend se comunicar com o sistema. O formato JSON garante a comunicação entre os diferentes componentes. A cadeia completa pode, portanto, ser representada como: Dados → Treinamento SVR → Arquivo PKL → Python → Node.js → Express → Previsão → Dashboard. Essa organização permite utilizar modelos reais de Machine Learning em Python em uma aplicação Web moderna, mantendo uma arquitetura modular e escalável.
