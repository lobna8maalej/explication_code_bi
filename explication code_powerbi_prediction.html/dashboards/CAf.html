📊 Explication détaillée du Dashboard CA

React • Redux Toolkit • Axios • API • Power BI • Recharts

1. Présentation générale du système frontend

Dans cette partie du projet, nous avons développé une interface frontend dédiée à la prédiction du chiffre d'affaires, appelée Dashboard CA. Cette interface est réalisée avec React et utilise plusieurs technologies complémentaires afin de communiquer avec le backend, gérer les données de manière centralisée, afficher les résultats de la prédiction et représenter graphiquement les données. Le fonctionnement général repose sur une communication entre le composant React, Redux Toolkit, Axios et l'API backend. Le composant React ne réalise pas directement toute la logique de communication avec le serveur. Il utilise Redux pour déclencher une action asynchrone qui envoie les données vers le backend. Axios est utilisé pour effectuer la requête HTTP vers l'URL http://localhost:3000/CA. Le backend reçoit alors les données concernant le chiffre d'affaires en TND et en EUR ainsi que le mode de prédiction. Il effectue ensuite le traitement nécessaire et retourne un résultat contenant notamment la prédiction. Redux récupère cette réponse et la stocke dans son état global. Le composant React utilise ensuite useSelector pour récupérer les données depuis Redux et afficher le résultat à l'écran. Le composant utilise également useEffect afin de lancer automatiquement la prédiction lorsque la page est chargée. Enfin, la bibliothèque Recharts permet de transformer les données reçues en graphique afin de comparer le chiffre d'affaires réel avec la valeur prédite. En parallèle, un rapport Power BI est intégré dans la page grâce à une balise iframe. On obtient donc une architecture frontend complète permettant de réunir la visualisation BI, la prédiction Machine Learning, la gestion d'état avec Redux, la communication avec le backend et la représentation graphique des résultats.

2. Importation de Redux Toolkit

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

Cette instruction permet d'importer deux fonctions importantes de Redux Toolkit. La fonction createAsyncThunk est utilisée pour créer une opération asynchrone, notamment pour effectuer une requête HTTP vers le backend. Dans notre projet, cette fonction permet d'envoyer les données du chiffre d'affaires à l'API et de récupérer le résultat de la prédiction. La fonction createSlice permet quant à elle de créer une partie du store Redux dédiée au chiffre d'affaires. Cette partie est appelée un slice. Le slice contient le nom de cette partie de l'état, son état initial ainsi que la logique permettant de modifier cet état lorsque la requête est en cours, réussie ou échoue. L'utilisation de Redux Toolkit simplifie donc considérablement la gestion de l'état global de l'application.

3. Importation d'Axios

import axios from "axios";

Axios est une bibliothèque JavaScript permettant d'effectuer des requêtes HTTP. Dans notre application, Axios sert d'intermédiaire entre le frontend React et le backend Node.js. Lorsque nous voulons lancer une prédiction, le frontend doit envoyer les données au serveur. Axios permet de réaliser cette opération avec la méthode axios.post(). Le serveur reçoit alors les données envoyées par React, réalise le traitement de prédiction et retourne une réponse JSON. Axios récupère cette réponse afin qu'elle puisse ensuite être stockée dans Redux et affichée dans le composant React. L'utilisation d'Axios permet donc de faciliter la communication entre les différentes parties de l'application.

4. Création de l'opération asynchrone avec createAsyncThunk

export const createPrediction = createAsyncThunk(
  "ca/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/CA",
        data
      );

      return res.data;

    } catch (err) {
      return rejectWithValue(
        err.response?.data || "Erreur serveur"
      );
    }
  }
);

Cette partie constitue le lien principal entre Redux et le backend. Nous créons une fonction appelée createPrediction avec createAsyncThunk. Le premier paramètre, "ca/create", représente le type de l'action Redux. Le deuxième paramètre est une fonction asynchrone qui reçoit les données dans la variable data. Cette fonction utilise ensuite Axios afin d'envoyer une requête HTTP POST vers l'adresse http://localhost:3000/CA. La méthode POST est utilisée car nous envoyons des informations au serveur afin qu'il puisse effectuer une prédiction. La variable data contient les paramètres nécessaires à la prédiction. Dans notre cas, elle contient notamment mode, ca_tnd et ca_eur. Le mot-clé await permet d'attendre la réponse du serveur avant de continuer l'exécution. Lorsque le serveur répond correctement, la réponse est stockée dans res et res.data contient les données JSON retournées par le backend. L'instruction return res.data transmet alors ces données à Redux. Si une erreur se produit pendant la requête, l'exécution passe dans le bloc catch. La fonction rejectWithValue() permet alors de transmettre une information d'erreur à Redux. L'expression err.response?.data permet de récupérer le message retourné par le serveur lorsqu'il existe. Si aucune réponse exploitable n'est disponible, le message "Erreur serveur" est utilisé. Cette structure permet donc de gérer proprement les deux situations possibles : une prédiction réussie ou une erreur lors de la communication avec le backend.

5. Création du caSlice

const caSlice = createSlice({
  name: "ca",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

Cette partie crée le slice Redux consacré au chiffre d'affaires. La propriété name: "ca" permet d'identifier cette partie du store Redux. L'application possède ainsi un espace d'état spécifiquement destiné aux données du CA. La propriété initialState définit l'état initial du système. predictionData est initialisée à null car aucune prédiction n'a encore été reçue. loading est initialisé à false car aucune requête n'est en cours au démarrage. Enfin, error est initialisée à null car aucune erreur n'existe au départ. La propriété reducers est vide dans notre cas parce que nous n'avons pas besoin de créer des actions synchrones classiques. La gestion de notre action asynchrone createPrediction est réalisée dans extraReducers. Cela permet à Redux de réagir automatiquement aux différents états de la requête asynchrone.

6. État pending : requête en cours

.addCase(createPrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

Lorsque la requête de prédiction commence, Redux déclenche automatiquement l'état pending. Cela signifie que la requête est actuellement en cours d'exécution. Dans cette situation, nous définissons state.loading = true. Cette information permet au composant React de savoir qu'il doit afficher un message indiquant que la prédiction est en cours de chargement. Nous réinitialisons également state.error = null afin d'effacer une éventuelle erreur provenant d'une requête précédente. Le système permet donc de maintenir une information claire sur l'état actuel de la communication avec le backend.

7. État fulfilled : prédiction réussie

.addCase(createPrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

Lorsque le backend répond correctement, Redux déclenche l'état fulfilled. Cela signifie que la requête asynchrone est terminée avec succès. Nous définissons alors state.loading = false puisque le chargement est terminé. Ensuite, nous enregistrons le résultat retourné par le serveur dans state.predictionData. La propriété action.payload contient les données retournées par return res.data dans le thunk. Redux conserve donc le résultat de la prédiction dans son état global. Le composant React pourra ensuite récupérer cette information grâce à useSelector.

8. État rejected : erreur de prédiction

.addCase(createPrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

Si la requête échoue, Redux déclenche automatiquement l'état rejected. Dans cette situation, state.loading repasse à false puisque la requête est terminée, même si elle s'est terminée avec une erreur. Le message d'erreur transmis par rejectWithValue() est ensuite stocké dans state.error. Le composant React peut alors récupérer cette erreur et l'afficher à l'utilisateur. Cette gestion des trois états pending, fulfilled et rejected permet de construire une interface dynamique qui indique clairement si la prédiction est en cours, terminée ou en erreur.

Ces trois instructions permettent au composant React de récupérer les informations stockées dans Redux. 17. Lancement automatique de la prédiction avec useEffect

useEffect(() => {
  dispatch(
    createPrediction({
      mode: "export",
      ca_tnd: 50000,
      ca_eur: 10000,
    })
  );
}, [dispatch]);

Cette partie est essentielle pour le fonctionnement automatique du Dashboard. Le hook useEffect permet d'exécuter une opération après le rendu du composant. Lorsque la page CA est chargée, le composant appelle dispatch() et déclenche createPrediction(). Nous envoyons alors trois informations au backend : mode: "export", ca_tnd: 50000 et ca_eur: 10000. Ces données représentent les valeurs utilisées par le modèle de prédiction. Redux transmet ensuite ces informations au thunk, le thunk utilise Axios pour envoyer une requête POST vers le backend et le backend effectue la prédiction. Le tableau [dispatch] indique les dépendances du useEffect. Dans ce cas, l'effet est exécuté lorsque le composant est monté et si la référence de dispatch change.

Le fonctionnement complet commence lorsque l'utilisateur ouvre le Dashboard CA. React charge le composant CA et le hook useEffect lance automatiquement l'action createPrediction. Si la requête échoue, Redux déclenche rejected et stocke l'erreur dans error, ce qui permet à React d'afficher le message correspondant.

30. Gestion des trois états de la requête

L'un des avantages importants de Redux Toolkit dans ce projet est la gestion automatique des différents états de l'opération asynchrone. Lorsque la requête commence, l'état pending est déclenché et loading devient true. Le frontend affiche alors le message de chargement. Lorsque le backend retourne correctement la prédiction, l'état fulfilled est déclenché, loading devient false et le résultat est enregistré dans predictionData. React peut alors afficher la carte de résultat et le graphique. Si une erreur survient pendant la requête, l'état rejected est déclenché, loading devient false et le message d'erreur est enregistré dans error. Le composant React affiche alors cette erreur. On obtient donc une gestion claire du cycle complet de la requête.

31. Architecture frontend utilisée

L'architecture utilisée dans cette fonctionnalité sépare clairement les responsabilités. Le composant React CA.jsx est responsable de l'interface et de l'affichage. Le fichier caSlice.js est responsable de la gestion de l'état Redux et de la communication asynchrone avec l'API. Axios est responsable de l'envoi de la requête HTTP. Le backend Node.js est responsable du traitement de la demande et de la génération de la prédiction. Recharts est responsable de la visualisation graphique du résultat et Power BI fournit une visualisation décisionnelle supplémentaire. Cette séparation rend le projet plus organisé et facilite la maintenance et l'évolution de l'application.

32. Différence entre Redux et React dans ce code

Dans cette architecture, React et Redux ont des responsabilités différentes mais complémentaires. React est principalement utilisé pour construire l'interface utilisateur : il affiche le titre, le rapport Power BI, le message de chargement, le résultat et le graphique. Redux est utilisé pour gérer l'état de la prédiction : il conserve les données reçues du backend, indique si une requête est en cours et conserve les éventuelles erreurs. useDispatch permet à React de demander à Redux de lancer une opération et useSelector permet à React de récupérer les données stockées par Redux. Cette séparation permet d'éviter de mélanger toute la logique de communication avec le serveur directement dans l'interface.

34. Résumé du fonctionnement

Pour résumer, lorsque l'utilisateur ouvre le Dashboard CA, React charge le composant CA. Le hook useEffect lance automatiquement une action Redux appelée createPrediction. Cette action est créée avec createAsyncThunk et utilise Axios pour envoyer une requête POST au backend sur http://localhost:3000/CA. Les données envoyées sont le mode export, un chiffre d'affaires en TND de 50000 et un chiffre d'affaires en EUR de 10000. Pendant l'exécution, Redux passe à l'état pending et React affiche le message de chargement. Lorsque le serveur retourne le résultat, Redux passe à l'état fulfilled et stocke la réponse dans predictionData. React récupère cette information grâce à useSelector, affiche la valeur prédite avec deux chiffres après la virgule et prépare les données nécessaires au graphique. Recharts affiche ensuite deux barres permettant de comparer le chiffre d'affaires réel avec la prédiction. En parallèle, Power BI est affiché dans une iframe afin de fournir une visualisation décisionnelle complémentaire. Si une erreur se produit, Redux passe à l'état rejected et React affiche le message d'erreur. Le système forme ainsi une chaîne complète entre l'interface React, Redux Toolkit, Axios, le backend Node.js, le modèle de prédiction, Recharts et Power BI.
