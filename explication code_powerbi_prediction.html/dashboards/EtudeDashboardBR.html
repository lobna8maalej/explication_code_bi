📊 Dashboard de Estudos com Redux Toolkit e React

Explicação detalhada do funcionamento do arquivo Redux etudeSlice.js e do componente React EtudeDashboard.jsx.

76 Apresentação geral

Esta parte do projeto implementa um dashboard dedicado à análise de dados relacionados aos estudos no exterior, utilizando várias tecnologias frontend complementares, principalmente React, Redux Toolkit, Axios e Recharts. O principal objetivo é recuperar automaticamente os dados do backend, armazená-los no store Redux, gerenciar os diferentes estados da requisição e, em seguida, apresentar os resultados em uma interface React na forma de lista e gráfico. O componente React EtudeDashboard se comunica com o backend por meio da ação assíncrona fetchEtudeData. Essa ação é criada com createAsyncThunk e utiliza Axios para enviar uma requisição HTTP GET para o endereço http://localhost:3000/etude/dashboard. O backend retorna os dados no formato JSON e o código recupera especificamente a propriedade data da resposta. Essas informações são então enviadas para o Redux, que as armazena na propriedade items do state global. O componente React recupera posteriormente os dados usando useSelector. O hook useEffect permite executar automaticamente a ação de recuperação quando a página é carregada. Os dados recuperados são então transformados com map() para criar um array adaptado ao Recharts. Cada elemento contém um nome correspondente ao modo, um valor real e um valor de previsão. O componente também exibe o dashboard do Power BI por meio de uma tag iframe. Por fim, o Recharts é utilizado para construir um gráfico de barras que permite visualizar as previsões. Essa arquitetura permite separar claramente o gerenciamento dos dados, realizado pelo Redux Toolkit, da apresentação e da interação, realizadas pelo React.

77 Importação do Redux Toolkit e Axios

O arquivo Redux começa importando createSlice e createAsyncThunk do Redux Toolkit. A função createSlice permite criar uma parte do store Redux dedicada aos dados dos estudos. Ela permite definir o nome do slice, o estado inicial e os tratamentos associados às diferentes situações da requisição assíncrona. A função createAsyncThunk permite criar uma ação assíncrona capaz de se comunicar com o backend. O código também importa axios, que é utilizado como cliente HTTP para realizar a requisição à API Node.js/Express. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

Essas importações constituem, portanto, a base da comunicação entre o frontend React, o store Redux e o backend.

78 Criação da ação assíncrona fetchEtudeData

A principal ação do arquivo Redux é fetchEtudeData. Ela é criada com createAsyncThunk. Essa função permite realizar uma operação assíncrona enquanto o Redux Toolkit gerencia automaticamente os estados pending, fulfilled e rejected. O primeiro argumento, "etude/fetchEtudeData", corresponde ao tipo da ação Redux. Ele permite identificar essa operação dentro da aplicação. O segundo argumento é uma função assíncrona que será executada quando a ação for chamada pelo componente React. 

export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        try {
            const response = await axios.get(
                "http://localhost:3000/etude/dashboard"
            );

            return response.data.data;

        } catch (error) {
            return thunkAPI.rejectWithValue(error.message);
        }
    }
);

O símbolo _ representa aqui o primeiro argumento da função, mas ele não é utilizado porque essa ação não precisa de nenhum dado enviado pelo componente. O segundo parâmetro thunkAPI permite, entre outras coisas, utilizar rejectWithValue para transmitir um erro personalizado para o state do Redux.

79 Requisição Axios para o backend

Dentro da função assíncrona, o Axios realiza uma requisição HTTP do tipo GET para a rota /etude/dashboard. O uso da palavra-chave await permite aguardar a resposta do servidor antes de continuar a execução. Quando o backend responde, o Axios coloca a resposta no objeto response. Os dados retornados pelo servidor podem ser acessados por meio de response.data. Neste projeto, a resposta contém outra propriedade data. Portanto, o código recupera response.data.data, que corresponde ao array que contém os dados necessários para o dashboard. 

const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

return response.data.data;

O return é particularmente importante, porque o valor retornado se torna o payload da ação quando a requisição é concluída com sucesso.

80 Tratamento de erros com try / catch

A requisição é colocada dentro de uma estrutura try / catch. O bloco try contém a requisição Axios e seu processamento normal. Se a requisição falhar, por exemplo, quando o servidor backend estiver desligado, quando a URL estiver incorreta ou quando ocorrer um erro de rede, a execução passa para o bloco catch. O código recupera então a mensagem do erro por meio de error.message e utiliza thunkAPI.rejectWithValue() para transmitir essa informação para o Redux. O componente React poderá posteriormente recuperar esse erro por meio da propriedade error. 

catch (error) {
    return thunkAPI.rejectWithValue(error.message);
}

81 Criação do etudeSlice

O código cria então o slice Redux dedicado aos estudos usando createSlice. A propriedade name define o nome dessa parte do store. Neste caso, o nome é etude. Essa identificação permite acessar os dados usando state.etude no componente React. 

const etudeSlice = createSlice({
    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    reducers: {},

    extraReducers: (builder) => {
        // ...
    }
});

O uso de extraReducers é adequado aqui porque a ação fetchEtudeData foi criada com createAsyncThunk. Os estados gerados automaticamente por essa ação são, portanto, tratados nesta seção.

82 Definição do initialState

O initialState representa o estado inicial do módulo de estudos. A propriedade items é inicializada com um array vazio porque nenhum dado foi recuperado ainda. A propriedade loading é inicializada com false, o que significa que nenhuma requisição está em andamento. Por fim, a propriedade error é inicializada com null, pois nenhum erro foi encontrado até o momento. Essas três propriedades permitem que o componente React conheça o estado atual da recuperação dos dados. 

initialState: {
    items: [],
    loading: false,
    error: null
}

83 Gerenciamento do estado pending

Quando o componente React executa dispatch(fetchEtudeData()), o Redux Toolkit ativa automaticamente o estado pending. Esse estado significa que a requisição está em andamento. O código define então state.loading como true e redefine a propriedade error para null. Graças a essa informação, o React pode exibir uma mensagem de carregamento para o usuário enquanto o backend processa a solicitação. 

.addCase(fetchEtudeData.pending, (state) => {
    state.loading = true;
    state.error = null;
})

84 Gerenciamento do estado fulfilled

Quando a requisição Axios é concluída corretamente, o Redux Toolkit ativa o estado fulfilled. Isso significa que o backend respondeu corretamente e que os dados foram recuperados. O código define loading como false, pois o carregamento foi concluído. Em seguida, action.payload contém os dados retornados por fetchEtudeData. Esses dados são armazenados diretamente em state.items. Eles ficam, portanto, disponíveis no store Redux. 

.addCase(fetchEtudeData.fulfilled, (state, action) => {
    state.loading = false;
    state.items = action.payload;
})

Essa etapa é essencial porque transfere os dados do backend para o store Redux. O componente React poderá então recuperá-los usando useSelector.

85 Gerenciamento do estado rejected

Se ocorrer um erro durante a requisição, o Redux Toolkit ativa o estado rejected. O código define primeiro loading como false, pois a requisição foi finalizada, e depois recupera a mensagem de erro por meio de action.payload. Esse valor corresponde à informação enviada por rejectWithValue dentro do bloco catch. O erro é então armazenado em state.error. Dessa forma, o componente React pode exibir esse erro para o usuário. 

.addCase(fetchEtudeData.rejected, (state, action) => {
    state.loading = false;
    state.error = action.payload;
})

86 Exportação do reducer

No final do arquivo Redux, o reducer do slice é exportado usando export default etudeSlice.reducer. Esse reducer poderá então ser adicionado ao store Redux principal da aplicação. Ele representa a lógica responsável por modificar o estado etude. 

export default etudeSlice.reducer;

87 Importação das funcionalidades do React

O arquivo React começa importando React e o hook useEffect. Ele também importa useDispatch e useSelector do React Redux. Em seguida, o componente importa a ação fetchEtudeData do arquivo Redux. Por fim, vários componentes do Recharts são importados para construir o gráfico de visualização. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchEtudeData } from "../redux/etudeSlice";

88 Uso do useDispatch

No componente EtudeDashboard, o hook useDispatch permite obter a função dispatch. Essa função é utilizada para enviar uma ação para o store Redux. No nosso caso, ela permite executar a ação fetchEtudeData(). O React não realiza diretamente a requisição Axios. Em vez disso, ele solicita ao Redux que realize essa operação. 

const dispatch = useDispatch();

89 Uso do useSelector

O hook useSelector permite que o componente React recupere os dados presentes no store Redux. O código acessa state.etude e extrai diretamente as propriedades items, loading e error. Dessa forma, o componente conhece os dados disponíveis, sabe se uma requisição está em andamento e também pode conhecer uma eventual mensagem de erro. 

const { items, loading, error } =
    useSelector(state => state.etude);

90 Recuperação automática com useEffect

O hook useEffect é utilizado para iniciar automaticamente a recuperação dos dados quando o componente é carregado. Dentro do hook, o código chama dispatch(fetchEtudeData()). Isso dispara a ação Redux e, consequentemente, a requisição Axios para o backend. O usuário não precisa clicar em nenhum botão para recuperar os dados. O carregamento é, portanto, automático quando a página do dashboard é aberta. 

useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

91 Transformação dos dados com map()

Depois de recuperar os dados do Redux, o componente cria uma nova variável chamada chartData. Essa variável é construída usando o método JavaScript map(). O método map permite percorrer cada elemento do array items e criar um novo objeto adaptado ao Recharts. Para cada elemento, a propriedade name recebe o valor de item.mode, a propriedade Value recebe o valor real item.value e a propriedade Prediction recebe a previsão. O operador ?? permite fornecer o valor 0 quando a previsão é null ou undefined. 

const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

Essa transformação permite obter exatamente a estrutura de dados esperada pelo componente BarChart.

92 Integração do dashboard do Power BI

O componente React também integra um relatório do Power BI por meio de uma tag iframe. Essa técnica permite exibir conteúdo externo diretamente na página Web. O atributo src contém o endereço do relatório Power BI publicado. Dessa forma, o usuário pode consultar o dashboard do Power BI diretamente pela interface React. A propriedade allowFullScreen também permite a exibição em tela cheia quando essa função estiver disponível. 

<iframe
    className="etude-iframe"
    title="etude A L'Etranger"
    src="URL_DU_RAPPORT_POWER_BI"
    allowFullScreen
/>

Essa integração permite reunir na mesma página as visualizações do Power BI e os dados dinâmicos provenientes do backend.

93 Gerenciamento de loading e error

O componente React utiliza as propriedades loading e error recuperadas do Redux para informar ao usuário sobre o estado da requisição. Quando loading é verdadeiro, o componente exibe uma mensagem Loading.... Quando error contém um valor, a mensagem de erro é exibida. Essa lógica torna a interface mais clara e permite que o usuário compreenda o que está acontecendo durante a recuperação dos dados. 

{loading && (
    <p className="etude-loading">
        Loading...
    </p>
)}

{error && (
    <p className="etude-error">
        {error}
    </p>
)}

94 Exibição dos dados em formato de lista

O componente exibe então os dados recuperados em formato de lista HTML. O método map() é utilizado para percorrer o array items. Para cada elemento, um elemento li é criado. A propriedade key permite que o React identifique cada elemento de forma única durante a renderização. Para cada linha, o componente exibe o modo, o valor real e a previsão. O operador ?? permite exibir N/A quando nenhuma previsão estiver disponível. 

<ul className="etude-list">

    {items.map((item, i) => (
        <li key={i}>
            Mode: {item.mode}
            | Value: {item.value}
            | Prediction: {item.prediction ?? "N/A"}
        </li>
    ))}

</ul>

95 Criação do gráfico com Recharts

A biblioteca Recharts é utilizada para transformar os dados em uma representação gráfica. O componente ResponsiveContainer permite que o gráfico se adapte automaticamente à largura disponível. O componente BarChart recebe o array chartData. Os componentes XAxis e YAxis representam respectivamente os eixos horizontal e vertical. CartesianGrid adiciona uma grade para facilitar a leitura do gráfico. Tooltip exibe informações quando o usuário passa o mouse sobre uma barra e Legend permite exibir a legenda. Por fim, o componente Bar utiliza a propriedade dataKey="Prediction" para representar graficamente as previsões. 

<ResponsiveContainer width="100%" height={350}>

    <BarChart data={chartData}>

        <CartesianGrid strokeDasharray="3 3" />

        <XAxis dataKey="name" />

        <YAxis />

        <Tooltip />

        <Legend />

        <Bar
            dataKey="Prediction"
            fill="#6366f1"
        />

    </BarChart>

</ResponsiveContainer>

96 Funcionamento geral do Redux e React

O funcionamento começa quando o usuário abre a página EtudeDashboard. O React monta o componente e executa o hook useEffect. Ele dispara dispatch(fetchEtudeData()). O Redux Toolkit inicia então a ação assíncrona criada com createAsyncThunk. O estado pending é ativado automaticamente e a propriedade loading passa a ser true. Em seguida, o Axios envia uma requisição GET para o backend. O backend processa a solicitação e retorna os dados do dashboard. Se a requisição for bem- sucedida, o Redux ativa fulfilled, altera loading para false e coloca os dados em state.items. O componente React recupera então esses dados usando useSelector. Eles são utilizados para construir a lista e o array chartData. Este último é enviado para o Recharts para construir o gráfico. Se ocorrer um erro, o estado rejected é ativado, o erro é armazenado no Redux e o React pode exibir a mensagem correspondente.

97 Arquitetura frontend completa

Essa funcionalidade demonstra uma arquitetura frontend organizada na qual cada tecnologia possui uma função específica. O React é responsável pela interface do usuário e pela renderização dos componentes. O Redux Toolkit é utilizado para centralizar os dados dos estudos no store global. O createAsyncThunk simplifica o gerenciamento da operação assíncrona. O Axios garante a comunicação HTTP entre o frontend e o backend. O useEffect permite iniciar automaticamente a recuperação dos dados. O useDispatch permite que o React envie a ação Redux e o useSelector permite recuperar os resultados do store. O método map() permite transformar os dados recebidos para adaptá-los ao gráfico. Por fim, o Recharts permite criar uma visualização gráfica interativa e o Power BI fornece uma visualização de Business Intelligence integrada na mesma página. Essa separação de responsabilidades torna o código mais organizado, mais fácil de manter e mais simples de evoluir.

98 Conclusão

O Dashboard de Estudos constitui um fluxo completo de recuperação, gerenciamento e visualização de dados. O processo começa no React com useEffect, que dispara a ação Redux fetchEtudeData. Essa ação utiliza createAsyncThunk e Axios para se comunicar com o backend. O Redux Toolkit gerencia automaticamente as três principais etapas da requisição: pending durante o carregamento, fulfilled quando os dados são recuperados com sucesso e rejected quando ocorre um erro. Os dados recebidos são armazenados em state.etude.items e posteriormente recuperados no React por meio de useSelector. O componente transforma então as informações usando map() para criar os dados necessários para o Recharts. Os resultados são exibidos em formato de lista e gráfico, enquanto o Power BI é integrado por meio de um iframe. Todo o conjunto forma uma arquitetura frontend completa na qual o backend fornece os dados, o Redux Toolkit os centraliza e o React os apresenta ao usuário. Essa organização permite construir um dashboard dinâmico capaz de exibir tanto os dados reais quanto os resultados das previsões em uma interface moderna.
