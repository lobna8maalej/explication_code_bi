Sistema de previsão Sanitaire

Integração de um modelo de Machine Learning desenvolvido em Python em uma aplicação Web Node.js / Express com comunicação por meio de JSON e conexão com um banco de dados MySQL.

Visão geral do sistema

O sistema Sanitaire é uma arquitetura Web que integra um modelo de Machine Learning com o objetivo de gerar automaticamente uma previsão a partir de variáveis numéricas. O objetivo dessa arquitetura é separar claramente o componente de Inteligência Artificial do componente da aplicação Web. O modelo de Machine Learning é desenvolvido e treinado em Python e posteriormente salvo em um arquivo denominado CASA.pkl. Esse arquivo contém o modelo já treinado e permite reutilizar o conhecimento aprendido sem precisar realizar novamente a etapa de treinamento para cada previsão. O script Python sanitaire.py representa o mecanismo de previsão. Ele carrega o modelo por meio da biblioteca joblib, recupera os valores enviados pelo Node.js, converte-os em números por meio de float(), cria um array NumPy e utiliza o método predict() do modelo para obter a previsão. O resultado é posteriormente convertido em um objeto JSON para que possa ser facilmente recuperado pelo backend Node.js. No lado do JavaScript, o serviço sanitaireService.js utiliza o módulo nativo child_process e a função spawn() para executar o programa Python a partir do Node.js. O serviço envia o tipo de modelo e os valores numéricos como argumentos para o processo Python. O Node.js recupera posteriormente a saída padrão stdout produzida pelo Python e procura a linha que contém o resultado JSON. Essa linha é analisada por meio de JSON.parse(). O router do Express sanitaireRoute.js expõe então uma API que permite ao frontend solicitar uma previsão. No exemplo fornecido, a rota chama o serviço utilizando o modelo identificado por "1" e os valores 10 e 20. O resultado é retornado ao frontend em formato JSON com uma propriedade message e uma propriedade data. Por fim, o projeto também contém um módulo de conexão com MySQL que permite estabelecer uma conexão com o banco de dados POWERBI_PREDICTION. A arquitetura completa forma, portanto, um sistema no qual Python gerencia o processamento de Machine Learning, Node.js gerencia a execução e a comunicação com Python, Express fornece a API Web e MySQL pode fornecer a persistência dos dados.

02

Script de previsão em Python

O arquivo sanitaire.py representa o núcleo do processamento de Machine Learning. Sua principal função é carregar o modelo CASA.pkl, recuperar as variáveis transmitidas pelo Node.js, preparar os dados em formato numérico e executar a previsão. O script começa importando várias bibliotecas. A função load do joblib é utilizada para carregar novamente o modelo de Machine Learning salvo. A biblioteca NumPy é utilizada para criar o array numérico que é passado ao modelo. O módulo sys fornece acesso aos argumentos enviados pelo Node.js, enquanto o módulo os é utilizado para construir um caminho confiável para o arquivo do modelo. Por fim, json é utilizado para converter o resultado da previsão para o formato JSON. O programa determina primeiro o diretório que contém o script por meio de os.path.dirname(__file__). Em seguida, o caminho para CASA.pkl é construído utilizando os.path.join(). O modelo é carregado por meio de load(). Depois, o script recupera os argumentos utilizando sys.argv[2:]. O segundo argumento e os seguintes correspondem aos valores numéricos, pois o primeiro argumento depois do script representa o tipo de modelo nessa arquitetura. Os valores são convertidos em números decimais por meio de map(float, ...). Em seguida, eles são colocados em um array NumPy utilizando np.array([values]). Essa estrutura corresponde ao formato esperado pelos modelos de Machine Learning do Scikit-learn. O script também exibe vários dados de depuração: os valores recebidos, o formato do array e o número de características esperadas pelo modelo por meio de model.n_features_in_. Essas informações permitem verificar se os dados transmitidos pelo Node.js correspondem à estrutura utilizada durante o treinamento. O método model.predict(X) realiza então a previsão. Por fim, o script cria um objeto JSON contendo o nome do modelo, a previsão e os valores utilizados. Esse objeto é enviado por meio de print(), permitindo que o Node.js o recupere através de stdout.

Importação das bibliotecas 

from joblib import load
import numpy as np
import sys
import os
import json

joblib é utilizado para carregar o modelo salvo. NumPy é utilizado para criar o array de entrada numérico. sys recupera os argumentos transmitidos pelo Node.js. os gerencia os caminhos dos arquivos, enquanto json gera uma resposta estruturada compatível com JavaScript.

Determinação do diretório do modelo 

BASE_DIR = os.path.dirname(__file__)

model = load(
    os.path.join(
        BASE_DIR,
        "CASA.pkl"
    )
)

BASE_DIR representa o diretório que contém o script Python. os.path.join() constrói posteriormente o caminho para CASA.pkl. O modelo é carregado por meio de joblib.load(). Essa abordagem evita que a aplicação dependa do diretório a partir do qual o Node.js executa o programa.

Recuperação dos argumentos 

values = list(
    map(float, sys.argv[2:])
)

O programa recupera os argumentos utilizando sys.argv[2:]. O primeiro argumento passado depois do script representa o tipo de modelo, enquanto os argumentos seguintes correspondem aos valores utilizados para a previsão. Cada valor é convertido em um número decimal por meio de float() para obter dados compatíveis com o modelo de Machine Learning.

Criação do array NumPy 

X = np.array([values])

Os valores são transformados em um array NumPy. O uso de colchetes ao redor de values representa os dados como uma observação contendo múltiplas características. Essa estrutura é compatível com o método predict() utilizado pelo modelo.

Validação dos dados 

print("VALUES =", values)
print("SHAPE =", X.shape)
print("FEATURES =", model.n_features_in_)

Essas três instruções são utilizadas principalmente para depuração. A primeira exibe os valores recebidos, a segunda exibe as dimensões do array NumPy e a terceira exibe o número de características esperadas pelo modelo. Isso permite detectar rapidamente uma incompatibilidade entre os dados enviados pelo Node.js e os dados utilizados durante o treinamento do modelo.

Execução da previsão 

prediction = model.predict(X)

O método predict() aplica o modelo de Machine Learning aos dados preparados. O modelo utiliza os parâmetros aprendidos durante o treinamento para calcular o valor previsto.

Criação da resposta JSON 

print(json.dumps({
    "model": "CASA",
    "prediction": float(prediction[0]),
    "values": values
}))

O resultado da previsão é colocado em um objeto contendo três elementos: o nome do modelo, o valor previsto e os valores de entrada. prediction[0] recupera a primeira previsão e float() converte esse valor em um número padrão do Python. json.dumps() converte posteriormente o objeto Python em uma string JSON. Essa string é recuperada pelo Node.js por meio de stdout.

03

Modelo de Machine Learning CASA

O arquivo CASA.pkl representa o modelo de Machine Learning utilizado pelo sistema Sanitaire. Diferentemente de um programa Python que precisaria treinar o modelo cada vez que fosse executado, o arquivo PKL contém diretamente o modelo já treinado. Portanto, o script Python precisa apenas carregar esse objeto por meio do Joblib e fornecer novos dados para realizar previsões. Essa separação entre treinamento e previsão é importante em uma arquitetura profissional, pois o treinamento pode ser realizado periodicamente sobre um conjunto completo de dados, enquanto o modelo salvo pode ser utilizado posteriormente pela aplicação Web. A propriedade model.n_features_in_ também permite determinar o número de variáveis esperadas pelo modelo. No código fornecido, o Node.js envia, por exemplo, dois valores: 10 e 20. Portanto, o modelo deve ser compatível com essa estrutura de entrada. Se o número de variáveis enviadas não corresponder ao número esperado pelo modelo, pode ocorrer um erro de dimensões. As informações de depuração exibidas pela aplicação permitem verificar essa correspondência.

Fluxo do modelo: Dados de entrada → Array NumPy → CASA.pkl → predict() → Valor previsto
04

Serviço Node.js e comunicação com Python

O arquivo sanitaireService.js atua como uma ponte entre Node.js e Python. O Node.js não realiza diretamente a previsão de Machine Learning; em vez disso, executa o programa Python utilizando o módulo nativo child_process. A função runPlotPython() retorna uma Promise, o que permite gerenciar o processo Python de forma assíncrona. A função recebe dois parâmetros: modelType e values. O parâmetro modelType representa o tipo de modelo que será utilizado, enquanto values contém as variáveis numéricas. A função spawn() executa o Python com o caminho do script sanitaire.py. O array passado para spawn contém o caminho do programa Python, o tipo de modelo e todos os valores convertidos em strings por meio de values.map(String). O Python recebe assim os dados como argumentos de linha de comando. O Node.js escuta posteriormente o evento data de stdout para recuperar progressivamente a saída gerada pelo programa Python. Como o Python também exibe informações de depuração antes do JSON, o serviço não tenta analisar imediatamente toda a saída. Quando o processo termina, o código utiliza split("\n") para separar as linhas, map(l => l.trim()) para remover espaços desnecessários e filter(l => l.startsWith("{")) para procurar as linhas que começam com uma chave e que, portanto, podem corresponder ao JSON final. O método pop() recupera então a última linha JSON encontrada. Finalmente, JSON.parse() converte a string JSON em um objeto JavaScript. Esse objeto pode ser posteriormente retornado para a rota do Express. Essa técnica permite que o Node.js recupere corretamente o resultado do Python mesmo quando o script também gera informações de depuração.

Importação dos módulos 

const { spawn } = require("child_process");
const path = require("path");

O módulo child_process fornece spawn(), que permite iniciar um processo externo. O módulo path é utilizado para construir de forma confiável o caminho para o script Python.

Criação do caminho do Python 

path.join(
    __dirname,
    "../../python/sanitaire.py"
)

__dirname representa o diretório do arquivo JavaScript atual. A função path.join() permite navegar até o diretório Python e localizar sanitaire.py.

Inicialização do processo Python 

const py = spawn("python", [
    path.join(
        __dirname,
        "../../python/sanitaire.py"
    ),
    modelType,
    ...values.map(String)
]);

Essa instrução inicia o Python e transmite os parâmetros necessários. O primeiro parâmetro é o caminho do script, o segundo é o tipo de modelo e os parâmetros seguintes correspondem aos valores numéricos. O operador spread ... permite adicionar cada valor individualmente ao array de argumentos.

Recuperação de stdout 

py.stdout.on("data", (data) => {
    output += data.toString();
});

O Python utiliza print() para retornar informações ao Node.js. O Node.js recebe esses dados por meio de stdout. Os fragmentos recebidos são adicionados à variável output para reconstruir toda a saída do Python.

Tratamento de erros 

py.stderr.on("data", (data) => {
    error += data.toString();
});

stderr é utilizado para recuperar possíveis mensagens de erro geradas pelo Python. Isso fornece ao Node.js informações adicionais quando ocorre um erro.

Análise da resposta do Python 

const jsonLine = output
    .split("\n")
    .map(l => l.trim())
    .filter(l => l.startsWith("{"))
    .pop();

Essa parte é especialmente importante porque o script Python exibe informações de depuração antes de imprimir o JSON. O serviço divide a saída em várias linhas, remove os espaços desnecessários, mantém as linhas que começam com uma chave e recupera a última linha correspondente. Essa última linha é então considerada o resultado JSON final.

Conversão JSON 

resolve(
    JSON.parse(jsonLine)
);

JSON.parse() transforma a string JSON produzida pelo Python em um objeto JavaScript. resolve() posteriormente transmite esse objeto para a função que chamou o serviço.

05

Rota Express e API Sanitaire

O arquivo sanitaireRoute.js representa a camada API do sistema. O Express é importado e um router é criado utilizando express.Router(). Em seguida, o serviço sanitaireService é importado para que a rota possa executar o programa Python. A rota GET / é declarada como uma função assíncrona utilizando a palavra-chave async. Quando uma solicitação é recebida, a rota chama runPlotPython("1", [10, 20]). O primeiro argumento representa o tipo de modelo e o array contém as variáveis numéricas. A rota utiliza await para aguardar a conclusão da execução do Python. Quando o serviço retorna o objeto JSON, o Express constrói uma resposta contendo message: "OK" e data: result. Essa resposta pode ser consumida posteriormente pelo frontend. Se ocorrer um erro durante a execução do Python ou durante a análise do JSON, o bloco catch intercepta o erro e retorna o status HTTP 500. Essa arquitetura evita que o frontend se comunique diretamente com o Python. O frontend se comunica apenas com a API do Express, enquanto o Express utiliza o serviço Node.js para executar o modelo Python.

Criação do router 

const express = require("express");

const router = express.Router();

O Express fornece as funcionalidades necessárias para criar a API. O router agrupa os endpoints relacionados ao domínio Sanitaire.

Chamada ao serviço Python 

const result = await runPlotPython(
    "1",
    [10, 20]
);

A rota solicita ao serviço Node.js que execute o Python utilizando o tipo de modelo "1" e duas variáveis numéricas. A palavra-chave await faz com que a rota aguarde o resultado antes de continuar.

Resposta da API 

res.json({
    message: "OK",
    data: result
});

O Express retorna uma resposta JSON. A propriedade message indica que a operação foi concluída com sucesso, enquanto data contém o resultado obtido a partir do Python.

Tratamento de erros 

catch (err) {
    res.status(500).json({
        error: err.toString()
    });
}

Em caso de erro, o Express retorna o status HTTP 500 juntamente com uma descrição do erro. Isso permite que o frontend identifique que ocorreu um problema no backend.

Conexão com MySQL

O projeto também contém um módulo dedicado a estabelecer uma conexão com um banco de dados MySQL. O arquivo sanitaireDb.js utiliza o pacote mysql2/promise, que permite comunicar-se com o MySQL utilizando Promises e, portanto, utilizar uma sintaxe async/await. A configuração contém o endereço do servidor localhost, o usuário root, uma senha vazia no ambiente apresentado e o banco de dados POWERBI_PREDICTION. A função getConnection() cria uma nova conexão utilizando mysql.createConnection() e então retorna essa conexão por meio de await. Manter essa lógica em um arquivo dedicado permite centralizar a configuração do banco de dados e reutilizar facilmente a função em diferentes controllers ou serviços. Na rota Sanitaire, a função getConnection pode ser importada quando necessário para recuperar ou armazenar dados no MySQL. O banco de dados pode complementar assim o componente de Machine Learning armazenando informações necessárias para a aplicação, resultados de previsão ou outros dados utilizados pelo dashboard. 

const mysql = require("mysql2/promise");

const dbConfig = {
    host: "localhost",
    user: "root",
    password: "",
    database:
        "POWERBI_PREDICTION"
};

async function getConnection() {
    return await
        mysql.createConnection(
            dbConfig
        );
}

module.exports = { getConnection };

O módulo exporta getConnection para que outros arquivos do backend possam utilizá-lo. O uso de mysql2/promise simplifica o gerenciamento assíncrono das conexões e permite integrar o MySQL à arquitetura Node.js.

07

Inicialização do servidor Express

O arquivo principal do servidor inicializa a aplicação Express. A constante express importa o framework e app = express() cria a aplicação. O middleware express.json() permite que o servidor processe dados JSON enviados por meio de solicitações HTTP. O projeto inicia posteriormente o processo Python utilizando spawn() e define o diretório de trabalho por meio de cwd. A rota Sanitaire é importada de sanitaireRoute e registrada utilizando app.use("/sanitaire", sanitaireRoute). Isso significa que os endpoints definidos no router estarão disponíveis sob o prefixo /sanitaire. Finalmente, app.listen(3000) inicia o servidor HTTP na porta 3000. A mensagem exibida no console confirma que a API foi iniciada. A configuração completa permite, portanto, acessar o sistema de Machine Learning por meio de uma API Web Node.js / Express. 

const express = require("express");

const app = express();

app.use(
    express.json()
);

console.log(
    "sanitaire API STARTED"
);

const sanitaireRoute = require(
    "./routes/sanitaireRoute"
);

app.use(
    "/sanitaire",
    sanitaireRoute
);

app.listen(
    3000,
    () => {
        console.log(
            "Server running on port 3000"
        );
    }
);

O servidor torna-se assim o ponto de entrada da aplicação Web. O frontend pode chamar a API utilizando a rota /sanitaire, após o que o Express ativa o serviço Node.js que executa Python e recupera a previsão.

Arquitetura completa do sistema

A arquitetura completa baseia-se na comunicação entre várias camadas. O processo começa no frontend ou no dashboard, que envia uma solicitação HTTP para a API do Express. O Express recebe a solicitação por meio da rota Sanitaire e chama a função runPlotPython() do serviço Node.js. Essa função utiliza spawn() para criar um processo Python independente. O Python recebe o tipo de modelo e as variáveis numéricas. O script sanitaire.py então carrega CASA.pkl utilizando Joblib. As variáveis recebidas são convertidas em números e depois transformadas em um array NumPy. O modelo utiliza posteriormente o método predict() para calcular a previsão. O Python cria um objeto JSON contendo o nome do modelo, a previsão e os valores de entrada. O Node.js recupera a saída do Python por meio de stdout. Como o script também exibe informações de depuração, o serviço procura a última linha que começa com uma chave para identificar o JSON final. JSON.parse() posteriormente converte essa string em um objeto JavaScript. O resultado é retornado ao Express, que cria a resposta HTTP destinada ao frontend. Paralelamente, o módulo MySQL permite que o backend estabeleça uma conexão com o banco de dados POWERBI_PREDICTION. Esse banco de dados pode ser utilizado para armazenar as informações necessárias para a aplicação ou conservar os resultados gerados pelo sistema. A arquitetura completa separa, portanto, as responsabilidades: o frontend gerencia a visualização, Express gerencia a API, Node.js gerencia a orquestração, Python gerencia o Machine Learning, Joblib gerencia o carregamento do modelo, NumPy gerencia a preparação dos dados e MySQL gerencia a persistência.

Função das tecnologias

Cada tecnologia utilizada nessa arquitetura possui uma responsabilidade específica. Python fornece o ambiente de execução para o modelo de Machine Learning. Joblib permite salvar e carregar novamente o modelo a partir do arquivo CASA.pkl. NumPy prepara as variáveis numéricas como um array compatível com o modelo. O módulo sys permite transmitir parâmetros entre Node.js e Python, enquanto json estrutura os resultados. Node.js fornece o ambiente de execução do backend JavaScript. O módulo child_process fornece a função spawn(), que permite executar o script Python. Express fornece a API REST e organiza as diferentes rotas da aplicação. JSON é utilizado como formato de intercâmbio entre Python, Node.js e o frontend. Por fim, MySQL gerencia os dados persistentes do sistema. Essa combinação permite construir uma arquitetura na qual cada tecnologia é utilizada para uma tarefa específica.

Exemplo prático de funcionamento

Para compreender o funcionamento completo, imagine que o frontend chama a API Sanitaire. O Express recebe a solicitação e executa a função runPlotPython("1", [10, 20]). O Node.js então executa o programa sanitaire.py utilizando Python. Os parâmetros transmitidos são o tipo de modelo 1, seguido pelos valores 10 e 20. O Python recupera esses parâmetros por meio de sys.argv. A expressão sys.argv[2:] recupera os dois valores numéricos e os converte em números decimais. O programa então cria X = np.array([values]). O modelo CASA.pkl é carregado por meio do Joblib e recebe o array através do método predict(). O Python obtém então a previsão e cria um objeto JSON contendo o modelo CASA, o valor previsto e os valores utilizados. O Node.js recupera toda a saída do Python por meio de stdout. Como o Python também exibe as informações de depuração VALUES, SHAPE e FEATURES, o serviço filtra as linhas para recuperar somente a última linha JSON. Essa string é posteriormente convertida em um objeto JavaScript por meio de JSON.parse(). Finalmente, o Express recebe esse objeto e retorna uma resposta JSON ao frontend. O dashboard pode então utilizar a previsão para exibir um KPI, um cartão estatístico, um gráfico ou uma tabela. Esse fluxo mostra claramente como uma previsão baseada em Python pode ser integrada a uma aplicação Web Node.js sem que o frontend precise executar Python diretamente.

Explicação para apresentar durante uma apresentação

Durante uma apresentação profissional, esse sistema pode ser apresentado como uma arquitetura de Inteligência Artificial integrada a uma aplicação Web para a área da saúde. O modelo de Machine Learning é previamente treinado e posteriormente salvo em CASA.pkl. Quando uma previsão é solicitada, o Node.js utiliza o módulo child_process e a função spawn() para executar o script Python. O Python recupera as variáveis, converte-as em dados numéricos e as prepara utilizando NumPy. Em seguida, o modelo CASA é carregado por meio do Joblib e o método predict() calcula o resultado. O Python então retorna o resultado em formato JSON. O Node.js recupera essa resposta por meio de stdout e a converte em um objeto JavaScript utilizando JSON.parse(). O Express posteriormente expõe o resultado por meio de uma API REST. O frontend pode então chamar a API e exibir as previsões em um dashboard. O MySQL completa a arquitetura fornecendo uma solução de armazenamento de dados. A principal vantagem dessa abordagem é a clara separação de responsabilidades: Python é especializado em Machine Learning, Node.js coordena a execução, Express gerencia as solicitações HTTP, JSON gerencia a troca de resultados e MySQL fornece a persistência. Essa organização torna o sistema mais modular e permite adicionar outros modelos, variáveis ou novas funcionalidades ao dashboard no futuro.

Conclusão

O sistema Sanitaire representa uma integração completa entre Machine Learning e desenvolvimento Web. O modelo treinado é salvo em CASA.pkl e o script Python o carrega por meio do Joblib. As variáveis recebidas do Node.js são convertidas em números e posteriormente preparadas com NumPy antes de serem passadas ao modelo por meio de predict(). O Python então retorna as informações em formato JSON. O Node.js utiliza child_process e spawn() para executar o programa Python e recuperar seu resultado. O serviço filtra a saída do Python para identificar o JSON final e posteriormente utiliza JSON.parse() para converter a resposta em um objeto JavaScript. O Express então expõe uma API acessível pelo frontend. Finalmente, o MySQL permite gerenciar o armazenamento de dados por meio do banco de dados POWERBI_PREDICTION. O sistema completo forma uma cadeia tecnológica coerente: Dados → Node.js → spawn() → Python → CASA.pkl → NumPy → predict() → JSON → Express → Dashboard. Essa arquitetura demonstra como um modelo de Data Science pode ser integrado a uma aplicação Web moderna, separando claramente as responsabilidades entre Machine Learning, backend, API, banco de dados e interface do usuário.
