📊 Kantra ML Dashboard — Documentation technique

Cette documentation explique en détail le fonctionnement du fichier kantraSlice.js, du composant PredictionForm.jsx et de leur liaison avec le fichier kantra.css.

L'architecture utilise React, Redux Toolkit, Axios, Recharts, Power BI et un backend chargé de réaliser la prédiction Machine Learning.

1. Présentation générale du projet

Le composant PredictionForm.jsx constitue l'interface utilisateur du Dashboard Machine Learning consacré à Kantra.

Il permet à l'utilisateur de saisir deux valeurs, A et B, puis de lancer une prédiction.

La prédiction est envoyée au backend à travers Redux Toolkit et Axios. Une fois le résultat reçu, celui-ci est ajouté à un historique.

Le composant affiche ensuite les dernières valeurs saisies, la prédiction obtenue et un graphique représentant l'historique des prédictions.

Le Dashboard contient également un rapport Power BI intégré grâce à un élément iframe.

``` PredictionForm.jsx ↓ Utilisateur saisit A et B ↓ handlePredict() ↓ dispatch(fetchPrediction({ a, b })) ↓ kantraSlice.js ↓ Axios POST /kantra ↓ Backend ↓ Machine Learning ↓ Résultat ↓ Redux history ↓ PredictionForm.jsx ↓ KPI + graphique ↓ kantra.css ↓ Interface finale
```

3. Importations de kantraSlice.js

Le fichier kantraSlice.js commence par importer deux fonctions importantes de Redux Toolkit : createSlice et createAsyncThunk. 

import {
createSlice,
createAsyncThunk
```

} from "@reduxjs/toolkit";
```

createSlice permet de créer une partie du store Redux avec son état initial et ses reducers.

createAsyncThunk permet de gérer une opération asynchrone, ici la requête de prédiction vers le backend.

Le fichier importe également Axios : 

import axios from "axios";

Axios est utilisé pour effectuer la requête HTTP POST vers le backend.

4. Création de fetchPrediction

La fonction fetchPrediction est créée avec createAsyncThunk. 

export const fetchPrediction = createAsyncThunk(
"kantra/fetchPrediction",
async ({ a, b }, { rejectWithValue }) => {
    ...
}
```

);
```

Le premier argument : 

"kantra/fetchPrediction"

correspond à l'identifiant de l'action Redux.

La fonction asynchrone reçoit un objet contenant deux paramètres : a et b.

Ces deux valeurs correspondent aux entrées fournies par l'utilisateur.

5. Requête Axios vers le backend

À l'intérieur de fetchPrediction, Axios envoie une requête POST : 

const res = await axios.post(
"http://localhost:3000/kantra",
{ a, b }
```

);
```

L'URL utilisée est : 

http://localhost:3000/kantra

Le backend reçoit donc un objet contenant : 

{
a,
b
```

}
```

Le serveur peut ensuite utiliser ces deux valeurs pour effectuer la prédiction avec le modèle de Machine Learning.

6. Conservation des valeurs d'entrée

Après la réponse du backend, le code retourne : 

return {
...res.data,
a,
b
```

};
```

L'opérateur ... récupère les propriétés présentes dans res.data.

Le code ajoute également les valeurs originales a et b.

Cela permet de conserver dans Redux à la fois les valeurs d'entrée et la prédiction obtenue.

Exemple : 
{
a: 100,
b: 200,
prediction: 350.25
```

}
```

L'historique peut donc savoir quelles valeurs ont produit quelle prédiction.

7. Gestion des erreurs dans fetchPrediction

La requête Axios est placée dans un bloc try/catch. 

try {
...
```

} catch (err) {
return rejectWithValue(
err.response?.data || "Erreur serveur"
);
}
```

Si le backend retourne une erreur, le code récupère éventuellement err.response.data.

Si aucune réponse n'est disponible, le message "Erreur serveur" est utilisé.

rejectWithValue permet ensuite de transmettre cette erreur au reducer rejected.

  • loading : indique si une prédiction est actuellement en cours.
  • error : contient une éventuelle erreur.

10. Le reducer resetKantra

Le slice possède un reducer appelé resetKantra. 

reducers: {
resetKantra: (state) => {
    state.history = [];
},
```

},
```

Son rôle est de vider complètement l'historique des prédictions.

Lorsque cette action est appelée, le tableau history redevient vide.

11. fetchPrediction.pending

Lorsque l'utilisateur lance une prédiction, createAsyncThunk déclenche d'abord l'état pending. 

.addCase(fetchPrediction.pending, (state) => {
state.loading = true;
state.error = null;
```

})
```

loading passe à true.

L'erreur précédente est également supprimée grâce à : 

state.error = null;

12. fetchPrediction.fulfilled

Lorsque le backend retourne correctement une prédiction, Redux passe dans l'état fulfilled. 

.addCase(fetchPrediction.fulfilled, (state, action) => {
state.loading = false;

state.history.unshift({
    a: action.payload.a,
    b: action.payload.b,
    prediction: action.payload.prediction,
    time: new Date().toLocaleTimeString(),
});
```

})
```

Le chargement est arrêté : 

state.loading = false;

Ensuite, un nouvel objet est ajouté au début de history grâce à : 

state.history.unshift(...)

L'utilisation de unshift() permet donc de placer la nouvelle prédiction en première position.

13. Contenu de l'historique

Chaque élément de l'historique contient quatre informations : 

{
a: action.payload.a,
b: action.payload.b,
prediction: action.payload.prediction,
time: new Date().toLocaleTimeString()
```

}
```
Propriété Signification
a Première valeur d'entrée.
b Deuxième valeur d'entrée.
prediction Résultat produit par le modèle.
time Heure à laquelle la prédiction a été réalisée.

14. fetchPrediction.rejected

Si la requête échoue, Redux passe dans l'état rejected. 

.addCase(fetchPrediction.rejected, (state, action) => {
state.loading = false;
state.error = action.payload;
```

})
```

Le chargement est arrêté et l'erreur est enregistrée dans : 

state.error

Le composant React pourra ensuite récupérer cette erreur grâce à useSelector.

```

La première condition :

45. Relation entre Redux et CSS

Redux ne communique pas directement avec CSS.

Redux gère les données et les états. React récupère ces informations puis décide quels éléments doivent être affichés. Enfin, les classes CSS déterminent leur apparence.

``` Redux ↓ history / loading / error ↓ PredictionForm.jsx ↓ JSX + className ↓ kantra.css ↓ Interface visuelle
```

50. Résumé final à retenir

React construit l'interface → Redux Toolkit gère l'état → Axios communique avec le backend → le Machine Learning produit la prédiction → Redux stocke l'historique → Recharts visualise les résultats → Power BI affiche le rapport → CSS contrôle la présentation.

Le fichier kantraSlice.js est responsable de la logique Redux. Il définit l'action asynchrone fetchPrediction, communique avec le backend grâce à Axios et gère les états pending, fulfilled et rejected.

Le composant PredictionForm.jsx constitue l'interface utilisateur. Il permet de saisir A et B, d'envoyer une demande de prédiction, d'afficher le dernier résultat, de conserver l'historique dans Redux et de représenter les prédictions dans un graphique.

Le fichier kantra.css est responsable de l'apparence visuelle. La liaison avec React est réalisée grâce à : 

import "./kantra.css";

puis grâce aux différents className utilisés dans le JSX.

Ainsi, la logique métier, la gestion des données, l'affichage et la présentation visuelle sont séparés dans des fichiers et des technologies spécialisés.
