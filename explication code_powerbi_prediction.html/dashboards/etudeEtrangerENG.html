01

General System Overview

This system implements a Machine Learning prediction architecture designed for a Web application related to studying abroad. The objective is to allow an application developed with Node.js and Express to use a Machine Learning model trained in Python. The operation is divided into several parts in order to make the application organized, modular and easily scalable. The first part corresponds to the Machine Learning model saved in the file eduworld.pkl. This file contains an already trained model that can be loaded by Python in order to produce a prediction without having to retrain the model for every request. The second part corresponds to the Python script predict.py. This script acts as the prediction engine. It retrieves the values sent as arguments from Node.js, converts them into numbers using float(), checks that the number of variables exactly matches the number of features expected by the model, transforms the data into a NumPy array and then calls the predict() method of the loaded model. The result is then sent to the standard output using print(). Another part of the project also uses Pandas to build and manipulate tabular data. The DataFrame created with Pandas can be converted into JSON objects in order to make them easier to use by a Web application. The third part corresponds to the Node.js service etudeEtranger. This service uses the native child_process module, particularly the spawn() function, to launch the Python program from Node.js. The values are passed to the Python script as command-line arguments. Node.js then listens to stdout to retrieve the result from Python and to stderr to retrieve any possible errors. Finally, an Express route called /dashboard uses this service several times with different prediction modes. The results are grouped into an array and then returned to the frontend as a JSON object. The complete architecture therefore makes it possible to connect a Python Machine Learning model to a modern Web application and centralize multiple predictions in a dashboard.

02

Python Prediction Script

The predict.py file represents the core of the Machine Learning processing. Its role is to load the saved model, receive the data sent by Node.js, validate it, prepare the variables in numerical form and then execute the prediction. The script begins by importing the required libraries. The sys module provides access to the arguments sent to the Python program from Node.js. The os module is used to build reliable file paths independently of the directory from which the program is launched. The pickle library allows the previously saved Machine Learning model to be reloaded. Finally, numpy is used to build the numerical array that will be passed to the model. After the imports, the script automatically determines the directory in which it is located using os.path.abspath(__file__) and os.path.dirname(). The path to eduworld.pkl is then built using os.path.join(). The file is opened in binary mode using "rb" and the model is loaded with pickle.load(). The model is then available in memory and can be used to perform a prediction.

Importing the Libraries 

import sys

import os
import pickle
import numpy as np

sys is used to retrieve the arguments passed to the Python script. os is used to manage file paths. pickle is used to load the Machine Learning model saved in a PKL file. Finally, NumPy is used to transform the received data into a numerical structure compatible with the model.

Determining the Python Directory 

BASE_DIR = os.path.dirname(
os.path.abspath(__file__)
)

This instruction determines the absolute path of the directory containing the Python script. __file__ represents the file currently being executed. abspath() transforms its path into an absolute path and dirname() retrieves only the directory. This approach avoids depending on the current directory from which Node.js launches Python.

Model Location 

MODEL_PATH = os.path.join(
BASE_DIR,
"eduworld.pkl"
)

The complete path to the model is built by combining the script directory with the eduworld.pkl filename. The model can therefore be loaded even when the application is executed from another location.

Loading the Model 

with open(
MODEL_PATH,
"rb"
) as f:

model = pickle.load(f)

The PKL file is opened in binary read mode using "rb". The pickle.load() function reconstructs the Machine Learning object that was previously saved. The model then becomes available in the model variable. The advantage of this approach is that an already trained model can be directly reused instead of retraining it for every prediction.

03

Receiving and Validating Variables

Once the model has been loaded, the script must retrieve the variables required for the prediction. In this architecture, Node.js sends the values to Python directly through the command line. Python can retrieve these values using sys.argv. The sys.argv[1:] expression retrieves only the arguments sent after the script name. The map(float, ...) function converts each received value into a decimal number. The entire result is then converted into a list using list(). The try / except block protects this operation. If a value cannot be converted into a number, the program displays an error message and uses sys.exit() to stop its execution. After this initial validation, the program checks the number of received variables. The model.n_features_in_ property makes it possible to determine the number of features used by the model during training. The script therefore compares the number of received values with the number of expected features. This verification is important because a model trained with four variables cannot arbitrarily receive one or five variables. If the number does not match, the script returns an explicit error. This step therefore helps secure the transfer of data between the Web application and the Machine Learning model.

Retrieving Arguments 

values = list(
map(float, sys.argv[1:])
)

sys.argv contains the arguments passed to the Python program. The expression sys.argv[1:] ignores the first element, which generally corresponds to the script name, and retrieves the actual prediction values. Each value is converted into a float.

Input Error Handling 

try:

values = list(
    map(float, sys.argv[1:])
)

except:

print(
    "error: invalid input format"
)

sys.exit()

The try block attempts to convert the data. If a value is invalid, the except block is executed. The program then displays a message indicating that the input format is incorrect and stops the process. This validation prevents incompatible data from being sent to the model.

Expected Number of Features 

expected_features =
model.n_features_in_

This property automatically determines the number of variables expected by the model. The script therefore does not directly assume a fixed number of variables: it asks the model how many features were used during its training.

Feature Validation 

if len(values) != expected_features:

print(
    f"error: expected {expected_features} features, got {len(values)}"
)

sys.exit()

The program compares the number of received values with the expected number of variables. If the two numbers are different, an error is returned. This verification protects the model against an incorrect input structure.

Data Preparation and Prediction

After validating the number of variables, the script prepares the data for the Machine Learning model. The values are transformed into a NumPy array using np.array([values]). This step produces a structure compatible with Scikit-learn models. The created structure represents an observation containing several features. The model can then receive this observation using the predict() method. The instruction model.predict(X) uses the model previously loaded with Pickle and applies the parameters learned during its training. The result is generally returned as a NumPy array. The code therefore retrieves the first value using prediction[0]. The float() function then converts the result into a standard Python number so that it can be easily displayed and transmitted to Node.js. This part represents the essential step between the numerical data received by the application and the result calculated by the Machine Learning model.

Creating the NumPy Array 

X = np.array([
values
])

NumPy transforms the list of values into a numerical array. Using np.array([values]) represents an observation containing all of its features in a structure suitable for Scikit-learn models.

Calculating the Prediction 

prediction = model.predict(X)

The predict() method applies the Machine Learning model to the X data. The model uses the knowledge learned during training to calculate the predicted value.

Returning the Result 

print(
float(prediction[0])
)

The result returned by model.predict() is generally contained in an array. The [0] index retrieves the first prediction. The float() function converts this value into a standard Python number. Finally, print() writes the prediction to stdout. Node.js retrieves this value through the child process.

Python Flow: Arguments → Validation → NumPy → PKL Model → predict() → Result

Node.js Service and Communication with Python

The service file etudeEtranger.js allows Node.js to communicate with the Python program. This communication is performed using the native child_process module. Node.js has the ability to launch external programs, and spawn() is used here to create an independent Python process. The runPrediction(values) function returns a Promise because the execution of Python is asynchronous. The Python script path is built using path.join(). Then, spawn("python", ...) launches Python and passes it the file path together with the received values. The split(",") method transforms a string such as "10,20,30" into the array ["10", "20", "30"]. The ... operator then allows each value to be passed as a separate argument to the Python program. During execution, Node.js listens to stdout in order to retrieve the prediction returned by Python. It also listens to stderr to retrieve any possible error messages. When Python finishes, the close event is triggered. Node.js then checks the exit code. If the code is different from zero, the Promise is rejected. Otherwise, the result is cleaned using trim() and returned using resolve(). This function therefore acts as the technical bridge between the JavaScript application and the Python Machine Learning model.

Importing the Modules 

const {
spawn
} = require(
"child_process"
);

const path =
require("path");

child_process provides the spawn() function used to launch Python. path provides the functions required to build the script path.

Creating the Function 

function runPrediction(
values
) {

return new Promise(
    (resolve, reject) => {

        ...

    }
);

}

The function receives the values as a string and returns a Promise. resolve() is used when Python produces a successful response, while reject() is used in case of an error.

Python Script Path 

const pyFile =
path.join(
    __dirname,
    "../../python/predict.py"
);

This instruction builds the path to the Python file. __dirname represents the directory of the current JavaScript file and path.join() correctly combines the different parts of the path.

Launching Python 

const py = spawn(
"python",
[
    pyFile,
    ...values.split(",")
]
);

spawn() starts Python. The first argument specifies the program to execute and the second argument contains the list of parameters. The script path is passed first, followed by each value as an individual argument. For example, the string "10,20,30" becomes three Python arguments: 10, 20 and 30.

Retrieving stdout 

py.stdout.on(
"data",
(data) => {

    result +=
        data.toString();

}
);

Python uses print() to send the prediction to stdout. Node.js listens to this output and adds the received data to the result variable. Since stdout can be received in several chunks, the code uses += to reconstruct the complete result.

Retrieving Errors 

py.stderr.on(
"data",
(data) => {

    error +=
        data.toString();

}
);

Any Python error messages are retrieved through stderr. This allows the backend to determine the reason for a Python process failure.

Process Completion 

py.on(
"close",
(code) => {

    if (code !== 0)
        return reject(error);

    resolve(
        result.trim()
    );

}
);

When Python finishes its execution, the close event is triggered. The exit code indicates whether the program completed successfully. A code different from zero indicates an error. In this case, the Promise is rejected. Otherwise, the result is cleaned using trim() and returned using resolve().

Express Dashboard Route

The Express router represents the API layer that allows the frontend or dashboard to request multiple predictions. The file begins by importing Express and then creates a router using express.Router(). The etudeEtranger service is then imported so that the runPrediction() function can be called. The GET /dashboard route represents the main entry point. When a request reaches this route, the server defines a models array containing several modes: edufrance, edutest, linked and eduworld. Each mode contains a string of values that will be sent to the Python service. A for...of loop iterates through each element of the array. For each model, the server calls await runPrediction() to wait for the Python process to finish. The prediction returned as text is converted into a number using parseFloat(). An object containing the mode, values and prediction is then added to the results array. Once all predictions are complete, Express returns a JSON object containing the data property. The frontend can then retrieve all predictions in a single request and display them in a dashboard using cards, charts, indicators or tables.

Creating the Router 

const express =
require("express");

const router =
express.Router();

Express is imported and an independent router is created. This makes it possible to separate routes from the rest of the backend application.

Importing the Service 

const runPrediction =
require(
    "../service/etudeEtranger"
);

The router imports the function responsible for launching Python. The route can therefore trigger the Machine Learning model through this function.

This route uses the HTTP GET method. It is declared async because it must wait for several asynchronous operations related to the execution of Python.

JSON Response

Once all predictions are complete, Express returns the results in JSON format. The frontend can then directly use this structure to populate its dashboard.

The catch block captures errors encountered during execution. The server then returns HTTP status 500, indicating an internal server error, together with a message that can help diagnose the problem.

Complete System Architecture

The overall architecture is based on a clear separation between Machine Learning and the Web application. The process starts at the dashboard or frontend level. It requests the required information through an HTTP request to the Express API. The /dashboard route receives this request and prepares the list of different prediction modes. For each mode, Express calls the runPrediction() function from the Node.js service. This function uses child_process.spawn() to launch the Python script. The variables are passed to Python as command-line arguments. The Python script then loads eduworld.pkl using Pickle. The received variables are converted into numbers and the number of features is verified using model.n_features_in_. The validated data is transformed into a NumPy array and then sent to the model using model.predict(). Python then produces the result using print(). Node.js retrieves this value through stdout and returns it to the Express route. Express converts each prediction into a number and builds the final results array. A JSON response containing all predictions is finally sent to the frontend. The dashboard can then use this data to display different performance indicators, charts or statistics. This architecture therefore makes it possible to keep Python for the Data Science and Machine Learning layer while using Node.js and Express for the Web and API layer.

Each technology plays a specific role in the architecture. Python provides the environment used to execute the Machine Learning model. Pickle allows the model object to be saved and then reloaded from the eduworld.pkl file. NumPy is used to represent input variables as a numerical array compatible with the model. Concrete Example of the Process

To understand the complete process, imagine that the frontend calls the GET /dashboard route. Express receives the request and builds the list of the four modes: edufrance, edutest, linked and eduworld. The first element contains, for example, the values "1,2,3,4". Express then calls runPrediction("1,2,3,4"). The Node.js service separates the string using split(","), producing the values 1, 2, 3 and 4. Using spawn(), Node.js then launches predict.py and passes these four values as arguments. Python retrieves the values using sys.argv, converts them into numbers using float() and then checks that four features are expected by the model. The data is then transformed into a NumPy array. The eduworld.pkl model has already been loaded into memory and the predict() method calculates the prediction. Python displays this value using print(). Node.js retrieves the result from stdout, removes unnecessary spaces using trim() and returns the value to the Express route. Express then uses parseFloat() to convert the prediction into a number. The result is added to the results array. The same process is repeated for the other modes. At the end, Express returns a JSON object containing all predictions. The frontend can then use this information to display the results in its dashboard.
