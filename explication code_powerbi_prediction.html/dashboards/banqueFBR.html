1 — Visão geral do sistema Frontend

Nesta parte do projeto, desenvolvemos o Frontend da aplicação utilizando React e Redux Toolkit com o objetivo de gerenciar a visualização do dashboard bancário, comunicar com o Backend e recuperar automaticamente o resultado de uma previsão. O Frontend atua como uma interface entre o usuário e o sistema de processamento de dados. O usuário acessa uma página chamada Banque, que apresenta um dashboard do Power BI, bem como um resultado de previsão gerado pelo Backend. Para organizar corretamente a comunicação entre os diferentes componentes, utilizamos o Redux Toolkit. O Redux permite centralizar e gerenciar o estado da aplicação, enquanto createAsyncThunk é utilizado para gerenciar uma operação assíncrona, neste caso, o envio de uma requisição HTTP para o Backend. Para realizar essa comunicação HTTP, utilizamos o Axios. Quando o componente React é carregado, a função useEffect() aciona automaticamente a ação Redux createBanquePrediction, enviando os valores x1: 10 e x2: 2. O Redux envia então uma requisição POST para http://localhost:3000/banque. O Backend recebe esses dados, realiza o processamento ou a previsão e retorna uma resposta. Essa resposta é posteriormente armazenada no store do Redux por meio do estado predictionData. O componente React recupera então os dados utilizando useSelector() e atualiza automaticamente a interface. O sistema também gerencia três situações importantes: o carregamento por meio de loading, o sucesso por meio de fulfilled e o erro por meio de rejected. Quando a previsão está disponível, o componente exibe seu valor em um cartão de resultado e também cria um gráfico com Recharts para comparar os valores X1, X2 e a previsão. Ao mesmo tempo, um relatório do Power BI é integrado à página utilizando um elemento HTML iframe. Portanto, temos uma arquitetura Frontend na qual o React gerencia a interface do usuário, o Redux Toolkit gerencia o estado e as operações assíncronas, o Axios gerencia a comunicação com o Backend, o Power BI exibe o dashboard de apoio à tomada de decisões e o Recharts representa graficamente o resultado da previsão.

2 — Redux Toolkit e gerenciamento do estado

O primeiro arquivo corresponde ao Redux Slice dedicado à previsão bancária. O Redux Toolkit é utilizado para simplificar o gerenciamento global do estado da aplicação. A primeira linha import { createSlice, createAsyncThunk } from "@reduxjs/toolkit"; permite importar duas funcionalidades importantes. createSlice é utilizado para criar uma parte do store do Redux chamada aqui de banque, enquanto createAsyncThunk é utilizado para criar uma ação assíncrona destinada a se comunicar com o Backend. A linha import axios from "axios"; importa o Axios, uma biblioteca utilizada para realizar requisições HTTP. Em nossa aplicação, o Axios é utilizado para enviar os dados da previsão ao servidor. O princípio consiste, portanto, em separar a lógica de comunicação com o Backend da lógica de visualização do componente React. Isso torna a aplicação mais organizada e mais fácil de manter. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

3 — Função createAsyncThunk

A função createBanquePrediction é criada com createAsyncThunk. Sua função é realizar uma operação assíncrona que envia dados para o Backend. O primeiro argumento "banque/create" representa o nome da ação Redux. O segundo argumento é uma função assíncrona que recebe os dados no parâmetro data. A função utiliza então axios.post() para enviar uma requisição HTTP POST para http://localhost:3000/banque. A palavra data representa os dados enviados pelo componente React. Em nosso exemplo, esses dados são compostos por x1: 10 e x2: 2. Portanto, o servidor recebe esses dois valores e pode utilizá-los para realizar a previsão. A palavra-chave await permite aguardar a resposta do servidor antes de continuar a execução. Depois que a resposta é recebida, res.data é utilizado para recuperar apenas os dados retornados pelo Backend. A função então retorna esses dados por meio de return res.data. O Redux Toolkit encaminhará automaticamente essa resposta para o reducer correspondente ao estado fulfilled. Se ocorrer um erro durante a requisição do Axios, a instrução catch intercepta o erro. Utilizamos então rejectWithValue() para transmitir o erro ao reducer do Redux. A expressão err.response?.data permite recuperar a mensagem enviada pelo servidor quando existe uma resposta. O símbolo ?. corresponde ao encadeamento opcional e evita um erro caso response não exista. Se nenhuma informação de erro estiver disponível por parte do servidor, a mensagem "Erreur serveur" será utilizada. Essa função atua, portanto, como uma ponte entre o Frontend Redux e o Backend. 

export const createBanquePrediction = createAsyncThunk(
  "banque/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/banque",
        data
      );

      return res.data;

    } catch (err) {

      return rejectWithValue(
        err.response?.data || "Erreur serveur"
      );

    }
  }
);

4 — Criação do banqueSlice e estado inicial

Depois de criar a ação assíncrona, criamos o banqueSlice utilizando createSlice(). Esse Slice representa a parte do store do Redux dedicada à funcionalidade bancária. A propriedade name: "banque" fornece um nome para essa parte do estado. A propriedade initialState define o estado inicial dessa funcionalidade. Temos três informações principais. A primeira é predictionData: null, o que significa que ainda não existe nenhuma previsão disponível quando a aplicação é iniciada. A segunda é loading: false, que indica que nenhuma requisição está em andamento no momento inicial. A terceira é error: null, que indica que nenhum erro ocorreu até o momento. Essa organização permite que o componente React saiba exatamente em qual situação a requisição se encontra: espera, carregamento, sucesso ou erro. 

const banqueSlice = createSlice({
  name: "banque",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

5 — Gerenciamento do estado pending

Quando createBanquePrediction é executado e a requisição para o Backend começa, o Redux Toolkit ativa automaticamente o estado pending. O código .addCase(createBanquePrediction.pending, (state) => { ... }) define o que deve acontecer durante o carregamento. Então definimos state.loading = true. Dessa forma, o componente React pode saber que existe uma requisição em andamento e exibir a mensagem Loading prediction.... Também redefinimos state.error = null para remover um possível erro anterior. Esse gerenciamento permite ter uma interface dinâmica e informar ao usuário que o sistema está atualmente recuperando a previsão. 

.addCase(createBanquePrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

6 — Gerenciamento do estado fulfilled

Quando a requisição do Axios termina corretamente e o Backend retorna uma resposta válida, o Redux Toolkit ativa o estado fulfilled. O código .addCase(createBanquePrediction.fulfilled, (state, action) => { ... }) recupera então a resposta do servidor em action.payload. Definimos state.loading = false porque a requisição terminou. Em seguida, state.predictionData = action.payload armazena o resultado da previsão no store do Redux. Esses dados ficam então disponíveis para os componentes React que utilizam useSelector(). O processo é, portanto, muito importante: o Backend produz o resultado, o Redux o armazena em seu estado global e o React recupera automaticamente esse novo valor para atualizar a visualização. 

.addCase(createBanquePrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

7 — Gerenciamento do estado rejected

Se a requisição falhar, por exemplo, se o Backend estiver parado, se a URL estiver incorreta ou se o servidor retornar um erro, o Redux Toolkit ativa o estado rejected. O código .addCase(createBanquePrediction.rejected, (state, action) => { ... }) gerencia essa situação. Definimos state.loading = false porque a requisição terminou, mesmo que tenha falhado. Em seguida, state.error = action.payload recupera a mensagem de erro enviada por meio de rejectWithValue(). O componente React pode então ler esse estado e exibir uma mensagem de erro para o usuário. Essa organização evita que o usuário fique sem informação quando ocorre uma falha na comunicação com o servidor. 

.addCase(createBanquePrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

8 — Ciclo completo do Redux

O funcionamento completo do Redux Toolkit pode ser resumido da seguinte forma: o componente React executa dispatch(createBanquePrediction(...)). O Redux Toolkit inicia então a ação assíncrona. Assim que a requisição começa, o estado pending é ativado e loading passa para true. O Axios envia então os dados para o Backend. Se o Backend retornar corretamente a previsão, o estado fulfilled é ativado e o resultado é armazenado em predictionData. Se a requisição falhar, o estado rejected é ativado e o erro é armazenado em error. O React observa as alterações no store por meio de useSelector() e atualiza automaticamente a interface. Essa arquitetura permite, portanto, gerenciar corretamente as operações assíncronas sem colocar toda a lógica diretamente dentro do componente React.

Fluxo de dados:

React → dispatch() → Redux Toolkit → createAsyncThunk → Axios → Backend → Previsão → Redux Store → useSelector() → Interface React

9 — Componente React Banque

O segundo arquivo corresponde ao componente React chamado Banque. Sua função é construir a interface do usuário do dashboard bancário e recuperar os dados da previsão armazenados no Redux. A primeira linha import React, { useEffect } from "react"; importa o React, bem como o Hook useEffect. Em seguida, useDispatch e useSelector são importados de react-redux. useDispatch() permite que o componente envie uma ação Redux, enquanto useSelector() permite que ele leia informações do store do Redux. O arquivo CSS Banque.css também é importado para gerenciar os estilos da página. Por fim, vários componentes do Recharts são importados para construir o gráfico: BarChart, Bar, XAxis, YAxis, Tooltip, CartesianGrid, ResponsiveContainer e Legend. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { createBanquePrediction } from "../redux/banqueSlice";
import "./Banque.css";

10 — useDispatch

No componente Banque, utilizamos const dispatch = useDispatch(). O Hook useDispatch() fornece a função dispatch, que é utilizada para enviar ações para o Redux. Por meio dessa função, o componente React pode solicitar ao Redux que execute a previsão bancária. Sem dispatch, o componente não poderia ativar diretamente nossa ação createBanquePrediction. O papel de dispatch é, portanto, transmitir uma ação do componente React para o sistema Redux. 

const dispatch = useDispatch();

11 — useSelector e recuperação do estado Redux

O Hook useSelector() permite que o componente React recupere os dados armazenados no store do Redux. Em nosso código, recuperamos três informações. A primeira é predictionData, que contém o resultado retornado pelo Backend. A segunda é loading, que indica se a requisição está em andamento. A terceira é error, que pode conter uma mensagem de erro. A expressão state.banque?.predictionData significa que procuramos a propriedade predictionData dentro da parte banque do store. O símbolo ?. evita um erro caso o objeto banque não exista temporariamente. Graças ao useSelector(), quando o Redux modifica essas informações, o React detecta a alteração e atualiza automaticamente o componente. 

const predictionData = useSelector(
  (state) => state.banque?.predictionData
);

const loading = useSelector(
  (state) => state.banque?.loading
);

const error = useSelector(
  (state) => state.banque?.error
);

12 — useEffect e execução automática da previsão

O Hook useEffect() é utilizado para executar automaticamente uma operação quando o componente é carregado. Em nosso código, utilizamos dispatch(createBanquePrediction({ x1: 10, x2: 2 })). Isso significa que, quando a página Banque é exibida, o componente envia automaticamente uma ação Redux para solicitar uma previsão ao Backend. Os valores enviados são x1: 10 e x2: 2. O array de dependências contém dispatch. Nesse contexto, o efeito é executado quando o componente é montado. Essa abordagem permite executar automaticamente a previsão sem que o usuário precise clicar em um botão. O processo é então: exibição do componente, execução de useEffect(), chamada de dispatch(), execução de createBanquePrediction, requisição Axios ao Backend, recebimento da resposta e atualização do Redux. 

useEffect(() => {
  dispatch(
    createBanquePrediction({
      x1: 10,
      x2: 2,
    })
  );
}, [dispatch]);

13 — Preparação dos dados do gráfico

Depois de recuperar o resultado do Redux, o componente cria uma nova variável chamada chartData. Essa variável é destinada ao Recharts. A expressão condicional predictionData ? [...] : [] significa que, se existir uma previsão, criamos um array contendo os dados do gráfico. Caso contrário, criamos um array vazio. O objeto contém uma propriedade name com o valor "Banque", seguida pelos valores X1, X2 e Prediction. Para X1, utilizamos predictionData.x1 || 0. Isso significa que, se o valor X1 existir, ele será utilizado; caso contrário, será utilizado o valor 0. O mesmo princípio é aplicado ao X2 e à previsão. Essa etapa transforma os dados recebidos do Backend em uma estrutura que pode ser utilizada diretamente pelo gráfico do Recharts. 

const chartData = predictionData
  ? [
      {
        name: "Banque",
        X1: predictionData.x1 || 0,
        X2: predictionData.x2 || 0,
        Prediction:
          predictionData.prediction || 0,
      },
    ]
  : [];

14 — Integração do Dashboard do Power BI

O componente React também integra um relatório do Power BI utilizando um elemento HTML iframe. O objetivo é exibir diretamente em nossa aplicação Web um dashboard de apoio à tomada de decisões criado com Power BI. A classe powerbi-frame permite aplicar o estilo definido em Banque.css. A propriedade title="BANQUE" fornece um título ao elemento integrado. A propriedade src contém o endereço do relatório do Power BI publicado. A propriedade frameBorder="0" remove a borda do iframe e allowFullScreen permite a visualização em tela cheia. Essa integração permite, portanto, reunir duas dimensões do projeto na mesma página: por um lado, o dashboard de apoio à tomada de decisões do Power BI e, por outro, a previsão gerada dinamicamente pelo Backend e exibida pelo React. 

<div className="powerbi-container">

  <iframe
    className="powerbi-frame"
    title="BANQUE"
    src="https://app.powerbi.com/view?..."
    frameBorder="0"
    allowFullScreen
  />

</div>

15 — Exibição do estado de carregamento

O componente utiliza a variável loading do Redux para informar ao usuário quando uma previsão está em andamento. A condição {loading && (...)} significa que o parágrafo será exibido somente quando loading for true. A mensagem exibida é Loading prediction.... Isso corresponde ao estado pending definido no Redux Slice. Existe, portanto, uma relação direta entre o Backend, o Redux e a interface: quando a requisição começa, o Redux ativa loading e o React exibe a mensagem de carregamento. 

{loading && (
  <p className="loading">
    Loading prediction...
  </p>
)}

16 — Exibição de erros

O componente também considera a possibilidade de ocorrer um erro. A condição {error && (...)} significa que a mensagem de erro será exibida somente quando existir um erro no store do Redux. Esse erro pode vir do Axios, do Backend ou de um problema de comunicação com o servidor. O valor de error foi armazenado no Redux quando o estado rejected foi ativado. O React recupera então esse valor utilizando useSelector() e o exibe ao usuário em um parágrafo com a classe CSS error. 

{error && (
  <p className="error">
    {error}
  </p>
)}

17 — Estado de espera

O componente também considera uma situação em que nenhuma previsão está disponível e nenhuma requisição está atualmente em andamento. A condição !loading && !error && !predictionData verifica três elementos: o carregamento terminou, não existe nenhum erro e ainda não há dados de previsão disponíveis. Nessa situação, a aplicação exibe a mensagem Waiting for prediction result.... Isso permite gerenciar corretamente o estado inicial da página antes de receber o resultado da previsão. 

{!loading &&
  !error &&
  !predictionData && (
    <p className="waiting">
      ⏳ Waiting for prediction result...
    </p>
)}

18 — Exibição do resultado da previsão

Quando predictionData existe, o componente exibe um cartão contendo o resultado da previsão. A condição {predictionData && (...)} renderiza essa parte da interface somente quando os dados estão disponíveis. O título 📌 Result indica claramente ao usuário que se trata do resultado produzido pelo modelo. O valor exibido utiliza predictionData.prediction?.toFixed(2). A propriedade prediction corresponde ao resultado enviado pelo Backend. A função toFixed(2) exibe o número com dois dígitos após o ponto decimal. O símbolo ?. verifica se a propriedade existe antes de chamar o método. Esse cartão representa, portanto, a principal parte da exibição do resultado preditivo. 

{predictionData && (
  <div className="prediction-card">

    <h2 className="prediction-title">
      📌 Result
    </h2>

    <div className="prediction-value">
      {predictionData.prediction?.toFixed(2)}
    </div>

  </div>
)}

19 — Criação do gráfico com Recharts

Depois de exibir o valor numérico, o componente cria um gráfico utilizando a biblioteca Recharts. O objetivo é representar visualmente os valores X1, X2 e Prediction. O componente ResponsiveContainer permite que o gráfico se adapte automaticamente à largura disponível. A propriedade width="100%" indica que o gráfico utiliza toda a largura de seu contêiner e height={350} define uma altura de 350 pixels. O componente BarChart recebe os dados por meio de data={chartData}. O componente CartesianGrid exibe uma grade que facilita a leitura do gráfico. XAxis define o eixo horizontal e utiliza dataKey="name" para exibir o nome da categoria, neste caso Banque. YAxis representa o eixo vertical que contém os valores numéricos. Tooltip exibe informações quando o usuário posiciona o cursor sobre uma barra. Legend exibe a legenda das diferentes séries. Por fim, três componentes Bar representam respectivamente X1, X2 e Prediction. Cada barra utiliza uma chave de dados diferente por meio de dataKey. O gráfico proporciona, portanto, uma representação visual e comparativa dos dados utilizados para a previsão e do resultado obtido. 

<ResponsiveContainer
  width="100%"
  height={350}
>

  <BarChart data={chartData}>

    <CartesianGrid strokeDasharray="3 3" />

    <XAxis dataKey="name" />

    <YAxis />

    <Tooltip />

    <Legend />

    <Bar
      dataKey="X1"
      fill="#2196F3"
      name="X1"
    />

    <Bar
      dataKey="X2"
      fill="#FFC107"
      name="X2"
    />

    <Bar
      dataKey="Prediction"
      fill="#FF4D4D"
      name="Prediction"
    />

  </BarChart>

</ResponsiveContainer>

20 — Arquitetura completa do Frontend

Os dois arquivos do Redux e do React trabalham juntos seguindo uma arquitetura organizada. O componente Banque representa a parte visual. Quando é carregado, useEffect() chama dispatch() com a ação createBanquePrediction. Essa ação é definida em banqueSlice.js utilizando createAsyncThunk. O Redux Toolkit inicia então uma requisição Axios para o Backend com os valores X1 e X2. Durante essa comunicação, o Redux entra no estado pending e a variável loading passa a ser true. Quando o Backend retorna uma resposta correta, o Redux entra no estado fulfilled e coloca a resposta em predictionData. O componente React recupera esses dados utilizando useSelector(). O React detecta automaticamente a alteração do estado e atualiza a interface. O resultado é então exibido no cartão de previsão e os dados são preparados em chartData para construir o gráfico do Recharts. Se ocorrer um erro durante a comunicação, o Redux entra no estado rejected, armazena o erro em error e o React exibe a mensagem correspondente. Ao mesmo tempo, o iframe do Power BI exibe o dashboard de apoio à tomada de decisões. Temos, portanto, uma separação clara entre apresentação, gerenciamento do estado, comunicação com o servidor e visualização dos dados.

21 — Função do Redux e função do React

Nessa arquitetura, React e Redux possuem responsabilidades diferentes, mas complementares. O React é principalmente responsável pela interface do usuário: ele constrói a página, exibe o dashboard do Power BI, exibe o resultado da previsão e cria o gráfico. O Redux Toolkit é responsável pelo gerenciamento do estado e pela comunicação com o Backend. O Redux Slice contém as informações predictionData, loading e error. createAsyncThunk gerencia a operação assíncrona e o Axios se comunica com o servidor. O React utiliza então useSelector() para ler o estado do Redux e useDispatch() para enviar ações. Essa separação torna o código mais organizado porque a lógica de recuperação dos dados não fica completamente misturada com o código de visualização. O React se concentra principalmente em apresentar as informações, enquanto o Redux organiza seu fluxo e seu estado dentro da aplicação.

22 — Gerenciamento dos três estados da requisição

Um elemento importante dessa arquitetura é o gerenciamento dos três estados gerados automaticamente pelo createAsyncThunk. O primeiro estado é pending: corresponde ao momento em que a requisição está em andamento e permite exibir um indicador de carregamento. O segundo estado é fulfilled: corresponde a uma requisição bem-sucedida e permite armazenar a resposta em predictionData. O terceiro estado é rejected: corresponde a uma requisição que falhou e permite armazenar o problema em error. Graças a esses três estados, a interface React pode reagir automaticamente às mudanças na comunicação com o Backend. O usuário sabe, portanto, se o sistema está processando, se a previsão está disponível ou se ocorreu um erro.

pending → Requisição em andamento → loading = true

fulfilled → Requisição bem-sucedida → predictionData = result

rejected → Requisição com falha → error = message

23 — Conclusão

Para concluir, esses dois arquivos constituem uma parte essencial do Frontend de nossa aplicação de previsão bancária. O arquivo Redux utiliza o Redux Toolkit para centralizar o estado da funcionalidade bancária e gerenciar a comunicação assíncrona com o Backend por meio de createAsyncThunk e Axios. O estado inicial contém as informações necessárias para conhecer o resultado da previsão, o estado de carregamento e os possíveis erros. Os três estados pending, fulfilled e rejected permitem gerenciar automaticamente as diferentes etapas da requisição. O componente React Banque utiliza então useDispatch() para ativar a ação Redux e useSelector() para recuperar as informações do store. O Hook useEffect() permite executar automaticamente a previsão quando o componente é carregado. Depois que o resultado é recebido, o React exibe o valor da previsão em um cartão e utiliza o Recharts para criar uma representação gráfica comparando X1, X2 e a previsão. O componente também integra um dashboard do Power BI por meio de um iframe com o objetivo de reunir a análise de apoio à tomada de decisões e a análise preditiva na mesma interface. A arquitetura final baseia-se, portanto, na comunicação entre React, Redux Toolkit, Axios, Backend, modelo de previsão, Power BI e Recharts. Essa organização permite construir uma aplicação Frontend dinâmica e estruturada, capaz de apresentar ao usuário tanto dados de apoio à tomada de decisões quanto resultados preditivos.

24 — Explicação oral para a apresentação

Para apresentar esta parte diante de uma banca, podemos explicar que o Frontend da aplicação foi desenvolvido com React e que o Redux Toolkit é utilizado para gerenciar o estado e a comunicação com o Backend. No arquivo Redux, criei uma ação assíncrona com createAsyncThunk. Essa ação utiliza o Axios para enviar os valores X1 e X2 ao Backend por meio de uma requisição POST. O Redux Toolkit gerencia automaticamente três estados: pending quando a requisição está em andamento, fulfilled quando a resposta é recebida corretamente e rejected quando ocorre um erro. O resultado retornado pelo Backend é armazenado em predictionData. No componente React Banque, utilizo useDispatch para ativar a ação e useSelector para recuperar os dados do Redux. Com useEffect, a previsão é executada automaticamente quando a página é carregada. Quando a resposta chega, o React exibe o resultado em um cartão e utiliza o Recharts para representar graficamente X1, X2 e a previsão. Também integrei um dashboard do Power BI por meio de um iframe para exibir os resultados de apoio à tomada de decisões na mesma interface. O objetivo é, portanto, combinar Business Intelligence com Power BI e Machine Learning com previsão em uma única aplicação, utilizando Redux para organizar o fluxo de dados entre o Frontend e o Backend.
