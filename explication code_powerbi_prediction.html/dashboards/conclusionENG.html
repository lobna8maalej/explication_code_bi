This documentation explains in detail how the React application, React Router, Redux Toolkit, user registration and login, private route protection, and the Footer work.

It manages several important features:

  • navigation between the different pages;
  • user registration;
  • user login;
  • user management with Redux Toolkit;
  • storage of the authentication token;
  • Dashboard protection;
  • display of contact information;
  • presentation of information related to payment by bank transfer.

63. Introduction to PrivateRoute.jsx

PrivateRoute.jsx is used to protect part of the application.

Its purpose is to check whether the user has the necessary information to access a protected route.

64. Importing Navigate 

import {
    Navigate
} from "react-router-dom";

Navigate allows the user to be automatically redirected to another route.

65. Retrieving user 

const user =
    useSelector(
        (state) =>
            state.users.user
    );

This instruction retrieves the user stored in Redux.

66. Retrieving the token 

const token =
    useSelector(
        (state) =>
            state.users.token
    );

This instruction retrieves the authentication token from Redux.

67. Checking localStorage 

const storedUser =
    localStorage.getItem("user");

The component also checks whether a user is stored in the browser.

68. Protection Condition 

if (
    !user &&
    !token &&
    !storedUser
) {
    return (
        <Navigate
            to="/login"
            replace
        />
    );
}

This condition checks three elements:

  • the user stored in Redux;
  • the token stored in Redux;
  • the user saved in localStorage.

If these three elements are absent, the user is considered unauthenticated and is redirected to the Login page.

69. Redirecting to Login 

<Navigate
    to="/login"
    replace
/>

The unauthenticated user is redirected to: 

/login

The replace property replaces the current entry in the navigation history instead of adding a new one.

70. Access Authorization 

return children;

If the blocking condition is not satisfied, the component returns children.

This means that the user is authorized to access the protected content.

89. Security and Banking Information

The Footer can inform visitors that payment by bank transfer is available.

However, complete banking information should not be publicly exposed in the source code of a portfolio or in a LinkedIn post.

A better approach is to display general information: 

Payment by bank transfer

Banking information is available
upon request after project confirmation.

After reaching an agreement with the client, the bank details can be communicated directly through a private method.

92. Final Summary to Remember

App.jsx is the central point of navigation → BrowserRouter enables React Router → Routes contains the different routes → Home represents the home page → Login represents the login page → Register represents registration → DashboardPage represents the Dashboard → Redux Toolkit centralizes the global state → userSlice manages authentication → RegisterUser manages registration → LoginUser manages login → Axios communicates with the Node.js backend → the backend returns a JSON response → Redux receives the data in action.payload → user and token are stored in Redux → user and token are also saved in localStorage → PrivateRoute checks authentication information → an unauthenticated user is redirected to /login → an authorized user can access the Dashboard → Footer displays contact information → Footer can indicate that payment by bank transfer is available → complete banking details should preferably be provided to the client privately → the client can then make the bank transfer after the project has been validated.
