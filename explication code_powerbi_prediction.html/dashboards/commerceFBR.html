🛒 Gerenciamento de Dados de Comércio com Redux Toolkit e React

Documentação completa do funcionamento do módulo Commerce: Redux Toolkit, React, Axios, Recharts e Power BI.

47 — Gerenciamento de Dados de Comércio com Redux Toolkit e React

Nesta parte do projeto, foi desenvolvido um sistema completo para recuperação, gerenciamento, transformação, filtragem e exibição de dados comerciais utilizando React, Redux Toolkit, Axios e Recharts. O objetivo desta funcionalidade é recuperar os dados de comércio do backend, armazená-los no store do Redux, transformá-los para facilitar sua utilização na interface do usuário e, em seguida, permitir que o usuário filtre os dados de acordo com o comércio selecionado, por exemplo, Jumia ou MG. Os dados recuperados são então utilizados em um gráfico de barras por meio da biblioteca Recharts, mas também são exibidos como uma lista detalhada. Esta parte do frontend se comunica diretamente com o backend por meio de uma requisição HTTP GET para o endereço http://localhost:3000/commerce/train. O funcionamento geral é o seguinte: quando o componente React Commerce é carregado, o hook useEffect dispara a ação Redux fetchCommerce. Essa ação utiliza createAsyncThunk para realizar uma requisição Axios ao backend. O backend retorna os dados de comércio, o Redux recupera esses dados e os armazena no estado global. O componente React utiliza então useSelector para recuperar os dados do Redux. Uma lógica de transformação é aplicada usando o método map() para adicionar uma propriedade label a cada elemento. O componente também utiliza useState para gerenciar o comércio selecionado no filtro. Quando o usuário seleciona Jumia ou MG, o estado local filter é modificado e os dados são filtrados usando o método filter(). Os dados filtrados são então utilizados simultaneamente para construir o gráfico com BarChart e para exibir a lista detalhada. O projeto também possui uma integração com Power BI por meio de um elemento iframe, permitindo exibir diretamente o dashboard do Power BI na página React. Essa arquitetura separa claramente a recuperação e o gerenciamento dos dados, realizados pelo Redux, da apresentação e da interação com o usuário, realizadas pelo React.

48 — Importação do Redux Toolkit e Axios

O arquivo Redux começa importando duas funcionalidades importantes do Redux Toolkit: createSlice e createAsyncThunk. A função createSlice permite criar uma parte do store Redux dedicada ao comércio. Ela permite definir o nome do slice, seu estado inicial e a lógica de processamento associada às diferentes situações da ação assíncrona. A função createAsyncThunk é utilizada para criar uma ação Redux capaz de realizar uma operação assíncrona, neste caso uma requisição HTTP para o backend. Esse recurso é especialmente adequado quando uma aplicação React precisa recuperar dados de uma API. O código também importa Axios, que é utilizado como cliente HTTP para enviar uma requisição GET ao servidor Node.js/Express. O papel desta parte é, portanto, conectar o frontend React/Redux ao backend que fornece os dados comerciais. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

49 — Criação da Ação Assíncrona fetchCommerce

A principal ação do arquivo Redux é fetchCommerce. Essa ação é criada com createAsyncThunk. O primeiro argumento "commerce/fetchCommerce" corresponde ao tipo da ação Redux e permite identificar essa operação. O segundo argumento é uma função assíncrona que será executada quando a ação for disparada. Dentro dessa função, o Axios realiza uma requisição HTTP GET para a URL http://localhost:3000/commerce/train. Essa rota corresponde a uma rota do backend responsável por fornecer os dados de comércio. A palavra-chave await permite aguardar a resposta do servidor antes de continuar a execução. Depois que a resposta é recebida, ela é armazenada na variável response. O Axios coloca os dados retornados pelo servidor em response.data. Neste projeto, o backend retorna uma estrutura contendo uma propriedade data. Portanto, o código recupera exatamente response.data.data. Esse valor corresponde ao array de dados de comércio que será transmitido ao Redux. O return dessa função se torna então o payload da ação Redux quando a requisição é concluída com sucesso. 

export const fetchCommerce = createAsyncThunk(
    "commerce/fetchCommerce",
    async () => {
        const response = await axios.get(
            "http://localhost:3000/commerce/train"
        );

        return response.data.data;
    }
);

50 — Criação do Commerce Slice

O código cria então o slice Redux utilizando createSlice(). Essa função permite organizar toda a lógica Redux relacionada ao comércio em uma única estrutura. A propriedade name: "commerce" fornece o nome do slice e permite identificar essa parte do store global. O initialState define o estado inicial dos dados. A propriedade data é inicializada com um array vazio, pois nenhum dado foi recuperado do backend ainda. A propriedade loading é inicialmente definida como false, o que significa que nenhuma recuperação de dados está em andamento no momento. Esses valores serão posteriormente modificados automaticamente de acordo com o estado da ação fetchCommerce. 

const commerceSlice = createSlice({
    name: "commerce",

    initialState: {
        data: [],
        loading: false
    },

    extraReducers: (builder) => {
        // Gerenciamento dos estados assíncronos
    }
});

51 — Gerenciamento do Estado pending

O Redux Toolkit gera automaticamente vários estados para uma ação criada com createAsyncThunk. O primeiro estado é pending. Esse estado é executado quando a requisição começa. Quando o componente React dispara dispatch(fetchCommerce()), o Redux entra automaticamente no estado pending. O código então modifica state.loading e atribui a ele o valor true. Isso significa que a aplicação sabe que a recuperação dos dados está em andamento. O componente React pode utilizar essa informação para exibir uma mensagem como Carregando.... Essa lógica permite, portanto, informar ao usuário que os dados estão sendo carregados. 

.addCase(fetchCommerce.pending, (state) => {
    state.loading = true;
})

52 — Gerenciamento do Estado fulfilled e Transformação dos Dados

Quando a requisição Axios é concluída com sucesso, o Redux Toolkit dispara o estado fulfilled. Isso significa que a requisição foi realizada com sucesso e que os dados foram recebidos. A primeira operação consiste em definir state.loading novamente como false, pois o carregamento foi concluído. Em seguida, os dados recebidos são armazenados em state.data. Antes de armazená-los, porém, o código utiliza o método JavaScript map(). Esse método percorre cada elemento do array recebido em action.payload. Para cada elemento, o operador spread ...item preserva todas as propriedades existentes e, em seguida, uma nova propriedade chamada label é adicionada. Essa propriedade é construída a partir dos valores de commerce e web_scraper. Por exemplo, se o comércio for Jumia e o scraper for Python, o novo valor poderá ser Jumia - Python. Essa transformação permite preparar os dados diretamente no Redux para que o componente React tenha informações prontas para serem utilizadas. 

.addCase(fetchCommerce.fulfilled, (state, action) => {
    state.loading = false;

    state.data = action.payload.map((item) => ({
        ...item,
        label: `${item.commerce} - ${item.web_scraper}`
    }));
})

53 — Gerenciamento do Estado rejected

O terceiro estado é rejected. Ele é executado quando a requisição falha. Isso pode acontecer se o servidor backend não estiver disponível, se a URL estiver incorreta ou quando um erro de rede impedir o Axios de receber os dados. Nessa situação, o código define loading novamente como false para indicar que o carregamento foi concluído. Nesta versão do slice, nenhuma propriedade error é armazenada no estado. Portanto, o componente sabe que o carregamento terminou, mas não recupera aqui os detalhes precisos do erro. O objetivo é gerenciar corretamente o ciclo de vida da requisição: pending quando a recuperação começa, fulfilled quando os dados são recuperados com sucesso e rejected quando ocorre um erro. 

.addCase(fetchCommerce.rejected, (state) => {
    state.loading = false;
})

54 — Importação das Funcionalidades do React

O arquivo Commerce.jsx utiliza várias funcionalidades importantes do React e React Redux. useEffect permite disparar uma operação depois que o componente é renderizado, especialmente para iniciar a recuperação dos dados. useState permite gerenciar um estado local, utilizado aqui para memorizar o comércio selecionado no filtro. useDispatch permite enviar uma ação Redux a partir do React, enquanto useSelector permite recuperar os dados armazenados no store Redux. O componente também importa a ação fetchCommerce do arquivo commerceSlice. Por fim, o arquivo Commerce.css é importado para aplicar o estilo visual ao dashboard. 

import React, { useEffect, useState } from "react";

import {
    useDispatch,
    useSelector
} from "react-redux";

import { fetchCommerce } from "../redux/commerceSlice";

import "./Commerce.css";

55 — Utilização do useDispatch

O hook useDispatch() fornece a função dispatch. Essa função permite enviar uma ação para o store Redux. Neste projeto, ela é utilizada para disparar a ação fetchCommerce(). Quando essa ação é enviada, o Redux Toolkit executa o processo assíncrono definido no slice e inicia a requisição Axios para o backend. O componente React, portanto, não precisa realizar diretamente a requisição HTTP. Ele simplesmente solicita ao Redux que recupere os dados. 

const dispatch = useDispatch();

dispatch(fetchCommerce());

56 — Recuperação dos Dados com useSelector

O hook useSelector() permite que o componente React acesse o estado global do Redux. Aqui, o código recupera data e loading de state.commerce. A propriedade data contém os dados de comércio recuperados do backend e transformados no slice Redux. A propriedade loading indica se a recuperação dos dados está atualmente em andamento. Graças a essa arquitetura, o componente React não gerencia diretamente o Axios. Ele recupera as informações do store Redux, permitindo separar claramente a lógica de recuperação dos dados da lógica de exibição. 

const { data, loading } =
    useSelector((state) => state.commerce);

57 — Gerenciamento do Filtro com useState

O hook useState() é utilizado para criar um estado local chamado filter. Seu valor inicial é Jumia. Isso significa que, quando o componente é exibido pela primeira vez, os dados apresentados no gráfico e na lista correspondem ao comércio Jumia. A função setFilter() pode então modificar esse valor quando o usuário seleciona outro comércio. O estado local é, portanto, utilizado para gerenciar a interação do usuário com o filtro sem modificar os dados armazenados no Redux. 

const [filter, setFilter] = useState("Jumia");

58 — Recuperação Automática dos Dados com useEffect

O hook useEffect() permite executar uma operação depois que o componente é renderizado. Aqui, seu objetivo é disparar automaticamente a recuperação dos dados quando a página Commerce é carregada. A instrução dispatch(fetchCommerce()) envia a ação Redux. O Redux Toolkit então inicia o createAsyncThunk, que realiza a requisição Axios para o backend. A dependência [dispatch] indica que o efeito depende da função dispatch. O fluxo pode, portanto, ser resumido da seguinte forma: o componente React é carregado, useEffect é executado, dispatch dispara fetchCommerce, o Redux inicia o Axios, o Axios se comunica com o backend, o backend retorna os dados, o Redux armazena os dados e o React os recupera utilizando useSelector. 

useEffect(() => {
    dispatch(fetchCommerce());
}, [dispatch]);

59 — Filtragem dos Dados

Após recuperar os dados, o código cria uma nova variável chamada filteredData. O método JavaScript filter() permite selecionar apenas os elementos correspondentes ao comércio selecionado. A condição item.commerce === filter compara a propriedade commerce de cada elemento com o valor atual do estado filter. Se o valor do filtro for Jumia, somente os dados cujo comércio é Jumia são mantidos. Se o usuário selecionar MG, o estado filter passa a ser MG e somente os dados correspondentes a MG são mantidos. O resultado é armazenado em filteredData, que será utilizado tanto pelo gráfico quanto pela lista detalhada. 

const filteredData = data
    ? data.filter((item) => item.commerce === filter)
    : [];

60 — Integração do Dashboard Power BI

O componente React também integra um dashboard Power BI por meio de um elemento iframe. Essa técnica permite exibir diretamente um relatório Power BI publicado em uma página Web. O dashboard Power BI representa a parte de análise e tomada de decisão do projeto e permite apresentar os indicadores e visualizações criados no Power BI. Essa integração permite, portanto, reunir dois tipos de visualização na mesma página: o relatório Power BI e os gráficos dinâmicos gerados com React e Recharts. A propriedade allowFullScreen também permite autorizar a exibição do relatório em tela cheia quando esse recurso estiver disponível. 

<iframe
    className="commerce-iframe"
    title="PRIX"
    src="https://app.powerbi.com/view?r=..."  
    frameBorder="0"  
    allowFullScreen  
></iframe>

61 — Criação do Filtro Commerce

A lista suspensa permite que o usuário selecione o comércio que deseja analisar. A propriedade value={filter} vincula o valor do componente HTML select ao estado React filter. Quando o usuário altera a seleção, o evento onChange é disparado e setFilter(e.target.value) recupera o novo valor. As duas opções disponíveis são Jumia e MG. Assim que o estado filter é modificado, o React realiza automaticamente uma nova renderização do componente. A variável filteredData é então recalculada, permitindo que o gráfico e a lista exibam imediatamente os dados correspondentes ao novo comércio. 

<select  
    className="filter-select"  
    value={filter}  
    onChange={(e) => setFilter(e.target.value)}  
>  
    <option value="Jumia">Jumia</option>  
    <option value="MG">MG</option>  
</select>

62 — Exibição do Gráfico Commerce com Recharts

O gráfico é construído com a biblioteca Recharts. O componente ResponsiveContainer permite que o gráfico se adapte automaticamente à largura disponível. O componente BarChart recebe os dados filtrados por meio de data={filteredData}. O gráfico utiliza então CartesianGrid para exibir uma grade, XAxis para o eixo horizontal, YAxis para o eixo vertical e Tooltip para exibir os valores quando o usuário passa o mouse sobre as barras. Duas barras são então utilizadas: uma barra para target e outra para prix. O gráfico permite, portanto, comparar visualmente o valor-alvo e o preço correspondentes aos dados comerciais selecionados. 

<ResponsiveContainer width="100%" height={300}>  
  
    <BarChart data={filteredData}>  
  
        <CartesianGrid strokeDasharray="3 3" />  
  
        <XAxis dataKey="commerce" />  
  
        <YAxis />  
  
        <Tooltip />  
  
        <Bar dataKey="target" name="Target" />  
  
        <Bar dataKey="prix" name="Prix" />  
  
    </BarChart>  
  
</ResponsiveContainer>

63 — Exibição dos Detalhes

Depois do gráfico, o componente exibe os dados como uma lista detalhada. O método map() percorre cada elemento do array filteredData e gera um elemento HTML correspondente. A propriedade key={item.id} permite que o React identifique cada elemento de forma única. Para cada dado, a interface exibe o comércio, o valor Target e o preço. Essa lista complementa o gráfico fornecendo as mesmas informações em um formato textual mais preciso e mais diretamente legível pelo usuário. 

{filteredData.map((item) => (  
    <li key={item.id} className="list-item">  
        {item.commerce}  
        → Target: {item.target}  
        | Prix: {item.prix}  
    </li>  
))}

64 — Funcionamento Geral entre Redux e React

O funcionamento completo desta funcionalidade depende de uma comunicação organizada entre React, Redux Toolkit, Axios e o backend. Quando o usuário abre a página Commerce, o componente React é carregado. O hook useEffect então dispara dispatch(fetchCommerce()). O Redux Toolkit inicia a ação assíncrona criada com createAsyncThunk. O estado pending é disparado e a propriedade loading passa a ser true. O Axios então envia uma requisição GET para o backend. O servidor processa a solicitação e retorna os dados de comércio no formato JSON. Quando a resposta chega com sucesso, o Redux dispara o estado fulfilled. A propriedade loading volta a ser false e os dados são transformados utilizando map(). Os dados são então armazenados em state.data. O componente React recupera os novos dados utilizando useSelector. O estado local filter permite então selecionar Jumia ou MG. O método filter() cria filteredData, que é enviado ao gráfico Recharts e à lista detalhada. Essa arquitetura separa claramente as responsabilidades: o Redux gerencia os dados, enquanto o React gerencia a interface e a interação com o usuário.

65 — Conclusão

A funcionalidade Commerce representa uma cadeia completa de processamento frontend que conecta o backend, Redux Toolkit, React, Recharts e Power BI. Os dados são recuperados automaticamente utilizando createAsyncThunk e Axios, depois armazenados no Redux para que estejam disponíveis no componente React. O gerenciamento dos estados pending, fulfilled e rejected permite gerenciar o ciclo de vida da requisição. Os dados recebidos são transformados utilizando map(), principalmente para adicionar a propriedade label. O React recupera então esses dados utilizando useSelector e utiliza useState para gerenciar o filtro entre Jumia e MG. O método filter() seleciona os dados correspondentes, e o Recharts os transforma em um gráfico para comparar target e prix. As informações também são apresentadas em uma lista detalhada. Ao mesmo tempo, o Power BI é integrado por meio de um iframe para exibir o dashboard de tomada de decisão. Essa arquitetura demonstra, portanto, o uso complementar de várias tecnologias modernas: React para a interface, Redux Toolkit para o gerenciamento de estado, Axios para a comunicação com o backend, Recharts para a visualização e Power BI para a análise de tomada de decisão. O resultado é um dashboard Commerce dinâmico capaz de recuperar, transformar, filtrar e visualizar automaticamente os dados provenientes do backend.
