🛒 Gestión de datos de Comercio con Redux Toolkit y React

Documentación completa del módulo de Comercio: Redux Toolkit, React, Axios, Recharts y Power BI.

47 — Gestión de datos de Comercio con Redux Toolkit y React

En esta parte del proyecto, se ha desarrollado un sistema completo para recuperar, gestionar, transformar, filtrar y mostrar datos comerciales utilizando React, Redux Toolkit, Axios y Recharts. El objetivo de esta funcionalidad es recuperar los datos del comercio desde el backend, almacenarlos en el store de Redux, transformarlos para facilitar su utilización en la interfaz de usuario y, posteriormente, permitir al usuario filtrar los datos según el comercio seleccionado, por ejemplo Jumia o MG. Los datos recuperados se utilizan posteriormente en un gráfico de barras mediante la biblioteca Recharts, pero también se muestran en forma de lista detallada. Esta parte del frontend se comunica directamente con el backend mediante una solicitud HTTP GET a la dirección http://localhost:3000/commerce/train. El funcionamiento general es el siguiente: cuando se carga el componente React Commerce, el hook useEffect activa la acción Redux fetchCommerce. Esta acción utiliza createAsyncThunk para realizar una solicitud Axios al backend. El backend devuelve los datos comerciales, Redux recupera estos datos y los almacena en el estado global. El componente React utiliza posteriormente useSelector para recuperar los datos desde Redux. Se aplica una lógica de transformación mediante el método map() para añadir una propiedad label a cada elemento. El componente también utiliza useState para gestionar el comercio seleccionado en el filtro. Cuando el usuario selecciona Jumia o MG, el estado local filter se modifica y los datos se filtran mediante el método filter(). Los datos filtrados se utilizan simultáneamente para construir el gráfico con BarChart y para mostrar la lista detallada. El proyecto también incluye una integración de Power BI mediante un elemento iframe, lo que permite mostrar directamente el dashboard de Power BI en la página React. Por lo tanto, esta arquitectura separa claramente la recuperación y gestión de los datos, realizadas con Redux, de su presentación y de la interacción con el usuario, realizadas con React.

48 — Importación de Redux Toolkit y Axios

El archivo Redux comienza importando dos funcionalidades importantes de Redux Toolkit: createSlice y createAsyncThunk. La función createSlice permite crear una parte del store Redux dedicada al comercio. Permite definir el nombre del slice, su estado inicial y la lógica de procesamiento asociada a las diferentes situaciones de la acción asíncrona. La función createAsyncThunk se utiliza para crear una acción Redux capaz de realizar una operación asíncrona, en este caso una solicitud HTTP al backend. Esta funcionalidad es especialmente adecuada cuando una aplicación React necesita recuperar datos desde una API. El código también importa Axios, que se utiliza como cliente HTTP para enviar una solicitud GET al servidor Node.js/Express. Por lo tanto, el objetivo de esta parte es conectar el frontend React/Redux con el backend que proporciona los datos comerciales. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

49 — Creación de la acción asíncrona fetchCommerce

La acción principal del archivo Redux es fetchCommerce. Esta acción se crea con createAsyncThunk. El primer argumento "commerce/fetchCommerce" corresponde al tipo de acción Redux y permite identificar esta operación. El segundo argumento es una función asíncrona que se ejecutará cuando se active la acción. Dentro de esta función, Axios realiza una solicitud HTTP GET a la URL http://localhost:3000/commerce/train. Esta ruta corresponde a una ruta del backend encargada de proporcionar los datos comerciales. La palabra clave await permite esperar la respuesta del servidor antes de continuar con la ejecución. Una vez recibida la respuesta, se almacena en la variable response. Axios coloca los datos devueltos por el servidor en response.data. En este proyecto, el backend devuelve una estructura que contiene una propiedad data. Por lo tanto, el código recupera exactamente response.data.data. Este valor corresponde al array de datos comerciales que será transmitido a Redux. El return de esta función se convierte posteriormente en el payload de la acción Redux cuando la solicitud termina correctamente. 

export const fetchCommerce = createAsyncThunk(
    "commerce/fetchCommerce",
    async () => {
        const response = await axios.get(
            "http://localhost:3000/commerce/train"
        );

        return response.data.data;
    }
);

50 — Creación del Commerce Slice

A continuación, el código crea el slice de Redux utilizando createSlice(). Esta función permite organizar toda la lógica Redux relacionada con el comercio dentro de una única estructura. La propiedad name: "commerce" proporciona el nombre del slice y permite identificar esta parte del store global. initialState define el estado inicial de los datos. La propiedad data se inicializa con un array vacío porque todavía no se han recuperado datos desde el backend. La propiedad loading se establece inicialmente en false, lo que significa que actualmente no se está realizando ninguna recuperación de datos. Estos valores serán modificados automáticamente según el estado de la acción fetchCommerce. 

const commerceSlice = createSlice({
    name: "commerce",

    initialState: {
        data: [],
        loading: false
    },

    extraReducers: (builder) => {
        // Gestion des états asynchrones
    }
});

51 — Gestión del estado pending

Redux Toolkit genera automáticamente varios estados para una acción creada con createAsyncThunk. El primero es pending. Este estado se ejecuta cuando comienza la solicitud. Cuando el componente React activa dispatch(fetchCommerce()), Redux entra automáticamente en el estado pending. El código modifica entonces state.loading y le asigna el valor true. Esto significa que la aplicación sabe que la recuperación de los datos está actualmente en curso. El componente React puede utilizar esta información para mostrar un mensaje como Loading.... Esta lógica permite informar al usuario de que los datos se están cargando. 

.addCase(fetchCommerce.pending, (state) => {
    state.loading = true;
})

52 — Gestión del estado fulfilled y transformación de los datos

Cuando la solicitud Axios termina correctamente, Redux Toolkit activa el estado fulfilled. Esto significa que la solicitud se realizó correctamente y que los datos han sido recibidos. La primera operación consiste en volver a establecer state.loading en false, porque la carga ha terminado. A continuación, los datos recibidos se almacenan en state.data. Sin embargo, antes de almacenarlos, el código utiliza el método JavaScript map(). Este método recorre cada elemento del array recibido en action.payload. Para cada elemento, el operador spread ...item conserva todas las propiedades existentes y, posteriormente, se añade una nueva propiedad llamada label. Esta propiedad se construye a partir de los valores de commerce y web_scraper. Por ejemplo, si el comercio es Jumia y el scraper es Python, el nuevo valor puede ser Jumia - Python. Esta transformación permite preparar los datos directamente en Redux para que el componente React disponga de información lista para utilizar. 

.addCase(fetchCommerce.fulfilled, (state, action) => {
    state.loading = false;

    state.data = action.payload.map((item) => ({
        ...item,
        label: `${item.commerce} - ${item.web_scraper}`
    }));
})

53 — Gestión del estado rejected

El tercer estado es rejected. Se ejecuta cuando la solicitud falla. Esto puede ocurrir si el servidor backend no está disponible, si la URL es incorrecta o cuando un error de red impide que Axios reciba los datos. En esta situación, el código vuelve a establecer loading en false para indicar que la carga ha terminado. En esta versión del slice, no se almacena ninguna propiedad error en el estado. Por lo tanto, el componente sabe que la carga ha terminado, pero aquí no recupera los detalles precisos del error. El objetivo es gestionar correctamente el ciclo de vida de la solicitud: pending cuando comienza la recuperación, fulfilled cuando los datos se recuperan correctamente y rejected cuando se produce un error. 

.addCase(fetchCommerce.rejected, (state) => {
    state.loading = false;
})

54 — Importación de las funcionalidades de React

El archivo Commerce.jsx utiliza varias funcionalidades importantes de React y React Redux. useEffect permite ejecutar una operación después de que el componente se haya renderizado, especialmente para iniciar la recuperación de datos. useState permite gestionar un estado local, utilizado aquí para recordar el comercio seleccionado en el filtro. useDispatch permite enviar una acción Redux desde React, mientras que useSelector permite recuperar los datos almacenados en el store Redux. El componente también importa la acción fetchCommerce del archivo commerceSlice. Finalmente, el archivo Commerce.css se importa para aplicar el estilo gráfico al dashboard. 

import React, { useEffect, useState } from "react";

import {
    useDispatch,
    useSelector
} from "react-redux";

import { fetchCommerce } from "../redux/commerceSlice";

import "./Commerce.css";

55 — Uso de useDispatch

El hook useDispatch() proporciona la función dispatch. Esta función permite enviar una acción al store Redux. En este proyecto, se utiliza para activar la acción fetchCommerce(). Cuando esta acción se envía, Redux Toolkit ejecuta el proceso asíncrono definido en el slice e inicia la solicitud Axios al backend. Por lo tanto, el componente React no necesita realizar directamente la solicitud HTTP. Simplemente solicita a Redux que recupere los datos. 

const dispatch = useDispatch();

dispatch(fetchCommerce());

56 — Recuperación de datos con useSelector

El hook useSelector() permite al componente React acceder al estado global de Redux. Aquí, el código recupera data y loading desde state.commerce. La propiedad data contiene los datos comerciales recuperados desde el backend y transformados en el slice Redux. La propiedad loading indica si la recuperación de datos está actualmente en curso. Gracias a esta arquitectura, el componente React no gestiona directamente Axios. Recupera la información desde el store Redux, lo que permite separar claramente la lógica de recuperación de datos de la lógica de visualización. 

const { data, loading } =
    useSelector((state) => state.commerce);

57 — Gestión del filtro con useState

El hook useState() se utiliza para crear un estado local llamado filter. Su valor inicial es Jumia. Esto significa que cuando el componente se muestra por primera vez, los datos presentados en el gráfico y en la lista corresponden al comercio Jumia. La función setFilter() permite posteriormente modificar este valor cuando el usuario selecciona otro comercio. Por lo tanto, el estado local se utiliza para gestionar la interacción del usuario con el filtro sin modificar los datos almacenados en Redux. 

const [filter, setFilter] = useState("Jumia");

58 — Recuperación automática de datos con useEffect

El hook useEffect() permite ejecutar una operación después de que el componente se haya renderizado. Aquí, su objetivo es activar automáticamente la recuperación de datos cuando se carga la página Commerce. La instrucción dispatch(fetchCommerce()) envía la acción Redux. Redux Toolkit inicia entonces el createAsyncThunk, que realiza la solicitud Axios al backend. La dependencia [dispatch] indica que el efecto depende de la función dispatch. El flujo puede resumirse de la siguiente manera: el componente React se carga, useEffect se ejecuta, dispatch activa fetchCommerce, Redux inicia Axios, Axios se comunica con el backend, el backend devuelve los datos, Redux almacena los datos y React los recupera mediante useSelector. 

useEffect(() => {
    dispatch(fetchCommerce());
}, [dispatch]);

59 — Filtrado de los datos

Después de recuperar los datos, el código crea una nueva variable llamada filteredData. El método JavaScript filter() permite seleccionar únicamente los elementos correspondientes al comercio seleccionado. La condición item.commerce === filter compara la propiedad commerce de cada elemento con el valor actual del estado filter. Si el valor del filtro es Jumia, solo se conservan los datos cuyo comercio es Jumia. Si el usuario selecciona MG, el estado filter pasa a ser MG y solo se conservan los datos correspondientes a MG. El resultado se almacena en filteredData, que posteriormente será utilizado tanto por el gráfico como por la lista detallada. 

const filteredData = data
    ? data.filter((item) => item.commerce === filter)
    : [];

60 — Integración del Dashboard de Power BI

El componente React también integra un dashboard de Power BI mediante un elemento iframe. Esta técnica permite mostrar directamente un informe de Power BI publicado en una página web. El dashboard de Power BI representa la parte de análisis para la toma de decisiones del proyecto y permite presentar los indicadores y las visualizaciones creadas en Power BI. Esta integración permite reunir en una misma página dos tipos de visualización: el informe de Power BI y los gráficos dinámicos generados con React y Recharts. La propiedad allowFullScreen también permite autorizar la visualización del informe en pantalla completa cuando esta funcionalidad está disponible. 

<iframe
    className="commerce-iframe"
    title="PRIX"
    src="https://app.powerbi.com/view?r=..."  
    frameBorder="0"  
    allowFullScreen  
></iframe>

61 — Creación del filtro de Comercio

La lista desplegable permite al usuario seleccionar el comercio que desea analizar. La propiedad value={filter} vincula el valor del componente HTML select con el estado React filter. Cuando el usuario modifica la selección, se activa el evento onChange y setFilter(e.target.value) recupera el nuevo valor. Las dos opciones disponibles son Jumia y MG. En cuanto se modifica el estado filter, React realiza automáticamente un nuevo renderizado del componente. La variable filteredData se recalcula entonces, lo que permite que el gráfico y la lista muestren inmediatamente los datos correspondientes al nuevo comercio. 

<select  
    className="filter-select"  
    value={filter}  
    onChange={(e) => setFilter(e.target.value)}  
>  
    <option value="Jumia">Jumia</option>  
    <option value="MG">MG</option>  
</select>

62 — Visualización del gráfico de Comercio con Recharts

El gráfico se construye con la biblioteca Recharts. El componente ResponsiveContainer permite que el gráfico se adapte automáticamente al ancho disponible. El componente BarChart recibe los datos filtrados mediante data={filteredData}. A continuación, el gráfico utiliza CartesianGrid para mostrar una cuadrícula, XAxis para el eje horizontal, YAxis para el eje vertical y Tooltip para mostrar los valores cuando el usuario mueve el ratón sobre las barras. Se utilizan dos barras: una barra para target y otra para prix. Por lo tanto, el gráfico permite comparar visualmente el valor objetivo y el precio correspondientes a los datos comerciales seleccionados. 

<ResponsiveContainer width="100%" height={300}>  
  
    <BarChart data={filteredData}>  
  
        <CartesianGrid strokeDasharray="3 3" />  
  
        <XAxis dataKey="commerce" />  
  
        <YAxis />  
  
        <Tooltip />  
  
        <Bar dataKey="target" name="Target" />  
  
        <Bar dataKey="prix" name="Prix" />  
  
    </BarChart>  
  
</ResponsiveContainer>

63 — Visualización de los detalles

Después del gráfico, el componente muestra los datos en forma de lista detallada. El método map() recorre cada elemento del array filteredData y genera un elemento HTML correspondiente. La propiedad key={item.id} permite a React identificar cada elemento de forma única. Para cada dato, la interfaz muestra el comercio, el valor Target y el precio. Esta lista complementa el gráfico proporcionando la misma información en una forma textual más precisa y más directamente legible para el usuario. 

{filteredData.map((item) => (  
    <li key={item.id} className="list-item">  
        {item.commerce}  
        → Target: {item.target}  
        | Prix: {item.prix}  
    </li>  
))}

64 — Funcionamiento general entre Redux y React

El funcionamiento completo de esta funcionalidad se basa en una comunicación organizada entre React, Redux Toolkit, Axios y el backend. Cuando el usuario abre la página Commerce, se carga el componente React. El hook useEffect activa entonces dispatch(fetchCommerce()). Redux Toolkit inicia la acción asíncrona creada con createAsyncThunk. Se activa el estado pending y la propiedad loading pasa a ser true. Axios envía posteriormente una solicitud GET al backend. El servidor procesa la solicitud y devuelve los datos comerciales en formato JSON. Cuando la respuesta llega correctamente, Redux activa el estado fulfilled. La propiedad loading vuelve a ser false y los datos se transforman mediante map(). A continuación, los datos se almacenan en state.data. El componente React recupera los nuevos datos mediante useSelector. El estado local filter permite posteriormente seleccionar Jumia o MG. El método filter() crea filteredData, que se transmite al gráfico de Recharts y a la lista de detalles. Por lo tanto, esta arquitectura separa claramente las responsabilidades: Redux gestiona los datos, mientras que React gestiona la interfaz y la interacción con el usuario.

65 — Conclusión

La funcionalidad Commerce constituye una cadena completa de procesamiento frontend que conecta el backend, Redux Toolkit, React, Recharts y Power BI. Los datos se recuperan automáticamente mediante createAsyncThunk y Axios, y posteriormente se almacenan en Redux para que estén disponibles en el componente React. La gestión de los estados pending, fulfilled y rejected permite gestionar el ciclo de vida de la solicitud. Los datos recibidos se transforman mediante map(), especialmente para añadir la propiedad label. React recupera posteriormente estos datos mediante useSelector y utiliza useState para gestionar el filtro entre Jumia y MG. El método filter() selecciona los datos correspondientes, y Recharts los transforma posteriormente en un gráfico para comparar target y prix. La información también se presenta en forma de lista detallada. Al mismo tiempo, Power BI se integra mediante un iframe para mostrar el dashboard de análisis para la toma de decisiones. Por lo tanto, esta arquitectura demuestra el uso complementario de varias tecnologías modernas: React para la interfaz, Redux Toolkit para la gestión del estado, Axios para la comunicación con el backend, Recharts para la visualización y Power BI para el análisis de toma de decisiones. El resultado es un dashboard Commerce dinámico capaz de recuperar, transformar, filtrar y visualizar automáticamente los datos procedentes del backend.
