01

Présentation générale du système

Le système de prédiction INFO constitue une architecture Web permettant d'intégrer plusieurs modèles de Machine Learning développés en Python dans une application Node.js et Express. L'objectif principal de cette architecture est de recevoir un ensemble de valeurs numériques depuis l'application Web, de transmettre ces données à Python, puis d'utiliser trois modèles Machine Learning différents afin de produire simultanément trois prédictions correspondant aux modèles INFO2, INFO3 et GoMyCode. Les modèles sont préalablement entraînés puis sauvegardés dans des fichiers .pkl. Le fichier INFO2.pkl correspond au premier modèle, INFO3.pkl au deuxième modèle et gomycode.pkl au troisième modèle. Le script Python info.py constitue le moteur de prédiction. Il commence par rechercher les fichiers des modèles dans le même répertoire que le script grâce à os.path, puis il charge chaque modèle avec la bibliothèque Python pickle. Après le chargement, le script récupère les données transmises par Node.js à travers sys.argv. Ces données sont envoyées sous la forme d'une chaîne JSON. Python utilise ensuite json.loads() pour convertir cette chaîne en structure Python, puis NumPy transforme les valeurs en tableau numérique à deux dimensions. Cette étape est importante car les modèles Scikit-learn attendent généralement une matrice contenant les observations et les caractéristiques. Le programme vérifie également que les données ne contiennent pas de valeurs NaN, afin d'éviter une erreur pendant la prédiction. Les trois modèles sont ensuite utilisés avec la méthode predict(). Le résultat de chaque modèle est converti en nombre flottant puis regroupé dans un objet JSON contenant info2_pred, info3_pred et gomycode_pred. Le résultat JSON est envoyé vers Node.js grâce à stdout. Du côté JavaScript, le fichier infoService.js utilise le module child_process et sa fonction spawn() afin de lancer le script Python. Les valeurs reçues depuis le frontend sont converties en JSON avec JSON.stringify() puis transmises au programme Python comme argument. Node.js récupère ensuite la sortie standard Python dans la variable output. Cette sortie est analysée avec JSON.parse() afin de reconstruire l'objet JavaScript contenant les trois prédictions. Le fichier infoRoute.js expose ensuite une route HTTP POST /predict. Cette route récupère la propriété values du corps de la requête, vérifie qu'il s'agit bien d'un tableau puis appelle runInfoPrediction(). Le résultat est finalement retourné au frontend dans une réponse JSON contenant une propriété success et une propriété data. Enfin, le fichier principal du serveur initialise Express, active CORS, active le traitement JSON avec express.json(), enregistre le routeur avec le préfixe /info et démarre le serveur sur le port 3000. L'architecture complète permet donc au frontend d'envoyer des données à Node.js, à Node.js de communiquer avec Python, à Python d'exécuter plusieurs modèles Machine Learning et de retourner les résultats sous forme JSON au dashboard.

Service Node.js et communication avec Python

Le fichier infoService.js constitue l'intermédiaire entre l'application Node.js et le script Python. Son rôle est de recevoir les valeurs provenant de la route Express, de lancer le programme Python et de récupérer les résultats de prédiction. Le module child_process fournit la fonction spawn(), qui permet à Node.js de créer un processus externe. Le module path permet de construire le chemin vers info.py. La fonction runInfoPrediction(values) retourne une Promise, ce qui permet à la route Express d'utiliser await et de patienter jusqu'à la fin de l'exécution Python. Les valeurs reçues sont converties en chaîne JSON avec JSON.stringify(values). Cette étape permet de transmettre un tableau JavaScript complet à Python sous la forme d'un seul argument. La fonction spawn() lance ensuite Python avec le chemin du script et la chaîne JSON. Node.js écoute stdout afin de récupérer la réponse générée par Python. Les données reçues sont progressivement ajoutées à la variable output. En parallèle, stderr récupère les éventuels messages d'erreur ou informations de debug. Lorsque le processus Python se termine, l'événement close fournit le code de sortie. Si ce code est différent de zéro, le service considère que Python a rencontré une erreur et rejette la Promise. Si l'exécution est réussie, Node.js utilise JSON.parse(output) afin de transformer le résultat JSON Python en objet JavaScript. L'objet obtenu est alors transmis à la route Express avec resolve(result).

Architecture complète

L'architecture complète du système fonctionne selon une chaîne de communication clairement séparée. Tout commence avec le frontend ou le dashboard qui prépare les variables nécessaires et les envoie à l'API Express avec une requête HTTP POST. Express reçoit cette requête sur /info/predict et récupère le tableau values depuis req.body. Après validation, Express appelle le service runInfoPrediction(). Le service Node.js transforme les valeurs en JSON grâce à JSON.stringify() puis utilise spawn() pour lancer le programme info.py. Python reçoit alors les valeurs grâce à sys.argv. Le script vérifie la présence des données, les convertit depuis JSON avec json.loads() et construit une matrice NumPy à deux dimensions. Les trois modèles INFO2.pkl, INFO3.pkl et gomycode.pkl sont chargés au démarrage du script avec pickle.load(). Chaque modèle reçoit ensuite la même matrice d'entrée et utilise predict() pour calculer sa propre prédiction. Les trois résultats sont regroupés dans un objet JSON. Python écrit ce résultat dans stdout. Node.js récupère cette sortie, utilise JSON.parse() pour convertir le JSON en objet JavaScript puis retourne cet objet au routeur Express. Express construit enfin la réponse HTTP contenant success: true et data. Le frontend peut alors exploiter les trois prédictions pour les afficher dans son interface. Cette architecture présente l'avantage de séparer clairement les responsabilités : le frontend assure la présentation, Express gère l'API, Node.js orchestre la communication, Python exécute le Machine Learning, NumPy prépare les données et les fichiers PKL contiennent les modèles entraînés.

Conclusion

Le système INFO représente une intégration complète entre Machine Learning et développement Web. Trois modèles entraînés sont sauvegardés dans des fichiers INFO2.pkl, INFO3.pkl et gomycode.pkl.
