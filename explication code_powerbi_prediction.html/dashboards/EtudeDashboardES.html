📊 Dashboard de Estudios con Redux Toolkit y React

Explicación detallada del funcionamiento del archivo Redux etudeSlice.js y del componente React EtudeDashboard.jsx.

76 Presentación general

Esta parte del proyecto implementa un dashboard dedicado al análisis de datos relacionados con los estudios en el extranjero utilizando varias tecnologías frontend complementarias, entre ellas React, Redux Toolkit, Axios y Recharts. El objetivo principal es recuperar automáticamente los datos desde el backend, almacenarlos en el store de Redux, gestionar los diferentes estados de la solicitud y, posteriormente, presentar los resultados en una interfaz React en forma de lista y gráfico. El componente React EtudeDashboard se comunica con el backend mediante la acción asíncrona fetchEtudeData. Esta acción se crea con createAsyncThunk y utiliza Axios para enviar una solicitud HTTP GET a la dirección http://localhost:3000/etude/dashboard. El backend devuelve los datos en formato JSON y el código recupera específicamente la propiedad data de la respuesta. Esta información se envía posteriormente a Redux, que la almacena en la propiedad items del estado global. El componente React recupera después los datos mediante useSelector. El hook useEffect permite ejecutar automáticamente la acción de recuperación cuando se carga la página. Los datos recuperados se transforman posteriormente mediante map() para crear un array adaptado a Recharts. Cada elemento contiene un nombre correspondiente al modo, un valor real y un valor de predicción. El componente también muestra el dashboard de Power BI mediante una etiqueta iframe. Finalmente, Recharts se utiliza para construir un gráfico de barras que permite visualizar las predicciones. Esta arquitectura permite separar claramente la gestión de los datos, realizada por Redux Toolkit, de la presentación y la interacción, gestionadas por React.

77 Importación de Redux Toolkit y Axios

El archivo Redux comienza importando createSlice y createAsyncThunk desde Redux Toolkit. La función createSlice permite crear una parte del store Redux dedicada a los datos de los estudios. Permite definir el nombre del slice, el estado inicial y los procesos asociados a las diferentes situaciones de la solicitud asíncrona. La función createAsyncThunk permite crear una acción asíncrona capaz de comunicarse con el backend. El código también importa axios, que se utiliza como cliente HTTP para realizar la solicitud hacia la API Node.js/Express. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

Estas importaciones constituyen, por lo tanto, la base de la comunicación entre el frontend React, el store Redux y el backend.

78 Creación de la acción asíncrona fetchEtudeData

La acción principal del archivo Redux es fetchEtudeData. Se crea mediante createAsyncThunk. Esta función permite realizar una operación asíncrona mientras Redux Toolkit gestiona automáticamente los estados pending, fulfilled y rejected. El primer argumento, "etude/fetchEtudeData", corresponde al tipo de la acción Redux. Permite identificar esta operación dentro de la aplicación. El segundo argumento es una función asíncrona que se ejecutará cuando la acción sea llamada desde el componente React. 

export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        try {
            const response = await axios.get(
                "http://localhost:3000/etude/dashboard"
            );

            return response.data.data;

        } catch (error) {
            return thunkAPI.rejectWithValue(error.message);
        }
    }
);

El símbolo _ representa aquí el primer argumento de la función, pero no se utiliza porque esta acción no necesita ningún dato enviado por el componente. El segundo parámetro thunkAPI permite, entre otras cosas, utilizar rejectWithValue para enviar un error personalizado al estado de Redux.

79 Solicitud Axios al backend

Dentro de la función asíncrona, Axios realiza una solicitud HTTP de tipo GET a la ruta /etude/dashboard. El uso de la palabra clave await permite esperar la respuesta del servidor antes de continuar la ejecución. Cuando el backend responde, Axios coloca la respuesta en el objeto response. Los datos devueltos por el servidor están disponibles mediante response.data. En este proyecto, la respuesta contiene a su vez una propiedad data. Por lo tanto, el código recupera response.data.data, que corresponde al array que contiene los datos necesarios para el dashboard. 

const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

return response.data.data;

El return es especialmente importante porque el valor devuelto se convierte en el payload de la acción cuando la solicitud finaliza correctamente.

80 Gestión de errores con try / catch

La solicitud se coloca dentro de una estructura try / catch. El bloque try contiene la solicitud Axios y su procesamiento normal. Si la solicitud falla, por ejemplo, cuando el servidor backend está detenido, cuando la URL es incorrecta o cuando ocurre un error de red, la ejecución pasa al bloque catch. El código recupera entonces el mensaje del error mediante error.message y utiliza thunkAPI.rejectWithValue() para enviar esta información a Redux. El componente React podrá recuperar posteriormente este error mediante la propiedad error. 

catch (error) {
    return thunkAPI.rejectWithValue(error.message);
}

81 Creación de etudeSlice

A continuación, el código crea el slice de Redux dedicado a los estudios mediante createSlice. La propiedad name define el nombre de esta parte del store. En este caso, el nombre es etude. Esta identificación permite acceder a los datos mediante state.etude dentro del componente React. 

const etudeSlice = createSlice({
    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    reducers: {},

    extraReducers: (builder) => {
        // ...
    }
});

El uso de extraReducers es apropiado aquí porque la acción fetchEtudeData fue creada con createAsyncThunk. Los estados generados automáticamente por esta acción se gestionan, por tanto, en esta sección.

82 Definición de initialState

El initialState representa el estado inicial del módulo de estudios. La propiedad items se inicializa con un array vacío porque todavía no se ha recuperado ningún dato. La propiedad loading se inicializa en false, lo que significa que actualmente no hay ninguna solicitud en curso. Finalmente, la propiedad error se inicializa en null, ya que todavía no se ha producido ningún error. Estas tres propiedades permiten al componente React conocer el estado actual de la recuperación de datos. 

initialState: {
    items: [],
    loading: false,
    error: null
}

83 Gestión del estado pending

Cuando el componente React ejecuta dispatch(fetchEtudeData()), Redux Toolkit activa automáticamente el estado pending. Este estado significa que la solicitud está en curso. El código establece entonces state.loading en true y vuelve a establecer la propiedad error en null. Gracias a esta información, React puede mostrar un mensaje de carga al usuario mientras el backend procesa la solicitud. 

.addCase(fetchEtudeData.pending, (state) => {
    state.loading = true;
    state.error = null;
})

84 Gestión del estado fulfilled

Cuando la solicitud Axios finaliza correctamente, Redux Toolkit activa el estado fulfilled. Esto significa que el backend respondió correctamente y que los datos fueron recuperados. El código establece loading en false porque la carga ha finalizado. A continuación, action.payload contiene los datos devueltos por fetchEtudeData. Estos datos se almacenan directamente en state.items. Por lo tanto, pasan a estar disponibles en el store de Redux. 

.addCase(fetchEtudeData.fulfilled, (state, action) => {
    state.loading = false;
    state.items = action.payload;
})

Este paso es fundamental porque permite transferir los datos del backend al store de Redux. El componente React podrá recuperarlos posteriormente mediante useSelector.

85 Gestión del estado rejected

Si se produce un error durante la solicitud, Redux Toolkit activa el estado rejected. El código establece primero loading en false, porque la solicitud ha finalizado, y después recupera el mensaje de error mediante action.payload. Este corresponde al valor enviado por rejectWithValue dentro del bloque catch. El error se almacena posteriormente en state.error. De esta manera, el componente React puede mostrar este error al usuario. 

.addCase(fetchEtudeData.rejected, (state, action) => {
    state.loading = false;
    state.error = action.payload;
})

86 Exportación del reducer

Al final del archivo Redux, el reducer del slice se exporta mediante export default etudeSlice.reducer. Este reducer podrá añadirse posteriormente al store principal de Redux de la aplicación. Representa la lógica responsable de modificar el estado etude. 

export default etudeSlice.reducer;

87 Importación de las funcionalidades de React

El archivo React comienza importando React y el hook useEffect. También importa useDispatch y useSelector desde React Redux. A continuación, el componente importa la acción fetchEtudeData desde el archivo Redux. Finalmente, se importan varios componentes de Recharts para construir el gráfico de visualización. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchEtudeData } from "../redux/etudeSlice";

88 Uso de useDispatch

En el componente EtudeDashboard, el hook useDispatch permite obtener la función dispatch. Esta función se utiliza para enviar una acción al store de Redux. En nuestro caso, permite ejecutar la acción fetchEtudeData(). React no realiza directamente la solicitud Axios. En su lugar, solicita a Redux que realice esta operación. 

const dispatch = useDispatch();

89 Uso de useSelector

El hook useSelector permite al componente React recuperar los datos presentes en el store de Redux. El código accede a state.etude y extrae directamente las propiedades items, loading y error. De esta manera, el componente conoce los datos disponibles, sabe si existe una solicitud en curso y también puede conocer el posible mensaje de error. 

const { items, loading, error } =
    useSelector(state => state.etude);

90 Recuperación automática con useEffect

El hook useEffect se utiliza para iniciar automáticamente la recuperación de datos cuando se carga el componente. Dentro del hook, el código ejecuta dispatch(fetchEtudeData()). Esto activa la acción Redux y, por lo tanto, la solicitud Axios hacia el backend. El usuario no necesita hacer clic en ningún botón para recuperar los datos. La carga de datos se realiza automáticamente cuando se abre la página del dashboard. 

useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

91 Transformación de los datos con map()

Después de recuperar los datos desde Redux, el componente crea una nueva variable llamada chartData. Esta variable se construye mediante el método JavaScript map(). El método map permite recorrer cada elemento del array items y crear un nuevo objeto adaptado a Recharts. Para cada elemento, la propiedad name recibe el valor de item.mode, la propiedad Value recibe el valor real item.value y la propiedad Prediction recibe la predicción. El operador ?? permite proporcionar el valor 0 cuando la predicción es null o undefined. 

const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

Esta transformación permite obtener exactamente la estructura de datos esperada por el componente BarChart.

92 Integración del dashboard de Power BI

El componente React también integra un informe de Power BI mediante una etiqueta iframe. Esta técnica permite mostrar contenido externo directamente dentro de la página web. El atributo src contiene la dirección del informe de Power BI publicado. De esta manera, el usuario puede consultar el dashboard de Power BI directamente desde la interfaz React. La propiedad allowFullScreen también permite mostrar el contenido en pantalla completa cuando esta función está disponible. 

<iframe
    className="etude-iframe"
    title="etude A L'Etranger"
    src="URL_DU_RAPPORT_POWER_BI"
    allowFullScreen
/>

Esta integración permite reunir en una misma página las visualizaciones de Power BI y los datos dinámicos procedentes del backend.

93 Gestión de loading y error

El componente React utiliza las propiedades loading y error recuperadas desde Redux para informar al usuario sobre el estado de la solicitud. Cuando loading es verdadero, el componente muestra un mensaje Loading.... Cuando error contiene un valor, se muestra el mensaje de error. Esta lógica hace que la interfaz sea más clara y permite al usuario comprender lo que ocurre durante la recuperación de los datos. 

{loading && (
    <p className="etude-loading">
        Loading...
    </p>
)}

{error && (
    <p className="etude-error">
        {error}
    </p>
)}

94 Visualización de los datos en forma de lista

El componente muestra posteriormente los datos recuperados en forma de lista HTML. El método map() se utiliza para recorrer el array items. Para cada elemento se crea un elemento li. La propiedad key permite a React identificar cada elemento de forma única durante el renderizado. Para cada fila, el componente muestra el modo, el valor real y la predicción. El operador ?? permite mostrar N/A cuando no existe ninguna predicción disponible. 

<ul className="etude-list">

    {items.map((item, i) => (
        <li key={i}>
            Mode: {item.mode}
            | Value: {item.value}
            | Prediction: {item.prediction ?? "N/A"}
        </li>
    ))}

</ul>

95 Creación del gráfico con Recharts

La biblioteca Recharts se utiliza para transformar los datos en una representación gráfica. El componente ResponsiveContainer permite que el gráfico se adapte automáticamente al ancho disponible. El componente BarChart recibe el array chartData. Los componentes XAxis y YAxis representan respectivamente los ejes horizontal y vertical. CartesianGrid añade una cuadrícula para facilitar la lectura del gráfico. Tooltip muestra información cuando el usuario pasa el cursor sobre una barra y Legend permite mostrar la leyenda. Finalmente, el componente Bar utiliza la propiedad dataKey="Prediction" para representar gráficamente las predicciones. 

<ResponsiveContainer width="100%" height={350}>

    <BarChart data={chartData}>

        <CartesianGrid strokeDasharray="3 3" />

        <XAxis dataKey="name" />

        <YAxis />

        <Tooltip />

        <Legend />

        <Bar
            dataKey="Prediction"
            fill="#6366f1"
        />

    </BarChart>

</ResponsiveContainer>

96 Funcionamiento global de Redux y React

El funcionamiento comienza cuando el usuario abre la página EtudeDashboard. React monta el componente y ejecuta el hook useEffect. Este activa dispatch(fetchEtudeData()). Redux Toolkit inicia entonces la acción asíncrona creada con createAsyncThunk. El estado pending se activa automáticamente y la propiedad loading pasa a true. Axios envía entonces una solicitud GET al backend. El backend procesa la solicitud y devuelve los datos del dashboard. Si la solicitud tiene éxito, Redux activa fulfilled, cambia loading a false y almacena los datos en state.items. El componente React recupera entonces estos datos mediante useSelector. Se utilizan para construir la lista y el array chartData. Este último se envía a Recharts para construir el gráfico. Si se produce un error, se activa el estado rejected, el error se almacena en Redux y React puede mostrar el mensaje correspondiente.

97 Arquitectura frontend completa

Esta funcionalidad muestra una arquitectura frontend organizada en la que cada tecnología tiene un papel específico. React es responsable de la interfaz de usuario y del renderizado de los componentes. Redux Toolkit se utiliza para centralizar los datos de los estudios en el store global. createAsyncThunk simplifica la gestión de la operación asíncrona. Axios se encarga de la comunicación HTTP entre el frontend y el backend. useEffect permite activar automáticamente la recuperación de los datos. useDispatch permite a React enviar la acción Redux y useSelector permite recuperar los resultados desde el store. El método map() permite transformar los datos recibidos para adaptarlos al gráfico. Finalmente, Recharts permite crear una visualización gráfica interactiva y Power BI proporciona una visualización de Business Intelligence integrada en la misma página. Esta separación de responsabilidades hace que el código sea más organizado, mantenible y fácil de evolucionar.

98 Conclusión

El Dashboard de Estudios constituye un flujo completo de recuperación, gestión y visualización de datos. El proceso comienza en React con useEffect, que activa la acción Redux fetchEtudeData. Esta acción utiliza createAsyncThunk y Axios para comunicarse con el backend. Redux Toolkit gestiona posteriormente de forma automática las tres etapas principales de la solicitud: pending durante la carga, fulfilled cuando los datos se recuperan correctamente y rejected cuando se produce un error. Los datos recibidos se almacenan en state.etude.items y posteriormente se recuperan en React mediante useSelector. El componente transforma después la información mediante map() para crear los datos necesarios para Recharts. Los resultados se muestran en forma de lista y gráfico, mientras que Power BI se integra mediante un iframe. En conjunto, se obtiene una arquitectura frontend completa en la que el backend proporciona los datos, Redux Toolkit los centraliza y React los presenta al usuario. Esta organización permite construir un dashboard dinámico capaz de mostrar tanto los datos reales como los resultados de predicción en una interfaz moderna.
