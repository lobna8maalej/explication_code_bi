Présentation générale

Ce module présente une architecture permettant d'intégrer des modèles de données ou de Machine Learning dans une application Web développée avec Node.js et Express, avec MySQL utilisé comme système de stockage des résultats. Dans ce projet de parapharmacie, deux fichiers Python au format PKL sont générés : biodream.pkl et bonheur.pkl. Ces fichiers représentent les objets qui sont sauvegardés avec la bibliothèque Python pickle. Le backend Node.js utilise ensuite Express pour exposer une API accessible depuis le frontend. Lorsqu'une requête est envoyée vers /parapharma, Express appelle une route dédiée. Cette route utilise ensuite le service parapharmaservice.js afin de produire les valeurs réelles et les valeurs prédites. Les résultats sont ensuite enregistrés dans la base de données MySQL, notamment dans la table gb_model1. L'objectif de cette architecture est donc de séparer les différentes responsabilités : les modèles et traitements sont gérés côté Python, Node.js assure la logique backend et la communication avec l'API, Express organise les routes HTTP, MySQL conserve les résultats et le frontend peut ensuite exploiter ces données pour afficher des graphiques, indicateurs ou tableaux de bord.

Génération des fichiers PKL

La première partie du projet concerne la sauvegarde des objets dans des fichiers .pkl. Le module Python utilise la bibliothèque pickle. Cette bibliothèque permet de sérialiser un objet Python, c'est-à-dire de transformer l'objet en une forme qui peut être enregistrée dans un fichier puis rechargée ultérieurement. Dans le code fourni, une fonction appelée save_pickle() est créée afin de centraliser cette opération de sauvegarde. La fonction reçoit deux paramètres : l'objet à sauvegarder et le nom du fichier. Le fichier est ouvert avec le mode wb, qui signifie "write binary", puis pickle.dump() enregistre l'objet dans le fichier. Le programme crée ensuite deux objets : data_biodream et data_bonheur. Le premier contient un score de 0.92 et le type "biodream_model", tandis que le second contient un score de 0.88 et le type "bonheur_model". Ces objets sont ensuite sauvegardés dans biodream.pkl et bonheur.pkl. Il est important de préciser que, dans le code fourni, ces fichiers PKL contiennent actuellement des dictionnaires Python de démonstration et non un modèle Machine Learning entraîné par une bibliothèque comme Scikit-learn. L'architecture permet cependant d'utiliser cette même logique avec un véritable modèle entraîné.

Service de prédiction

Le fichier parapharmaservice.js contient la fonction trainModels(). Cette fonction représente la couche de service du backend. Son rôle est de préparer les données et de produire les prédictions qui seront ensuite envoyées vers la route Express. Le tableau X contient les valeurs d'entrée 1, 2, 3, 4 et 5. Le tableau y contient les valeurs réelles 100, 200, 300, 400 et 500. Ensuite, la méthode map() parcourt chaque valeur de X et applique la règle v * 100. Le résultat est placé dans le tableau predictions. Ainsi, pour 1 la prédiction est 100, pour 2 elle est 200, pour 3 elle est 300, pour 4 elle est 400 et pour 5 elle est 500. La fonction retourne ensuite un objet contenant success et un objet data contenant X, y et predictions. Il est important de préciser que cette fonction ne réalise pas actuellement un véritable entraînement de modèle Machine Learning. Elle simule une prédiction avec une formule mathématique simple. Dans une version avancée, cette fonction pourrait appeler un véritable modèle entraîné ou un service Python chargé de réaliser la prédiction.

Route Express et traitement des résultats

Le fichier parapharmaRoute.js constitue le point de coordination entre le service de prédiction et la base de données MySQL. La route utilise router.get("/"), ce qui signifie que lorsqu'un client appelle GET /parapharma, cette fonction est exécutée. La première étape consiste à ouvrir une connexion avec MySQL grâce à getConnection(). La deuxième étape consiste à appeler trainModels(). Le résultat retourné contient les valeurs réelles et les prédictions. Le code récupère donc result.data.y dans la variable real et result.data.predictions dans la variable pred. Ensuite, Math.min() permet de déterminer le nombre d'éléments communs aux deux tableaux. Une boucle for parcourt ensuite les valeurs et utilise connection.execute() pour insérer chaque couple valeur réelle / prédiction dans la table gb_model1. Après l'insertion, Express retourne une réponse JSON contenant un message de succès, le nombre de lignes insérées et les valeurs réelles associées aux prédictions. La route représente donc le lien entre le service de calcul et la base de données.

📄 parapharmaRoute.js 
const express = require("express");
```

const router = express.Router();

const {
getConnection
} = require("../DBMysql/parapharmadb");

const {
trainModels
} = require("../service/parapharmaservice");

router.get("/", async (req, res) => {

```
let connection;

try {

    connection =
        await getConnection();


    const result =
        await trainModels();


    const real =
        result.data.y;


    const pred =
        result.data.predictions;


    const length =
        Math.min(
            real.length,
            pred.length
        );


    for (
        let i = 0;
        i < length;
        i++
    ) {

        await connection.execute(

            `INSERT INTO gb_model1
            (real_value, prediction)
            VALUES (?, ?)`,

            [
                real[i],
                pred[i]
            ]

        );

    }


    res.status(200).json({

        message:
            "Model trained and saved",

        rowsInserted:
            length,

        data:
            real.map((r, i) => ({

                real: r,

                prediction:
                    pred[i]

            }))

    });


} catch (err) {

    res.status(500).json({

        error:
            err.message

    });


} finally {

    if (connection) {

        await connection.end();

    }

}
```

});

Architecture complète

L'architecture complète fonctionne comme une chaîne de traitement. Le frontend ou le dashboard appelle l'API Node.js sur l'endpoint /parapharma. Express reçoit cette requête et exécute la route définie dans parapharmaRoute.js. La route ouvre une connexion vers MySQL puis appelle trainModels(). Le service prépare les données X et y et calcule les prédictions. Les valeurs réelles et prédites sont ensuite récupérées par la route. Pour chaque observation, Node.js exécute une requête SQL afin d'enregistrer la valeur réelle et la prédiction dans gb_model1. Lorsque toutes les lignes sont enregistrées, Express retourne une réponse JSON au frontend. Le dashboard peut alors récupérer ces données depuis l'API et les représenter sous forme de graphiques ou d'indicateurs. Les fichiers biodream.pkl et bonheur.pkl font partie de la couche Python de sauvegarde des objets et pourront être utilisés comme base pour intégrer de véritables modèles prédictifs.
