📊 Explication du composant InfoDashboard.jsx, du fichier infoSlice.js et de leur liaison avec CSS

Cette documentation explique le fonctionnement du Dashboard GOMYCODE AI et la communication entre React, Redux Toolkit, Axios, le backend, le Machine Learning, Power BI, Recharts et le fichier CSS associé.

1. Présentation générale

Le composant InfoDashboard.jsx constitue l'interface React du Dashboard consacré à l'analyse et à la prédiction des données GOMYCODE. Il utilise plusieurs technologies complémentaires afin de récupérer une prédiction depuis le backend, de gérer son état avec Redux Toolkit, d'afficher un rapport Power BI intégré et de représenter la prédiction sous forme de graphique avec Recharts.

Le fichier infoSlice.js constitue la partie Redux Toolkit responsable de la récupération et de la gestion des données de prédiction.

Enfin, le fichier InfoDashboard.css est responsable de la présentation visuelle du composant InfoDashboard.jsx.

InfoDashboard.jsx ↓ useEffect() ↓ dispatch(fetchInfoData()) ↓ infoSlice.js ↓ Axios ↓ Backend / Machine Learning ↓ Résultat de prédiction ↓ Redux ↓ InfoDashboard.jsx ↓ InfoDashboard.css ↓ Interface finale

2. Les imports de InfoDashboard.jsx

Le fichier InfoDashboard.jsx commence par l'importation de React et du hook useEffect. Le hook useEffect permet d'exécuter automatiquement une opération après le chargement du composant.

Le composant importe également useDispatch et useSelector depuis react-redux. useDispatch permet d'envoyer une action Redux, tandis que useSelector permet de récupérer les données stockées dans le store Redux.

Le composant importe ensuite fetchInfoData depuis ../redux/infoSlice. Cette fonction asynchrone est responsable de lancer la requête vers le backend afin d'obtenir la prédiction.

Plusieurs composants de la bibliothèque Recharts sont également importés : BarChart, Bar, XAxis, YAxis, Tooltip, CartesianGrid et ResponsiveContainer.

Point important :

Le fichier React contient également : 

import "./InfoDashboard.css";

Cette instruction est placée dans InfoDashboard.jsx, et non dans le fichier HTML de documentation.

3. Comment InfoDashboard.jsx est lié à InfoDashboard.css ?

La liaison entre React et CSS se fait de deux manières principales.

Première liaison : l'importation du CSS

import "./InfoDashboard.css";

Cette instruction indique à l'application React de charger le fichier InfoDashboard.css.

Deuxième liaison : les className

Dans le JSX, les éléments HTML utilisent des propriétés className. Ces noms correspondent aux classes définies dans le fichier CSS. 

<div className="info-container">

<h1 className="info-title">
    📊 GOMYCODE AI Dashboard
</h1>

<div className="prediction-card">

<h1 className="prediction-value">

<div className="chart-box">

Dans InfoDashboard.css, ces classes peuvent être définies de la manière suivante : 

.info-container {
    width: 100%;
    min-height: 100vh;
    padding: 30px;
}

.info-title {
    text-align: center;
    font-size: 32px;
}

.prediction-card {
    padding: 30px;
    text-align: center;
    border-radius: 15px;
}

.prediction-value {
    font-size: 42px;
    font-weight: bold;
}

.chart-box {
    width: 100%;
    max-width: 900px;
    margin: auto;
}
InfoDashboard.jsx ↓ className="prediction-card" ↓ InfoDashboard.css ↓ .prediction-card { ... } ↓ Style appliqué à la carte

4. La fonction InfoDashboard

La fonction InfoDashboard représente le composant React principal.

Au début du composant, const dispatch = useDispatch() permet de récupérer la fonction dispatch de Redux.

Cette fonction permet au composant d'envoyer l'action fetchInfoData() vers le store Redux.

Ensuite, useSelector est utilisé avec (state) => state.info afin de récupérer les trois informations principales :

  • data : contient le résultat de la prédiction.
  • loading : indique si la requête est en cours.
  • error : contient une éventuelle erreur.

5. Le rôle de useEffect

Le hook useEffect joue un rôle important dans le fonctionnement du Dashboard. 

useEffect(() => {
    dispatch(fetchInfoData());
}, [dispatch]);

Lorsque l'utilisateur ouvre la page GOMYCODE AI Dashboard, React charge le composant puis exécute le useEffect.

Celui-ci déclenche : 

dispatch(fetchInfoData());

Redux reçoit alors l'action et lance la fonction asynchrone définie dans infoSlice.js.

Chargement du composant ↓ useEffect() ↓ dispatch(fetchInfoData()) ↓ Redux ↓ Axios ↓ Backend ↓ Machine Learning

6. Préparation de chartData

La constante chartData prépare les données nécessaires à Recharts. 

const chartData = data
    ? [
        {
            name: "GOMYCODE",
            prediction: data.gomycode_pred
        }
    ]
    : [];

Si data existe, un tableau contenant un objet est créé.

L'objet possède :

  • name avec la valeur "GOMYCODE"
  • prediction avec la valeur data.gomycode_pred

Si les données ne sont pas encore disponibles, un tableau vide est retourné : 

[]

Cette précaution évite d'utiliser des données inexistantes lors du premier rendu.

7. Le conteneur principal et son CSS

Dans la partie return, l'ensemble du contenu est placé dans : 

<div className="info-container">

La classe info-container permet de relier cet élément au fichier InfoDashboard.css.

Par exemple : 

.info-container {
    width: 100%;
    min-height: 100vh;
    padding: 30px;
    box-sizing: border-box;
}

Le CSS contrôle donc la largeur, la hauteur minimale, l'espacement intérieur et la gestion de la boîte.

<h1 className="info-title">

Le contenu du titre est défini par React, tandis que son apparence est contrôlée par CSS. 

.info-title {

    margin-bottom: 30px;

Ainsi, React définit le texte et CSS définit sa présentation.

10. Gestion de l'état loading

Lorsque la requête est en cours, le composant utilise : 

{loading && (
    <p className="loading">
        Loading prediction...
    </p>
)}

Si loading vaut true, le message est affiché.

Le CSS peut ensuite contrôler son apparence : 

.loading {
    text-align: center;
    font-size: 18px;
    margin: 20px;
}
À retenir :

Redux décide si loading est vrai ou faux. React décide d'afficher ou non l'élément. CSS décide comment cet élément apparaît.

11. Gestion de l'erreur

Lorsque la requête échoue, le composant affiche : 

{error && (
    <p className="error">
        {JSON.stringify(error)}
    </p>
)}

Si error contient une valeur, React affiche le paragraphe.

La classe error peut être stylisée avec : 

.error {
    text-align: center;
    font-weight: bold;
    margin: 20px;
}
Erreur backend ↓ Redux ↓ error ↓ React ↓ className="error" ↓ InfoDashboard.css ↓ Message d'erreur stylisé

12. La carte de prédiction

Lorsque les données sont disponibles, le composant affiche une carte grâce à : 

{data && (

        <h1 className="prediction-value">
            {Number(data.gomycode_pred).toFixed(2)}
        </h1>

    </div>
)}

La classe prediction-card permet au CSS de contrôler l'apparence de la carte. 

.prediction-card {
    width: 100%;
    max-width: 600px;
    margin: 30px auto;
    padding: 30px;
    text-align: center;
    border-radius: 15px;
}

13. La valeur prediction-value

La valeur de la prédiction possède sa propre classe : 

<h1 className="prediction-value">
    {Number(data.gomycode_pred).toFixed(2)}
</h1>

Cette classe permet de mettre le résultat principal en évidence. 

.prediction-value {
    font-size: 42px;
    font-weight: bold;
    margin: 10px 0;
}

L'expression Number(data.gomycode_pred).toFixed(2) convertit la valeur en nombre puis limite l'affichage à deux chiffres après la virgule.

Par exemple, une valeur comme 1234.5678 pourra être affichée sous la forme 1234.57.

16. Le fichier infoSlice.js

Le fichier infoSlice.js constitue la partie Redux Toolkit responsable de la récupération et de la gestion des données de prédiction.

Il importe notamment :

  • createSlice
  • createAsyncThunk
  • axios

La fonction fetchInfoData est créée avec createAsyncThunk. 

createAsyncThunk(
    "info/fetchInfoData",
    async (_, thunkAPI) => {
        ...
    }
)

Cette fonction représente l'opération asynchrone qui permet de communiquer avec le backend.

17. Requête Axios

Axios utilise axios.post() pour envoyer une requête HTTP POST vers : 

http://localhost:3000/info/predict

Le corps de la requête contient : 

{
    values: [1000, 2500]
}

Ces valeurs représentent les données d'entrée transmises au système de prédiction.

[1000, 2500] ↓ Axios ↓ POST /info/predict ↓ Node.js ↓ Machine Learning ↓ Prédiction ↓ Réponse HTTP ↓ Redux

18. Gestion de la réponse

Après l'exécution de la requête Axios, le code : 

return res.data.data;

récupère les données utiles dans la réponse HTTP.

Cette valeur devient ensuite le résultat de l'action asynchrone Redux.

19. Gestion des erreurs avec try/catch

La fonction utilise un bloc try/catch afin de gérer le succès ou l'échec de la requête. 

try {
    ...
} catch (err) {
    ...
}

En cas d'erreur, le code utilise : 

thunkAPI.rejectWithValue(
    err.response?.data || err.message
)

L'opérateur ?. permet d'accéder à response.data uniquement si response existe.

Si aucune réponse serveur n'est disponible, err.message est utilisé.

20. initialState

Le slice possède un état initial : 

initialState: {
    data: null,
    loading: false,
    error: null
}

Au départ :

  • data ne contient aucune prédiction.
  • loading indique qu'aucune requête n'est en cours.
  • error ne contient aucune erreur.

21. fetchInfoData.pending

Lorsque la requête commence, Redux déclenche : 

fetchInfoData.pending

Le state est alors modifié : 

state.loading = true;
state.error = null;

React récupère ensuite cette nouvelle valeur grâce à useSelector.

Redux ↓ loading = true ↓ React ↓ className="loading" ↓ InfoDashboard.css ↓ Message de chargement stylisé

22. fetchInfoData.fulfilled

Lorsque la requête réussit, Redux déclenche : 

fetchInfoData.fulfilled

Le code met alors : 

state.loading = false;
state.data = action.payload;

La prédiction est donc stockée dans state.info.data.

Grâce à useSelector, le composant React récupère automatiquement la nouvelle donnée et actualise son interface.

23. fetchInfoData.rejected

Si la requête échoue, Redux déclenche : 

fetchInfoData.rejected

Le state devient : 

state.loading = false;
state.error = action.payload;

React récupère ensuite error et affiche le message correspondant avec la classe CSS error.

24. Liaison entre Redux, React et CSS

Il est important de comprendre que Redux ne communique pas directement avec le CSS.

Redux fournit les données et les états à React. React décide ensuite quels éléments doivent être affichés. Les className permettent enfin de relier ces éléments au fichier CSS.

infoSlice.js ↓ data / loading / error ↓ InfoDashboard.jsx ↓ JSX + className ↓ InfoDashboard.css ↓ Présentation visuelle

27. Flux complet du projet

Lorsque l'utilisateur ouvre le Dashboard, React charge InfoDashboard.jsx.

Le useEffect est alors exécuté et déclenche : 

dispatch(fetchInfoData());

Redux Toolkit passe dans l'état pending et met loading à true.

Axios envoie ensuite les valeurs : 

[1000, 2500]

vers : 

POST /info/predict

Le backend reçoit ces valeurs et utilise le modèle de Machine Learning pour calculer la prédiction.

Le résultat revient ensuite vers Redux.

Si la requête réussit, Redux passe dans l'état fulfilled et stocke le résultat dans : 

state.info.data

useSelector récupère alors la nouvelle donnée. React actualise automatiquement l'interface.

La valeur data.gomycode_pred est affichée dans la carte de prédiction et utilisée pour construire chartData.

Recharts utilise ensuite chartData pour créer le graphique.

En parallèle, l'iframe affiche le rapport Power BI.

Enfin, InfoDashboard.css applique les styles aux différents éléments grâce aux className.

28. Schéma final de l'architecture

BACKEND │ ▼ Machine Learning │ ▼ Axios │ ▼ infoSlice.js │ ┌─────────┼─────────┐ ▼ ▼ ▼ data loading error │ │ │ └─────────┼─────────┘ ▼ InfoDashboard.jsx │ ┌──────────────┼──────────────┐ ▼ ▼ ▼ prediction-card loading error │ prediction-value │ chart-box │ ▼ InfoDashboard.css │ ▼ Interface visuelle

29. Résumé à retenir pour la présentation

React construit → Redux gère → Axios communique → Backend prédit → Recharts visualise → Power BI analyse → CSS présente.

Le composant InfoDashboard.jsx construit l'interface et récupère les informations depuis Redux. Le fichier infoSlice.js gère la requête asynchrone et les états data, loading et error.

Axios assure la communication avec le backend qui utilise le système de Machine Learning pour produire la prédiction.

Recharts transforme ensuite la prédiction en représentation graphique et Power BI fournit le rapport décisionnel intégré.

Enfin, InfoDashboard.css ne réalise ni la prédiction ni la récupération des données. Son rôle est de contrôler l'apparence des éléments créés par React.

La liaison entre React et CSS se fait grâce à import "./InfoDashboard.css"; dans le fichier JSX et grâce aux className qui correspondent aux sélecteurs CSS.
