🛒 Commerce Data Management with Redux Toolkit and React

Complete documentation of the Commerce module: Redux Toolkit, React, Axios, Recharts and Power BI.

47 — Commerce Data Management with Redux Toolkit and React

In this part of the project, a complete system for retrieving, managing, transforming, filtering and displaying commercial data has been developed using React, Redux Toolkit, Axios and Recharts. The objective of this feature is to retrieve commerce data from the backend, store it in the Redux store, transform it to facilitate its use in the user interface, and then allow the user to filter the data according to the selected commerce, for example Jumia or MG. The retrieved data is then used in a bar chart through the Recharts library, but it is also displayed as a detailed list. This frontend part communicates directly with the backend through an HTTP GET request to the address http://localhost:3000/commerce/train. The general workflow is as follows: when the React component Commerce is loaded, the useEffect hook triggers the Redux action fetchCommerce. This action uses createAsyncThunk to perform an Axios request to the backend. The backend returns the commerce data, Redux retrieves this data and stores it in the global state. The React component then uses useSelector to retrieve the data from Redux. A transformation logic is applied using the map() method to add a label property to each element. The component also uses useState to manage the selected commerce in the filter. When the user selects Jumia or MG, the local state filter is modified and the data is filtered using the filter() method. The filtered data is then used simultaneously to build the chart with BarChart and to display the detailed list. The project also includes Power BI integration through an iframe element, which makes it possible to directly display the Power BI dashboard in the React page. This architecture therefore clearly separates data retrieval and management, handled by Redux, from presentation and user interaction, handled by React.

48 — Importing Redux Toolkit and Axios

The Redux file begins by importing two important features from Redux Toolkit: createSlice and createAsyncThunk. The createSlice function makes it possible to create a part of the Redux store dedicated to commerce. It allows the application to define the name of the slice, its initial state and the processing logic associated with the different situations of the asynchronous action. The createAsyncThunk function is used to create a Redux action capable of performing an asynchronous operation, in this case an HTTP request to the backend. This feature is particularly suitable when a React application needs to retrieve data from an API. The code also imports Axios, which is used as an HTTP client to send a GET request to the Node.js/Express server. The role of this part is therefore to connect the React/Redux frontend with the backend that provides the commerce data. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

49 — Creating the fetchCommerce Asynchronous Action

The main action of the Redux file is fetchCommerce. This action is created with createAsyncThunk. The first argument "commerce/fetchCommerce" corresponds to the Redux action type and allows this operation to be identified. The second argument is an asynchronous function that will be executed when the action is triggered. Inside this function, Axios performs an HTTP GET request to the URL http://localhost:3000/commerce/train. This route corresponds to a backend route responsible for providing the commerce data. The keyword await makes it possible to wait for the server response before continuing execution. Once the response is received, it is stored in the response variable. Axios places the data returned by the server in response.data. In this project, the backend returns a structure containing a data property. The code therefore retrieves precisely response.data.data. This value corresponds to the array of commerce data that will be transmitted to Redux. The return of this function then becomes the payload of the Redux action when the request completes successfully. 

export const fetchCommerce = createAsyncThunk(
    "commerce/fetchCommerce",
    async () => {
        const response = await axios.get(
            "http://localhost:3000/commerce/train"
        );

        return response.data.data;
    }
);

50 — Creating the Commerce Slice

The code then creates the Redux slice using createSlice(). This function makes it possible to organize all Redux logic related to commerce within a single structure. The name: "commerce" property gives the slice its name and allows this part of the global store to be identified. The initialState defines the initial state of the data. The data property is initialized with an empty array because no data has yet been retrieved from the backend. The loading property is initially set to false, which means that no data retrieval is currently in progress. These values will then be modified automatically according to the state of the fetchCommerce action. 

const commerceSlice = createSlice({
    name: "commerce",

    initialState: {
        data: [],
        loading: false
    },

    extraReducers: (builder) => {
        // Gestion des états asynchrones
    }
});

51 — Managing the pending State

Redux Toolkit automatically generates several states for an action created with createAsyncThunk. The first state is pending. This state is executed when the request begins. When the React component triggers dispatch(fetchCommerce()), Redux automatically enters the pending state. The code then modifies state.loading and assigns it the value true. This means that the application knows that data retrieval is currently in progress. The React component can use this information to display a message such as Loading.... This logic therefore makes it possible to inform the user that the data is currently being loaded. 

.addCase(fetchCommerce.pending, (state) => {
    state.loading = true;
})

52 — Managing the fulfilled State and Data Transformation

When the Axios request completes successfully, Redux Toolkit triggers the fulfilled state. This means that the request was successful and that the data has been received. The first operation is to set state.loading back to false, because the loading process is complete. The received data is then stored in state.data. Before storing it, however, the code uses the JavaScript map() method. This method iterates through each element of the array received in action.payload. For each element, the spread operator ...item preserves all existing properties, and then a new property called label is added. This property is built from the values of commerce and web_scraper. For example, if the commerce is Jumia and the scraper is Python, the new value may be Jumia - Python. This transformation makes it possible to prepare the data directly in Redux so that the React component has information ready to be used. 

.addCase(fetchCommerce.fulfilled, (state, action) => {
    state.loading = false;

    state.data = action.payload.map((item) => ({
        ...item,
        label: `${item.commerce} - ${item.web_scraper}`
    }));
})

53 — Managing the rejected State

The third state is rejected. It is executed when the request fails. This can happen if the backend server is unavailable, if the URL is incorrect, or when a network error prevents Axios from receiving the data. In this situation, the code sets loading back to false to indicate that the loading process is complete. In this version of the slice, no error property is stored in the state. The component therefore knows that loading has finished, but it does not retrieve the precise error details here. The objective is to properly manage the request lifecycle: pending when data retrieval begins, fulfilled when the data is successfully retrieved, and rejected when an error occurs. 

.addCase(fetchCommerce.rejected, (state) => {
    state.loading = false;
})

54 — Importing React Features

The Commerce.jsx file uses several important features from React and React Redux. useEffect makes it possible to trigger an operation after the component has rendered, particularly to start data retrieval. useState makes it possible to manage local state, here used to remember the selected commerce in the filter. useDispatch makes it possible to send a Redux action from React, while useSelector makes it possible to retrieve data stored in the Redux store. The component also imports the fetchCommerce action from the commerceSlice file. Finally, the Commerce.css file is imported to apply the graphical styling to the dashboard. 

import React, { useEffect, useState } from "react";

import {
    useDispatch,
    useSelector
} from "react-redux";

import { fetchCommerce } from "../redux/commerceSlice";

import "./Commerce.css";

55 — Using useDispatch

The useDispatch() hook provides the dispatch function. This function makes it possible to send an action to the Redux store. In this project, it is used to trigger the fetchCommerce() action. When this action is dispatched, Redux Toolkit executes the asynchronous process defined in the slice and starts the Axios request to the backend. The React component therefore does not need to perform the HTTP request directly. It simply asks Redux to retrieve the data. 

const dispatch = useDispatch();

dispatch(fetchCommerce());

56 — Retrieving Data with useSelector

The useSelector() hook allows the React component to access the global Redux state. Here, the code retrieves data and loading from state.commerce. The data property contains the commerce data retrieved from the backend and transformed in the Redux slice. The loading property indicates whether data retrieval is currently in progress. Thanks to this architecture, the React component does not directly manage Axios. It retrieves information from the Redux store, which makes it possible to clearly separate the data retrieval logic from the display logic. 

const { data, loading } =
    useSelector((state) => state.commerce);

57 — Managing the Filter with useState

The useState() hook is used to create a local state called filter. Its initial value is Jumia. This means that when the component is displayed for the first time, the data presented in the chart and in the list correspond to the Jumia commerce. The setFilter() function can then modify this value when the user selects another commerce. The local state is therefore used to manage the user's interaction with the filter without modifying the data stored in Redux. 

const [filter, setFilter] = useState("Jumia");

58 — Automatically Retrieving Data with useEffect

The useEffect() hook makes it possible to execute an operation after the component has rendered. Here, its purpose is to automatically trigger data retrieval when the Commerce page is loaded. The instruction dispatch(fetchCommerce()) sends the Redux action. Redux Toolkit then launches the createAsyncThunk, which performs the Axios request to the backend. The dependency [dispatch] indicates that the effect depends on the dispatch function. The workflow can therefore be summarized as follows: the React component is loaded, useEffect executes, dispatch triggers fetchCommerce, Redux launches Axios, Axios communicates with the backend, the backend returns the data, Redux stores the data, and React retrieves it using useSelector. 

useEffect(() => {
    dispatch(fetchCommerce());
}, [dispatch]);

59 — Filtering the Data

After retrieving the data, the code creates a new variable called filteredData. The JavaScript filter() method makes it possible to select only the elements corresponding to the selected commerce. The condition item.commerce === filter compares the commerce property of each element with the current value of the filter state. If the filter value is Jumia, only the data whose commerce is Jumia is kept. If the user selects MG, the filter state becomes MG and only the data corresponding to MG is kept. The result is stored in filteredData, which will then be used both by the chart and by the detailed list. 

const filteredData = data
    ? data.filter((item) => item.commerce === filter)
    : [];

60 — Power BI Dashboard Integration

The React component also integrates a Power BI dashboard through an iframe element. This technique makes it possible to directly display a published Power BI report on a web page. The Power BI dashboard represents the decision-making part of the project and makes it possible to present the indicators and visualizations created in Power BI. This integration therefore makes it possible to bring together two types of visualization on the same page: the Power BI report and the dynamic charts generated with React and Recharts. The allowFullScreen property also makes it possible to allow the report to be displayed in full screen when this feature is available. 

<iframe
    className="commerce-iframe"
    title="PRIX"
    src="https://app.powerbi.com/view?r=..." 
    frameBorder="0" 
    allowFullScreen 
></iframe>

61 — Creating the Commerce Filter

The dropdown list allows the user to select the commerce they want to analyze. The value={filter} property binds the value of the HTML select component to the React filter state. When the user changes the selection, the onChange event is triggered and setFilter(e.target.value) retrieves the new value. The two available options are Jumia and MG. As soon as the filter state is modified, React automatically performs a new render of the component. The filteredData variable is then recalculated, allowing the chart and the list to immediately display the data corresponding to the new commerce. 

<select 
    className="filter-select" 
    value={filter} 
    onChange={(e) => setFilter(e.target.value)} 
> 
    <option value="Jumia">Jumia</option> 
    <option value="MG">MG</option> 
</select>

62 — Displaying the Commerce Chart with Recharts

The chart is built with the Recharts library. The ResponsiveContainer component allows the chart to automatically adapt to the available width. The BarChart component receives the filtered data through data={filteredData}. The chart then uses CartesianGrid to display a grid, XAxis for the horizontal axis, YAxis for the vertical axis, and Tooltip to display values when the user moves the mouse over the bars. Two bars are then used: one bar for target and another for prix. The chart therefore makes it possible to visually compare the target value and the price corresponding to the selected commerce data. 

<ResponsiveContainer width="100%" height={300}> 
 
    <BarChart data={filteredData}> 
 
        <CartesianGrid strokeDasharray="3 3" /> 
 
        <XAxis dataKey="commerce" /> 
 
        <YAxis /> 
 
        <Tooltip /> 
 
        <Bar dataKey="target" name="Target" /> 
 
        <Bar dataKey="prix" name="Prix" /> 
 
    </BarChart> 
 
</ResponsiveContainer>

63 — Displaying the Details

After the chart, the component displays the data as a detailed list. The map() method iterates through each element of the filteredData array and generates a corresponding HTML element. The key={item.id} property allows React to uniquely identify each element. For each data item, the interface displays the commerce, the Target value and the price. This list complements the chart by providing the same information in a more precise textual form that is more directly readable by the user. 

{filteredData.map((item) => ( 
    <li key={item.id} className="list-item"> 
        {item.commerce} 
        → Target: {item.target} 
        | Prix: {item.prix} 
    </li> 
))}

64 — Overall Operation between Redux and React

The complete operation of this feature relies on organized communication between React, Redux Toolkit, Axios and the backend. When the user opens the Commerce page, the React component is loaded. The useEffect hook then triggers dispatch(fetchCommerce()). Redux Toolkit launches the asynchronous action created with createAsyncThunk. The pending state is triggered and the loading property becomes true. Axios then sends a GET request to the backend. The server processes the request and returns the commerce data in JSON format. When the response arrives successfully, Redux triggers the fulfilled state. The loading property becomes false again and the data is transformed using map(). The data is then stored in state.data. The React component retrieves the new data using useSelector. The local filter state then makes it possible to select Jumia or MG. The filter() method creates filteredData, which is passed to the Recharts chart and to the detailed list. This architecture therefore clearly separates responsibilities: Redux manages the data, while React manages the interface and user interaction.

65 — Conclusion

The Commerce feature represents a complete frontend processing chain that connects the backend, Redux Toolkit, React, Recharts and Power BI. The data is retrieved automatically using createAsyncThunk and Axios, then stored in Redux so that it is available in the React component. The management of the pending, fulfilled and rejected states makes it possible to manage the request lifecycle. The received data is transformed using map(), particularly to add the label property. React then retrieves this data using useSelector and uses useState to manage the filter between Jumia and MG. The filter() method selects the corresponding data, and Recharts then transforms it into a chart to compare target and prix. The information is also presented as a detailed list. At the same time, Power BI is integrated through an iframe to display the decision-making dashboard. This architecture therefore demonstrates the complementary use of several modern technologies: React for the interface, Redux Toolkit for state management, Axios for backend communication, Recharts for visualization and Power BI for decision-making analysis. The result is a dynamic Commerce dashboard capable of automatically retrieving, transforming, filtering and visualizing data coming from the backend.
