Prediction System INFO

Integration of multiple Python Machine Learning models into a Node.js / Express Web application to generate simultaneous predictions for INFO2, INFO3 and GoMyCode.

Start Documentation
01

General System Overview

The INFO prediction system is a Web architecture that integrates multiple Machine Learning models developed in Python into a Node.js and Express application. The main objective of this architecture is to receive a set of numerical values from the Web application, transmit these data to Python, and then use three different Machine Learning models to simultaneously generate three predictions corresponding to the INFO2, INFO3 and GoMyCode models. The models are previously trained and saved in .pkl files. The INFO2.pkl file corresponds to the first model, INFO3.pkl to the second model and gomycode.pkl to the third model. The Python script info.py represents the prediction engine. It first searches for the model files in the same directory as the script using os.path, and then loads each model using the Python pickle library. After loading the models, the script retrieves the data transmitted by Node.js through sys.argv. These data are sent as a JSON string. Python then uses json.loads() to convert this string into a Python structure, while NumPy transforms the values into a two-dimensional numerical array. This step is important because Scikit-learn models generally expect a matrix containing observations and features. The program also checks that the data do not contain NaN values in order to prevent errors during prediction. The three models are then used with the predict() method. The result of each model is converted into a floating-point number and grouped into a JSON object containing info2_pred, info3_pred and gomycode_pred. The JSON result is sent to Node.js through stdout. On the JavaScript side, the infoService.js file uses the child_process module and its spawn() function to launch the Python script. The values received from the frontend are converted into JSON using JSON.stringify() and then passed to the Python program as an argument. Node.js then retrieves the Python standard output in the output variable. This output is analyzed using JSON.parse() to reconstruct the JavaScript object containing the three predictions. The infoRoute.js file then exposes an HTTP POST /predict route. This route retrieves the values property from the request body, checks that it is an array, and then calls runInfoPrediction(). The result is finally returned to the frontend in a JSON response containing a success property and a data property. Finally, the main server file initializes Express, enables CORS, enables JSON processing with express.json(), registers the router with the /info prefix and starts the server on port 3000. The complete architecture therefore allows the frontend to send data to Node.js, Node.js to communicate with Python, Python to execute several Machine Learning models, and the results to be returned as JSON to the dashboard.

02

Python Prediction Script

The info.py file represents the Machine Learning engine of the system. Its role is to load the three saved models, retrieve the data sent by Node.js, prepare these data in numerical form and perform the three predictions. The script starts by importing the required libraries. os is used to manage file paths, pickle is used to load saved Machine Learning models, json is used to exchange structured data between JavaScript and Python, sys is used to retrieve command-line arguments sent by Node.js, and NumPy is used to build the numerical array passed to the models. The program then determines the script directory using os.path.dirname(os.path.abspath(__file__)). This method provides a reliable absolute path regardless of the directory from which Python is executed. The files dictionary then associates each logical identifier with its model file. The for loop iterates through these files, builds their complete path using os.path.join(), checks their existence using os.path.exists(), and opens them using pickle.load(). The loaded models are stored in the models dictionary. This organization makes it possible to manage multiple models within a single structure and facilitates their use during the prediction phase.

Library Imports 

import os
import pickle
import json
import sys
import numpy as np

These libraries perform the different operations required by the script. os manages paths and files, pickle reloads saved Machine Learning models, json provides structured communication with Node.js, sys retrieves command-line arguments, and NumPy prepares numerical data as a matrix.

Determining the Directory 

BASE_DIR = os.path.dirname(
    os.path.abspath(__file__)
)

This instruction retrieves the absolute path of the directory containing info.py. This ensures that the model files can be located correctly even if Node.js launches Python from another directory.

03

Loading the Three Machine Learning Models

The system uses three different Machine Learning models. The files dictionary contains the mapping between the names used in the code and the physical model files located in the Python directory. The INFO2.pkl model is associated with the info2 identifier. The INFO3.pkl model is associated with the info3 identifier. The gomycode.pkl model is associated with the gomycode identifier. The loop iterates through each element of the dictionary. For each model, the program builds its complete path and first checks whether the file exists. If the file is missing, the program raises an exception indicating the exact missing path. If the file exists, it is opened in binary mode using open(..., "rb"), and pickle.load() reloads the Machine Learning object. The loaded model is then stored in models[key]. At the end of this loop, all three models are available in memory and can be used independently to generate predictions. 

models = {}

files = {
    "info2": "INFO2.pkl",
    "info3": "INFO3.pkl",
    "gomycode": "gomycode.pkl"
}

Loading the Models 

for key, file in files.items():

    path = os.path.join(
        BASE_DIR,
        file
    )

    if not os.path.exists(path):
        raise Exception(
            f"Missing model file: {path}"
        )

    with open(path, "rb") as f:
        models[key] = pickle.load(f)

04

Data Reception and Preparation

After loading the models, the script checks whether data have been transmitted by Node.js. The condition if len(sys.argv) < 2 checks whether an additional argument is available. If no argument is available, the program stops its execution and indicates that the data coming from Node.js are missing. When data are available, they are retrieved using sys.argv[1]. Node.js sends a JavaScript array transformed into a JSON string. Python therefore uses json.loads() to convert this JSON string into a Python structure. Then, np.array([...], dtype=float) converts the values into floating-point numbers and adds an additional dimension in order to obtain a two-dimensional matrix. This step is particularly important for Scikit-learn, because Machine Learning models generally expect an input in the form of a matrix [number_of_observations, number_of_features]. The program then performs a validation using np.isnan(input_data).any(). This instruction detects invalid or missing numerical values. If a NaN value is detected, an exception is raised to prevent the model from making a prediction using incorrect data. 

if len(sys.argv) < 2:
    raise Exception(
        "Missing input data from Node.js"
    )

input_data = np.array(
    [json.loads(sys.argv[1])],
    dtype=float
)

if np.isnan(input_data).any():
    raise Exception(
        f"Invalid input received: {input_data}"
    )
Preparation: JSON → Python → NumPy → 2D Array → ML Models
05

Execution of the Three Predictions

Once the data have been prepared, the program executes the three Machine Learning models. The result dictionary contains three properties. The first property, info2_pred, calls the model stored in models["info2"] using the predict(input_data) method. The second property uses models["info3"] and produces info3_pred. Finally, the third property uses models["gomycode"] and produces gomycode_pred. The notation [0] retrieves the first prediction returned by the model, since a Scikit-learn prediction is generally returned as an array. The float() function then converts the result into a standard Python number to facilitate JSON serialization. The program is therefore capable of producing three different results from the same set of input variables. This allows the dashboard to compare predictions from the different models and display them simultaneously to the user. 

result = {

    "info2_pred":
        float(
            models["info2"]
            .predict(input_data)[0]
        ),

    "info3_pred":
        float(
            models["info3"]
            .predict(input_data)[0]
        ),

    "gomycode_pred":
        float(
            models["gomycode"]
            .predict(input_data)[0]
        )
}
06

JSON Result and Error Handling

After executing the models, the program also displays monitoring information in stderr. This separation is important because debug messages are not sent to the standard output used for the JSON response. The program first writes a title indicating the beginning of the results, then iterates through the result dictionary and displays each prediction with four decimal places. The response intended for Node.js is then generated using json.dumps(result) and displayed using print(). Node.js can therefore directly retrieve the JSON string. The prediction process is placed inside a try block. If an error occurs while executing a model, the program enters the except block. It then creates a JSON object containing an error property with the exception message. Finally, sys.exit(1) indicates to the Node.js process that the Python program terminated with an error.

07

Node.js Service and Communication with Python

The infoService.js file acts as the intermediary between the Node.js application and the Python script. Its role is to receive the values coming from the Express route, launch the Python program and retrieve the prediction results. The child_process module provides the spawn() function, which allows Node.js to create an external process. The path module is used to build the path to info.py. The runInfoPrediction(values) function returns a Promise, allowing the Express route to use await and wait until the Python process has completed. The received values are converted into a JSON string using JSON.stringify(values). This step makes it possible to transmit a complete JavaScript array to Python as a single argument. The spawn() function then launches Python with the script path and the JSON string. Node.js listens to stdout to retrieve the response generated by Python. The received data are progressively added to the output variable. At the same time, stderr retrieves possible error messages or debug information. When the Python process finishes, the close event provides the exit code. If this code is different from zero, the service considers that Python encountered an error and rejects the Promise. If the execution is successful, Node.js uses JSON.parse(output) to transform the Python JSON result into a JavaScript object. The resulting object is then passed to the Express route using resolve(result).

Converting Data to JSON 

const inputJson =
    JSON.stringify(values);

JSON.stringify() transforms the JavaScript array into a JSON string. This string can then be passed as an argument to the Python program.

Launching Python 

const py = spawn("python", [
    pyPath,
    inputJson
]);

This instruction launches the Python program and sends it the input data. Node.js therefore acts as a bridge between the Web API and the Machine Learning engine.

Retrieving stdout 

py.stdout.on("data", (data) => {
    output += data.toString();
});

The standard output of the Python program is retrieved progressively and stored in output. This variable ultimately contains the JSON generated by info.py.

Parsing the JSON 

const result = JSON.parse(output);

resolve(result);

JSON.parse() transforms the string produced by Python into a JavaScript object. Node.js can then pass this object to Express.

08

Express Prediction Route

The infoRoute.js file defines the endpoint used by the frontend to request a prediction. Express is imported and a router is created using express.Router(). The runInfoPrediction() service is then imported so that the route can execute the Python model. The route uses the HTTP POST method with the /predict path. When a request arrives, the program retrieves values from req.body. An initial validation checks that this variable exists and is an array using Array.isArray(values). If the data are invalid, the API immediately returns a 400 status with the message Invalid input. When the data are valid, the route calls await runInfoPrediction(values). The server then waits for the Python process to finish and retrieves the three predictions. Express then returns a JSON response containing success: true and data: result. If an error occurs at any stage, the catch block handles the error and returns an HTTP 500 response. This route therefore represents the communication point between the frontend and the Machine Learning system.

Endpoint

POST /info/predict

Data Validation 

const { values } = req.body;

if (!values || !Array.isArray(values)) {

    return res.status(400).json({

}

const result =

Response Sent to the Frontend 

res.json({
    success: true,
    data: result

The frontend therefore receives a JSON structure containing the results of the three models. It can then use this information to display KPI cards, charts, comparison tables or other visualizations in the dashboard.

09

Main Express Server

The main file initializes the Node.js Web application. The Express framework is imported and an application instance is created using express(). The cors() middleware is enabled to allow communication between the frontend and backend when they are running on different origins. The express.json() middleware allows the server to process requests containing JSON data in their body. The server uses port 3000. The infoRoute router is then registered using app.use("/info", ...). This means that all routes defined in the router will be accessible using the /info prefix. Since the router contains a POST /predict route, the final endpoint becomes POST /info/predict. Finally, app.listen() starts the server and displays a message in the console. The backend is therefore accessible to the frontend and can receive the data required for the predictions. 

const express = require("express");
const cors = require("cors");

const app = express();

app.use(cors());
app.use(express.json());

const PORT = 3000;

app.use(
    "/info",
    require("./Routes/infoRoute")
);

app.listen(PORT, () => {

    console.log(
        `Server running on http://localhost:${PORT}`
    );

});

Complete Architecture

The complete architecture of the system operates through a clearly separated communication chain. Everything begins with the frontend or dashboard, which prepares the required variables and sends them to the Express API using an HTTP POST request. Express receives this request at /info/predict and retrieves the values array from req.body. After validation, Express calls the runInfoPrediction() service. The Node.js service transforms the values into JSON using JSON.stringify() and then uses spawn() to launch the info.py program. Python receives the values through sys.argv. The script checks that the data are present, converts them from JSON using json.loads(), and creates a two-dimensional NumPy matrix. The three models INFO2.pkl, INFO3.pkl and gomycode.pkl are loaded when the script starts using pickle.load(). Each model then receives the same input matrix and uses predict() to calculate its own prediction. The three results are grouped into a JSON object. Python writes this result to stdout. Node.js retrieves the output, uses JSON.parse() to convert the JSON into a JavaScript object, and then returns this object to the Express router. Express finally builds the HTTP response containing success: true and data. The frontend can then use the three predictions in its interface. This architecture has the advantage of clearly separating responsibilities: the frontend handles presentation, Express manages the API, Node.js orchestrates communication, Python executes Machine Learning, NumPy prepares the data, and PKL files contain the trained models.

Role of the Technologies

Each technology used in this architecture has a specific role. Python provides the execution environment for Machine Learning. Pickle is used to save and reload trained models from PKL files. NumPy prepares numerical data in a structure compatible with Scikit-learn. JSON provides the data exchange format between Node.js and Python. The sys module allows parameters to be passed to the Python script. Node.js provides the JavaScript backend and orchestrates the system. child_process provides spawn(), which allows Python to be launched. Express is used to create the REST API and manage HTTP routes. CORS allows communication between the frontend and backend. Finally, the files INFO2.pkl, INFO3.pkl and gomycode.pkl contain the already-trained Machine Learning models. The combination of these technologies makes it possible to transform a Data Science model into a service that can be used by a Web application.

For example, a request can send several variables as an array. Express retrieves this array through req.body, validates it, and then passes it to the Node.js service. The service then converts the array into JSON and sends it to the Python program. Python converts the JSON into a NumPy array and passes this array to the three models. The three results are finally grouped into a JSON response.

Conclusion

The INFO system represents a complete integration between Machine Learning and Web development. Three trained models are saved in the INFO2.pkl, INFO3.pkl and gomycode.pkl files. The Python script info.py loads these models using Pickle, retrieves the data sent by Node.js, transforms them into a NumPy array and executes the three predictions using the predict() method. The results are then grouped into a JSON object and transmitted to Node.js through stdout. The infoService.js service uses child_process and spawn() to launch Python and retrieve the results. Express then provides the REST API through the POST /info/predict endpoint. The frontend can therefore communicate only with the API without needing to execute Python directly. This architecture makes it possible to clearly separate the different responsibilities while maintaining simple communication based on JSON. The overall operation can be summarized by the following chain: Data → Express → Node.js → spawn() → Python → NumPy → INFO2/INFO3/GoMyCode → predict() → JSON → Node.js → Express → Dashboard . This organization makes the system modular, understandable and scalable, and allows multiple Data Science models to be integrated into a Web application designed for analysis and decision-making.
