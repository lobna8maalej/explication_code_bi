👕 Vetement ML Dashboard — Technical Documentation

This documentation explains in detail how the VetementDashboard.jsx component works, its communication with the backend using Fetch API, the structure of the vetementSlice.js file, as well as the use of React, Redux Toolkit, Recharts, ScatterChart, Power BI and the Machine Learning system.

The Clothing Dashboard automatically sends data related to a clothing product to the backend.

The data sent are:

  • Prix_C1 = 150
  • Prix_C2 = 180
  • numbers = 15
  • Target = 1

The request is sent using the HTTP POST method to: 

http://localhost:3000/vetement

The backend then processes this data and returns a JSON response. This response is stored in the state variable items.

The returned data are then used to build a Scatter Plot with Recharts.

In parallel, a Power BI report is displayed directly in the Dashboard using an iframe.

1. General Project Overview

The VetementDashboard.jsx component represents the React interface of the Dashboard dedicated to clothing data.

Its purpose is to automatically send data to the backend in order to retrieve a response from the processing and Machine Learning system.

The component then displays the received data as a Scatter Plot.

It also contains a Power BI report integrated through an iframe.

39. Overview of the vetementSlice.js File

The vetementSlice.js file uses Redux Toolkit to define Redux logic dedicated to Clothing data.

It notably contains the asynchronous action: 

fetchVetementData

This action uses Axios to perform a GET request to the backend.

40. Importing Redux Toolkit 

import {
    createSlice,
    createAsyncThunk
} from "@reduxjs/toolkit";

createSlice allows the Redux structure of the Clothing module to be created.

createAsyncThunk allows an asynchronous operation to be handled, in this case retrieving data from the backend.

41. Importing Axios 

import axios from "axios";

Axios is used in the Slice to communicate with the backend.

42. Creating fetchVetementData 

export const fetchVetementData = createAsyncThunk(
    "vetement/fetch",
    async (_, thunkAPI) => {
        ...
    }
);

This function creates an asynchronous Redux action called: 

vetement/fetch

It allows data to be retrieved from the /vetement endpoint.

43. GET Request with Axios 

const res = await axios.get(
    "http://localhost:3000/vetement"
);

Axios sends an HTTP GET request here.

The backend then returns the data available for the Clothing module.

44. Returning res.data 

return res.data;

This instruction returns the data received from the backend to the Redux system.

The response may have a structure such as: 

{
    message: "...",
    size: ...,
    data: [...]
}

The exact structure depends on the response provided by the backend.

45. Error Handling in the Slice 

catch (error) {
    return thunkAPI.rejectWithValue(
        error.response?.data?.error ||
        error.message
    );
}

If Axios encounters an error, the Slice uses rejectWithValue() to send a custom error message to Redux.

The ?. operator checks that the intermediate properties exist before accessing them.

46. Creating the Slice 

const vetementSlice = createSlice({
    name: "vetement",
    initialState: {
        items: null,
        loading: false,
        error: null,
    },
    ...
});

This instruction creates the Redux Slice called vetement.

initialState: {
    items: null,

}
Property Initial Value Role
items null Will contain the retrieved data.

48. extraReducers 

extraReducers: (builder) => {
    builder
        ...
}

extraReducers allows the Slice to react to the different states of the asynchronous action fetchVetementData.

Three main states are handled:

  • pending
  • fulfilled
  • rejected

49. Pending State 

.addCase(
    fetchVetementData.pending,
    (state) => {
        state.loading = true;
        state.error = null;
    }
)

When the request starts, Redux sets: 

loading = true

The previous error is also cleared: 

error = null

50. Fulfilled State 

.addCase(
    fetchVetementData.fulfilled,
    (state, action) => {
        state.loading = false;
        state.items = action.payload;
    }
)

When the request succeeds:

  • loading becomes false
  • items receives the data returned by the asynchronous action. 
Successful request
      ↓
fulfilled
      ↓
loading = false
      ↓
items = action.payload

51. Rejected State 

.addCase(
    fetchVetementData.rejected,
    (state, action) => {
        state.loading = false;
        state.error = action.payload;
    }
)

If the request fails: 

loading = false

and the error message is stored in: 

error = action.payload

54. Important Point: Fetch and Redux Are Not Used Together in This Component

In the provided code, VetementDashboard.jsx directly uses Fetch API with useState.

It does not use useDispatch() or useSelector().

However, the vetementSlice.js file has its own Redux logic with fetchVetementData() and Axios.

Therefore, the two flows must be distinguished:

/vetement

55. Why Is This Distinction Important?

This distinction makes it possible to understand precisely the current architecture of the project.

The Dashboard currently uses local React state: 

const [items, setItems] = useState(null);

while the Redux Slice has its own state: 

{
    items: null,
    loading: false,
    error: null
}

Therefore, there are currently two mechanisms for managing Clothing data.
