✈️ Voyage ML Dashboard — Technical Documentation

This documentation explains in detail how the VoyageDashboard.jsx component and the voyageSlice.js file work, how communication with the backend is handled using Axios, how state is managed with Redux Toolkit, how data is visualized with Recharts, and how Power BI and the Machine Learning system are integrated.

Introduction

The Voyage Dashboard automatically sends data related to travel prices to the backend.

The data sent to the backend are:

  • prix_concurrent_2 = 1900
  • prix_concurrent_agence2 = 2000
  • prix_extra = 50

The request is sent using the HTTP POST method to: 

http://localhost:3000/voyage

The backend then processes the data and returns a JSON response containing, in particular, a prediction.

This response is retrieved by Redux Toolkit and stored in the state of the voyage module.

The prediction value is then used to build a bar chart with Recharts.

At the same time, a Power BI report is directly integrated into the Dashboard using an iframe.

1. General Project Overview

The VoyageDashboard.jsx component represents the React interface of the Dashboard dedicated to the analysis and prediction of travel data.

Its purpose is to automatically send several variables related to travel prices to the backend.

The backend then processes this data according to the logic defined in the Machine Learning system.

The result returned by the backend is retrieved by Redux Toolkit.

The Dashboard then displays the prediction as well as a chart that allows a real value to be compared with the predicted value.

22. Error Handling 

catch (error) {
```

return thunkAPI.rejectWithValue(
error.response?.data?.error ||
error.message
);
}
```

If the request fails, the catch block is executed.

rejectWithValue() allows a custom error message to be transmitted to the Redux Store.

```
```

23. Optional Chaining in Error Handling 

error.response?.data?.error

The ?. operator allows a property to be accessed only if the previous object exists.

This notably prevents an error if error.response does not exist.

If the backend message is not available, the code uses: 

error.message
