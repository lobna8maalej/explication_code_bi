Sistema de predicción Sanitaire

Integración de un modelo de Machine Learning desarrollado en Python en una aplicación Web Node.js / Express con comunicación mediante JSON y conexión a una base de datos MySQL.

01

Descripción general del sistema

El sistema Sanitaire es una arquitectura Web que integra un modelo de Machine Learning con el fin de generar automáticamente una predicción a partir de variables numéricas. El objetivo de esta arquitectura es separar claramente el componente de Inteligencia Artificial del componente de la aplicación Web. El modelo de Machine Learning se desarrolla y entrena en Python y posteriormente se guarda en un archivo denominado CASA.pkl. Este archivo contiene el modelo ya entrenado y permite reutilizar el conocimiento aprendido sin tener que realizar nuevamente la fase de entrenamiento para cada predicción. El script de Python sanitaire.py representa el motor de predicción. Carga el modelo mediante la biblioteca joblib, recupera los valores enviados por Node.js, los convierte en números mediante float(), crea un array de NumPy y utiliza el método predict() del modelo para obtener la predicción. El resultado se convierte posteriormente en un objeto JSON para que pueda ser recuperado fácilmente por el backend de Node.js. En el lado de JavaScript, el servicio sanitaireService.js utiliza el módulo nativo child_process y la función spawn() para ejecutar el programa Python desde Node.js. El servicio pasa el tipo de modelo y los valores numéricos como argumentos al proceso Python. Node.js recupera posteriormente la salida estándar stdout producida por Python y busca la línea que contiene el resultado JSON. Esta línea se analiza mediante JSON.parse(). El router de Express sanitaireRoute.js expone entonces una API que permite al frontend solicitar una predicción. En el ejemplo proporcionado, la ruta llama al servicio utilizando el modelo identificado por "1" y los valores 10 y 20. El resultado se devuelve al frontend en formato JSON con una propiedad message y una propiedad data. Finalmente, el proyecto también contiene un módulo de conexión a MySQL que permite establecer una conexión con la base de datos POWERBI_PREDICTION. La arquitectura completa forma, por tanto, un sistema en el que Python gestiona el procesamiento de Machine Learning, Node.js gestiona la ejecución y la comunicación con Python, Express proporciona la API Web y MySQL puede proporcionar la persistencia de los datos.

02

Script de predicción en Python

El archivo sanitaire.py representa el núcleo del procesamiento de Machine Learning. Su función principal es cargar el modelo CASA.pkl, recuperar las variables transmitidas por Node.js, preparar los datos en formato numérico y ejecutar la predicción. El script comienza importando varias bibliotecas. La función load de joblib se utiliza para volver a cargar el modelo de Machine Learning guardado. La biblioteca NumPy se utiliza para crear el array numérico que se pasa al modelo. El módulo sys proporciona acceso a los argumentos enviados por Node.js, mientras que el módulo os se utiliza para construir una ruta fiable hacia el archivo del modelo. Finalmente, json se utiliza para convertir el resultado de la predicción al formato JSON. El programa determina primero el directorio que contiene el script mediante os.path.dirname(__file__). A continuación, se construye la ruta hacia CASA.pkl utilizando os.path.join(). El modelo se carga mediante load(). Después, el script recupera los argumentos mediante sys.argv[2:]. El segundo argumento y los siguientes corresponden a los valores numéricos, ya que el primer argumento después del script representa el tipo de modelo en esta arquitectura. Los valores se convierten en números decimales mediante map(float, ...). A continuación, se colocan en un array de NumPy utilizando np.array([values]). Esta estructura corresponde al formato esperado por los modelos de Machine Learning de Scikit-learn. El script también muestra varios datos de depuración: los valores recibidos, la forma del array y el número de características esperadas por el modelo mediante model.n_features_in_. Esta información permite verificar que los datos transmitidos por Node.js coinciden con la estructura utilizada durante el entrenamiento. El método model.predict(X) realiza entonces la predicción. Finalmente, el script crea un objeto JSON que contiene el nombre del modelo, la predicción y los valores utilizados. Este objeto se envía mediante print(), permitiendo que Node.js lo recupere a través de stdout.

Importación de las bibliotecas 

from joblib import load
import numpy as np
import sys
import os
import json

joblib se utiliza para cargar el modelo guardado. NumPy se utiliza para crear el array de entrada numérico. sys recupera los argumentos transmitidos por Node.js. os gestiona las rutas de los archivos, mientras que json genera una respuesta estructurada compatible con JavaScript.

Determinación del directorio del modelo 

BASE_DIR = os.path.dirname(__file__)

model = load(
os.path.join(
BASE_DIR,
"CASA.pkl"
)
)

BASE_DIR representa el directorio que contiene el script de Python. os.path.join() construye posteriormente la ruta hacia CASA.pkl. El modelo se carga mediante joblib.load(). Este enfoque evita que la aplicación dependa del directorio desde el cual Node.js ejecuta el programa.

Recuperación de los argumentos 

values = list(
map(float, sys.argv[2:])
)

El programa recupera los argumentos mediante sys.argv[2:]. El primer argumento pasado después del script representa el tipo de modelo, mientras que los siguientes argumentos corresponden a los valores utilizados para la predicción. Cada valor se convierte en un número decimal mediante float() para obtener datos compatibles con el modelo de Machine Learning.

Creación del array NumPy 

X = np.array([values])

Los valores se transforman en un array de NumPy. El uso de corchetes alrededor de values representa los datos como una observación que contiene múltiples características. Esta estructura es compatible con el método predict() utilizado por el modelo.

Validación de los datos 

print("VALUES =", values)
print("SHAPE =", X.shape)
print("FEATURES =", model.n_features_in_)

Estas tres instrucciones se utilizan principalmente para la depuración. La primera muestra los valores recibidos, la segunda muestra las dimensiones del array de NumPy y la tercera muestra el número de características esperadas por el modelo. Esto permite detectar rápidamente una incompatibilidad entre los datos enviados por Node.js y los datos utilizados durante el entrenamiento del modelo.

Ejecución de la predicción 

prediction = model.predict(X)

El método predict() aplica el modelo de Machine Learning a los datos preparados. El modelo utiliza los parámetros aprendidos durante el entrenamiento para calcular el valor predicho.

Creación de la respuesta JSON 

print(json.dumps({
"model": "CASA",
"prediction": float(prediction[0]),
"values": values
}))

El resultado de la predicción se coloca en un objeto que contiene tres elementos: el nombre del modelo, el valor predicho y los valores de entrada. prediction[0] recupera la primera predicción y float() convierte este valor en un número estándar de Python. json.dumps() convierte posteriormente el objeto Python en una cadena JSON. Esta cadena es recuperada por Node.js mediante stdout.

03

Modelo de Machine Learning CASA

El archivo CASA.pkl representa el modelo de Machine Learning utilizado por el sistema Sanitaire. A diferencia de un programa Python que tendría que entrenar el modelo cada vez que se ejecuta, el archivo PKL contiene directamente el modelo ya entrenado. Por lo tanto, el script de Python solo necesita cargar este objeto mediante Joblib y proporcionarle nuevos datos para realizar predicciones. Esta separación entre el entrenamiento y la predicción es importante en una arquitectura profesional, ya que el entrenamiento puede realizarse periódicamente sobre un conjunto de datos completo, mientras que el modelo guardado puede ser utilizado posteriormente por la aplicación Web. La propiedad model.n_features_in_ también permite determinar el número de variables esperadas por el modelo. En el código proporcionado, Node.js envía, por ejemplo, dos valores: 10 y 20. Por lo tanto, el modelo debe ser compatible con esta estructura de entrada. Si el número de variables enviadas no coincide con el número esperado por el modelo, puede producirse un error de dimensiones. La información de depuración mostrada por la aplicación permite verificar esta correspondencia.

Flujo del modelo: Datos de entrada → Array NumPy → CASA.pkl → predict() → Valor predicho
04

Servicio Node.js y comunicación con Python

El archivo sanitaireService.js actúa como puente entre Node.js y Python. Node.js no realiza directamente la predicción de Machine Learning; en su lugar, ejecuta el programa Python utilizando el módulo nativo child_process. La función runPlotPython() devuelve una Promise, lo que permite gestionar el proceso Python de forma asíncrona. La función recibe dos parámetros: modelType y values. El parámetro modelType representa el tipo de modelo que se utilizará, mientras que values contiene las variables numéricas. La función spawn() ejecuta Python con la ruta del script sanitaire.py. El array pasado a spawn contiene la ruta del programa Python, el tipo de modelo y todos los valores convertidos en cadenas mediante values.map(String). Python recibe así los datos como argumentos de línea de comandos. Node.js escucha posteriormente el evento data de stdout para recuperar progresivamente la salida generada por el programa Python. Como Python también muestra información de depuración antes del JSON, el servicio no intenta analizar inmediatamente toda la salida. Cuando el proceso termina, el código utiliza split("\n") para separar las líneas, map(l => l.trim()) para eliminar espacios innecesarios y filter(l => l.startsWith("{")) para buscar las líneas que comienzan con una llave y que, por tanto, pueden corresponder al JSON final. El método pop() recupera entonces la última línea JSON encontrada. Finalmente, JSON.parse() convierte la cadena JSON en un objeto JavaScript. Este objeto puede ser devuelto posteriormente a la ruta de Express. Esta técnica permite que Node.js recupere correctamente el resultado de Python incluso cuando el script también genera información de depuración.

Importación de los módulos 

const { spawn } =
require("child_process");

const path =
require("path");

El módulo child_process proporciona spawn(), que permite iniciar un proceso externo. El módulo path se utiliza para construir de forma fiable la ruta hacia el script Python.

Creación de la ruta de Python 

path.join(
__dirname,
"../../python/sanitaire.py"
)

__dirname representa el directorio del archivo JavaScript actual. La función path.join() permite navegar hasta el directorio Python y localizar sanitaire.py.

Lanzamiento del proceso Python 

const py = spawn("python", [
path.join(
    __dirname,
    "../../python/sanitaire.py"
),
modelType,
...values.map(String)
]);

Esta instrucción inicia Python y transmite los parámetros necesarios. El primer parámetro es la ruta del script, el segundo es el tipo de modelo y los siguientes parámetros corresponden a los valores numéricos. El operador spread ... permite añadir cada valor individualmente al array de argumentos.

Recuperación de stdout 

py.stdout.on("data", (data) => {
output += data.toString();
});

Python utiliza print() para devolver información a Node.js. Node.js recibe estos datos mediante stdout. Los fragmentos recibidos se agregan a la variable output para reconstruir toda la salida de Python.

Gestión de errores 

py.stderr.on("data", (data) => {
error += data.toString();
});

stderr se utiliza para recuperar posibles mensajes de error generados por Python. Esto proporciona a Node.js información adicional cuando se produce un error.

Análisis de la respuesta de Python 

const jsonLine = output
.split("\n")
.map(l => l.trim())
.filter(l => l.startsWith("{"))
.pop();

Esta parte es especialmente importante porque el script Python muestra información de depuración antes de imprimir el JSON. El servicio divide la salida en varias líneas, elimina los espacios innecesarios, conserva las líneas que comienzan con una llave y recupera la última línea coincidente. Esta última línea se considera entonces el resultado JSON final.

Conversión JSON 

resolve(
JSON.parse(jsonLine)
);

JSON.parse() transforma la cadena JSON producida por Python en un objeto JavaScript. resolve() transmite posteriormente este objeto a la función que llamó al servicio.

05

Ruta Express y API Sanitaire

El archivo sanitaireRoute.js representa la capa API del sistema. Se importa Express y se crea un router utilizando express.Router(). A continuación, se importa el servicio sanitaireService para que la ruta pueda ejecutar el programa Python. La ruta GET / se declara como una función asíncrona utilizando la palabra clave async. Cuando se recibe una solicitud, la ruta llama a runPlotPython("1", [10, 20]). El primer argumento representa el tipo de modelo y el array contiene las variables numéricas. La ruta utiliza await para esperar a que finalice la ejecución de Python. Cuando el servicio devuelve el objeto JSON, Express construye una respuesta que contiene message: "OK" y data: result. Esta respuesta puede ser consumida posteriormente por el frontend. Si se produce un error durante la ejecución de Python o durante el análisis del JSON, el bloque catch intercepta el error y devuelve el estado HTTP 500. Esta arquitectura evita que el frontend se comunique directamente con Python. El frontend se comunica únicamente con la API de Express, mientras que Express utiliza el servicio Node.js para ejecutar el modelo Python.

Creación del router 

const express =
require("express");

const router =
express.Router();

Express proporciona las funcionalidades necesarias para crear la API. El router agrupa los endpoints relacionados con el dominio Sanitaire.

Llamada al servicio Python 

const result =
await runPlotPython(
"1",
[10, 20]
);

La ruta solicita al servicio Node.js que ejecute Python utilizando el tipo de modelo "1" y dos variables numéricas. La palabra clave await hace que la ruta espere el resultado antes de continuar.

Respuesta de la API 

res.json({
message: "OK",
data: result
});

Express devuelve una respuesta JSON. La propiedad message indica que la operación se completó correctamente, mientras que data contiene el resultado obtenido desde Python.

Gestión de errores 

catch (err) {

res.status(500).json({
    error: err.toString()
});
}

En caso de error, Express devuelve el estado HTTP 500 junto con una descripción del error. Esto permite al frontend identificar que se ha producido un problema en el backend.

Conexión a MySQL

El proyecto también contiene un módulo dedicado a establecer una conexión con una base de datos MySQL. El archivo sanitaireDb.js utiliza el paquete mysql2/promise, que permite comunicarse con MySQL mediante Promises y, por tanto, utilizar una sintaxis async/await. La configuración contiene la dirección del servidor localhost, el usuario root, una contraseña vacía en el entorno presentado y la base de datos POWERBI_PREDICTION. La función getConnection() crea una nueva conexión utilizando mysql.createConnection() y luego devuelve esta conexión mediante await. Mantener esta lógica en un archivo dedicado permite centralizar la configuración de la base de datos y reutilizar fácilmente la función en diferentes controladores o servicios. En la ruta Sanitaire, la función getConnection puede importarse cuando sea necesario para recuperar o almacenar datos en MySQL. La base de datos puede complementar así el componente de Machine Learning almacenando información requerida por la aplicación, resultados de predicción u otros datos utilizados por el dashboard. 

const mysql =
require("mysql2/promise");

const dbConfig = {

host: "localhost",

user: "root",

password: "",

database:
    "POWERBI_PREDICTION"

};

async function getConnection() {

return await
    mysql.createConnection(
        dbConfig
    );

}

module.exports = {
getConnection
};

El módulo exporta getConnection para que otros archivos del backend puedan utilizarlo. El uso de mysql2/promise simplifica la gestión asíncrona de las conexiones y permite integrar MySQL en la arquitectura Node.js.

Inicio del servidor Express

El archivo principal del servidor inicializa la aplicación Express. La constante express importa el framework y app = express() crea la aplicación. El middleware express.json() permite al servidor procesar datos JSON enviados mediante solicitudes HTTP. El proyecto inicia posteriormente el proceso Python utilizando spawn() y define el directorio de trabajo mediante cwd. La ruta Sanitaire se importa desde sanitaireRoute y se registra utilizando app.use("/sanitaire", sanitaireRoute). Esto significa que los endpoints definidos en el router estarán disponibles bajo el prefijo /sanitaire. Finalmente, app.listen(3000) inicia el servidor HTTP en el puerto 3000. El mensaje mostrado en la consola confirma que la API se ha iniciado. La configuración completa permite, por tanto, acceder al sistema de Machine Learning mediante una API Web Node.js / Express. 

const express =
require("express");

const app =
express();

app.use(
express.json()
);

console.log(
"sanitaire API STARTED"
);

const sanitaireRoute =
require(

app.use(
"/sanitaire",
sanitaireRoute
);

app.listen(
3000,
() => {

    console.log(
        "Server running on port 3000"
    );

}
);

El servidor se convierte así en el punto de entrada de la aplicación Web. El frontend puede llamar a la API utilizando la ruta /sanitaire, después de lo cual Express activa el servicio Node.js que ejecuta Python y recupera la predicción.

Arquitectura completa del sistema

La arquitectura completa se basa en la comunicación entre varias capas. El proceso comienza en el frontend o en el dashboard, que envía una solicitud HTTP a la API de Express. Express recibe la solicitud mediante la ruta Sanitaire y llama a la función runPlotPython() del servicio Node.js. Esta función utiliza spawn() para crear un proceso Python independiente. Python recibe el tipo de modelo y las variables numéricas. El script sanitaire.py carga entonces CASA.pkl utilizando Joblib. Las variables recibidas se convierten en números y luego se transforman en un array de NumPy. El modelo utiliza posteriormente el método predict() para calcular la predicción. Python crea un objeto JSON que contiene el nombre del modelo, la predicción y los valores de entrada. Node.js recupera la salida de Python mediante stdout. Como el script también muestra información de depuración, el servicio busca la última línea que comienza con una llave para identificar el JSON final. JSON.parse() convierte posteriormente esta cadena en un objeto JavaScript. El resultado se devuelve a Express, que crea la respuesta HTTP destinada al frontend. Paralelamente, el módulo MySQL permite al backend establecer una conexión con la base de datos POWERBI_PREDICTION. Esta base de datos puede utilizarse para almacenar la información necesaria para la aplicación o conservar los resultados generados por el sistema. La arquitectura completa separa, por tanto, las responsabilidades: el frontend gestiona la visualización, Express gestiona la API, Node.js gestiona la orquestación, Python gestiona el Machine Learning, Joblib gestiona la carga del modelo, NumPy gestiona la preparación de los datos y MySQL gestiona la persistencia.

Función de las tecnologías

Cada tecnología utilizada en esta arquitectura tiene una responsabilidad específica. Python proporciona el entorno de ejecución para el modelo de Machine Learning. Joblib permite guardar y volver a cargar el modelo desde el archivo CASA.pkl. NumPy prepara las variables numéricas como un array compatible con el modelo. El módulo sys permite transmitir parámetros entre Node.js y Python, mientras que json estructura los resultados. Node.js proporciona el entorno de ejecución del backend JavaScript. El módulo child_process proporciona la función spawn(), que permite ejecutar el script Python. Express proporciona la API REST y organiza las diferentes rutas de la aplicación. JSON se utiliza como formato de intercambio entre Python, Node.js y el frontend. Finalmente, MySQL gestiona los datos persistentes del sistema. Esta combinación permite construir una arquitectura en la que cada tecnología se utiliza para una tarea específica.

Ejemplo práctico del funcionamiento

Para comprender el funcionamiento completo, imagine que el frontend llama a la API Sanitaire. Express recibe la solicitud y ejecuta la función runPlotPython("1", [10, 20]). Node.js ejecuta entonces el programa sanitaire.py utilizando Python. Los parámetros transmitidos son el tipo de modelo 1, seguido de los valores 10 y 20. Python recupera estos parámetros mediante sys.argv. La expresión sys.argv[2:] recupera los dos valores numéricos y los convierte en números decimales. El programa crea entonces X = np.array([values]). El modelo CASA.pkl se carga mediante Joblib y recibe el array a través del método predict(). Python obtiene entonces la predicción y crea un objeto JSON que contiene el modelo CASA, el valor predicho y los valores utilizados. Node.js recupera toda la salida de Python mediante stdout. Como Python también muestra la información de depuración VALUES, SHAPE y FEATURES, el servicio filtra las líneas para recuperar únicamente la última línea JSON. Esta cadena se convierte posteriormente en un objeto JavaScript mediante JSON.parse(). Finalmente, Express recibe este objeto y devuelve una respuesta JSON al frontend. El dashboard puede utilizar entonces la predicción para mostrar un KPI, una tarjeta estadística, un gráfico o una tabla. Este flujo muestra claramente cómo una predicción basada en Python puede integrarse en una aplicación Web Node.js sin necesidad de que el frontend ejecute Python directamente.

Explicación para dar durante una presentación

Durante una presentación profesional, este sistema puede presentarse como una arquitectura de Inteligencia Artificial integrada en una aplicación Web para el ámbito sanitario. El modelo de Machine Learning se entrena previamente y posteriormente se guarda en CASA.pkl. Cuando se solicita una predicción, Node.js utiliza el módulo child_process y la función spawn() para ejecutar el script Python. Python recupera las variables, las convierte en datos numéricos y las prepara utilizando NumPy. A continuación, el modelo CASA se carga mediante Joblib y el método predict() calcula el resultado. La principal ventaja de este enfoque es la clara separación de responsabilidades: Python se especializa en Machine Learning, Node.js coordina la ejecución, Express gestiona las solicitudes HTTP, JSON gestiona el intercambio de resultados y MySQL proporciona la persistencia. Esta organización hace que el sistema sea más modular y permite añadir otros modelos, variables o nuevas funcionalidades al dashboard en el futuro.

Conclusión

El sistema Sanitaire representa una integración completa entre Machine Learning y desarrollo Web. El modelo entrenado se guarda en CASA.pkl y el script Python lo carga mediante Joblib. Las variables recibidas desde Node.js se convierten en números y posteriormente se preparan con NumPy antes de pasarlas al modelo mediante predict(). Python devuelve entonces la información en formato JSON. Node.js utiliza child_process y spawn() para ejecutar el programa Python y recuperar su resultado. El servicio filtra la salida de Python para identificar el JSON final y utiliza posteriormente JSON.parse() para convertir la respuesta en un objeto JavaScript. Express expone después una API accesible desde el frontend. Finalmente, MySQL permite gestionar el almacenamiento de datos mediante la base de datos POWERBI_PREDICTION. El sistema completo forma una cadena tecnológica coherente: Datos → Node.js → spawn() → Python → CASA.pkl → NumPy → predict() → JSON → Express → Dashboard. Esta arquitectura demuestra cómo un modelo de Data Science puede integrarse en una aplicación Web moderna separando claramente las responsabilidades entre Machine Learning, backend, API, base de datos e interfaz de usuario.
