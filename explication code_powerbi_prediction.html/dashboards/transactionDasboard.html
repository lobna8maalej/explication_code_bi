💳 Transaction ML Dashboard — Documentation technique

Cette documentation explique en détail le fonctionnement du composant TransactionDashboard.jsx, sa liaison avec transactionSlice.js, son fichier TransactionDashboard.css, ainsi que l'utilisation de React, Redux Toolkit, Recharts, Power BI et du système de prédiction Machine Learning.

Le Dashboard permet de déclencher une prédiction Machine Learning concernant une transaction de type facture. Une valeur de 18175 TND est envoyée à Redux grâce à l'action createTransaction().

Le résultat de la prédiction est ensuite récupéré depuis Redux et affiché dans une carte KPI. Le Dashboard compare également la valeur prédite avec une valeur fixe correspondant au Compte Global (NCG).

En parallèle, un rapport Power BI est intégré dans l'interface grâce à un élément iframe.

1. Présentation générale du projet

Le composant TransactionDashboard.jsx représente l'interface React d'un Dashboard consacré à l'analyse et à la prédiction de données de transactions.

Il utilise React pour construire l'interface utilisateur.

Il utilise également Redux Toolkit pour déclencher la création d'une transaction et récupérer les données de prédiction.

Le composant utilise aussi la bibliothèque Recharts afin de représenter graphiquement la valeur prédite et la valeur du Compte Global (NCG).

Enfin, un rapport Power BI est intégré directement dans la page grâce à une balise iframe.

const lastTransaction =
  items.length > 0 ? items[items.length - 1] : null;

Cette instruction recherche le dernier élément du tableau items.

Si le tableau est vide, la variable reçoit : 

null

15. Pourquoi récupérer la dernière transaction ?

Le composant souhaite afficher principalement le résultat de la transaction la plus récente.

La variable lastTransaction permet donc d'accéder directement à la dernière transaction disponible.

Elle est ensuite utilisée pour afficher :

  • la valeur de la transaction ;
  • la prédiction ;
  • les données du graphique.

59. Exemple concret du fonctionnement

Lorsque le composant est chargé, il envoie automatiquement : 

{
    mode: "facture",
    value: 18175
}

La demande est transmise à Redux avec : 

dispatch(
  createTransaction({
    mode: "facture",
    value: 18175,
  })
);

Le système traite ensuite cette donnée et retourne une prédiction.

Supposons que le système retourne par exemple : 

prediction = 25000

Le composant récupère cette valeur avec : 

lastTransaction.prediction

puis l'affiche dans la carte : 

25000.00 TND

et l'utilise également dans le graphique.

60. Résumé final à retenir

React construit l'interface → useEffect déclenche automatiquement createTransaction() au chargement → useDispatch envoie l'action à Redux → transactionSlice.js traite la transaction → le système Machine Learning produit une prédiction → Redux met à jour items, loading et error → useSelector récupère ces informations → lastTransaction récupère la dernière transaction → chartData prépare les données du graphique → la carte KPI affiche la valeur et la prédiction → Recharts représente la prédiction et le Compte Global NCG sous forme de graphique en barres → Power BI affiche le rapport analytique → TransactionDashboard.css assure la présentation visuelle.

Le composant TransactionDashboard.jsx constitue donc l'interface utilisateur du système de prédiction des transactions.

Contrairement à un Dashboard qui demande à l'utilisateur de saisir manuellement plusieurs variables, ce composant déclenche automatiquement une transaction lors de son chargement grâce au Hook useEffect.

La transaction envoyée à Redux contient le mode "facture" et une valeur de 18175.

La fonction dispatch() transmet cette demande à createTransaction(), provenant de transactionSlice.js.

Redux gère ensuite l'état de l'opération à travers items, loading et error.

Lorsque les données sont disponibles, le composant récupère la dernière transaction grâce à : 

items[items.length - 1]

Cette dernière transaction permet d'obtenir la valeur prédite avec : 

lastTransaction.prediction

La prédiction est affichée dans une carte KPI et formatée avec deux chiffres après la virgule grâce à toFixed(2).

Les données sont ensuite préparées dans chartData afin d'être utilisées par Recharts.

En parallèle, le rapport Power BI est intégré grâce à une iframe.

Enfin, TransactionDashboard.css contrôle l'apparence visuelle du Dashboard.
