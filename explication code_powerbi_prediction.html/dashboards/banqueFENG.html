📊 Frontend Documentation

React • Redux Toolkit • Axios • Power BI • Recharts

1 — General Overview of the Frontend System

In this part of the project, we developed the Frontend of the application using React and Redux Toolkit in order to manage the display of the banking dashboard, communicate with the Backend and automatically retrieve the result of a prediction. The Frontend acts as an interface between the user and the data processing system. The user accesses a page called Banque that displays a Power BI dashboard as well as a prediction result generated by the Backend. To properly organize communication between the different components, we used Redux Toolkit. Redux makes it possible to centralize and manage the application state, while createAsyncThunk is used to manage an asynchronous operation, in our case sending an HTTP request to the Backend. To perform this HTTP communication, we use Axios. When the React component is loaded, the useEffect() function automatically triggers the Redux action createBanquePrediction by sending the values x1: 10 and x2: 2. Redux then sends a POST request to http://localhost:3000/banque. The Backend receives this data, performs the processing or prediction and returns a response. This response is then stored in the Redux store through the predictionData state. The React component then retrieves the data using useSelector() and automatically updates the interface. The system also manages three important situations: loading with loading, success with fulfilled and error with rejected. When the prediction is available, the component displays its value in a result card and also creates a chart with Recharts to compare the X1, X2 and prediction values. At the same time, a Power BI report is integrated into the page using an HTML iframe element. We therefore have a Frontend architecture in which React handles the user interface, Redux Toolkit manages the state and asynchronous operations, Axios handles communication with the Backend, Power BI displays the decision-support dashboard and Recharts graphically represents the prediction result.

2 — Redux Toolkit and State Management

The first file corresponds to the Redux Slice dedicated to banking prediction. Redux Toolkit is used to simplify global state management in the application. The first line import { createSlice, createAsyncThunk } from "@reduxjs/toolkit"; allows us to import two important features. createSlice is used to create a part of the Redux store called banque here, while createAsyncThunk is used to create an asynchronous action intended to communicate with the Backend. The line import axios from "axios"; imports Axios, a library used to perform HTTP requests. In our application, Axios is used to send prediction data to the server. The principle is therefore to separate the communication logic with the Backend from the display logic of the React component. This makes the application more organized and easier to maintain. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

3 — createAsyncThunk Function

The createBanquePrediction function is created with createAsyncThunk. Its role is to perform an asynchronous operation that sends data to the Backend. The first argument "banque/create" represents the Redux action name. The second argument is an asynchronous function that receives the data in the data parameter. The function then uses axios.post() to send an HTTP POST request to http://localhost:3000/banque. The word data represents the data sent by the React component. In our example, this data consists of x1: 10 and x2: 2. The server therefore receives these two values and can use them to perform the prediction. The await keyword makes it possible to wait for the server response before continuing execution. Once the response is received, res.data is used to retrieve only the data returned by the Backend. The function then returns this data with return res.data. Redux Toolkit will automatically pass this response to the reducer corresponding to the fulfilled state. If an error occurs during the Axios request, the catch statement intercepts the error. We then use rejectWithValue() to pass the error to the Redux reducer. The expression err.response?.data makes it possible to retrieve the message sent by the server when a response exists. The symbol ?. corresponds to optional chaining and prevents an error if response does not exist. If no error information from the server is available, the message "Erreur serveur" is used. This function therefore acts as the bridge between the Redux Frontend and the Backend. 

export const createBanquePrediction = createAsyncThunk(
  "banque/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/banque",
        data
      );

      return res.data;

    } catch (err) {

      return rejectWithValue(
        err.response?.data || "Erreur serveur"
      );

    }
  }
);

4 — Creating banqueSlice and Initial State

After creating the asynchronous action, we create the banqueSlice using createSlice(). This Slice represents the part of the Redux store dedicated to the banking functionality. The property name: "banque" gives a name to this part of the state. The initialState property defines the initial state of this functionality. We have three main pieces of information. The first is predictionData: null, which means that no prediction is available yet at startup. The second is loading: false, which indicates that no request is currently in progress at the initial moment. The third is error: null, which indicates that no error has yet been encountered. This organization allows the React component to know precisely what situation the request is in: waiting, loading, success or error. 

const banqueSlice = createSlice({
  name: "banque",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

5 — Managing the pending State

When createBanquePrediction is executed and the request to the Backend begins, Redux Toolkit automatically triggers the pending state. The code .addCase(createBanquePrediction.pending, (state) => { ... }) defines what should happen during loading. We then set state.loading = true. The React component can therefore know that a request is in progress and display the message Loading prediction.... We also reset state.error = null in order to remove a possible previous error. This management makes it possible to have a dynamic interface and inform the user that the system is currently retrieving the prediction. 

.addCase(createBanquePrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

6 — Managing the fulfilled State

When the Axios request is completed successfully and the Backend returns a correct response, Redux Toolkit triggers the fulfilled state. The code .addCase(createBanquePrediction.fulfilled, (state, action) => { ... }) then retrieves the server response in action.payload. We set state.loading = false because the request is finished. Then, state.predictionData = action.payload stores the prediction result in the Redux store. This data then becomes available to React components that use useSelector(). The process is therefore very important: the Backend produces the result, Redux stores it in its global state and React automatically retrieves this new value in order to update the display. 

.addCase(createBanquePrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

7 — Managing the rejected State

If the request fails, for example if the Backend is stopped, if the URL is incorrect or if the server returns an error, Redux Toolkit triggers the rejected state. The code .addCase(createBanquePrediction.rejected, (state, action) => { ... }) manages this situation. We set state.loading = false because the request is finished even though it failed. Then, state.error = action.payload retrieves the error message passed by rejectWithValue(). The React component can then read this state and display an error message to the user. This organization prevents the user from being left without information when communication with the server fails. 

.addCase(createBanquePrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

8 — Complete Redux Cycle

The complete operation of Redux Toolkit can be summarized as follows: the React component triggers dispatch(createBanquePrediction(...)). Redux Toolkit then launches the asynchronous action. As soon as the request begins, the pending state is triggered and loading becomes true. Axios then sends the data to the Backend. If the Backend correctly returns the prediction, the fulfilled state is triggered and the result is stored in predictionData. If the request fails, the rejected state is triggered and the error is stored in error. React observes changes in the store through useSelector() and automatically updates the interface. This architecture therefore makes it possible to properly manage asynchronous operations without placing all the logic directly inside the React component.

Data Flow:

React → dispatch() → Redux Toolkit → createAsyncThunk → Axios → Backend → Prediction → Redux Store → useSelector() → React Interface

9 — Banque React Component

The second file corresponds to the React component called Banque. Its role is to build the user interface of the banking dashboard and retrieve the prediction data stored in Redux. The first line import React, { useEffect } from "react"; imports React as well as the useEffect Hook. Then, useDispatch and useSelector are imported from react-redux. useDispatch() allows the component to send a Redux action, while useSelector() allows it to read information from the Redux store. The CSS file Banque.css is also imported to manage the page styling. Finally, several Recharts components are imported to build the chart: BarChart, Bar, XAxis, YAxis, Tooltip, CartesianGrid, ResponsiveContainer and Legend. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { createBanquePrediction } from "../redux/banqueSlice";
import "./Banque.css";

10 — useDispatch

In the Banque component, we use const dispatch = useDispatch(). The useDispatch() Hook provides the dispatch function, which is used to send actions to Redux. Through this function, the React component can ask Redux to execute the banking prediction. Without dispatch, the component could not directly trigger our createBanquePrediction action. The role of dispatch is therefore to transmit an action from the React component to the Redux system. 

const dispatch = useDispatch();

11 — useSelector and Retrieving the Redux State

The useSelector() Hook allows the React component to retrieve data stored in the Redux store. In our code, we retrieve three pieces of information. The first is predictionData, which contains the result returned by the Backend. The second is loading, which indicates whether the request is in progress. The third is error, which may contain an error message. The expression state.banque?.predictionData means that we are looking for the predictionData property in the banque part of the store. The ?. symbol prevents an error if the banque object temporarily does not exist. Thanks to useSelector(), when Redux modifies this information, React detects the change and automatically updates the component. 

const predictionData = useSelector(
  (state) => state.banque?.predictionData
);

const loading = useSelector(
  (state) => state.banque?.loading
);

const error = useSelector(
  (state) => state.banque?.error
);

12 — useEffect and Automatic Prediction Launch

The useEffect() Hook is used to automatically execute an operation when the component is loaded. In our code, we use dispatch(createBanquePrediction({ x1: 10, x2: 2 })). This means that when the Banque page is displayed, the component automatically sends a Redux action to request a prediction from the Backend. The values sent are x1: 10 and x2: 2. The dependency array contains dispatch. In this context, the effect is executed when the component is mounted. This approach therefore makes it possible to automatically launch the prediction without requiring the user to click a button. The process is then: component display, execution of useEffect(), call to dispatch(), launch of createBanquePrediction, Axios request to the Backend, reception of the response and update of Redux. 

useEffect(() => {
  dispatch(
    createBanquePrediction({
      x1: 10,
      x2: 2,
    })
  );
}, [dispatch]);

13 — Preparing the Chart Data

After retrieving the result from Redux, the component creates a new variable called chartData. This variable is intended for Recharts. The conditional expression predictionData ? [...] : [] means that if a prediction exists, we create an array containing the chart data. Otherwise, we create an empty array. The object contains a name property with the value "Banque", followed by the values X1, X2 and Prediction. For X1, we use predictionData.x1 || 0. This means that if the X1 value exists, it is used; otherwise, the value 0 is used. The same principle is applied to X2 and the prediction. This step therefore transforms the data received from the Backend into a structure that can be directly used by the Recharts chart. 

const chartData = predictionData
  ? [
      {
        name: "Banque",
        X1: predictionData.x1 || 0,
        X2: predictionData.x2 || 0,
        Prediction:
          predictionData.prediction || 0,
      },
    ]
  : [];

14 — Power BI Dashboard Integration

The React component also integrates a Power BI report using an HTML iframe element. The objective is to display a decision-support dashboard created with Power BI directly inside our Web application. The powerbi-frame class makes it possible to apply the style defined in Banque.css. The title="BANQUE" property gives a title to the integrated element. The src property contains the address of the published Power BI report. The frameBorder="0" property removes the iframe border and allowFullScreen allows full-screen display. This integration therefore makes it possible to bring together two dimensions of the project on the same page: on the one hand, the Power BI decision-support dashboard and, on the other hand, the prediction dynamically generated by the Backend and displayed by React. 

<div className="powerbi-container">

  <iframe
    className="powerbi-frame"
    title="BANQUE"
    src="https://app.powerbi.com/view?..."
    frameBorder="0"
    allowFullScreen
  />

</div>

15 — Displaying the Loading State

The component uses the loading variable from Redux to inform the user when a prediction is in progress. The condition {loading && (...)} means that the paragraph is displayed only when loading is true. The displayed message is Loading prediction.... This corresponds to the pending state defined in the Redux Slice. There is therefore a direct relationship between the Backend, Redux and the interface: when the request starts, Redux activates loading and React displays the loading message. 

{loading && (
  <p className="loading">
    Loading prediction...
  </p>
)}

16 — Displaying Errors

The component also provides for the possibility that an error may occur. The condition {error && (...)} means that the error message is displayed only when an error exists in the Redux store. This error may come from Axios, the Backend or a communication problem with the server. The value of error was stored in Redux when the rejected state was triggered. React therefore retrieves this value using useSelector() and displays it to the user in a paragraph with the CSS class error. 

{error && (
  <p className="error">
    {error}
  </p>
)}

17 — Waiting State

The component also provides for a situation in which no prediction is available and no request is currently in progress. The condition !loading && !error && !predictionData checks three elements: loading is finished, no error exists and no prediction data is available yet. In this situation, the application displays the message Waiting for prediction result.... This makes it possible to properly manage the initial state of the page before the prediction result is received. 

{!loading &&
  !error &&
  !predictionData && (
    <p className="waiting">
      ⏳ Waiting for prediction result...
    </p>
)}

18 — Displaying the Prediction Result

When predictionData exists, the component displays a card containing the prediction result. The condition {predictionData && (...)} renders this part of the interface only when the data is available. The title 📌 Result clearly indicates to the user that this is the result produced by the model. The displayed value uses predictionData.prediction?.toFixed(2). The prediction property corresponds to the result sent by the Backend. The toFixed(2) function displays the number with two digits after the decimal point. The ?. symbol checks that the property exists before calling the method. This card therefore represents the main part of the predictive result display. 

{predictionData && (
  <div className="prediction-card">

    <h2 className="prediction-title">
      📌 Result
    </h2>

    <div className="prediction-value">
      {predictionData.prediction?.toFixed(2)}
    </div>

  </div>
)}

19 — Creating the Chart with Recharts

After displaying the numerical value, the component creates a chart using the Recharts library. The objective is to visually present the X1, X2 and Prediction values. The ResponsiveContainer component allows the chart to automatically adapt to the available width. The width="100%" property indicates that the chart uses the full width of its container and height={350} defines a height of 350 pixels. The BarChart component receives the data through data={chartData}. The CartesianGrid component displays a grid that makes the chart easier to read. XAxis defines the horizontal axis and uses dataKey="name" to display the category name, here Banque. YAxis represents the vertical axis containing the numerical values. Tooltip displays information when the user places the mouse over a bar. Legend displays the legend for the different series. Finally, three Bar components respectively represent X1, X2 and Prediction. Each bar uses a different data key through dataKey. The chart therefore provides a visual and comparative representation of the data used for the prediction and the result obtained. 

<ResponsiveContainer
  width="100%"
  height={350}

  <BarChart data={chartData}>

      dataKey="X1"

      dataKey="X2"

</ResponsiveContainer>

20 — Complete Frontend Architecture

The two Redux and React files work together according to an organized architecture. The Banque component represents the visual part. When it is loaded, useEffect() calls dispatch() with the createBanquePrediction action. This action is defined in banqueSlice.js using createAsyncThunk. Redux Toolkit then starts an Axios request to the Backend with the X1 and X2 values. During this communication, Redux enters the pending state and the loading variable becomes true. When the Backend returns a correct response, Redux enters the fulfilled state and places the response in predictionData. The React component retrieves this data using useSelector(). React automatically detects the state change and updates the interface. The result is then displayed in the prediction card and the data is prepared in chartData to build the Recharts chart. If an error occurs during communication, Redux enters the rejected state, stores the error in error and React displays the corresponding message. At the same time, the Power BI iframe displays the decision-support dashboard. We therefore have a clear separation between presentation, state management, server communication and data visualization.

21 — Role of Redux and Role of React

In this architecture, React and Redux have different but complementary responsibilities. React is mainly responsible for the user interface: it builds the page, displays the Power BI dashboard, displays the prediction result and creates the chart. Redux Toolkit is responsible for state management and communication with the Backend. The Redux Slice contains the information predictionData, loading and error. createAsyncThunk manages the asynchronous operation and Axios communicates with the server. React then uses useSelector() to read the Redux state and useDispatch() to send actions. This separation makes the code cleaner because the data retrieval logic is not completely mixed with the display code. React therefore mainly focuses on presenting information, while Redux organizes its flow and state within the application.

22 — Managing the Three Request States

An important element of this architecture is the management of the three states automatically generated by createAsyncThunk. The first state is pending: it corresponds to the moment when the request is in progress and allows a loading indicator to be displayed. The second state is fulfilled: it corresponds to a successful request and allows the response to be stored in predictionData. The third state is rejected: it corresponds to a failed request and allows the problem to be stored in error. Thanks to these three states, the React interface can automatically react to changes in communication with the Backend. The user therefore knows whether the system is working, whether the prediction is available or whether an error has occurred.

pending → Request in progress → loading = true

fulfilled → Successful request → predictionData = result

rejected → Failed request → error = message

23 — Conclusion

To conclude, these two files constitute an essential part of the Frontend of our banking prediction application. The Redux file uses Redux Toolkit to centralize the state of the banking functionality and manage asynchronous communication with the Backend through createAsyncThunk and Axios. The initial state contains the information necessary to know the prediction result, the loading state and any possible errors. The three states pending, fulfilled and rejected make it possible to automatically manage the different stages of the request. The React component Banque then uses useDispatch() to trigger the Redux action and useSelector() to retrieve information from the store. The useEffect() Hook allows the prediction to be automatically launched when the component is loaded. Once the result is received, React displays the prediction value in a card and uses Recharts to create a graphical representation comparing X1, X2 and the prediction. The component also integrates a Power BI dashboard through an iframe in order to bring decision-support analysis and predictive analysis together in the same interface. The final architecture is therefore based on communication between React, Redux Toolkit, Axios, the Backend, the prediction model, Power BI and Recharts. This organization makes it possible to build a dynamic and structured Frontend application capable of presenting the user with both decision-support data and predictive results.
