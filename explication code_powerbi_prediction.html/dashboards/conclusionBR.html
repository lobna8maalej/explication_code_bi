🌐 Web Dashboard — Documentação técnica

Esta documentação explica detalhadamente como funcionam a aplicação React, o React Router, o Redux Toolkit, o cadastro e o login de usuários, a proteção de rotas privadas e o Footer.

Introdução

Esta parte do projeto fornece a estrutura geral da aplicação Web.

Ela gerencia várias funcionalidades importantes:

  • navegação entre as diferentes páginas;
  • cadastro de usuários;
  • login de usuários;
  • gerenciamento de usuários com Redux Toolkit;
  • armazenamento do token de autenticação;
  • proteção do Dashboard;
  • exibição das informações de contato;
  • apresentação de informações relacionadas ao pagamento por transferência bancária.

18. Introdução ao userSlice.js

O arquivo userSlice.js gerencia o cadastro de usuários, o login, o token, o usuário autenticado e o logout.

Ele utiliza principalmente:

  • Redux Toolkit;
  • createAsyncThunk;
  • Axios;
  • localStorage.

19. Importação do Redux Toolkit 

import {
    createSlice,
    createAsyncThunk
} from "@reduxjs/toolkit";

createSlice é utilizado para criar um Redux Slice que contém o estado inicial, os reducers e as ações associadas.

createAsyncThunk é utilizado para gerenciar operações assíncronas, como requisições HTTP.

33. Criação do logout 

reducers: {
    logout: (state) => {
        state.user = null;
        state.token = null;
        state.error = null;

        localStorage.removeItem("token");
        localStorage.removeItem("user");
    }
}

A ação logout permite que o usuário encerre a sessão.

Ela também remove os dados de autenticação armazenados no navegador.

35. RegisterUser.fulfilled 

.addCase(
    RegisterUser.fulfilled,
    (state, action) => {
        state.user =
            action.payload.user;

        state.token =
            action.payload.token;

        state.error = null;
    }
)

Quando o registro é realizado com sucesso, o Redux recupera a resposta enviada pelo backend.

O usuário é armazenado em: 

state.user

O token é armazenado em: 

state.token

36. Salvando os dados no localStorage 

localStorage.setItem(
    "user",
    JSON.stringify(
        action.payload.user
    )
);

localStorage.setItem(
    "token",
    action.payload.token
);

As informações também são salvas no navegador.

Isso permite que a aplicação recupere o usuário e o token quando a página for carregada novamente.

37. RegisterUser.rejected 

.addCase(
    RegisterUser.rejected,
    (state, action) => {
        state.error =
            action.payload;
    }
)

Se o cadastro falhar, o Redux armazena o erro em: 

state.error

38. LoginUser.fulfilled 

.addCase(
    LoginUser.fulfilled,
    (state, action) => {

        state.user =
            action.payload.user;

        state.token =
            action.payload.token;

        state.error = null;

        localStorage.setItem(
            "user",
            JSON.stringify(
                action.payload.user
            )
        );

        localStorage.setItem(
            "token",
            action.payload.token
        );
    }
)

Quando o login é realizado com sucesso, o Redux recupera o usuário e o token retornados pelo backend.

Essas informações são então armazenadas tanto no Redux quanto no localStorage.

39. LoginUser.rejected 

.addCase(
    LoginUser.rejected,
    (state, action) => {
        state.error =
            action.payload;
    }
)

Se o login falhar, a mensagem de erro ou os dados do erro são armazenados em state.error.

63. Introdução ao PrivateRoute.jsx

PrivateRoute.jsx é utilizado para proteger parte da aplicação.

Seu objetivo é verificar se o usuário possui as informações necessárias para acessar uma rota protegida.

64. Importando Navigate 

import {
    Navigate
} from "react-router-dom";

Navigate permite que o usuário seja redirecionado automaticamente para outra rota.

65. Recuperando user 

const user =
    useSelector(
        (state) =>
            state.users.user
    );

Esta instrução recupera o usuário armazenado no Redux.

66. Recuperando o token 

const token =
    useSelector(
        (state) =>
            state.users.token
    );

Esta instrução recupera o token de autenticação do Redux.

67. Verificando o localStorage 

const storedUser =
    localStorage.getItem("user");

O componente também verifica se um usuário está armazenado no navegador.

68. Condição de proteção 

if (
    !user &&
    !token &&
    !storedUser
) {
    return (
        <Navigate
            to="/login"
            replace
        />
    );
}

Esta condição verifica três elementos:

  • o usuário armazenado no Redux;
  • o token armazenado no Redux;
  • o usuário salvo no localStorage.

Se esses três elementos estiverem ausentes, o usuário será considerado não autenticado e será redirecionado para a página de Login.

69. Redirecionando para Login 

<Navigate
    to="/login"
    replace
/>

O usuário não autenticado é redirecionado para: 

/login

A propriedade replace substitui a entrada atual no histórico de navegação em vez de adicionar uma nova entrada.

70. Autorização de acesso 

return children;

Se a condição de bloqueio não for satisfeita, o componente retorna children.

Isso significa que o usuário está autorizado a acessar o conteúdo protegido.

O Footer pode servir como um ponto de informação para um cliente que deseja pagar pelo trabalho realizado. 

Pessoa interessada
        ↓

        ↓

        ↓

        ↓

        ↓

        ↓
Informações bancárias fornecidas
        ↓

No entanto, para um site público, é preferível não exibir os dados bancários completos diretamente no código-fonte ou em uma publicação acessível a todos.

As informações bancárias estão disponíveis
mediante solicitação após a validação do projeto.

Os dados bancários completos podem então ser fornecidos diretamente ao cliente por e-mail ou por outro método privado.

87. Papel do localStorage

O localStorage permite que determinadas informações sejam armazenadas no navegador.

No seu projeto, ele é utilizado para armazenar:

  • as informações do usuário;
  • o token de autenticação.

Isso permite que a aplicação recupere essas informações após o recarregamento da página.

89. Segurança e informações bancárias

O Footer pode informar aos visitantes que o pagamento por transferência bancária está disponível.

No entanto, as informações bancárias completas não devem ser expostas publicamente no código-fonte de um portfólio ou em uma publicação do LinkedIn.

Uma abordagem melhor é exibir informações gerais: 

Pagamento por transferência bancária

As informações bancárias estão disponíveis
mediante solicitação após a confirmação do projeto.

Após chegar a um acordo com o cliente, os dados bancários podem ser comunicados diretamente por meio de um método privado.
