📊 Kantra ML Dashboard — Documentación técnica

Esta documentación explica en detalle cómo funcionan el kantraSlice.js, el componente PredictionForm.jsx y su conexión con el archivo kantra.css.

La arquitectura utiliza React, Redux Toolkit, Axios, Recharts, Power BI y un backend responsable de realizar las predicciones mediante Machine Learning.

1. Descripción general del proyecto

El componente PredictionForm.jsx es la interfaz de usuario del Dashboard de Machine Learning dedicado a Kantra.

Permite al usuario introducir dos valores, A y B, y posteriormente iniciar una predicción.

La predicción se envía al backend mediante Redux Toolkit y Axios. Una vez recibido el resultado, este se añade a un historial.

A continuación, el componente muestra los últimos valores introducidos, la predicción obtenida y un gráfico que representa el historial de predicciones.

El Dashboard también contiene un informe de Power BI integrado mediante un elemento iframe.

PredictionForm.jsx ↓ El usuario introduce A y B ↓ handlePredict() ↓ dispatch(fetchPrediction({ a, b })) ↓ kantraSlice.js ↓ Axios POST /kantra ↓ Backend ↓ Machine Learning ↓ Resultado ↓ Historial de Redux ↓ PredictionForm.jsx ↓ KPI + gráfico ↓ kantra.css ↓ Interfaz final

3. Imports en kantraSlice.js

El archivo kantraSlice.js comienza importando dos funciones importantes de Redux Toolkit: createSlice y createAsyncThunk. 

import {
createSlice,
createAsyncThunk
} from "@reduxjs/toolkit";

createSlice se utiliza para crear una sección del store de Redux con su estado inicial y sus reducers.

createAsyncThunk se utiliza para gestionar una operación asíncrona, en este caso la solicitud de predicción al backend.

El archivo también importa Axios: 

import axios from "axios";

Axios se utiliza para realizar la solicitud HTTP POST al backend.

4. Creación de fetchPrediction

La función fetchPrediction se crea utilizando createAsyncThunk. 

export const fetchPrediction = createAsyncThunk(
"kantra/fetchPrediction",
async ({ a, b }, { rejectWithValue }) => {
    ...
}
);

El primer argumento: 

"kantra/fetchPrediction"

corresponde al identificador de la acción de Redux.

La función asíncrona recibe un objeto que contiene dos parámetros: a y b.

Estos dos valores corresponden a los datos introducidos por el usuario.

5. Solicitud Axios al backend

Dentro de fetchPrediction, Axios envía una solicitud POST: 

const res = await axios.post(
"http://localhost:3000/kantra",
{ a, b }
);

La URL utilizada es: 

http://localhost:3000/kantra

Por lo tanto, el backend recibe un objeto que contiene: 

{
a,
b
}

El servidor puede utilizar estos dos valores para realizar la predicción mediante el modelo de Machine Learning.

6. Conservación de los valores de entrada

Después de recibir la respuesta del backend, el código devuelve: 

return {
...res.data,
a,
b
};

El operador ... recupera las propiedades contenidas en res.data.

El código también añade los valores originales a y b.

Esto permite conservar tanto los valores de entrada como la predicción obtenida en Redux.

Ejemplo: 
{
a: 100,
b: 200,
prediction: 350.25
}

De esta manera, el historial puede identificar qué valores produjeron cada predicción.

7. Gestión de errores en fetchPrediction

La solicitud Axios se encuentra dentro de un bloque try/catch. 

try {
...
} catch (err) {
return rejectWithValue(
err.response?.data || "Error del servidor"
);
}

Si el backend devuelve un error, el código obtiene err.response.data cuando está disponible.

Si no hay ninguna respuesta disponible, se utiliza el mensaje "Error del servidor".

rejectWithValue permite entonces pasar este error al reducer rejected.

8. Creación de kantraSlice

A continuación, el código crea el slice de Redux: 

const kantraSlice = createSlice({
name: "kantra",
...
});

La propiedad: 

name: "kantra"

identifica esta sección del store de Redux.

Por lo tanto, el componente React puede acceder a este estado mediante: 

s.kantra

9. initialState

El estado inicial del slice es: 

initialState: {
history: [],
loading: false,
error: null,
}

Contiene tres propiedades.

  • history: contiene el historial de predicciones.
  • loading: indica si una predicción está siendo procesada actualmente.
  • error: contiene un posible error.

10. El reducer resetKantra

El slice contiene un reducer llamado resetKantra. 

reducers: {
resetKantra: (state) => {
    state.history = [];
},
},

Su función es borrar completamente el historial de predicciones.

Cuando se ejecuta esta acción, el array history vuelve a estar vacío.

11. fetchPrediction.pending

Cuando el usuario inicia una predicción, createAsyncThunk activa primero el estado pending. 

.addCase(fetchPrediction.pending, (state) => {
state.loading = true;
state.error = null;
})

loading pasa a ser true.

El error anterior también se elimina mediante: 

state.error = null;

12. fetchPrediction.fulfilled

Cuando el backend devuelve correctamente una predicción, Redux pasa al estado fulfilled. 

.addCase(fetchPrediction.fulfilled, (state, action) => {
state.loading = false;

state.history.unshift({
    a: action.payload.a,
    b: action.payload.b,
    prediction: action.payload.prediction,
    time: new Date().toLocaleTimeString(),
});
})

La carga se detiene: 

state.loading = false;

Después, se añade un nuevo objeto al principio de history utilizando: 

state.history.unshift(...)

Por lo tanto, el uso de unshift() coloca la nueva predicción en la primera posición.

13. Contenido del historial

Cada elemento del historial contiene cuatro datos: 

{
a: action.payload.a,
b: action.payload.b,
prediction: action.payload.prediction,
time: new Date().toLocaleTimeString()
}
Propiedad Significado
a Primer valor de entrada.
b Segundo valor de entrada.
prediction Resultado producido por el modelo.
time Hora en la que se realizó la predicción.

14. fetchPrediction.rejected

Si la solicitud falla, Redux pasa al estado rejected. 

.addCase(fetchPrediction.rejected, (state, action) => {
state.loading = false;
state.error = action.payload;
})

La carga se detiene y el error se almacena en: 

state.error

El componente React puede recuperar este error mediante useSelector.

15. Exportación del reducer

Al final del archivo, el reducer se exporta: 

export default kantraSlice.reducer;

A continuación, puede integrarse en el store de Redux de la aplicación.

La acción resetKantra también se exporta: 

export {
resetKantra
};

23. Gestión de los campos A y B

Se crean dos estados locales: 

const [a, setA] = useState("");
const [b, setB] = useState("");

a contiene el valor introducido en el primer campo.

b contiene el valor introducido en el segundo campo.

Las funciones setA y setB permiten modificar estos valores.

24. Función handlePredict

La función handlePredict se ejecuta cuando el usuario hace clic en el botón Predict. 

const handlePredict = () => {
if (!a || !b) return;

dispatch(
    fetchPrediction({
        a: Number(a),
        b: Number(b)
    })
);
};

La primera condición: 

if (!a || !b) return;

evita que se envíe la solicitud si falta uno de los dos valores.

A continuación, Number(a) y Number(b) convierten los valores introducidos en números.

Después, la acción de Redux se envía mediante: 

dispatch(fetchPrediction({
a: Number(a),
b: Number(b)
}));

25. Recuperación de la última predicción

const last = history[0];

Como kantraSlice.js utiliza unshift(), la predicción más reciente se coloca en la primera posición del array.

Por lo tanto, history[0] corresponde a la última predicción.

26. Preparación de los datos del gráfico

const chartData = history
.slice(0, 10)
.map((h, i) => ({
    name: `P${i + 1}`,
    prediction: h.prediction,
}));

El método slice(0, 10) limita la visualización a las diez últimas predicciones.

El método map() transforma cada elemento del historial en un objeto adecuado para Recharts.

El nombre se crea mediante: 

name: `P${i + 1}`

Por lo tanto, las predicciones se identificarán como P1, P2, P3, etc.

El valor utilizado por la barra es: 

prediction: h.prediction

45. Relación entre Redux y CSS

Redux no se comunica directamente con CSS.

Redux gestiona los datos y el estado. React recupera esta información y decide qué elementos deben mostrarse. Finalmente, las clases CSS determinan su apariencia.

Redux ↓ history / loading / error ↓ PredictionForm.jsx ↓ JSX + className ↓ kantra.css ↓ Interfaz visual

50. Resumen final para recordar

React construye la interfaz → Redux Toolkit gestiona el estado → Axios se comunica con el backend → Machine Learning produce la predicción → Redux almacena el historial → Recharts visualiza los resultados → Power BI muestra el informe → CSS controla la presentación.

El archivo kantraSlice.js es responsable de la lógica de Redux. Define la acción asíncrona fetchPrediction, se comunica con el backend mediante Axios y gestiona los estados pending, fulfilled y rejected.

El componente PredictionForm.jsx es la interfaz de usuario. Permite al usuario introducir A y B, enviar una solicitud de predicción, mostrar el último resultado, mantener el historial en Redux y representar las predicciones en un gráfico.

El archivo kantra.css es responsable de la apariencia visual. La conexión con React se realiza mediante: 

import "./kantra.css";

y posteriormente mediante los diferentes atributos className utilizados en JSX.

Por lo tanto, la lógica de negocio, la gestión de datos, la visualización y la presentación visual están separadas en archivos y tecnologías especializadas.
