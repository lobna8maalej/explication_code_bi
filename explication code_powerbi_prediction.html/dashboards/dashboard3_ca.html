1. Présentation du Dashboard Banque

Ce dashboard bancaire a été développé à partir d'un fichier comptable contenant les données nécessaires à l'analyse financière.

Le projet met en place une chaîne complète de traitement des données, depuis le fichier comptable source jusqu'à la visualisation dans Power BI et l'intégration d'un modèle de Machine Learning destiné à effectuer des prédictions.

Une attention particulière a été accordée à la qualité des données. Le fichier comptable présentait plusieurs anomalies nécessitant une phase de nettoyage, d'identification des valeurs manquantes et aberrantes, ainsi que des transformations adaptées à la structure des données.

2. Source des données — Fichier comptable

La source initiale du projet est un fichier comptable contenant les données utilisées pour construire les analyses bancaires.

Avant l'intégration dans le processus ETL, la structure du fichier a été analysée afin d'identifier les différents problèmes de qualité susceptibles d'affecter les analyses et les modèles prédictifs.

Problèmes rencontrés

  • Valeurs manquantes
  • Valeurs aberrantes
  • Incohérences dans les données
  • Formats de données nécessitant une transformation
  • Structure des colonnes nécessitant une adaptation

3. Nettoyage et transformation avec Python

Python intervient dans la préparation des données avant leur intégration dans la chaîne ETL.

Cette étape permet d'analyser la qualité du fichier comptable, d'identifier les anomalies et de transformer les données afin d'obtenir une structure exploitable pour les étapes suivantes.

3.1 Identification des valeurs manquantes

Les données sont analysées afin d'identifier les champs incomplets ou manquants. Le traitement est réalisé selon la nature des données et leur importance pour l'analyse.

3.2 Identification des valeurs aberrantes

Les valeurs inhabituelles sont également identifiées afin d'éviter qu'elles ne perturbent les indicateurs du dashboard ou les résultats du Machine Learning.

3.3 Transformation des données

Après l'identification des problèmes, les données sont transformées afin de respecter la structure nécessaire à leur intégration dans la Staging Area et le Data Warehouse.

3.4 Objectif de la préparation Python

L'objectif de cette étape est de produire des données propres, cohérentes et structurées pouvant être utilisées à la fois pour l'analyse décisionnelle et pour la modélisation prédictive.

7. Machine Learning — Prédiction

Après la préparation et l'analyse des données, une composante Machine Learning est intégrée au projet.

Le modèle utilise les données préparées afin de produire une valeur prédictive à partir des variables d'entrée.

7.1 Variables utilisées

Le script Python de prédiction reçoit deux variables d'entrée :

  • ca_tnd — chiffre d'affaires en TND
  • ca_eur — chiffre d'affaires en EUR

7.2 Chargement du modèle

Le modèle Machine Learning préalablement entraîné est sauvegardé dans un fichier EXPORT.pkl.

Le script Python charge ce modèle à l'aide de la bibliothèque pickle.

7.3 Fichier Python — ca.py 


```

import sys
import json
import pickle
import os

mode = sys.argv[1]
ca_tnd = float(sys.argv[2])
ca_eur = float(sys.argv[3])

BASE_DIR = os.path.dirname(os.path.abspath(**file**))
model_path = os.path.join(BASE_DIR, "EXPORT.pkl")

model = pickle.load(open(model_path, "rb"))

prediction = model.predict([[ca_tnd, ca_eur]])

result = {
"mode": mode,
"ca_tnd": ca_tnd,
"ca_eur": ca_eur,
"prediction": float(prediction[0])
}

print(json.dumps(result))
```

7.4 Explication du fichier ca.py

  1. Importation des bibliothèques : Python utilise sys, json, pickle et os pour gérer les paramètres, le modèle et la communication.
  2. Récupération des paramètres : les valeurs mode, ca_tnd et ca_eur sont récupérées depuis les arguments transmis au script.
  3. Conversion numérique : les valeurs de chiffre d'affaires sont converties en nombres décimaux avec float().
  4. Localisation du modèle : os.path permet de construire le chemin vers le fichier EXPORT.pkl.
  5. Chargement du modèle : pickle.load() permet de restaurer le modèle Machine Learning entraîné.
  6. Prédiction : model.predict() reçoit les deux variables ca_tnd et ca_eur et génère la prédiction.
  7. Création de la réponse : le résultat est organisé dans un objet Python contenant le mode, les valeurs d'entrée et la prédiction.
  8. Communication JSON : json.dumps() transforme le résultat en JSON afin qu'il puisse être récupéré par Node.js.

8. Intégration Python avec Node.js

Node.js joue le rôle d'intermédiaire entre l'application et le script Python.

Le module child_process et la fonction spawn() permettent à Node.js d'exécuter le programme Python et de récupérer son résultat.

8.1 Service CaService.js 


```

const { spawn } = require("child_process");

function runPython(file, args = []) {

return new Promise((resolve, reject) => {

```
const py = spawn("python", ["-u", file, ...args]);

let output = "";

py.stdout.on("data", (data) => {
  output += data.toString();
});

py.stderr.on("data", (err) => {
  console.error(err.toString());
});

py.on("close", (code) => {

  if (code !== 0) {
    return reject("Python error code " + code);
  }

  try {
    resolve(JSON.parse(output.trim()));
  } catch (e) {
    reject("JSON parse error");
  }

});
```

});

}

module.exports = runPython;
```

8.2 Fonctionnement du service

  1. Node.js reçoit le chemin du fichier Python.
  2. Les paramètres nécessaires sont transmis au script.
  3. spawn() démarre le processus Python.
  4. Node.js récupère les données produites par stdout.
  5. Les erreurs Python sont récupérées avec stderr.
  6. Le résultat JSON est analysé avec JSON.parse().
  7. Le résultat final est retourné au contrôleur Express.

9. API Node.js / Express

Express expose une route API permettant à l'application d'envoyer les données nécessaires au système de prédiction.

9.1 Route CARoute.js 


```

const express = require("express");
const router = express.Router();
const path = require("path");
const runPython = require("../service/CaService");

router.use(express.json());

router.post("/", async (req, res) => {

try {

```
const { mode, ca_tnd, ca_eur } = req.body;

console.log("REQUEST BODY:", req.body);

if (ca_tnd == null || ca_eur == null) {

  return res.status(400).json({
    error: "ca_tnd and ca_eur are required"
  });

}

const result = await runPython(
  path.join(__dirname, "../../python/ca.py"),
  [
    mode || "export",
    String(ca_tnd),
    String(ca_eur)
  ]
);

return res.status(200).json(result);
```

} catch (error) {

```
console.error("SERVER ERROR:", error);

return res.status(500).json({
  error: error.toString()
});
```

}

});

module.exports = router;
```

9.2 Explication de la route

La route utilise la méthode POST afin de recevoir les données envoyées par l'application.

Le serveur récupère ensuite mode, ca_tnd et ca_eur depuis req.body.

Une validation vérifie que les deux valeurs de chiffre d'affaires nécessaires sont présentes.

Le service runPython() est ensuite appelé afin d'exécuter ca.py avec les paramètres reçus.

Enfin, le résultat de la prédiction est retourné au client sous forme de réponse JSON.

10. Serveur Express

Le fichier principal du serveur initialise Express, active la réception des données JSON et enregistre la route de prédiction. 


```

const express = require("express");

const app = express();

app.use(express.json());

const CARoute = require("./routes/CARoute");

app.use("/CA", CARoute);

app.listen(3000, () => {

console.log("SERVER STARTED");

});
```

12. Résultats du projet

Ce projet permet de transformer un fichier comptable contenant des données brutes et potentiellement incohérentes en données structurées et exploitables.
