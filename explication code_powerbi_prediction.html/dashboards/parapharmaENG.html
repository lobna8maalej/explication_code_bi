01

General Overview

This module presents an architecture for integrating data or Machine Learning models into a Web application developed with Node.js and Express, with MySQL used as the storage system for the results. In this parapharmacy project, two Python files in PKL format are generated: biodream.pkl and bonheur.pkl. These files represent objects that are saved using the Python pickle library. The Node.js backend then uses Express to expose an API accessible from the frontend. When a request is sent to /parapharma, Express calls a dedicated route. This route then uses the parapharmaservice.js service to produce real values and predicted values. The results are then stored in the MySQL database, particularly in the gb_model1 table. The objective of this architecture is therefore to separate the different responsibilities: models and processing are handled on the Python side, Node.js manages backend logic and API communication, Express organizes HTTP routes, MySQL stores the results, and the frontend can then use this data to display charts, indicators, or dashboards.

PKL File Generation

The first part of the project concerns saving objects into .pkl files. The Python module uses the pickle library. This library allows a Python object to be serialized, meaning that the object is transformed into a format that can be stored in a file and loaded again later. In the provided code, a function called save_pickle() is created to centralize this saving operation. The function receives two parameters: the object to be saved and the file name. The file is opened using the wb mode, which means "write binary", and then pickle.dump() saves the object into the file. The program then creates two objects: data_biodream and data_bonheur. The first contains a score of 0.92 and the type "biodream_model", while the second contains a score of 0.88 and the type "bonheur_model". These objects are then saved into biodream.pkl and bonheur.pkl. It is important to specify that, in the provided code, these PKL files currently contain Python demonstration dictionaries rather than a Machine Learning model trained with a library such as Scikit-learn. However, the architecture can use the same logic with a real trained model.

Node.js Server with Express

The second part of the system concerns the Node.js backend. Node.js is the JavaScript runtime environment used on the server side. Express is used as the framework for creating the API. The server first imports Express using require("express"), then creates an application with express(). The instruction app.use(express.json()) allows the server to process requests containing data in JSON format. Next, the routes for the parapharmacy module are imported from ./Routes/parapharmaRoute. The line app.use("/parapharma", parapharmaRoutes) associates these routes with the /parapharma prefix. Finally, the server listens on port 3000. This means that the API can be accessed from http://localhost:3000 and that the main module route is available through GET /parapharma.

Prediction Service

The parapharmaservice.js file contains the trainModels() function. This function represents the service layer of the backend. Its role is to prepare the data and produce the predictions that will then be sent to the Express route. The X array contains the input values 1, 2, 3, 4 and 5. The y array contains the real values 100, 200, 300, 400 and 500. The map() method then iterates through each value of X and applies the rule v * 100. The result is stored in the predictions array. Therefore, for 1 the prediction is 100, for 2 it is 200, for 3 it is 300, for 4 it is 400 and for 5 it is 500. The function then returns an object containing success and a data object containing X, y and predictions. It is important to specify that this function does not currently perform actual Machine Learning model training. It simulates a prediction using a simple mathematical formula. In an advanced version, this function could call a real trained model or a Python service responsible for performing the prediction.

Express Route and Result Processing

The parapharmaRoute.js file serves as the coordination point between the prediction service and the MySQL database. The route uses router.get("/"), which means that when a client calls GET /parapharma, this function is executed. The first step is to open a MySQL connection using getConnection(). The second step is to call trainModels(). The returned result contains the real values and the predictions. The code therefore retrieves result.data.y into the real variable and result.data.predictions into the pred variable. Then, Math.min() determines the number of elements shared by the two arrays. A for loop then iterates through the values and uses connection.execute() to insert each real value / prediction pair into the gb_model1 table. After the insertion, Express returns a JSON response containing a success message, the number of inserted rows and the real values associated with their predictions. The route therefore represents the connection between the calculation service and the database.

Complete Architecture

The complete architecture works as a processing chain. The frontend or dashboard calls the Node.js API through the /parapharma endpoint. Express receives this request and executes the route defined in parapharmaRoute.js. The route opens a connection to MySQL and then calls trainModels(). The service prepares the X and y data and calculates the predictions. The real and predicted values are then retrieved by the route. For each observation, Node.js executes an SQL query to store the real value and the prediction in gb_model1. Once all rows have been stored, Express returns a JSON response to the frontend. The dashboard can then retrieve this data from the API and display it as charts or indicators. The biodream.pkl and bonheur.pkl files belong to the Python layer responsible for saving objects and can later be used as a foundation for integrating real predictive models.

Explanation to Give During a Sales Presentation

During a business presentation, it is not necessary to present every line of code to the client. The main objective is to explain how the system works and the value it provides. You can explain that the parapharmacy module uses an architecture divided into several layers. Data and models are prepared on the Python side and can be saved as PKL files. In this version, two objects are saved: biodream.pkl and bonheur.pkl. The Node.js backend then uses Express to expose an API. When the frontend requests the results through /parapharma, Express executes the corresponding route. This route calls the trainModels() service, which prepares the data and calculates the predictions. The results are then compared with the real values and stored in MySQL in the gb_model1 table. Once the processing is complete, the API returns the data to the frontend in JSON format. The dashboard can then use this information to create charts and indicators that help visualize model performance. The main advantage of this architecture is the separation of responsibilities: Python is used for the model and processing, Node.js and Express handle backend communication, MySQL stores the results, and the frontend provides visualization. This organization allows the project to gradually evolve into a real predictive system by replacing the current simulation with a genuinely trained Machine Learning model.

🎤 Example of an Oral Explanation

"In this part of the project, I implemented a prediction architecture for the parapharmacy sector. The system is organized around several technologies that communicate with each other.

First, we have Python, which allows us to save objects or models as PKL files. In our example, we have two files: biodream.pkl and bonheur.pkl.

Then, we have Node.js and Express, which form the backend. Express exposes an API through the /parapharma route. When this route is called, it triggers the prediction service.

The service prepares the real data and the predictions. In this demonstration version, the prediction is calculated using a simple rule. In a final version, this part can be replaced by a real trained Machine Learning model.

Once the results are obtained, Node.js retrieves them and stores them in MySQL. Each real value is associated with its predicted value in the gb_model1 table.

Finally, the API returns the results to the frontend in JSON format. The dashboard can then use this data to display charts, compare real and predicted values and provide decision-making insights to the user.

The advantage of this architecture is that each technology has a specific role. Python handles the models, Node.js and Express handle the API, MySQL handles storage, and the frontend handles visualization. The system is therefore organized, scalable and can be adapted to real predictive models in a professional version."

PKL files allow Python objects to be saved, while Node.js and Express provide access to the functionality from a Web application. In a future version, the calculation currently simulated inside trainModels() can be replaced with a real Machine Learning model trained on real data.
