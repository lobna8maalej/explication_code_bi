React • Redux Toolkit • Axios • API • Power BI • Recharts

1. General Overview of the Frontend System

In this part of the project, we developed a frontend interface dedicated to revenue prediction, called the CA Dashboard. This interface is built with React and uses several complementary technologies to communicate with the backend, manage data centrally, display prediction results and represent data graphically. The general operation is based on communication between the React component, Redux Toolkit, Axios and the backend API. The React component does not directly handle all communication logic with the server. It uses Redux to trigger an asynchronous action that sends data to the backend. Axios is used to perform the HTTP request to the URL http://localhost:3000/CA. The backend then receives the revenue data in TND and EUR as well as the prediction mode. It performs the necessary processing and returns a result containing, in particular, the prediction. Redux receives this response and stores it in the global state. The React component then uses useSelector to retrieve the data from Redux and display the result on the screen. The component also uses useEffect to automatically launch the prediction when the page is loaded. Finally, the Recharts library transforms the received data into a chart in order to compare the actual revenue with the predicted value. At the same time, a Power BI report is integrated into the page using an iframe element. We therefore obtain a complete frontend architecture combining BI visualization, Machine Learning prediction, state management with Redux, communication with the backend and graphical representation of the results.

2. Importing Redux Toolkit

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

This instruction imports two important functions from Redux Toolkit. The createAsyncThunk function is used to create an asynchronous operation, particularly to perform an HTTP request to the backend. In our project, this function is used to send revenue data to the API and retrieve the prediction result. The createSlice function is used to create a part of the Redux store dedicated to revenue. This part is called a slice. The slice contains the name of this part of the state, its initial state and the logic used to modify this state when the request is pending, successful or fails. Using Redux Toolkit therefore considerably simplifies global state management in the application.

3. Importing Axios

import axios from "axios";

Axios is a JavaScript library used to perform HTTP requests. In our application, Axios acts as an intermediary between the React frontend and the Node.js backend. When we want to launch a prediction, the frontend must send the data to the server. Axios allows us to perform this operation using the axios.post() method. The server then receives the data sent by React, performs the prediction processing and returns a JSON response. Axios retrieves this response so that it can then be stored in Redux and displayed in the React component. Using Axios therefore makes communication between the different parts of the application easier.

4. Creating the Asynchronous Operation with createAsyncThunk

export const createPrediction = createAsyncThunk(
  "ca/create",
  async (data, { rejectWithValue }) => {
    try {
      const res = await axios.post(
        "http://localhost:3000/CA",
        data
      );

      return res.data;

    } catch (err) {
      return rejectWithValue(
        err.response?.data || "Server error"
      );
    }
  }
);

This part represents the main link between Redux and the backend. We create a function called createPrediction using createAsyncThunk. The first parameter, "ca/create", represents the Redux action type. The second parameter is an asynchronous function that receives the data in the data variable. This function then uses Axios to send an HTTP POST request to http://localhost:3000/CA. The POST method is used because we are sending information to the server so that it can perform a prediction. The data variable contains the parameters required for the prediction. In our case, it contains in particular mode, ca_tnd and ca_eur. The await keyword waits for the server response before continuing execution. When the server responds correctly, the response is stored in res and res.data contains the JSON data returned by the backend. The instruction return res.data then passes this data to Redux. If an error occurs during the request, execution enters the catch block. The rejectWithValue() function then allows an error message to be passed to Redux. The expression err.response?.data retrieves the message returned by the server when it exists. If no usable response is available, the message "Server error" is used. This structure therefore properly handles the two possible situations: a successful prediction or an error during communication with the backend.

5. Creating the caSlice

const caSlice = createSlice({
  name: "ca",

  initialState: {
    predictionData: null,
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    ...
  },
});

This part creates the Redux slice dedicated to revenue. The property name: "ca" identifies this part of the Redux store. The application therefore has a specific state space dedicated to CA data. The initialState property defines the initial state of the system. predictionData is initialized to null because no prediction has been received yet. loading is initialized to false because no request is running at startup. Finally, error is initialized to null because there is no error initially. The reducers property is empty in our case because we do not need to create traditional synchronous actions. The management of our asynchronous action createPrediction is handled in extraReducers. This allows Redux to automatically react to the different states of the asynchronous request.

6. Pending State: Request in Progress

.addCase(createPrediction.pending, (state) => {
  state.loading = true;
  state.error = null;
})

When the prediction request starts, Redux automatically triggers the pending state. This means that the request is currently being executed. In this situation, we set state.loading = true. This information allows the React component to know that it should display a message indicating that the prediction is loading. We also reset state.error = null in order to clear a possible error from a previous request. The system can therefore maintain clear information about the current state of communication with the backend.

7. Fulfilled State: Successful Prediction

.addCase(createPrediction.fulfilled, (state, action) => {
  state.loading = false;
  state.predictionData = action.payload;
})

When the backend responds correctly, Redux triggers the fulfilled state. This means that the asynchronous request has completed successfully. We then set state.loading = false because loading is finished. Next, we store the result returned by the server in state.predictionData. The property action.payload contains the data returned by return res.data in the thunk. Redux therefore stores the prediction result in its global state. The React component can then retrieve this information using useSelector.

8. Rejected State: Prediction Error

.addCase(createPrediction.rejected, (state, action) => {
  state.loading = false;
  state.error = action.payload;
})

If the request fails, Redux automatically triggers the rejected state. In this situation, state.loading becomes false because the request has finished, even if it finished with an error. The error message passed by rejectWithValue() is then stored in state.error. The React component can then retrieve this error and display it to the user. Managing the three states pending, fulfilled and rejected therefore makes it possible to build a dynamic interface that clearly indicates whether the prediction is in progress, completed or has encountered an error.

9. Exporting the Redux Reducer

export default caSlice.reducer;

This instruction exports the reducer created by caSlice. The reducer represents the logic that allows Redux to modify the CA state according to the different actions received. It can then be integrated into the application's Redux store. Through this export, the React component can indirectly access the data stored in the ca part of the store.

11. useDispatch and useSelector

import {
  useDispatch,
  useSelector
} from "react-redux";

These two hooks allow the React component to connect to Redux. useDispatch() allows an action to be sent to Redux. In our case, it is used to trigger createPrediction(). useSelector() is used to retrieve information stored in the Redux store. Thanks to it, the component can retrieve the prediction result, the loading state and any possible error. We can therefore consider dispatch as the mechanism that allows the component to send an instruction to Redux, while useSelector allows the component to read the data stored by Redux.

16. Retrieving Data with useSelector

const predictionData =
  useSelector((state) => state.ca?.predictionData);

const loading =
  useSelector((state) => state.ca?.loading);

const error =
  useSelector((state) => state.ca?.error);

These three instructions allow the React component to retrieve the information stored in Redux. The first retrieves predictionData, which is the prediction result returned by the backend. The second retrieves loading, which indicates whether the request is currently in progress. The third retrieves error, which may contain an error. The notation state.ca means that we are accessing the part of the store corresponding to the CA slice. The ?. operator is the optional chaining operator, which helps prevent certain errors when an intermediate value does not exist.

17. Automatically Launching the Prediction with useEffect

useEffect(() => {
  dispatch(
    createPrediction({
      mode: "export",
      ca_tnd: 50000,
      ca_eur: 10000,
    })
  );
}, [dispatch]);

This part is essential for the automatic operation of the Dashboard. The useEffect hook allows an operation to be executed after the component has rendered. When the CA page is loaded, the component calls dispatch() and triggers createPrediction(). We then send three pieces of information to the backend: mode: "export", ca_tnd: 50000 and ca_eur: 10000. These data represent the values used by the prediction model. Redux then passes this information to the thunk, the thunk uses Axios to send a POST request to the backend and the backend performs the prediction. The array [dispatch] indicates the dependencies of useEffect. In this case, the effect runs when the component is mounted and if the reference to dispatch changes.

19. Preparing the Chart Data

const chartData = predictionData
  ? [

This part prepares the data required by Recharts. The code first checks whether predictionData exists. If the prediction result is available, an array containing one object is created. The Prediction property retrieves the predicted value from predictionData.prediction. The || 0 operator allows zero to be used when a value is not available. If no prediction exists yet, chartData simply receives an empty array. This preparation is necessary because Recharts expects an array of data to build the chart.

The complete process begins when the user opens the CA Dashboard. React loads the CA component and the useEffect hook automatically launches the createPrediction action. This action is sent to Redux through dispatch. Redux Toolkit then executes the createAsyncThunk, which uses Axios to send the data to the backend endpoint /CA. The backend receives the values mode, ca_tnd and ca_eur, performs the prediction processing and returns a JSON response. If the request succeeds, Redux triggers fulfilled and stores the response in predictionData. The React component detects the new value through useSelector and automatically re-renders. It then displays the numerical result and builds the chart with Recharts. If the request fails, Redux triggers rejected and stores the error in error, allowing React to display the corresponding message.

30. Managing the Three Request States

One of the important advantages of Redux Toolkit in this project is the automatic management of the different states of the asynchronous operation. When the request starts, the pending state is triggered and loading becomes true. The frontend then displays the loading message. When the backend successfully returns the prediction, the fulfilled state is triggered, loading becomes false and the result is stored in predictionData. React can then display the result card and the chart. If an error occurs during the request, the rejected state is triggered, loading becomes false and the error message is stored in error. The React component then displays this error. We therefore obtain clear management of the complete request lifecycle.

31. Frontend Architecture Used

The architecture used in this feature clearly separates responsibilities. The React component CA.jsx is responsible for the interface and display. The caSlice.js file is responsible for Redux state management and asynchronous communication with the API. Axios is responsible for sending the HTTP request. The Node.js backend is responsible for processing the request and generating the prediction. Recharts is responsible for graphical visualization of the result and Power BI provides an additional decision-support visualization. This separation makes the project more organized and facilitates application maintenance and evolution.

32. Difference Between Redux and React in This Code

In this architecture, React and Redux have different but complementary responsibilities. React is mainly used to build the user interface: it displays the title, the Power BI report, the loading message, the result and the chart. Redux is used to manage the prediction state: it stores the data received from the backend, indicates whether a request is in progress and stores possible errors. useDispatch allows React to ask Redux to launch an operation and useSelector allows React to retrieve the data stored by Redux. This separation prevents all server communication logic from being mixed directly into the interface.

33. Relationship Between Power BI and Machine Learning Prediction

The CA Dashboard brings together two complementary types of functionality. On the one hand, Power BI provides indicators and decision-support visualizations based on the project's data. On the other hand, the React and Redux part allows the application to call the backend in order to obtain a Machine Learning prediction. The result of this prediction is then presented numerically and graphically using Recharts. The advantage of this architecture is therefore that it combines Business Intelligence and predictive analytics within the same interface. Power BI makes it possible to understand historical data and indicators, while the prediction model makes it possible to obtain an estimate based on the data sent to the backend.

34. Summary of the Operation

In summary, when the user opens the CA Dashboard, React loads the CA component. The useEffect hook automatically launches a Redux action called createPrediction. This action is created with createAsyncThunk and uses Axios to send a POST request to the backend at http://localhost:3000/CA. The data sent are the export mode, revenue in TND of 50000 and revenue in EUR of 10000. During execution, Redux enters the pending state and React displays the loading message. When the server returns the result, Redux enters the fulfilled state and stores the response in predictionData. React retrieves this information through useSelector, displays the predicted value with two decimal places and prepares the data required for the chart. Recharts then displays two bars allowing the actual revenue to be compared with the prediction. At the same time, Power BI is displayed inside an iframe to provide additional decision-support visualization. If an error occurs, Redux enters the rejected state and React displays the error message. The system therefore forms a complete chain between the React interface, Redux Toolkit, Axios, the Node.js backend, the prediction model, Recharts and Power BI.
