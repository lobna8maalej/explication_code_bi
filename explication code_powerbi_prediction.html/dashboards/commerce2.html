Présentation générale

Ce module met en place une architecture de prédiction destinée au domaine du commerce et permettant de comparer ou d'estimer des résultats pour deux enseignes : Carrefour et Aziza. L'architecture repose sur plusieurs technologies qui communiquent entre elles. La première partie est développée en Python et utilise la bibliothèque Scikit-learn ainsi que l'algorithme SVR, ou Support Vector Regression. Deux modèles Machine Learning indépendants sont entraînés à partir des mêmes variables d'entrée X, mais avec deux ensembles de valeurs cibles différents : un ensemble pour Carrefour et un autre pour Aziza. Une fois entraînés, les modèles sont sérialisés avec la bibliothèque pickle et sauvegardés sous forme de fichiers carrefour.pkl et aziza.pkl. La deuxième partie du système concerne le script Python chargé de recevoir les données depuis Node.js. Ce script lit un objet JSON envoyé sur l'entrée standard, identifie le modèle demandé, charge le fichier PKL correspondant, récupère les variables x1 et x2, puis utilise la méthode predict() du modèle SVR pour produire une prédiction. La troisième partie est développée en Node.js. Le backend utilise le module natif child_process afin de lancer Python depuis Node.js. La fonction runCommerce() prépare le chemin de l'interpréteur Python, localise le script de prédiction, lance le processus Python et lui transmet les données au format JSON. Le résultat produit par Python est récupéré depuis stdout, converti depuis JSON vers un objet JavaScript puis retourné au backend. Enfin, Express expose une API REST avec une route de test /train et une route POST /predict. Le frontend ou le dashboard peut donc envoyer le nom du modèle ainsi que les variables d'entrée, et recevoir automatiquement la prédiction calculée par le véritable modèle Machine Learning.

Entraînement des modèles SVR

La première étape du système consiste à créer les modèles Machine Learning. Le code Python importe SVR depuis sklearn.svm. SVR signifie Support Vector Regression et constitue une version de la méthode des Support Vector Machines adaptée aux problèmes de régression. Contrairement à une simple formule mathématique codée manuellement, le modèle SVR est entraîné à partir de données d'entrée et de valeurs cibles. Dans ce projet, le tableau X contient quatre observations et deux variables pour chaque observation. La première observation possède les valeurs 10 et 1, la deuxième 20 et 2, la troisième 30 et 3 et la quatrième 40 et 4. Ces deux variables constituent les caractéristiques utilisées par le modèle pour apprendre la relation avec la variable cible. Pour Carrefour, le tableau y_carrefour contient les valeurs 120, 240, 360 et 480. Un premier objet SVR() est créé puis la méthode fit() est appelée avec X et y_carrefour. Le modèle apprend ainsi une relation entre les deux variables d'entrée et les valeurs cibles de Carrefour. Le modèle est ensuite sauvegardé dans le fichier carrefour.pkl. Le même principe est appliqué à Aziza. Le tableau y_aziza contient les valeurs 100, 200, 300 et 400. Un deuxième modèle SVR est créé, entraîné avec les mêmes variables X mais avec les valeurs cibles d'Aziza, puis sauvegardé dans aziza.pkl. On obtient donc deux modèles indépendants capables de produire des prédictions différentes à partir des mêmes variables d'entrée.

Importation de SVR 

from sklearn.svm import SVR

Cette instruction importe la classe SVR depuis le module sklearn.svm. Elle permet de créer un modèle de régression basé sur les Support Vector Machines. Le modèle pourra ensuite être entraîné avec la méthode fit() et utilisé pour produire des prédictions avec predict().

Importation de Pickle 

import pickle

La bibliothèque pickle est utilisée pour sérialiser le modèle entraîné. Après l'entraînement, le modèle SVR existe comme objet Python en mémoire. Pickle permet de transformer cet objet en fichier afin de pouvoir le sauvegarder et le recharger ultérieurement sans devoir entraîner le modèle à chaque prédiction.

Gestion du chemin du projet 

BASE_DIR = os.path.dirname(
    os.path.abspath(__file__)
)

Cette partie permet de déterminer automatiquement le dossier dans lequel se trouve le script Python. os.path.abspath(__file__) récupère le chemin absolu du fichier actuel tandis que os.path.dirname() récupère le dossier qui contient ce fichier. Cette méthode est particulièrement utile pour construire des chemins fiables vers les fichiers PKL.

Le modèle reçoit donc deux caractéristiques pour chaque prédiction. Par exemple, la première observation est composée de 10 et 1. Ces deux valeurs seront ensuite envoyées au modèle SVR afin qu'il puisse calculer une estimation.

Création et entraînement du modèle Carrefour 

carrefour_model = SVR()

carrefour_model.fit(

SVR() crée une nouvelle instance du modèle Support Vector Regression. La méthode fit() lance ensuite l'apprentissage. Le premier argument correspond aux variables d'entrée X et le deuxième correspond aux valeurs cibles y_carrefour. Le modèle analyse les données fournies afin d'apprendre une relation permettant ensuite de produire des prédictions sur de nouvelles valeurs.

Un nouvel objet SVR() est créé puis entraîné avec X et y_aziza. Cette séparation permet de construire deux modèles distincts. Le modèle Carrefour apprend les relations présentes dans les données Carrefour, tandis que le modèle Aziza apprend les relations présentes dans les données Aziza.

Script Python de prédiction

Après avoir entraîné et sauvegardé les modèles, un deuxième script Python est utilisé pour réaliser les prédictions. Son rôle est particulièrement important car il constitue le pont entre Node.js et les modèles Machine Learning Python. Le script importe sys, json, pickle et os. Il commence par lire les données envoyées par Node.js grâce à sys.stdin.read(). Ces données sont envoyées sous forme JSON et sont converties en objet Python avec json.loads(). Le script récupère ensuite le nom du modèle avec data.get("model", "carrefour"). Si aucun modèle n'est fourni, Carrefour devient le modèle par défaut. Un dictionnaire file_map permet ensuite d'associer le nom logique du modèle au fichier PKL correspondant. Si le nom reçu n'existe pas dans ce dictionnaire, le programme déclenche une erreur. Lorsque le modèle est valide, le chemin du fichier PKL est construit automatiquement puis le fichier est ouvert en mode binaire. pickle.load() recharge alors le modèle SVR entraîné. Une vérification de sécurité utilise hasattr(model, "predict") afin de vérifier que l'objet chargé possède bien une méthode de prédiction. Les variables x1 et x2 sont ensuite récupérées depuis les données reçues et converties en nombres décimaux avec float(). Le modèle est finalement appelé avec model.predict([[x1, x2]]). La double liste est nécessaire car Scikit-learn attend généralement une structure représentant une ou plusieurs observations avec leurs caractéristiques. Le résultat est récupéré puis converti en float. Enfin, le script produit un objet JSON contenant success, le nom du modèle et la prédiction. Si une erreur se produit à n'importe quelle étape, le bloc except retourne également un JSON, mais avec success: false et le message de l'erreur.

Lecture des données Node.js 

data = json.loads(
    sys.stdin.read()
)

sys.stdin.read() permet au script Python de lire les données envoyées par le processus Node.js. Comme Node.js envoie les informations sous forme JSON, json.loads() transforme cette chaîne JSON en dictionnaire Python exploitable par le programme.

Sélection du modèle 

model_name = data.get(
    "model",
    "carrefour"
).lower()

Cette instruction récupère le nom du modèle demandé. La méthode get() utilise Carrefour comme valeur par défaut si la propriété model n'est pas fournie. La méthode lower() transforme le texte en minuscules afin d'éviter certains problèmes liés aux majuscules.

Association modèle / fichier PKL 

file_map = {
    "carrefour": "carrefour.pkl",
    "aziza": "aziza.pkl"
}

Le dictionnaire file_map permet de faire correspondre le nom envoyé par le frontend au fichier physique contenant le modèle. Si model = carrefour, le programme charge carrefour.pkl. Si model = aziza, il charge aziza.pkl. Cette organisation évite de construire directement un nom de fichier à partir d'une donnée utilisateur non contrôlée.

Chargement du modèle 

with open(
    model_path,
    "rb"
) as f:

    model = pickle.load(f)

Le fichier PKL est ouvert avec le mode rb, qui signifie lecture binaire. pickle.load() reconstruit l'objet Python sauvegardé précédemment. Le modèle SVR entraîné est donc restauré en mémoire et peut immédiatement être utilisé pour réaliser une prédiction.

Vérification du modèle 

if not hasattr(
    model,
    "predict"
):

    raise Exception(
        "Invalid ML model loaded"
    )

Cette vérification permet de s'assurer que l'objet chargé possède bien une méthode predict(). Comme le système attend un modèle Machine Learning capable de produire une prédiction, cette vérification permet d'éviter de continuer le traitement avec un objet incompatible.

Récupération des variables 

x1 = float(
    data["x1"]
)

x2 = float(
    data["x2"]
)

Les deux variables envoyées par Node.js sont récupérées depuis l'objet JSON. La fonction float() permet de convertir les valeurs en nombres décimaux afin qu'elles puissent être utilisées correctement par le modèle SVR.

Production de la prédiction 

prediction = model.predict(
    [[x1, x2]]
)[0]

Cette instruction constitue l'étape principale du Machine Learning. Le modèle SVR reçoit les deux variables d'entrée et utilise les paramètres appris pendant l'entraînement pour calculer une prédiction. La méthode predict() retourne un tableau contenant le résultat. L'indice [0] permet de récupérer la première prédiction.

Retour JSON 

print(json.dumps({
    "success": True,
    "model": model_name,
    "prediction": float(prediction)
}))

Le résultat est transformé en JSON avec json.dumps(). Ce format est essentiel car Node.js pourra facilement récupérer la réponse depuis la sortie standard du processus Python puis la convertir en objet JavaScript. En cas de réussite, la réponse contient le statut, le nom du modèle et la valeur prédite.

Service Node.js et communication avec Python

Le fichier server.js côté service constitue la passerelle entre le backend Node.js et le programme Python. Le module child_process fourni par Node.js permet de lancer un processus externe. Ici, la fonction spawn() est utilisée pour démarrer l'interpréteur Python. La fonction runCommerce() retourne une Promise, ce qui permet à la route Express d'utiliser await et d'attendre la fin du traitement Python. Le service construit d'abord le chemin vers l'interpréteur Python situé dans l'environnement virtuel .venv. Il construit ensuite le chemin vers le script commerce2.py. Avant de lancer Python, le code utilise fs.existsSync() afin de vérifier que l'interpréteur et le script existent réellement. Cette étape est particulièrement utile pour le diagnostic des erreurs de chemin. Lorsque les deux fichiers sont disponibles, spawn() lance Python avec le script de prédiction. Node.js envoie ensuite les données au processus Python grâce à python.stdin.write(). Les données sont converties en JSON avec JSON.stringify(). Python lit ces données avec sys.stdin.read(). Pendant l'exécution, Node.js écoute stdout pour récupérer le résultat produit par Python et écoute également stderr afin de récupérer les éventuels messages d'erreur. Lorsque Python termine, l'événement close est déclenché. Le code vérifie alors le code de sortie du processus. Si le code est différent de zéro, cela signifie que le processus Python s'est terminé avec une erreur. Si le résultat est vide, une autre erreur est retournée. Enfin, si Python a produit une réponse, JSON.parse() transforme le texte JSON en objet JavaScript. Cet objet est ensuite retourné avec resolve(). Le service réalise donc une véritable communication entre l'environnement JavaScript et le modèle Machine Learning Python.

Importation des modules Node.js

const path =
require("path");

const fs =
require("fs");

child_process permet de lancer Python depuis Node.js. path permet de construire des chemins de fichiers compatibles avec le système d'exploitation. fs permet notamment de vérifier l'existence des fichiers.

Création de la Promise 

function runCommerce(inputData) {

    return new Promise(
        (resolve, reject) => {

        ...
    });

}

La fonction retourne une Promise car l'exécution de Python est une opération asynchrone. Node.js doit lancer Python, attendre son résultat puis retourner ce résultat à la route Express.

Localisation de Python 

const pythonPath = path.resolve(
    __dirname,
    "../../.venv/Scripts/python.exe"
);

Cette instruction construit le chemin absolu vers l'interpréteur Python utilisé par le projet. Ici, le programme utilise le Python présent dans l'environnement virtuel .venv. Cela permet d'utiliser précisément l'environnement dans lequel les bibliothèques nécessaires, notamment Scikit-learn, sont installées.

Localisation du script Python 

const scriptPath = path.resolve(
    __dirname,
    "../../python/commerce2.py"
);

Le chemin vers le script Python de prédiction est également construit de manière absolue. Node.js saura ainsi exactement quel fichier exécuter.

Vérification des fichiers 

fs.existsSync(pythonPath)

fs.existsSync(scriptPath)

Ces vérifications permettent de détecter rapidement si Python ou le script sont introuvables. Dans un projet réel, cela facilite énormément le diagnostic lorsqu'un chemin est incorrect ou lorsqu'un fichier a été déplacé.

Lancement de Python 

const python = spawn(
    pythonPath,
    [scriptPath]
);

spawn() lance l'interpréteur Python et lui transmet le chemin du script commerce2.py. Node.js possède alors un processus enfant avec lequel il peut communiquer grâce à stdin, stdout et stderr.

Envoi des données vers Python 

python.stdin.write(
    JSON.stringify(inputData)
);

python.stdin.end();

Les données reçues par Node.js sont converties en chaîne JSON puis envoyées dans l'entrée standard du processus Python. stdin.end() indique que Node.js a terminé l'envoi des données. Python peut alors lire l'ensemble du contenu avec sys.stdin.read().

Récupération du résultat Python 

python.stdout.on(
    "data",
    (data) => {

        result += data.toString();

    }
);

Node.js écoute les données envoyées par Python sur stdout. Les morceaux reçus sont convertis en texte puis ajoutés à la variable result. Lorsque Python termine, cette variable contient la réponse JSON.

Gestion des erreurs Python 

python.stderr.on(
    "data",
    (data) => {

        error += data.toString();

    }
);

stderr est utilisé pour récupérer les messages d'erreur produits par Python. Cela permet au backend de connaître la cause d'un éventuel problème.

Conversion du JSON 

const parsedResult =
    JSON.parse(
        result.trim()
    );

resolve(
    parsedResult
);

Python retourne une chaîne JSON. Node.js utilise JSON.parse() pour transformer cette chaîne en objet JavaScript. L'objet obtenu est ensuite retourné à la route grâce à resolve().

Route Express de prédiction

Le fichier serverRoutes.js définit les endpoints accessibles par le frontend. Il crée un routeur Express avec express.Router(), puis importe le service runCommerce(). Une première route GET appelée /train sert de route de test. Elle ne lance pas réellement l'entraînement des modèles ; elle retourne simplement un message indiquant que Carrefour et Aziza sont prêts. L'entraînement réel est effectué par le script Python de création des modèles. La deuxième route, POST /predict, est la route principale de prédiction. Elle récupère les informations envoyées dans req.body, notamment le nom du modèle, x1 et x2. Une validation vérifie que x1 et x2 sont présents. Si une valeur est absente, l'API retourne une réponse HTTP 400. Lorsque les données sont valides, la route appelle runCommerce() avec les informations reçues. Le service Node.js lance alors le script Python, charge le modèle PKL correspondant et calcule la prédiction. Une fois la réponse reçue, Express la retourne directement au client avec res.status(200).json(result). Le frontend peut donc appeler cette API et recevoir directement le résultat du modèle Machine Learning.

Création du routeur

Cette partie importe Express puis crée un routeur indépendant. Cela permet d'organiser les endpoints dans un fichier séparé du serveur principal.

Le routeur récupère la fonction runCommerce() depuis le service. Cette fonction sera appelée lorsqu'une requête de prédiction sera reçue.

Cette route reçoit les données nécessaires pour réaliser une prédiction. Comme elle utilise POST, les informations sont envoyées dans le corps de la requête HTTP sous forme JSON.

    x2

Les trois informations principales sont récupérées depuis la requête : le modèle à utiliser et les deux variables d'entrée. Le modèle peut être carrefour ou aziza.

Validation

Cette validation empêche le backend d'appeler Python lorsque les variables nécessaires ne sont pas fournies. Dans ce cas, le serveur retourne une erreur HTTP 400 indiquant que x1 et x2 sont obligatoires.

        x2

Réponse finale 

return res.status(200).json(

);

Une fois que Python a retourné le résultat, Express l'envoie au client sous forme JSON. Le frontend reçoit donc la prédiction calculée par le véritable modèle SVR.

Serveur principal Node.js / Express

Le fichier principal du backend initialise l'application Express et connecte les routes de prédiction. Express est importé puis une instance d'application est créée avec express(). Le middleware express.json() est activé afin que le serveur puisse recevoir et analyser les données JSON envoyées par le frontend. Le fichier serverRoutes est ensuite importé puis monté avec le préfixe /server. Cela signifie que toutes les routes définies dans serverRoutes sont accessibles à partir de cette base. Ainsi, la route router.post("/predict") devient l'endpoint complet POST /server/predict. Le serveur contient également une route racine GET / qui retourne { status: "OK" }. Cette route peut être utilisée comme Health Check afin de vérifier que le backend est bien démarré. Enfin, app.listen(3000) démarre le serveur sur le port 3000. Le backend peut alors recevoir les requêtes du frontend et déclencher les prédictions Python.

07

Architecture complète du système

L'architecture complète repose sur une communication en plusieurs étapes. Tout commence avec le frontend ou le dashboard qui possède les données nécessaires à la prédiction. Il envoie une requête HTTP POST vers l'endpoint /server/predict. Express reçoit la requête et récupère les propriétés model, x1 et x2. Après validation, la route appelle le service runCommerce(). Celui-ci utilise le module Node.js child_process pour lancer le programme Python. Node.js transmet les données au programme Python sous forme JSON via stdin. Le script Python lit les données, identifie le modèle demandé et sélectionne le fichier PKL correspondant grâce au dictionnaire file_map. Le modèle SVR est ensuite rechargé avec pickle.load(). Les variables x1 et x2 sont récupérées et transmises au modèle grâce à predict(). Le modèle produit une valeur prédite. Python transforme ensuite cette valeur en JSON et l'écrit dans stdout. Node.js récupère le contenu de stdout, analyse le JSON avec JSON.parse() et retourne le résultat à la route Express. Express renvoie finalement la réponse JSON au frontend. Cette architecture permet donc d'utiliser un véritable modèle Machine Learning développé en Python tout en conservant un backend Web moderne basé sur Node.js et Express.

Rôle des technologies

Chaque technologie utilisée dans cette architecture possède une responsabilité précise. Python et Scikit-learn sont utilisés pour la partie Machine Learning. SVR constitue l'algorithme de régression utilisé pour apprendre la relation entre les variables d'entrée et les valeurs cibles. Pickle permet de sauvegarder les modèles entraînés et de les recharger lors des prédictions. Node.js constitue l'environnement d'exécution du backend JavaScript. Express permet de créer l'API REST et de gérer les requêtes HTTP. Le module child_process permet à Node.js de lancer Python et de communiquer avec lui. JSON constitue le format d'échange entre les deux environnements. Enfin, le frontend ou le dashboard utilise l'API pour envoyer les variables d'entrée et afficher le résultat de la prédiction.
