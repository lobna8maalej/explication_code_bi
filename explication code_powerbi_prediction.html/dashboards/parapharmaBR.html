01

Visão Geral

Este módulo apresenta uma arquitetura para integrar dados ou modelos de Machine Learning em uma aplicação Web desenvolvida com Node.js e Express, utilizando MySQL como sistema de armazenamento dos resultados. Neste projeto de parafarmácia, são gerados dois arquivos Python no formato PKL: biodream.pkl e bonheur.pkl. Esses arquivos representam objetos que são salvos utilizando a biblioteca Python pickle. O backend Node.js utiliza Express para fornecer uma API acessível pelo frontend. Quando uma solicitação é enviada para /parapharma, o Express chama uma rota específica. Essa rota utiliza o serviço parapharmaservice.js para produzir valores reais e valores previstos. Os resultados são posteriormente armazenados no banco de dados MySQL, especialmente na tabela gb_model1. O objetivo dessa arquitetura é separar as diferentes responsabilidades: os modelos e o processamento são gerenciados no lado do Python, o Node.js gerencia a lógica do backend e a comunicação com a API, o Express organiza as rotas HTTP, o MySQL armazena os resultados e o frontend pode utilizar esses dados para exibir gráficos, indicadores ou dashboards.

02

Geração dos Arquivos PKL

A primeira parte do projeto refere-se ao armazenamento de objetos em arquivos .pkl. O módulo Python utiliza a biblioteca pickle. Essa biblioteca permite serializar um objeto Python, ou seja, transformar o objeto em um formato que pode ser armazenado em um arquivo e carregado novamente posteriormente. No código fornecido, é criada uma função chamada save_pickle() para centralizar essa operação de armazenamento. A função recebe dois parâmetros: o objeto que será salvo e o nome do arquivo. O arquivo é aberto utilizando o modo wb, que significa "write binary", e então pickle.dump() salva o objeto dentro do arquivo. O programa cria então dois objetos: data_biodream e data_bonheur. O primeiro contém um score de 0.92 e o tipo "biodream_model", enquanto o segundo contém um score de 0.88 e o tipo "bonheur_model". Esses objetos são posteriormente salvos nos arquivos biodream.pkl e bonheur.pkl. É importante especificar que, no código fornecido, esses arquivos PKL atualmente contêm dicionários Python de demonstração e não um modelo de Machine Learning treinado com uma biblioteca como Scikit-learn. No entanto, a arquitetura pode utilizar a mesma lógica com um modelo real previamente treinado.

Servidor Node.js com Express

A segunda parte do sistema refere-se ao backend Node.js. Node.js é o ambiente de execução de JavaScript utilizado no lado do servidor. Express é utilizado como framework para criar a API. O servidor primeiro importa o Express utilizando require("express") e depois cria uma aplicação com express(). A instrução app.use(express.json()) permite que o servidor processe solicitações que contêm dados no formato JSON. Em seguida, as rotas do módulo de parafarmácia são importadas de ./Routes/parapharmaRoute. A linha app.use("/parapharma", parapharmaRoutes) associa essas rotas ao prefixo /parapharma. Finalmente, o servidor fica escutando na porta 3000. Isso significa que a API pode ser acessada por http://localhost:3000 e que a rota principal do módulo está disponível por meio de GET /parapharma.

📄 server.js 
const express = require("express");

const app = express();

app.use(express.json());

const parapharmaRoutes =
require("./Routes/parapharmaRoute");

app.use(
"/parapharma",
parapharmaRoutes
);

// INICIAR SERVIDOR

const PORT = 3000;

app.listen(PORT, () => {

console.log(
`🚀 Servidor executando na porta ${PORT}`

});

04

Serviço de Previsão

O arquivo parapharmaservice.js contém a função trainModels(). Essa função representa a camada de serviço do backend. Sua função é preparar os dados e produzir as previsões que posteriormente serão enviadas para a rota Express. O array X contém os valores de entrada 1, 2, 3, 4 e 5. O array y contém os valores reais 100, 200, 300, 400 e 500. O método map() percorre cada valor de X e aplica a regra v * 100. O resultado é armazenado no array predictions. Portanto, para 1 a previsão é 100, para 2 é 200, para 3 é 300, para 4 é 400 e para 5 é 500. A função retorna então um objeto que contém success e um objeto data que contém X, y e predictions. É importante especificar que essa função atualmente não realiza um treinamento real de Machine Learning. Ela simula uma previsão utilizando uma fórmula matemática simples. Em uma versão avançada, essa função poderia chamar um modelo real previamente treinado ou um serviço Python responsável por realizar a previsão.

📄 parapharmaservice.js 
async function trainModels() {

const X = [

1,

2,

3,

4,

5

];

const y = [

100,

200,

300,

400,

500

];

const predictions =

X.map(v => v * 100);

return {

success: true,

data: {

X,

y,

predictions

}

};

}

module.exports = {

trainModels

};

O array X representa os valores de entrada utilizados para produzir as previsões.

Valores Reais y

100,

O array y contém os valores reais correspondentes às diferentes observações. Esses valores podem ser comparados com as previsões para avaliar a diferença entre o valor real e o valor previsto.

Cálculo da Previsão

O método map() percorre cada valor do array X. Para cada valor, aplica a fórmula v * 100. Portanto, o array resultante contém os valores previstos.

Importante:

Na versão atual do código, trainModels() não realiza realmente um treinamento de Machine Learning. As previsões são calculadas diretamente utilizando a regra v * 100. Os arquivos biodream.pkl e bonheur.pkl também são atualmente objetos Python salvos e não modelos treinados. No entanto, essa arquitetura pode servir como base para integrar posteriormente um modelo preditivo real.

05

Rota Express e Processamento dos Resultados

O arquivo parapharmaRoute.js funciona como ponto de coordenação entre o serviço de previsão e o banco de dados MySQL. A rota utiliza router.get("/"), o que significa que, quando um cliente chama GET /parapharma, essa função é executada. O primeiro passo consiste em abrir uma conexão MySQL utilizando getConnection(). O segundo passo consiste em chamar trainModels(). O resultado retornado contém os valores reais e as previsões. O código recupera então result.data.y na variável real e result.data.predictions na variável pred. Em seguida, Math.min() determina o número de elementos compartilhados pelos dois arrays. Um loop for percorre então os valores e utiliza connection.execute() para inserir cada par valor real / previsão na tabela gb_model1. Após a inserção, o Express retorna uma resposta JSON que contém uma mensagem de sucesso, o número de linhas inseridas e os valores reais associados às suas previsões. Portanto, a rota representa a conexão entre o serviço de cálculo e o banco de dados.

📄 parapharmaRoute.js 
const express = require("express");

const router = express.Router();

const {
getConnection
} = require("../DBMysql/parapharmadb");

const {
trainModels
} = require("../service/parapharmaservice");

router.get("/", async (req, res) => {

let connection;

try {

connection =
await getConnection();

const result =
await trainModels();

const real =
result.data.y;

const pred =
result.data.predictions;

const length =
Math.min(
real.length,
pred.length
);

for (

let i = 0;

i < length;

i++

) {

await connection.execute(

    `INSERT INTO gb_model1
    (real_value, prediction)
    VALUES (?, ?)`,

    [
        real[i],
        pred[i]
    ]

);

}

res.status(200).json({

message:
    "Modelo treinado e salvo",

rowsInserted:
    length,

data:
    real.map((r, i) => ({

        real: r,

        prediction:
            pred[i]

    }))

});

} catch (err) {

res.status(500).json({

error:
    err.message

});

} finally {

if (connection) {

await connection.end();

}

}

});

module.exports = router;

Criando o Router 

const router = express.Router();

Essa instrução cria um router do Express. O router permite organizar os endpoints da aplicação e separar as diferentes rotas da API.

Arquitetura

A arquitetura geral do módulo separa o processamento em diferentes camadas. O Python é responsável pelos objetos e modelos armazenados em arquivos PKL. O serviço Node.js prepara os dados e produz as previsões. O Express gerencia a API e as rotas HTTP. O MySQL armazena os resultados. O frontend pode posteriormente consumir a API e apresentar os resultados em gráficos, indicadores ou dashboards.

Python / PKL ↓ biodream.pkl bonheur.pkl ↓ parapharmaservice.js ↓ trainModels() ↓ parapharmaRoute.js ↓ Express API ↓ MySQL ↓ gb_model1 ↓ Frontend ↓ Dashboard
