🏥 SANITAIRE Analytics Dashboard — Documentação Técnica

Esta documentação explica em detalhes como funciona o componente CasaDashboard.jsx, sua conexão com sanitaireSlice.js, seu arquivo CasaDashboard.css, assim como o uso de Redux Toolkit, Axios, Recharts e Power BI.

O componente fornece uma interface de análise que exibe um relatório do Power BI, recupera dados sanitários do armazenamento Redux e representa os valores e a previsão por meio de um gráfico de barras.

1. Visão geral do projeto

O componente CasaDashboard.jsx representa a interface principal do Dashboard dedicada aos dados de SANITAIRE.

Ele utiliza React para construir a interface, Redux Toolkit para recuperar e gerenciar os dados globais, Axios para se comunicar com o backend e Recharts para criar um BarChart.

O Dashboard também contém um relatório do Power BI integrado diretamente na página por meio de um elemento iframe.

CasaDashboard.jsx ↓ useEffect() ↓ dispatch(fetchSanitaireData()) ↓ sanitaireSlice.js ↓ Axios ↓ GET /sanitaire ↓ Backend ↓ Redux Store ↓ data / loading / error ↓ CasaDashboard.jsx ↓ Informações + BarChart ↓ CasaDashboard.css ↓ Interface final

17. Função assíncrona do Thunk

...
}

A função é declarada com async porque precisa aguardar a resposta do servidor.

O primeiro parâmetro é representado por _. Isso significa que nenhum dado específico é enviado como argumento dessa ação.

thunkAPI fornece várias funcionalidades internas do Redux Toolkit, incluindo rejectWithValue, utilizado para gerenciar erros.

27. Uso de extraReducers

extraReducers: (builder) => {

builder
    ...
}

extraReducers gerencia as diferentes etapas da ação assíncrona criada com createAsyncThunk.

São gerenciados três estados principais:

fetchSanitaireData.pending ↓ Requisição em andamento fetchSanitaireData.fulfilled ↓ Requisição realizada com sucesso fetchSanitaireData.rejected ↓ Requisição falhou

28. Estado pending

.addCase(fetchSanitaireData.pending, (state) => {

state.loading = true;

state.error = null;

})

pending significa que a requisição está atualmente em andamento.

O Redux então define: 

state.loading = true;

e redefine o erro: 

state.error = null;

No React, isso permite exibir a seguinte mensagem: 

Loading...

29. Estado fulfilled

.addCase(fetchSanitaireData.fulfilled, (state, action) => {

state.loading = false;

state.data = action.payload;

})

fulfilled significa que a requisição foi realizada com sucesso.

O carregamento é finalizado: 

state.loading = false;

Os dados recebidos são então armazenados em: 

state.data = action.payload;

action.payload corresponde ao valor retornado por: 

return response.data.data;

30. Estado rejected

.addCase(fetchSanitaireData.rejected, (state, action) => {

state.loading = false;

state.error = action.payload;

})

rejected é ativado quando a recuperação dos dados falha.

O carregamento é interrompido: 

state.loading = false;

O erro é então armazenado em: 

state.error = action.payload;

O componente React pode posteriormente exibir esse erro.

69. O que CasaDashboard.jsx realmente faz

O componente CasaDashboard.jsx atua principalmente como uma camada de apresentação e orquestração.

Ele não contém diretamente a lógica interna da requisição HTTP.

Ele solicita a recuperação dos dados por meio de: 

dispatch(fetchSanitaireData());

O slice Redux se comunica posteriormente com o backend por meio do Axios.

O componente recupera então o resultado por meio de: 

useSelector((state) => state.sanitaire)

Finalmente, ele utiliza os dados para exibir o modelo, a previsão, o gráfico e o relatório Power BI.

75. Resumo final para lembrar

React constrói a interface → useEffect ativa fetchSanitaireData() → Redux Toolkit gerencia o estado → createAsyncThunk inicia a operação assíncrona → Axios se comunica com o backend → /sanitaire retorna os dados → Redux armazena data, loading e error → useSelector recupera essas informações → React exibe o modelo e a previsão → chartData prepara os dados → Recharts constrói o BarChart → Power BI exibe o relatório de análise → CasaDashboard.css controla a apresentação.

O componente CasaDashboard.jsx constitui, portanto, a interface principal do Dashboard SANITAIRE.

Ele ativa a recuperação dos dados por meio de dispatch(fetchSanitaireData()) e recupera o estado Redux por meio de: 

useSelector((state) => state.sanitaire)

O arquivo sanitaireSlice.js é responsável pela lógica de recuperação dos dados. Ele utiliza createAsyncThunk e Axios para enviar uma requisição GET para: 

http://localhost:3000/sanitaire

O slice gerencia posteriormente os três estados da requisição: pending, fulfilled e rejected.

Quando os dados estão disponíveis, eles são armazenados em state.sanitaire.data. O componente recupera então o modelo, os valores e a previsão.

Os valores são posteriormente transformados em chartData para construir um BarChart utilizando Recharts.

O gráfico compara três elementos: Value 1, Value 2 e Prediction.

Ao mesmo tempo, o relatório Power BI é integrado por meio de um iframe, permitindo que o relatório de Business Intelligence seja exibido diretamente dentro da aplicação React.

Finalmente, CasaDashboard.css é responsável pela apresentação visual do Dashboard, enquanto sanitaireSlice.js gerencia os dados e o estado Redux.
