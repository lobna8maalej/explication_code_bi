01

General System Overview

The Sanitaire system is a Web architecture that integrates a Machine Learning model in order to automatically produce a prediction from numerical variables. The objective of this architecture is to clearly separate the Artificial Intelligence component from the Web application component. The Machine Learning model is developed and trained in Python and then saved in a file called CASA.pkl. This file contains the already-trained model and makes it possible to reuse the learned knowledge without having to perform the training phase again for every prediction. The Python script sanitaire.py represents the prediction engine. It loads the model using the joblib library, retrieves the values sent by Node.js, converts them into numbers using float(), creates a NumPy array and then uses the model's predict() method to obtain the prediction. The result is then converted into a JSON object so that it can be easily retrieved by the Node.js backend. On the JavaScript side, the sanitaireService.js service uses the native child_process module and the spawn() function to launch the Python program from Node.js. The service passes the model type and numerical values as arguments to the Python process. Node.js then retrieves the standard output stdout produced by Python and searches for the line containing the JSON result. This line is then parsed using JSON.parse(). The Express router sanitaireRoute.js then exposes an API that allows the frontend to request a prediction. In the provided example, the route calls the service using the model identified by "1" and the values 10 and 20. The result is then returned to the frontend as JSON with a message property and a data property. Finally, the project also contains a MySQL connection module that allows a connection to the POWERBI_PREDICTION database. The complete architecture therefore forms a system in which Python handles the Machine Learning processing, Node.js handles execution and communication with Python, Express provides the Web API, and MySQL can provide data persistence.

Python Prediction Script

The file sanitaire.py represents the core of the Machine Learning processing. Its main role is to load the CASA.pkl model, retrieve the variables transmitted by Node.js, prepare the data in numerical form and execute the prediction. The script begins by importing several libraries. The load function from joblib is used to reload the saved Machine Learning model. The NumPy library is used to create the numerical array passed to the model. The sys module provides access to the arguments sent by Node.js, while the os module is used to construct a reliable path to the model file. Finally, json is used to convert the prediction result into JSON format. The program first determines the directory containing the script using os.path.dirname(__file__). The path to CASA.pkl is then constructed using os.path.join(). The model is loaded using load(). The script then retrieves the arguments from sys.argv[2:]. The second argument and the following arguments correspond to the numerical values, because the first argument after the script represents the model type in this architecture. The values are converted into decimal numbers using map(float, ...). They are then placed into a NumPy array using np.array([values]). This structure corresponds to the format expected by Scikit-learn Machine Learning models. The script also displays several debugging details: the received values, the shape of the array and the number of features expected by the model through model.n_features_in_. This information makes it possible to verify that the data transmitted by Node.js matches the structure used during training. The model.predict(X) method then performs the prediction. Finally, the script creates a JSON object containing the model name, the prediction and the values used. This object is sent using print(), allowing Node.js to retrieve it through stdout.

Importing the Libraries 

from joblib import load
import numpy as np
import sys
import os
import json

joblib is used to load the saved model. NumPy is used to create the numerical input array. sys retrieves the arguments transmitted by Node.js. os manages file paths, while json produces a structured response compatible with JavaScript.

Determining the Model Directory 

BASE_DIR = os.path.dirname(__file__)

model = load(
os.path.join(
BASE_DIR,
"CASA.pkl"
)
)

BASE_DIR represents the directory containing the Python script. os.path.join() then constructs the path to CASA.pkl. The model is loaded using joblib.load(). This approach prevents the application from depending on the directory from which Node.js launches the program.

Retrieving Arguments 

values = list(
map(float, sys.argv[2:])
)

The program retrieves the arguments from sys.argv[2:]. The first argument passed after the script represents the model type, while the following arguments correspond to the values used for the prediction. Each value is converted into a decimal number using float() in order to obtain data compatible with the Machine Learning model.

Creating the NumPy Array 

X = np.array([values])

The values are transformed into a NumPy array. Using brackets around values represents the data as an observation containing multiple features. This structure is compatible with the predict() method used by the model.

Data Validation 

print("VALUES =", values)
print("SHAPE =", X.shape)
print("FEATURES =", model.n_features_in_)

These three instructions are mainly used for debugging. The first displays the received values, the second displays the dimensions of the NumPy array, and the third displays the number of features expected by the model. This makes it possible to quickly detect an incompatibility between the data sent by Node.js and the data used during model training.

Executing the Prediction 

prediction = model.predict(X)

The predict() method applies the Machine Learning model to the prepared data. The model uses the parameters learned during training to calculate the predicted value.

Creating the JSON Response 

print(json.dumps({
"model": "CASA",
"prediction": float(prediction[0]),
"values": values
}))

The prediction result is placed into an object containing three pieces of information: the model name, the predicted value and the input values. prediction[0] retrieves the first prediction and float() converts this value into a standard Python number. json.dumps() then converts the Python object into a JSON string. This string is retrieved by Node.js through stdout.

03

CASA Machine Learning Model

The file CASA.pkl represents the Machine Learning model used by the Sanitaire system. Unlike a Python program that would have to train the model every time it runs, the PKL file directly contains the already-trained model. The Python script therefore only needs to load this object using Joblib and provide it with new data to predict. This separation between training and prediction is important in a professional architecture because training can be performed periodically on a complete dataset, while the saved model can then be used by the Web application. The model.n_features_in_ property also makes it possible to determine the number of variables expected by the model. In the provided code, Node.js sends, for example, two values: 10 and 20. The model must therefore be compatible with this input structure. If the number of variables sent does not match the number expected by the model, a dimension error may occur. The debugging information displayed by the application makes it possible to verify this correspondence.

Model workflow: Input Data → NumPy Array → CASA.pkl → predict() → Predicted Value

Node.js Service and Communication with Python

The file sanitaireService.js acts as a bridge between Node.js and Python. Node.js does not directly perform the Machine Learning prediction; instead, it launches the Python program using the native child_process module. The runPlotPython() function returns a Promise, which makes it possible to handle the Python process asynchronously. The function receives two parameters: modelType and values. The modelType parameter represents the type of model to use, while values contains the numerical variables. The spawn() function then launches Python with the path to the sanitaire.py script. The array passed to spawn contains the Python program path, the model type and all values converted to strings using values.map(String). Python therefore receives the data as command-line arguments. Node.js then listens to the data event of stdout in order to progressively retrieve the output generated by the Python program. Because Python also displays debugging information before the JSON, the service does not immediately attempt to parse the entire output. When the process finishes, the code uses split("\n") to separate the lines, map(l => l.trim()) to remove unnecessary spaces, and filter(l => l.startsWith("{")) to search for lines beginning with a brace and therefore potentially corresponding to the final JSON. The pop() method then retrieves the last JSON line found. Finally, JSON.parse() converts the JSON string into a JavaScript object. This object can then be returned to the Express route. This technique allows Node.js to properly retrieve the Python result even when the script also produces debugging information.

Importing the Modules 

const { spawn } =
require("child_process");

const path =
require("path");

The child_process module provides spawn(), which allows an external process to be launched. The path module is used to reliably construct the path to the Python script.

Creating the Python Path 

path.join(
__dirname,
"../../python/sanitaire.py"
)

__dirname represents the directory of the current JavaScript file. The path.join() function makes it possible to navigate to the Python directory and locate sanitaire.py.

Launching the Python Process 

const py = spawn("python", [
path.join(
    __dirname,
    "../../python/sanitaire.py"
),
modelType,
...values.map(String)
]);

This instruction launches Python and passes the required parameters. The first parameter is the script path, the second is the model type, and the following parameters correspond to the numerical values. The spread operator ... allows each value to be added individually to the arguments array.

Retrieving stdout 

py.stdout.on("data", (data) => {
output += data.toString();
});

Python uses print() to return information to Node.js. Node.js receives this data through stdout. The received chunks are added to the output variable in order to reconstruct the complete Python output.

Error Handling 

py.stderr.on("data", (data) => {
error += data.toString();
});

stderr is used to retrieve possible error messages generated by Python. This provides Node.js with additional information when an error occurs.

Parsing the Python Response 

const jsonLine = output
.split("\n")
.map(l => l.trim())
.filter(l => l.startsWith("{"))
.pop();

This part is particularly important because the Python script displays debugging information before printing the JSON. The service splits the output into multiple lines, removes unnecessary spaces, keeps the lines beginning with a brace and retrieves the last matching line. This last line is then considered the final JSON result.

JSON Conversion 

resolve(
JSON.parse(jsonLine)
);

JSON.parse() transforms the JSON string produced by Python into a JavaScript object. resolve() then passes this object to the function that called the service.

Express Route and Sanitaire API

The file sanitaireRoute.js represents the API layer of the system. Express is imported and a router is created using express.Router(). The sanitaireService service is then imported so that the route can trigger the Python program. The GET / route is declared as an asynchronous function using the async keyword. When a request is received, the route calls runPlotPython("1", [10, 20]). The first argument represents the model type and the array contains the numerical variables. The route uses await to wait for the Python execution to complete. When the service returns the JSON object, Express builds a response containing message: "OK" and data: result. This response can then be consumed by the frontend. If an error occurs during Python execution or JSON parsing, the catch block intercepts the error and returns HTTP status 500. This architecture prevents the frontend from communicating directly with Python. The frontend communicates only with the Express API, while Express uses the Node.js service to launch the Python model.

Creating the Router 

const express =
require("express");

const router =
express.Router();

Express provides the functionality required to create the API. The router groups the endpoints related to the Sanitaire domain.

Calling the Python Service 

const result =
await runPlotPython(
"1",
[10, 20]
);

The route asks the Node.js service to execute Python using model type "1" and two numerical variables. The await keyword makes the route wait for the result before continuing.

API Response 

res.json({
message: "OK",
data: result
});

Express returns a JSON response. The message property indicates that the operation completed successfully, while data contains the result obtained from Python.

Error Handling 

catch (err) {

res.status(500).json({
    error: err.toString()
});
}

In case of an error, Express returns HTTP status 500 together with a description of the error. This allows the frontend to identify that a problem occurred in the backend.

MySQL Connection

The project also contains a module dedicated to connecting to a MySQL database. The file sanitaireDb.js uses the mysql2/promise package, which allows communication with MySQL using Promises and therefore an async/await syntax. The configuration contains the server address localhost, the user root, an empty password in the presented environment, and the database POWERBI_PREDICTION. The getConnection() function creates a new connection using mysql.createConnection() and then returns this connection using await. Keeping this logic in a dedicated file makes it possible to centralize the database configuration and easily reuse the function in different controllers or services. In the Sanitaire route, the getConnection function can be imported whenever necessary to retrieve or store data in MySQL. The database can therefore complement the Machine Learning component by storing information required by the application, prediction results or other data used by the dashboard.

The module exports getConnection so that other backend files can use it. Using mysql2/promise simplifies asynchronous connection management and makes it possible to integrate MySQL into the Node.js architecture.

Starting the Express Server

The main server file initializes the Express application. The express constant imports the framework and app = express() creates the application. The express.json() middleware allows the server to process JSON data sent through HTTP requests. The project then starts the Python process using spawn() and defines the working directory through cwd. The Sanitaire route is then imported from sanitaireRoute and registered using app.use("/sanitaire", sanitaireRoute). This means that the endpoints defined in the router will be accessible under the /sanitaire prefix. Finally, app.listen(3000) starts the HTTP server on port 3000. The message displayed in the console confirms that the API has started. The complete configuration therefore makes the Machine Learning system accessible through a Node.js / Express Web API.

Complete System Architecture

The complete architecture is based on communication across several layers. The process starts at the frontend or dashboard level, which sends an HTTP request to the Express API. Express receives the request through the Sanitaire route and calls the runPlotPython() function from the Node.js service. This function uses spawn() to create an independent Python process. Python receives the model type and numerical variables. The sanitaire.py script then loads CASA.pkl using Joblib. The received variables are converted into numbers and then transformed into a NumPy array. The model then applies the predict() method to calculate the prediction. Python creates a JSON object containing the model name, the prediction and the input values. Node.js retrieves the Python output through stdout. Since the script also displays debugging information, the service searches for the last line beginning with a brace in order to identify the final JSON. JSON.parse() then converts this string into a JavaScript object. The result is returned to Express, which creates the HTTP response intended for the frontend. In parallel, the MySQL module allows the backend to establish a connection to the POWERBI_PREDICTION database. This database can be used to store information required by the application or to keep the results generated by the system. The complete architecture therefore separates responsibilities: the frontend handles visualization, Express handles the API, Node.js handles orchestration, Python handles Machine Learning, Joblib handles model loading, NumPy handles data preparation, and MySQL handles persistence.

Practical Example of the Workflow

To understand the complete workflow, imagine that the frontend calls the Sanitaire API. Express receives the request and executes the runPlotPython("1", [10, 20]) function. Node.js then launches the sanitaire.py program using Python. The transmitted parameters are model type 1, followed by the values 10 and 20. Python retrieves these parameters using sys.argv. The expression sys.argv[2:] retrieves the two numerical values and converts them into decimal numbers. The program then creates X = np.array([values]). The CASA.pkl model is loaded using Joblib and receives the array through the predict() method. Python then obtains the prediction and creates a JSON object containing the CASA model, the predicted value and the values used. Node.js retrieves the complete Python output through stdout. Because Python also displays the debug information VALUES, SHAPE and FEATURES, the service filters the lines in order to retrieve only the last JSON line. This string is then converted into a JavaScript object using JSON.parse(). Express finally receives this object and returns a JSON response to the frontend. The dashboard can then use the prediction to display a KPI, statistical card, chart or table. This workflow clearly shows how a Python-based prediction can be integrated into a Node.js Web application without requiring the frontend to execute Python directly.
