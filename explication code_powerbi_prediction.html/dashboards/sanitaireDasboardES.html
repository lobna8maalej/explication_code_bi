🏥 SANITAIRE Analytics Dashboard — Documentación Técnica

Esta documentación explica en detalle cómo funciona el componente CasaDashboard.jsx, su conexión con sanitaireSlice.js, su archivo CasaDashboard.css, así como el uso de Redux Toolkit, Axios, Recharts y Power BI.

El componente proporciona una interfaz de análisis que muestra un informe de Power BI, recupera datos sanitarios desde el almacén Redux y representa los valores y la predicción mediante un gráfico de barras.

1. Descripción general del proyecto

El componente CasaDashboard.jsx representa la interfaz principal del Dashboard dedicada a los datos de SANITAIRE.

Utiliza React para construir la interfaz, Redux Toolkit para recuperar y gestionar los datos globales, Axios para comunicarse con el backend y Recharts para crear un BarChart.

El Dashboard también contiene un informe de Power BI integrado directamente en la página mediante un elemento iframe.

CasaDashboard.jsx ↓ useEffect() ↓ dispatch(fetchSanitaireData()) ↓ sanitaireSlice.js ↓ Axios ↓ GET /sanitaire ↓ Backend ↓ Redux Store ↓ data / loading / error ↓ CasaDashboard.jsx ↓ Información + BarChart ↓ CasaDashboard.css ↓ Interfaz final

La función se declara con async porque debe esperar la respuesta del servidor.

thunkAPI proporciona varias funcionalidades internas de Redux Toolkit, incluyendo rejectWithValue, que se utiliza para gestionar errores.

28. Estado pending

state.loading = true;

state.error = null;

})

pending significa que la solicitud está actualmente en progreso.

Redux establece entonces:

En React, esto permite mostrar el siguiente mensaje:

29. Estado fulfilled

.addCase(fetchSanitaireData.fulfilled, (state, action) => {

state.loading = false;

state.data = action.payload;

})

fulfilled significa que la solicitud se realizó correctamente.

La carga finaliza: 

state.loading = false;

Los datos recibidos se almacenan entonces en: 

state.data = action.payload;

action.payload corresponde al valor devuelto por:

30. Estado rejected

.addCase(fetchSanitaireData.rejected, (state, action) => {

state.loading = false;

state.error = action.payload;

})

rejected se activa cuando falla la recuperación de datos.

La carga se detiene: 

state.loading = false;

El error se almacena entonces en: 

state.error = action.payload;

El componente React puede mostrar posteriormente este error.

69. Qué hace realmente CasaDashboard.jsx

El componente CasaDashboard.jsx actúa principalmente como una capa de presentación y orquestación.

No contiene directamente la lógica interna de la solicitud HTTP.

Solicita la recuperación de datos mediante: 

dispatch(fetchSanitaireData());

El slice Redux se comunica posteriormente con el backend mediante Axios.

El componente recupera entonces el resultado mediante: 

useSelector((state) => state.sanitaire)

Finalmente, utiliza los datos para mostrar el modelo, la predicción, el gráfico y el informe Power BI.

75. Resumen final para recordar

React construye la interfaz → useEffect activa fetchSanitaireData() → Redux Toolkit gestiona el estado → createAsyncThunk inicia la operación asíncrona → Axios se comunica con el backend → /sanitaire devuelve los datos → Redux almacena data, loading y error → useSelector recupera esta información → React muestra el modelo y la predicción → chartData prepara los datos → Recharts construye el BarChart → Power BI muestra el informe de análisis → CasaDashboard.css controla la presentación.

El componente CasaDashboard.jsx constituye por lo tanto la interfaz principal del Dashboard SANITAIRE.

Activa la recuperación de datos mediante dispatch(fetchSanitaireData()) y recupera el estado Redux mediante: 

useSelector((state) => state.sanitaire)

El archivo sanitaireSlice.js es responsable de la lógica de recuperación de datos. Utiliza createAsyncThunk y Axios para enviar una solicitud GET a: 

http://localhost:3000/sanitaire

El slice gestiona posteriormente los tres estados de la solicitud: pending, fulfilled y rejected.

Cuando los datos están disponibles, se almacenan en state.sanitaire.data. El componente recupera entonces el modelo, los valores y la predicción.

Los valores se transforman posteriormente en chartData para construir un BarChart utilizando Recharts.

El gráfico compara tres elementos: Value 1, Value 2 y Prediction.

Al mismo tiempo, el informe Power BI se integra mediante un iframe, permitiendo que el informe de Business Intelligence se muestre directamente dentro de la aplicación React.

Finalmente, CasaDashboard.css se encarga de la presentación visual del Dashboard, mientras que sanitaireSlice.js gestiona los datos y el estado Redux.
