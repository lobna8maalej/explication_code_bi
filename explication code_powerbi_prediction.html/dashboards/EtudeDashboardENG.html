📊 Study Dashboard with Redux Toolkit and React

Detailed explanation of how the Redux file etudeSlice.js and the React component EtudeDashboard.jsx work.

76 General Overview

This part of the project implements a dashboard dedicated to analyzing study-abroad data using several complementary frontend technologies, including React, Redux Toolkit, Axios and Recharts. The main objective is to automatically retrieve data from the backend, store it in the Redux store, manage the different request states, and then present the results in a React interface in the form of a list and a chart. The React component EtudeDashboard communicates with the backend through the asynchronous action fetchEtudeData. This action is created with createAsyncThunk and uses Axios to send an HTTP GET request to http://localhost:3000/etude/dashboard. The backend returns the data in JSON format and the code specifically retrieves the data property from the response. This information is then sent to Redux, which stores it in the items property of the global state. The React component then retrieves the data using useSelector. The useEffect hook is used to automatically trigger the data retrieval action when the page is loaded. The retrieved data is then transformed using map() in order to create an array adapted to Recharts. Each element contains a name corresponding to the mode, a real value, and a prediction value. The component also displays the Power BI dashboard through an iframe element. Finally, Recharts is used to create a bar chart for visualizing the predictions. This architecture therefore clearly separates data management, handled by Redux Toolkit, from presentation and interaction, handled by React.

77 Importing Redux Toolkit and Axios

The Redux file begins by importing createSlice and createAsyncThunk from Redux Toolkit. The createSlice function is used to create a part of the Redux store dedicated to study data. It allows us to define the slice name, the initial state, and the processing associated with the different situations of the asynchronous request. The createAsyncThunk function is used to create an asynchronous action capable of communicating with the backend. The code also imports axios, which is used as an HTTP client to send the request to the Node.js/Express API. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

These imports therefore form the basis of communication between the React frontend, the Redux store, and the backend.

78 Creating the fetchEtudeData Asynchronous Action

The main action of the Redux file is fetchEtudeData. It is created using createAsyncThunk. This function makes it possible to perform an asynchronous operation while allowing Redux Toolkit to automatically manage the pending, fulfilled, and rejected states. The first argument, "etude/fetchEtudeData", corresponds to the Redux action type. It allows this operation to be identified within the application. The second argument is an asynchronous function that will be executed when the action is called from the React component. 

export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        try {
            const response = await axios.get(
                "http://localhost:3000/etude/dashboard"
            );

            return response.data.data;

        } catch (error) {
            return thunkAPI.rejectWithValue(error.message);
        }
    }
);

The _ symbol represents the first argument of the function, but it is not used because this action does not require any data to be sent by the component. The second parameter thunkAPI makes it possible, among other things, to use rejectWithValue to send a custom error to the Redux state.

79 Axios Request to the Backend

Inside the asynchronous function, Axios performs an HTTP GET request to the /etude/dashboard route. The use of the await keyword makes it possible to wait for the server response before continuing execution. When the backend responds, Axios places the response inside the response object. The data returned by the server can be accessed through response.data. In this project, the response itself contains a data property. Therefore, the code retrieves response.data.data, which corresponds to the array containing the data required by the dashboard. 

const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

return response.data.data;

The return statement is particularly important because the returned value becomes the payload of the action when the request completes successfully.

80 Error Handling with try / catch

The request is placed inside a try / catch structure. The try block contains the Axios request and its normal processing. If the request fails, for example when the backend server is stopped, when the URL is incorrect, or when a network error occurs, execution moves to the catch block. The code then retrieves the error message using error.message and uses thunkAPI.rejectWithValue() to send this information to Redux. The React component can then retrieve this error through the error property. 

catch (error) {
    return thunkAPI.rejectWithValue(error.message);
}

81 Creating the etudeSlice

The code then creates the Redux slice dedicated to study data using createSlice. The name property defines the name of this part of the store. In this case, the name is etude. This identification makes it possible to access the data through state.etude in the React component. 

const etudeSlice = createSlice({
    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    reducers: {},

    extraReducers: (builder) => {
        // ...
    }
});

The use of extraReducers is appropriate here because the fetchEtudeData action was created with createAsyncThunk. The states automatically generated by this action are therefore handled in this section.

82 Defining the initialState

The initialState represents the initial state of the study module. The items property is initialized with an empty array because no data has been retrieved yet. The loading property is initialized to false, which means that no request is currently in progress. Finally, the error property is initialized to null because no error has occurred yet. These three properties allow the React component to know the current state of the data retrieval process. 

initialState: {
    items: [],
    loading: false,
    error: null
}

83 Managing the pending State

When the React component executes dispatch(fetchEtudeData()), Redux Toolkit automatically triggers the pending state. This state means that the request is in progress. The code then sets state.loading to true and resets the error property to null. Thanks to this information, React can display a loading message to the user while the backend processes the request. 

.addCase(fetchEtudeData.pending, (state) => {
    state.loading = true;
    state.error = null;
})

84 Managing the fulfilled State

When the Axios request completes successfully, Redux Toolkit triggers the fulfilled state. This means that the backend responded correctly and the data was retrieved. The code sets loading to false because the loading process is complete. Then, action.payload contains the data returned by fetchEtudeData. This data is directly stored in state.items. It therefore becomes available in the Redux store. 

.addCase(fetchEtudeData.fulfilled, (state, action) => {
    state.loading = false;
    state.items = action.payload;
})

This step is essential because it moves the data from the backend into the Redux store. The React component can then retrieve it using useSelector.

85 Managing the rejected State

If an error occurs during the request, Redux Toolkit triggers the rejected state. The code first sets loading to false because the request has finished, then retrieves the error message through action.payload. This corresponds to the value sent by rejectWithValue inside the catch block. The error is then stored in state.error. The React component can therefore display this error to the user. 

.addCase(fetchEtudeData.rejected, (state, action) => {
    state.loading = false;
    state.error = action.payload;
})

86 Exporting the Reducer

At the end of the Redux file, the slice reducer is exported using export default etudeSlice.reducer. This reducer can then be added to the application's main Redux store. It represents the logic responsible for modifying the etude state. 

export default etudeSlice.reducer;

87 Importing React Features

The React file begins by importing React as well as the useEffect hook. It also imports useDispatch and useSelector from React Redux. The component then imports the fetchEtudeData action from the Redux file. Finally, several Recharts components are imported in order to build the visualization chart. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchEtudeData } from "../redux/etudeSlice";

88 Using useDispatch

Inside the EtudeDashboard component, the useDispatch hook provides access to the dispatch function. This function is used to send an action to the Redux store. In our case, it is used to trigger the fetchEtudeData() action. React therefore does not directly perform the Axios request. Instead, it asks Redux to perform this operation. 

const dispatch = useDispatch();

89 Using useSelector

The useSelector hook allows the React component to retrieve data stored in the Redux store. The code accesses state.etude and directly extracts the items, loading, and error properties. Therefore, the component knows which data is available, whether a request is in progress, and whether an error message exists. 

const { items, loading, error } =
    useSelector(state => state.etude);

90 Automatic Data Retrieval with useEffect

The useEffect hook is used to automatically start data retrieval when the component is loaded. Inside the hook, the code calls dispatch(fetchEtudeData()). This triggers the Redux action and therefore the Axios request to the backend. The user does not need to click a button to retrieve the data. The data loading process is therefore automatic when the dashboard page is opened. 

useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

91 Transforming Data with map()

After retrieving the data from Redux, the component creates a new variable called chartData. This variable is built using the JavaScript map() method. The map method iterates through each element of the items array and creates a new object adapted to Recharts. For each element, the name property receives the value of item.mode, the Value property receives the real value item.value, and the Prediction property receives the prediction. The ?? operator provides the value 0 when the prediction is null or undefined. 

const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

This transformation produces exactly the data structure expected by the BarChart component.

92 Power BI Dashboard Integration

The React component also integrates a Power BI report using an iframe element. This technique makes it possible to display external content directly inside the web page. The src attribute contains the address of the published Power BI report. The user can therefore access the Power BI dashboard directly from the React interface. The allowFullScreen property also allows full-screen display when this feature is available. 

<iframe
    className="etude-iframe"
    title="etude A L'Etranger"
    src="URL_DU_RAPPORT_POWER_BI"
    allowFullScreen
/>

This integration makes it possible to combine Power BI visualizations and dynamic data coming from the backend on the same page.

93 Managing loading and error

The React component uses the loading and error properties retrieved from Redux to inform the user about the state of the request. When loading is true, the component displays a Loading... message. When error contains a value, the error message is displayed. This logic makes the interface clearer and allows the user to understand what is happening while the data is being retrieved. 

{loading && (
    <p className="etude-loading">
        Loading...
    </p>
)}

{error && (
    <p className="etude-error">
        {error}
    </p>
)}

94 Displaying Data as a List

The component then displays the retrieved data as an HTML list. The map() method is used to iterate through the items array. For each element, an li element is created. The key property allows React to uniquely identify each element during rendering. For each row, the component displays the mode, the real value, and the prediction. The ?? operator displays N/A when no prediction is available. 

<ul className="etude-list">

    {items.map((item, i) => (
        <li key={i}>
            Mode: {item.mode}
            | Value: {item.value}
            | Prediction: {item.prediction ?? "N/A"}
        </li>
    ))}

</ul>

95 Creating the Chart with Recharts

The Recharts library is used to transform the data into a graphical representation. The ResponsiveContainer component allows the chart to automatically adapt to the available width. The BarChart component receives the chartData array. The XAxis and YAxis components respectively represent the horizontal and vertical axes. CartesianGrid adds a grid to make the chart easier to read. Tooltip displays information when the user moves the mouse over a bar, while Legend displays the chart legend. Finally, the Bar component uses the dataKey="Prediction" property to represent the predictions graphically. 

<ResponsiveContainer width="100%" height={350}>

    <BarChart data={chartData}>

        <CartesianGrid strokeDasharray="3 3" />

        <XAxis dataKey="name" />

        <YAxis />

        <Tooltip />

        <Legend />

        <Bar
            dataKey="Prediction"
            fill="#6366f1"
        />

    </BarChart>

</ResponsiveContainer>

96 Overall Redux and React Workflow

The process starts when the user opens the EtudeDashboard page. React mounts the component and executes the useEffect hook. This triggers dispatch(fetchEtudeData()). Redux Toolkit then launches the asynchronous action created with createAsyncThunk. The pending state is automatically triggered and the loading property becomes true. Axios then sends a GET request to the backend. The backend processes the request and returns the dashboard data. If the request succeeds, Redux triggers fulfilled, sets loading to false, and stores the data in state.items. The React component then retrieves this data using useSelector. The data is used to build the list and the chartData array. This array is passed to Recharts to create the chart. If an error occurs, the rejected state is triggered, the error is stored in Redux, and React can display the corresponding message.

97 Complete Frontend Architecture

This feature illustrates an organized frontend architecture in which each technology has a specific role. React is responsible for the user interface and component rendering. Redux Toolkit is used to centralize study data in the global store. createAsyncThunk simplifies the management of asynchronous operations. Axios handles HTTP communication between the frontend and backend. useEffect automatically triggers data retrieval. useDispatch allows React to send the Redux action, while useSelector allows the results to be retrieved from the store. The map() method transforms the received data to adapt it to the chart. Finally, Recharts creates an interactive graphical visualization, while Power BI provides business intelligence visualization integrated into the same page. This separation of responsibilities makes the code more organized, maintainable, and easier to evolve.

98 Conclusion

The Study Dashboard represents a complete data retrieval, management, and visualization pipeline. The process starts in React with useEffect, which triggers the Redux action fetchEtudeData. This action uses createAsyncThunk and Axios to communicate with the backend. Redux Toolkit then automatically manages the three main stages of the request: pending while the data is loading, fulfilled when the data is successfully retrieved, and rejected when an error occurs. The received data is stored in state.etude.items and then retrieved in React using useSelector. The component then transforms the information using map() to create the data required by Recharts. The results are displayed as a list and a chart, while Power BI is integrated through an iframe. The entire system therefore forms a complete frontend architecture in which the backend provides the data, Redux Toolkit centralizes it, and React presents it to the user. This organization makes it possible to build a dynamic dashboard capable of displaying both real data and prediction results in a modern interface.
