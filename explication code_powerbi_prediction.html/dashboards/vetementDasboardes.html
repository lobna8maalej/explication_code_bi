👕 Vetement ML Dashboard — Documentación técnica

Esta documentación explica en detalle el funcionamiento del componente VetementDashboard.jsx, su comunicación con el backend mediante Fetch API, la estructura del archivo vetementSlice.js, así como el uso de React, Redux Toolkit, Recharts, ScatterChart, Power BI y del sistema de Machine Learning.

El Dashboard de Ropa permite enviar automáticamente datos relacionados con un producto de vestuario al backend.

Los datos enviados son:

  • Prix_C1 = 150
  • Prix_C2 = 180
  • numbers = 15
  • Target = 1

La solicitud se envía mediante el método HTTP POST a: 

http://localhost:3000/vetement

El backend procesa estos datos y devuelve una respuesta JSON. Esta respuesta se almacena en la variable de estado items.

Los datos devueltos se utilizan después para construir un Scatter Plot con Recharts.

En paralelo, un informe de Power BI se muestra directamente en el Dashboard mediante un iframe.

1. Presentación general del proyecto

El componente VetementDashboard.jsx representa la interfaz React del Dashboard dedicado a los datos de ropa.

Su objetivo es enviar automáticamente datos al backend para obtener una respuesta del sistema de procesamiento y Machine Learning.

El componente muestra después los datos recibidos en forma de un Scatter Plot.

También contiene un informe de Power BI integrado mediante un iframe.

48. extraReducers 

extraReducers: (builder) => {
    builder
        ...
}

extraReducers permite que el Slice reaccione a los diferentes estados de la acción asíncrona fetchVetementData.

Se gestionan tres estados principales:

  • pending
  • fulfilled
  • rejected

49. Estado pending 

.addCase(
    fetchVetementData.pending,
    (state) => {
        state.loading = true;
        state.error = null;
    }
)

Cuando comienza la solicitud, Redux establece: 

loading = true

El error anterior también se elimina: 

error = null

50. Estado fulfilled 

.addCase(
    fetchVetementData.fulfilled,
    (state, action) => {
        state.loading = false;
        state.items = action.payload;
    }
)

Cuando la solicitud tiene éxito:

  • loading se convierte en false
  • items recibe los datos devueltos por la acción asíncrona. 
Solicitud exitosa
      ↓
fulfilled
      ↓
loading = false
      ↓
items = action.payload

51. Estado rejected 

.addCase(
    fetchVetementData.rejected,
    (state, action) => {
        state.loading = false;
        state.error = action.payload;
    }
)

Si la solicitud falla: 

loading = false

y el mensaje de error se almacena en: 

error = action.payload

54. Punto importante: Fetch y Redux no se utilizan juntos en este componente

En el código proporcionado, VetementDashboard.jsx utiliza directamente Fetch API con useState.

No utiliza useDispatch() ni useSelector().

Sin embargo, vetementSlice.js tiene su propia lógica de Redux con fetchVetementData() y Axios.

Por lo tanto, es necesario distinguir los dos flujos:

Backend
        ↓

        ↓
ScatterChart


FLUJO REDUX DEL SLICE

fetchVetementData()
        ↓
Axios GET
        ↓
/vetement
        ↓
Redux
        ↓
items / loading / error

55. ¿Por qué es importante esta distinción?

Esta distinción permite comprender con precisión la arquitectura actual del proyecto.

Actualmente, el Dashboard utiliza un estado local de React: 

const [items, setItems] = useState(null);

mientras que el Slice de Redux tiene su propio estado: 

{
    items: null,
    loading: false,
    error: null
}

Por lo tanto, actualmente existen dos mecanismos para gestionar los datos de Ropa.
