🛒 Gestion des données Commerce avec Redux Toolkit et React

Documentation complète du fonctionnement du module Commerce : Redux Toolkit, React, Axios, Recharts et Power BI.

47 — Gestion des données Commerce avec Redux Toolkit et React

Dans cette partie du projet, un système complet de récupération, de gestion, de transformation, de filtrage et d'affichage des données commerciales a été développé en utilisant React, Redux Toolkit, Axios et Recharts. L'objectif de cette fonctionnalité est de récupérer les données du commerce depuis le backend, de les stocker dans le store Redux, de les transformer afin de faciliter leur utilisation dans l'interface utilisateur, puis de permettre à l'utilisateur de filtrer les données selon le commerce sélectionné, par exemple Jumia ou MG. Les données récupérées sont ensuite utilisées dans un graphique de type histogramme grâce à la bibliothèque Recharts, mais elles sont également affichées sous forme de liste détaillée. Cette partie frontend communique directement avec le backend grâce à une requête HTTP GET vers l'adresse http://localhost:3000/commerce/train. Le fonctionnement général est le suivant : lorsque le composant React Commerce est chargé, le hook useEffect déclenche l'action Redux fetchCommerce. Cette action utilise createAsyncThunk pour effectuer une requête Axios vers le backend. Le backend retourne les données commerciales, Redux récupère ces données et les stocke dans le state global. Le composant React utilise ensuite useSelector pour récupérer les données depuis Redux. Une logique de transformation est appliquée avec la méthode map() afin d'ajouter une propriété label à chaque élément. Le composant utilise également useState pour gérer le commerce sélectionné dans le filtre. Lorsque l'utilisateur choisit Jumia ou MG, le state local filter est modifié et les données sont filtrées grâce à la méthode filter(). Les données filtrées sont ensuite utilisées simultanément pour construire le graphique avec BarChart et pour afficher la liste des détails. Le projet possède également une intégration Power BI à travers une balise iframe, ce qui permet d'afficher directement le dashboard Power BI dans la page React. Cette architecture sépare donc clairement la récupération et la gestion des données, réalisées avec Redux, de leur présentation et de leur interaction avec l'utilisateur, réalisées avec React.

48 — Importation de Redux Toolkit et Axios

Le fichier Redux commence par l'importation de deux fonctionnalités importantes de Redux Toolkit : createSlice et createAsyncThunk. La fonction createSlice permet de créer une partie du store Redux consacrée au commerce. Elle permet notamment de définir le nom du slice, son état initial et les traitements associés aux différentes situations de l'action asynchrone. La fonction createAsyncThunk permet quant à elle de créer une action Redux capable d'effectuer une opération asynchrone, ici une requête HTTP vers le backend. Cette fonctionnalité est particulièrement adaptée lorsqu'une application React doit récupérer des données depuis une API. Le code importe également Axios, qui est utilisé comme client HTTP afin d'envoyer une requête GET au serveur Node.js/Express. Le rôle de cette partie est donc de faire le lien entre le frontend React/Redux et le backend qui fournit les données commerciales. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

49 — Création de l'action asynchrone fetchCommerce

L'action principale du fichier Redux est fetchCommerce. Cette action est créée avec createAsyncThunk. Le premier argument "commerce/fetchCommerce" correspond au type de l'action Redux et permet d'identifier cette opération. Le deuxième argument est une fonction asynchrone qui sera exécutée lorsque l'action sera déclenchée. À l'intérieur de cette fonction, Axios effectue une requête HTTP GET vers l'URL http://localhost:3000/commerce/train. Cette route correspond à une route du backend chargée de fournir les données commerciales. Le mot-clé await permet d'attendre la réponse du serveur avant de continuer l'exécution. Une fois la réponse reçue, elle est stockée dans la variable response. Axios place les données retournées par le serveur dans response.data. Dans ce projet, le backend retourne une structure contenant une propriété data. Le code récupère donc précisément response.data.data. Cette valeur correspond au tableau de données commerciales qui sera transmis à Redux. Le return de cette fonction devient ensuite le payload de l'action Redux lorsque la requête se termine correctement. 

export const fetchCommerce = createAsyncThunk(
    "commerce/fetchCommerce",
    async () => {
        const response = await axios.get(
            "http://localhost:3000/commerce/train"
        );

        return response.data.data;
    }
);

50 — Création du Commerce Slice

Le code crée ensuite le slice Redux avec createSlice(). Cette fonction permet d'organiser toute la logique Redux concernant le commerce dans une seule structure. La propriété name: "commerce" donne le nom du slice et permet d'identifier cette partie du store global. Le initialState définit l'état initial des données. La propriété data est initialisée avec un tableau vide car aucune donnée n'a encore été récupérée depuis le backend. La propriété loading est initialement définie à false, ce qui signifie qu'aucune récupération de données n'est actuellement en cours. Ces valeurs seront ensuite modifiées automatiquement selon l'état de l'action fetchCommerce. 

const commerceSlice = createSlice({
    name: "commerce",

    initialState: {
        data: [],
        loading: false
    },

    extraReducers: (builder) => {
        // Gestion des états asynchrones
    }
});

51 — Gestion de l'état pending

Redux Toolkit génère automatiquement plusieurs états pour une action créée avec createAsyncThunk. Le premier état est pending. Cet état est exécuté au moment où la requête commence. Lorsque le composant React déclenche dispatch(fetchCommerce()), Redux passe automatiquement par l'état pending. Le code modifie alors state.loading et lui attribue la valeur true. Cela signifie que l'application sait qu'une récupération des données est actuellement en cours. Le composant React peut utiliser cette information pour afficher un message comme Loading.... Cette logique permet donc d'informer l'utilisateur que les données sont en train d'être chargées. 

.addCase(fetchCommerce.pending, (state) => {
    state.loading = true;
})

52 — Gestion de l'état fulfilled et transformation des données

Lorsque la requête Axios se termine correctement, Redux Toolkit déclenche l'état fulfilled. Cela signifie que la requête a réussi et que les données ont été reçues. La première opération consiste à remettre state.loading à false, car le chargement est terminé. Ensuite, les données reçues sont enregistrées dans state.data. Avant leur enregistrement, le code utilise cependant la méthode JavaScript map(). Cette méthode parcourt chaque élément du tableau reçu dans action.payload. Pour chaque élément, l'opérateur spread ...item permet de conserver toutes les propriétés existantes, puis une nouvelle propriété appelée label est ajoutée. Cette propriété est construite à partir des valeurs commerce et web_scraper. Par exemple, si le commerce est Jumia et que le scraper est Python, la nouvelle valeur pourra être Jumia - Python. Cette transformation permet de préparer les données directement dans Redux afin que le composant React dispose d'informations prêtes à être utilisées. 

.addCase(fetchCommerce.fulfilled, (state, action) => {
    state.loading = false;

    state.data = action.payload.map((item) => ({
        ...item,
        label: `${item.commerce} - ${item.web_scraper}`
    }));
})

53 — Gestion de l'état rejected

Le troisième état est rejected. Il est exécuté lorsque la requête échoue. Cela peut arriver si le serveur backend n'est pas disponible, si l'URL est incorrecte ou lorsqu'une erreur réseau empêche Axios de recevoir les données. Dans cette situation, le code remet loading à false afin d'indiquer que le chargement est terminé. Dans cette version du slice, aucune propriété error n'est enregistrée dans le state. Le composant sait donc que le chargement est terminé, mais il ne récupère pas ici le détail précis de l'erreur. L'objectif est de gérer proprement le cycle de vie de la requête : pending lorsque la récupération commence, fulfilled lorsque les données sont récupérées avec succès et rejected lorsqu'une erreur se produit. 

.addCase(fetchCommerce.rejected, (state) => {
    state.loading = false;
})

54 — Importation des fonctionnalités React

Le fichier Commerce.jsx utilise plusieurs fonctionnalités importantes de React et React Redux. useEffect permet de déclencher une opération après le rendu du composant, notamment pour lancer la récupération des données. useState permet de gérer un état local, ici utilisé pour mémoriser le commerce sélectionné dans le filtre. useDispatch permet d'envoyer une action Redux depuis React tandis que useSelector permet de récupérer les données présentes dans le store Redux. Le composant importe également l'action fetchCommerce provenant du fichier commerceSlice. Enfin, le fichier Commerce.css est importé afin d'appliquer le style graphique au dashboard. 

import React, { useEffect, useState } from "react";

import {
    useDispatch,
    useSelector
} from "react-redux";

import { fetchCommerce } from "../redux/commerceSlice";

import "./Commerce.css";

55 — Utilisation de useDispatch

Le hook useDispatch() fournit la fonction dispatch. Cette fonction permet d'envoyer une action au store Redux. Dans ce projet, elle est utilisée pour déclencher l'action fetchCommerce(). Lorsque cette action est envoyée, Redux Toolkit exécute le processus asynchrone défini dans le slice et lance la requête Axios vers le backend. Le composant React n'a donc pas besoin d'effectuer directement la requête HTTP. Il se contente de demander à Redux de récupérer les données. 

const dispatch = useDispatch();

dispatch(fetchCommerce());

56 — Récupération des données avec useSelector

Le hook useSelector() permet au composant React d'accéder au state global Redux. Le code récupère ici data et loading depuis state.commerce. La propriété data contient les données commerciales récupérées depuis le backend et transformées dans le slice Redux. La propriété loading indique si la récupération des données est actuellement en cours. Grâce à cette architecture, le composant React ne gère pas directement Axios. Il récupère les informations depuis le store Redux, ce qui permet de séparer clairement la logique de récupération des données de la logique d'affichage. 

const { data, loading } =
    useSelector((state) => state.commerce);

57 — Gestion du filtre avec useState

Le hook useState() est utilisé pour créer un état local appelé filter. Sa valeur initiale est Jumia. Cela signifie que lorsque le composant est affiché pour la première fois, les données présentées dans le graphique et dans la liste correspondent au commerce Jumia. La fonction setFilter() permet ensuite de modifier cette valeur lorsque l'utilisateur sélectionne un autre commerce. Le state local est donc utilisé pour gérer l'interaction de l'utilisateur avec le filtre sans modifier les données stockées dans Redux. 

const [filter, setFilter] = useState("Jumia");

58 — Récupération automatique des données avec useEffect

Le hook useEffect() permet d'exécuter une opération après le rendu du composant. Ici, son objectif est de déclencher automatiquement la récupération des données lorsque la page Commerce est chargée. L'instruction dispatch(fetchCommerce()) envoie l'action Redux. Redux Toolkit lance ensuite le createAsyncThunk, qui effectue la requête Axios vers le backend. La dépendance [dispatch] indique que l'effet dépend de la fonction dispatch. Le fonctionnement peut donc être résumé ainsi : le composant React est chargé, useEffect s'exécute, dispatch déclenche fetchCommerce, Redux lance Axios, Axios communique avec le backend, le backend retourne les données, Redux stocke les données et React les récupère avec useSelector. 

useEffect(() => {
    dispatch(fetchCommerce());
}, [dispatch]);

59 — Filtrage des données

Après récupération des données, le code crée une nouvelle variable appelée filteredData. La méthode JavaScript filter() permet de sélectionner uniquement les éléments correspondant au commerce choisi. La condition item.commerce === filter compare la propriété commerce de chaque élément avec la valeur actuelle de l'état filter. Si la valeur du filtre est Jumia, seules les données dont le commerce est Jumia sont conservées. Si l'utilisateur sélectionne MG, le state filter devient MG et seules les données correspondant à MG sont conservées. Le résultat est stocké dans filteredData, qui sera ensuite utilisé à la fois par le graphique et par la liste détaillée. 

const filteredData = data
    ? data.filter((item) => item.commerce === filter)
    : [];

60 — Intégration du Dashboard Power BI

Le composant React intègre également un dashboard Power BI grâce à une balise iframe. Cette technique permet d'afficher directement un rapport Power BI publié dans une page Web. Le dashboard Power BI constitue la partie décisionnelle du projet et permet de présenter les indicateurs et les visualisations créés dans Power BI. Cette intégration permet donc de réunir dans une même page deux types de visualisation : le rapport Power BI et les graphiques dynamiques générés avec React et Recharts. La propriété allowFullScreen permet également d'autoriser l'affichage du rapport en plein écran lorsque cette fonctionnalité est disponible. 

<iframe
    className="commerce-iframe"
    title="PRIX"
    src="https://app.powerbi.com/view?r=..."
    frameBorder="0"
    allowFullScreen
></iframe>

61 — Création du filtre Commerce

La liste déroulante permet à l'utilisateur de sélectionner le commerce qu'il souhaite analyser. La propriété value={filter} lie la valeur du composant HTML select au state React filter. Lorsque l'utilisateur modifie la sélection, l'événement onChange est déclenché et setFilter(e.target.value) récupère la nouvelle valeur. Les deux options disponibles sont Jumia et MG. Dès que le state filter est modifié, React effectue automatiquement un nouveau rendu du composant. La variable filteredData est alors recalculée, ce qui permet au graphique et à la liste de présenter immédiatement les données correspondant au nouveau commerce. 

<select
    className="filter-select"
    value={filter}
    onChange={(e) => setFilter(e.target.value)}
>
    <option value="Jumia">Jumia</option>
    <option value="MG">MG</option>
</select>

62 — Affichage du graphique Commerce avec Recharts

Le graphique est construit avec la bibliothèque Recharts. Le composant ResponsiveContainer permet au graphique de s'adapter automatiquement à la largeur disponible. Le composant BarChart reçoit les données filtrées grâce à data={filteredData}. Le graphique utilise ensuite CartesianGrid pour afficher une grille, XAxis pour l'axe horizontal, YAxis pour l'axe vertical et Tooltip pour afficher les valeurs lorsque l'utilisateur passe la souris sur les barres. Deux barres sont ensuite utilisées : une barre pour target et une autre pour prix. Le graphique permet donc de comparer visuellement la valeur cible et le prix correspondant aux données commerciales sélectionnées. 

<ResponsiveContainer width="100%" height={300}>

    <BarChart data={filteredData}>

        <CartesianGrid strokeDasharray="3 3" />

        <XAxis dataKey="commerce" />

        <YAxis />

        <Tooltip />

        <Bar dataKey="target" name="Target" />

        <Bar dataKey="prix" name="Prix" />

    </BarChart>

</ResponsiveContainer>

63 — Affichage des détails

Après le graphique, le composant affiche les données sous forme de liste détaillée. La méthode map() parcourt chaque élément du tableau filteredData et génère un élément HTML correspondant. La propriété key={item.id} permet à React d'identifier chaque élément de manière unique. Pour chaque donnée, l'interface affiche le commerce, la valeur Target et le prix. Cette liste complète le graphique en fournissant les mêmes informations sous une forme textuelle plus précise et plus directement lisible par l'utilisateur. 

{filteredData.map((item) => (
    <li key={item.id} className="list-item">
        {item.commerce}
        → Target: {item.target}
        | Prix: {item.prix}
    </li>
))}

64 — Fonctionnement global entre Redux et React

Le fonctionnement complet de cette fonctionnalité repose sur une communication organisée entre React, Redux Toolkit, Axios et le backend. Lorsque l'utilisateur ouvre la page Commerce, le composant React est chargé. Le hook useEffect déclenche alors dispatch(fetchCommerce()). Redux Toolkit lance l'action asynchrone créée avec createAsyncThunk. L'état pending est déclenché et la propriété loading devient true. Axios envoie ensuite une requête GET vers le backend. Le serveur traite la demande et retourne les données commerciales sous forme JSON. Lorsque la réponse arrive correctement, Redux déclenche l'état fulfilled. La propriété loading redevient false et les données sont transformées avec map(). Elles sont ensuite stockées dans state.data. Le composant React récupère les nouvelles données avec useSelector. Le state local filter permet ensuite de choisir Jumia ou MG. La méthode filter() crée filteredData, qui est transmis au graphique Recharts et à la liste des détails. Cette architecture permet donc de séparer clairement les responsabilités : Redux gère les données et React gère l'interface et l'interaction utilisateur.

65 — Conclusion

La fonctionnalité Commerce constitue une chaîne complète de traitement frontend permettant de connecter le backend, Redux Toolkit, React, Recharts et Power BI. Les données sont récupérées automatiquement grâce à createAsyncThunk et Axios, puis stockées dans Redux afin d'être disponibles dans le composant React. Le traitement des états pending, fulfilled et rejected permet de gérer le cycle de vie de la requête. Les données reçues sont transformées grâce à map() afin notamment d'ajouter la propriété label. React récupère ensuite ces données avec useSelector et utilise useState pour gérer le filtre entre Jumia et MG. La méthode filter() sélectionne les données correspondantes, puis Recharts les transforme en graphique afin de comparer target et prix. Les informations sont également présentées sous forme de liste détaillée. En parallèle, Power BI est intégré grâce à une iframe afin d'afficher le dashboard décisionnel. Cette architecture démontre donc l'utilisation complémentaire de plusieurs technologies modernes : React pour l'interface, Redux Toolkit pour la gestion d'état, Axios pour la communication avec le backend, Recharts pour la visualisation et Power BI pour l'analyse décisionnelle. Le résultat est un dashboard Commerce dynamique capable de récupérer, transformer, filtrer et visualiser automatiquement les données provenant du backend.
