✈️ Voyage ML Dashboard — Documentação técnica

Esta documentação explica em detalhes o funcionamento do componente VoyageDashboard.jsx, do arquivo voyageSlice.js, da comunicação com o backend por meio do Axios, do gerenciamento de estado com Redux Toolkit, da visualização com Recharts, bem como da integração do Power BI e do sistema de Machine Learning.

Introdução

O Dashboard Voyage permite enviar automaticamente dados relacionados aos preços de uma viagem para o backend.

Os dados enviados ao backend são:

  • prix_concurrent_2 = 1900
  • prix_concurrent_agence2 = 2000
  • prix_extra = 50

A requisição é enviada usando o método HTTP POST para: 

http://localhost:3000/voyage

O backend processa os dados e retorna uma resposta JSON contendo, entre outras informações, uma previsão.

A resposta é recuperada pelo Redux Toolkit e armazenada no estado do módulo voyage.

O valor da previsão é então utilizado para construir um gráfico de barras com o Recharts.

Paralelamente, um relatório do Power BI é integrado diretamente ao Dashboard usando um iframe.

1. Apresentação geral do projeto

O componente VoyageDashboard.jsx representa a interface React do Dashboard dedicado à análise e previsão de dados de viagens.

Seu objetivo é enviar automaticamente várias variáveis relacionadas aos preços de uma viagem para o backend.

O backend processa esses dados de acordo com a lógica definida no sistema de Machine Learning.

O resultado retornado pelo backend é recuperado pelo Redux Toolkit.

O Dashboard exibe então a previsão e também um gráfico que permite comparar um valor real com o valor previsto.

Essa instrução retorna os dados recebidos do backend para o sistema Redux Toolkit.

}
}

22. Gerenciamento de erros 

catch (error) {
return thunkAPI.rejectWithValue(
    error.response?.data?.error ||
    error.message
);
}

Se a requisição falhar, o bloco catch será executado.

rejectWithValue() permite transmitir uma mensagem de erro personalizada para o Redux Store.

23. Optional Chaining no gerenciamento de erros 

error.response?.data?.error

O operador ?. permite acessar uma propriedade somente quando o objeto anterior existe.

Isso evita um erro caso error.response não exista.

Se a mensagem do backend não estiver disponível, o código utiliza: 

error.message
