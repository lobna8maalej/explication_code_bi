01

Visión general del proyecto

Este módulo implementa una arquitectura de predicción diseñada para el sector del comercio y permite comparar o estimar resultados para dos marcas: Carrefour y Aziza. La arquitectura se basa en varias tecnologías que se comunican entre sí. La primera parte está desarrollada en Python y utiliza la biblioteca Scikit-learn junto con el algoritmo SVR, o Support Vector Regression. Se entrenan dos modelos independientes de Machine Learning utilizando las mismas variables de entrada X, pero con dos conjuntos diferentes de valores objetivo: un conjunto para Carrefour y otro para Aziza. Una vez entrenados, los modelos se serializan utilizando la biblioteca pickle y se guardan como archivos carrefour.pkl y aziza.pkl. La segunda parte del sistema corresponde al script de Python responsable de recibir los datos desde Node.js. Este script lee un objeto JSON enviado mediante la entrada estándar, identifica el modelo solicitado, carga el archivo PKL correspondiente, recupera las variables x1 y x2 y, a continuación, utiliza el método predict() del modelo SVR para producir una predicción. La tercera parte está desarrollada en Node.js. El backend utiliza el módulo nativo child_process para ejecutar Python desde Node.js. La función runCommerce() prepara la ruta hacia el intérprete de Python, localiza el script de predicción, inicia el proceso de Python y le envía los datos en formato JSON. El resultado producido por Python se recupera desde stdout, se convierte de JSON a un objeto JavaScript y posteriormente se devuelve al backend. Finalmente, Express expone una API REST con una ruta de prueba /train y una ruta POST /predict. Por lo tanto, el frontend o dashboard puede enviar el nombre del modelo junto con las variables de entrada y recibir automáticamente la predicción calculada por el modelo real de Machine Learning.

02

Entrenamiento del modelo SVR

El primer paso del sistema consiste en crear los modelos de Machine Learning. El código Python importa SVR desde sklearn.svm. SVR significa Support Vector Regression y es una versión del método Support Vector Machines adaptada a problemas de regresión. A diferencia de una fórmula matemática simple programada manualmente, el modelo SVR se entrena utilizando datos de entrada y valores objetivo. En este proyecto, el array X contiene cuatro observaciones y dos variables para cada observación. La primera observación contiene los valores 10 y 1, la segunda 20 y 2, la tercera 30 y 3 y la cuarta 40 y 4. Estas dos variables representan las características utilizadas por el modelo para aprender la relación con la variable objetivo. Para Carrefour, el array y_carrefour contiene los valores 120, 240, 360 y 480. Se crea un primer objeto SVR() y se llama al método fit() con X y y_carrefour. Por lo tanto, el modelo aprende una relación entre las dos variables de entrada y los valores objetivo de Carrefour. A continuación, el modelo se guarda en el archivo carrefour.pkl. El mismo principio se aplica a Aziza. El array y_aziza contiene los valores 100, 200, 300 y 400. Se crea un segundo modelo SVR, se entrena utilizando las mismas variables X pero con los valores objetivo de Aziza y, posteriormente, se guarda como aziza.pkl. De esta manera obtenemos dos modelos independientes capaces de producir predicciones diferentes a partir de las mismas variables de entrada.

Importación de SVR 

from sklearn.svm import SVR

Esta instrucción importa la clase SVR desde el módulo sklearn.svm. Permite crear un modelo de regresión basado en Support Vector Machines. El modelo puede entrenarse utilizando el método fit() y utilizarse para producir predicciones mediante predict().

Importación de Pickle 

import pickle

La biblioteca pickle se utiliza para serializar el modelo entrenado. Después del entrenamiento, el modelo SVR existe como un objeto Python en memoria. Pickle permite transformar este objeto en un archivo para poder guardarlo y cargarlo posteriormente sin tener que volver a entrenar el modelo para cada predicción.

Gestión de la ruta del proyecto 

BASE_DIR = os.path.dirname(

)

Esta parte determina automáticamente la carpeta en la que se encuentra el script Python. os.path.abspath(__file__) obtiene la ruta absoluta del archivo actual, mientras que os.path.dirname() obtiene la carpeta que contiene este archivo. Este método es especialmente útil para construir rutas fiables hacia los archivos PKL.

Datos comunes 

X = [
    [10, 1],
    [20, 2],
    [30, 3],
    [40, 4]

El array X representa los datos de entrada de Machine Learning. Cada fila corresponde a una observación y contiene dos variables. Por lo tanto, el modelo recibe dos características para cada predicción. Por ejemplo, la primera observación está formada por 10 y 1. Estos dos valores se enviarán posteriormente al modelo SVR para que pueda calcular una estimación.

Datos de Carrefour 

y_carrefour = [
    120,

    360,
    480

El array y_carrefour representa la variable objetivo utilizada para entrenar el modelo de Carrefour. Cada valor corresponde a una observación del array X. Por lo tanto, el modelo debe aprender la relación entre las dos variables de entrada y estos cuatro valores objetivo.

Creación y entrenamiento del modelo Carrefour 

carrefour_model = SVR()

carrefour_model.fit(
    X,
    y_carrefour
)

SVR() crea una nueva instancia del modelo Support Vector Regression. El método fit() inicia posteriormente el proceso de aprendizaje. El primer argumento corresponde a las variables de entrada X y el segundo corresponde a los valores objetivo y_carrefour. El modelo analiza los datos proporcionados para aprender una relación que posteriormente pueda utilizarse para producir predicciones para nuevos valores.

Guardado del modelo Carrefour 

carrefour_path = os.path.join(

with open(
    carrefour_path,
    "wb"

    pickle.dump(
        carrefour_model,
        f

La ruta al archivo carrefour.pkl se construye utilizando os.path.join(). A continuación, el archivo se abre utilizando el modo wb, que significa escritura binaria. La función pickle.dump() serializa el objeto carrefour_model y lo guarda en el archivo. Por lo tanto, el modelo entrenado puede reutilizarse posteriormente sin volver a entrenarlo.

Modelo Aziza

aziza_model = SVR()

aziza_model.fit(

El modelo Aziza utiliza exactamente las mismas variables de entrada X, pero tiene una variable objetivo diferente. El array y_aziza contiene los valores 100, 200, 300 y 400. Se crea un nuevo objeto SVR() y posteriormente se entrena con X y y_aziza. Esta separación permite construir dos modelos distintos. El modelo Carrefour aprende las relaciones presentes en los datos de Carrefour, mientras que el modelo Aziza aprende las relaciones presentes en los datos de Aziza.

03

Script de predicción en Python

Después de entrenar y guardar los modelos, se utiliza un segundo script Python para realizar las predicciones. Su función es especialmente importante porque actúa como puente entre Node.js y los modelos de Machine Learning desarrollados en Python. El script importa sys, json, pickle y os. Comienza leyendo los datos enviados por Node.js mediante sys.stdin.read(). Estos datos se envían en formato JSON y se convierten en un objeto Python mediante json.loads(). A continuación, el script recupera el nombre del modelo utilizando data.get("model", "carrefour"). Si no se proporciona ningún modelo, Carrefour se convierte en el modelo predeterminado. Después, un diccionario file_map se utiliza para asociar el nombre lógico del modelo con el archivo PKL correspondiente. Si el nombre recibido no existe en este diccionario, el programa genera un error. Cuando el modelo es válido, la ruta del archivo PKL se construye automáticamente y el archivo se abre en modo binario. pickle.load() vuelve a cargar el modelo SVR entrenado. Una comprobación de seguridad utiliza hasattr(model, "predict") para verificar que el objeto cargado realmente dispone de un método de predicción. A continuación, las variables x1 y x2 se recuperan de los datos recibidos y se convierten en números decimales mediante float(). Finalmente, el modelo se ejecuta con model.predict([[x1, x2]]). La lista doble es necesaria porque Scikit-learn generalmente espera una estructura que represente una o varias observaciones con sus características. El resultado se recupera y se convierte en un float. Finalmente, el script genera un objeto JSON que contiene success, el nombre del modelo y la predicción. Si se produce un error en cualquier etapa, el bloque except también devuelve JSON, pero con success: false y el mensaje de error.

Lectura de los datos de Node.js 

data = json.loads(
    sys.stdin.read()
)

sys.stdin.read() permite al script Python leer los datos enviados por el proceso Node.js. Como Node.js envía la información en formato JSON, json.loads() transforma esta cadena JSON en un diccionario Python que puede ser utilizado por el programa.

Selección del modelo 

model_name = data.get(
    "model",
    "carrefour"
).lower()

Esta instrucción recupera el nombre del modelo solicitado. El método get() utiliza Carrefour como valor predeterminado si la propiedad model no se proporciona. El método lower() convierte el texto a minúsculas para evitar determinados problemas relacionados con las letras mayúsculas.

Asociación modelo / archivo PKL 

file_map = {
    "carrefour": "carrefour.pkl",
    "aziza": "aziza.pkl"
}

El diccionario file_map asocia el nombre enviado por el frontend con el archivo físico que contiene el modelo. Si model = carrefour, el programa carga carrefour.pkl. Si model = aziza, carga aziza.pkl. Esta organización evita construir directamente un nombre de archivo a partir de una entrada de usuario no controlada.

Carga del modelo 

with open(
    model_path,
    "rb"
) as f:

    model = pickle.load(f)

El archivo PKL se abre utilizando el modo rb, que significa lectura binaria. pickle.load() reconstruye el objeto Python guardado anteriormente. De esta manera, el modelo SVR entrenado se restaura en memoria y puede utilizarse inmediatamente para realizar una predicción.

Validación del modelo 

if not hasattr(
    model,
    "predict"
):

    raise Exception(
        "Invalid ML model loaded"
    )

Esta validación garantiza que el objeto cargado realmente dispone de un método predict(). Como el sistema espera un modelo de Machine Learning capaz de producir una predicción, esta verificación evita que el proceso continúe con un objeto incompatible.

Recuperación de las variables 

x1 = float(
    data["x1"]
)

x2 = float(
    data["x2"]
)

Las dos variables enviadas por Node.js se recuperan del objeto JSON. La función float() convierte los valores en números decimales para que puedan utilizarse correctamente con el modelo SVR.

Producción de la predicción 

prediction = model.predict(
    [[x1, x2]]
)[0]

Esta instrucción representa el paso principal de Machine Learning. El modelo SVR recibe las dos variables de entrada y utiliza los parámetros aprendidos durante el entrenamiento para calcular una predicción. El método predict() devuelve un array que contiene el resultado. El índice [0] recupera la primera predicción.

Respuesta JSON 

print(json.dumps({
    "success": True,
    "model": model_name,
    "prediction": float(prediction)
}))

El resultado se convierte a JSON utilizando json.dumps(). Este formato es esencial porque Node.js puede recuperar fácilmente la respuesta desde la salida estándar del proceso Python y posteriormente convertirla en un objeto JavaScript. En caso de éxito, la respuesta contiene el estado, el nombre del modelo y el valor predicho.

04

Servicio Node.js y comunicación con Python

El archivo de servicio server.js actúa como puerta de enlace entre el backend Node.js y el programa Python. El módulo child_process proporcionado por Node.js permite iniciar un proceso externo. En este caso, se utiliza la función spawn() para iniciar el intérprete de Python. La función runCommerce() devuelve una Promise, lo que permite que la ruta Express utilice await y espere a que finalice el procesamiento de Python. El servicio primero construye la ruta hacia el intérprete de Python ubicado en el entorno virtual .venv. Después construye la ruta hacia el script commerce2.py. Antes de iniciar Python, el código utiliza fs.existsSync() para verificar que el intérprete y el script realmente existan. Este paso es especialmente útil para diagnosticar errores de rutas. Cuando ambos archivos están disponibles, spawn() inicia Python con el script de predicción. Node.js envía entonces los datos al proceso Python mediante python.stdin.write(). Los datos se convierten en JSON utilizando JSON.stringify(). Python lee estos datos mediante sys.stdin.read(). Durante la ejecución, Node.js escucha stdout para recuperar el resultado producido por Python y también escucha stderr para recuperar posibles mensajes de error. Cuando Python finaliza, se activa el evento close. El código comprueba entonces el código de salida del proceso. Si el código es diferente de cero, significa que el proceso Python terminó con un error. Si el resultado está vacío, se devuelve otro error. Finalmente, si Python produjo una respuesta, JSON.parse() transforma el texto JSON en un objeto JavaScript. Este objeto se devuelve mediante resolve(). Por lo tanto, el servicio proporciona una comunicación real entre el entorno JavaScript y el modelo de Machine Learning desarrollado en Python.

Importación de módulos Node.js

child_process permite iniciar Python desde Node.js. path permite construir rutas de archivos compatibles con el sistema operativo. fs se utiliza principalmente para verificar la existencia de archivos.

Creación de la Promise 

function runCommerce(inputData) {

    });

}

La función devuelve una Promise porque la ejecución de Python es una operación asíncrona. Node.js debe iniciar Python, esperar su resultado y posteriormente devolver ese resultado a la ruta Express.

Localización de Python 

const pythonPath = path.resolve(
    __dirname,
    "../../.venv/Scripts/python.exe"
);

Esta instrucción construye la ruta absoluta hacia el intérprete de Python utilizado por el proyecto. Aquí, el programa utiliza la instalación de Python ubicada en el entorno virtual .venv. Esto permite utilizar exactamente el entorno en el que están instaladas las bibliotecas necesarias, especialmente Scikit-learn.

Localización del script Python 

const scriptPath = path.resolve(
    __dirname,
    "../../python/commerce2.py"
);

La ruta al script Python de predicción también se construye como una ruta absoluta. De esta manera, Node.js sabe exactamente qué archivo debe ejecutar.

Verificación de archivos 

fs.existsSync(pythonPath)

fs.existsSync(scriptPath)

Estas comprobaciones permiten detectar rápidamente si Python o el script no pueden encontrarse. En un proyecto real, esto facilita considerablemente el diagnóstico cuando una ruta es incorrecta o cuando un archivo ha sido movido.

Inicio de Python 

const python = spawn(
    pythonPath,
    [scriptPath]
);

spawn() inicia el intérprete de Python y le proporciona la ruta al script commerce2.py. Node.js dispone ahora de un proceso hijo con el que puede comunicarse mediante stdin, stdout y stderr.

Envío de datos a Python 

python.stdin.write(
    JSON.stringify(inputData)
);

python.stdin.end();

Los datos recibidos por Node.js se convierten en una cadena JSON y posteriormente se envían a la entrada estándar del proceso Python. stdin.end() indica que Node.js ha terminado de enviar los datos. Python puede entonces leer todo el contenido utilizando sys.stdin.read().

Recuperación del resultado de Python 

python.stdout.on(
    "data",
    (data) => {

        result += data.toString();

    }
);

Node.js escucha los datos enviados por Python a través de stdout. Los fragmentos recibidos se convierten en texto y se agregan a la variable result. Cuando Python termina, esta variable contiene la respuesta JSON.

Gestión de errores de Python 

python.stderr.on(
    "data",
    (data) => {

        error += data.toString();

    }
);

stderr se utiliza para recuperar los mensajes de error producidos por Python. Esto permite al backend determinar la causa de un posible problema.

Conversión JSON 

const parsedResult =
    JSON.parse(
        result.trim()
    );

resolve(
    parsedResult
);

Python devuelve una cadena JSON. Node.js utiliza JSON.parse() para transformar esta cadena en un objeto JavaScript. El objeto resultante se devuelve posteriormente a la ruta mediante resolve().

Ruta de predicción de Express

El archivo serverRoutes.js define los endpoints accesibles por el frontend. Crea un router de Express utilizando express.Router() y posteriormente importa el servicio runCommerce(). Una primera ruta GET llamada /train sirve como ruta de prueba. No entrena realmente los modelos; simplemente devuelve un mensaje indicando que Carrefour y Aziza están listos. El entrenamiento real se realiza mediante el script Python de creación de modelos. La segunda ruta, POST /predict, es la ruta principal de predicción. Recupera la información enviada en req.body, incluyendo el nombre del modelo, x1 y x2. Una validación comprueba que x1 y x2 estén presentes. Si falta un valor, la API devuelve una respuesta HTTP 400. Cuando los datos son válidos, la ruta llama a runCommerce() con la información recibida. El servicio Node.js inicia entonces el script Python, carga el modelo PKL correspondiente y calcula la predicción. Una vez recibida la respuesta, Express la devuelve directamente al cliente utilizando res.status(200).json(result). Por lo tanto, el frontend puede llamar a esta API y recibir directamente el resultado del modelo de Machine Learning.

Creación del Router 

const express =
require("express");

const router =
express.Router();

Esta parte importa Express y posteriormente crea un router independiente. Esto permite organizar los endpoints en un archivo separado del servidor principal.

Importación del servicio 

const serverService =
require("../service/server");

const runCommerce =
serverService.runCommerce;

El router recupera la función runCommerce() desde el servicio. Esta función se ejecutará cada vez que se reciba una solicitud de predicción.

Ruta de prueba 

router.get(
    "/train",
    (req, res) => {

    return res.status(200).json({

        success: true,

        message:
            "Carrefour + Aziza ready"

    });

});

Esta ruta permite verificar rápidamente que el router funciona y que el backend responde correctamente. Devuelve un estado HTTP 200 junto con un mensaje que indica que ambos modelos están disponibles.

Ruta POST /predict 

router.post(
    "/predict",
    async (req, res) => {

        ...
    }
);

Esta ruta recibe los datos necesarios para realizar una predicción. Como utiliza POST, la información se envía en el cuerpo de la solicitud HTTP en formato JSON.

Recuperación de los datos 

const {
    model,
    x1,
    x2
} = req.body || {};

Las tres informaciones principales se recuperan de la solicitud: el modelo que se utilizará y las dos variables de entrada. El modelo puede ser carrefour o aziza.

Validación 

if (
    x1 === undefined ||
    x1 === null ||
    x2 === undefined ||
    x2 === null
) {

    return res.status(400).json({

        success: false,

        error:
            "x1 and x2 required"

    });

}

Esta validación evita que el backend llame a Python cuando las variables necesarias no se proporcionan. En este caso, el servidor devuelve un error HTTP 400 indicando que x1 y x2 son obligatorios.

Llamada al servicio Python 

const result =
    await runCommerce({

        model,
        x1,
        x2

    });

Esta instrucción crea el vínculo entre la ruta Express y el servicio Node.js. Gracias a await, la ruta espera a que el proceso Python termine el cálculo antes de continuar.

Respuesta final 

return res.status(200).json(
    result
);

Una vez que Python devuelve el resultado, Express lo envía al cliente en formato JSON. Por lo tanto, el frontend recibe la predicción calculada por el modelo SVR real.

Servidor principal Node.js / Express

El archivo principal del backend inicializa la aplicación Express y conecta las rutas de predicción. Express se importa y se crea una instancia de la aplicación mediante express(). El middleware express.json() se habilita para que el servidor pueda recibir y analizar datos JSON enviados por el frontend. A continuación, se importa el archivo serverRoutes y se monta utilizando el prefijo /server. Esto significa que todas las rutas definidas en serverRoutes son accesibles desde esta ruta base. Por lo tanto, la ruta router.post("/predict") se convierte en el endpoint completo POST /server/predict. El servidor también contiene una ruta raíz GET / que devuelve { status: "OK" }. Esta ruta puede utilizarse como Health Check para verificar que el backend se ha iniciado correctamente. Finalmente, app.listen(3000) inicia el servidor en el puerto 3000. El backend puede entonces recibir solicitudes del frontend y activar las predicciones de Python.

Inicialización de Express 

const express =
require("express");

const app =
express();

Express se importa y posteriormente se crea una instancia de la aplicación. Esta instancia representa el servidor HTTP que recibirá las solicitudes.

Middleware JSON 

app.use(
    express.json()
);

Este middleware permite que Express comprenda las solicitudes cuyo cuerpo contiene datos JSON. Es esencial aquí porque el frontend envía el modelo y las variables x1 y x2 en formato JSON.

Montaje de las rutas 

const serverRoutes =
require("./routes/serverRoutes");

app.use(
    "/server",
    serverRoutes
);

El servidor importa el router que contiene los endpoints de predicción y lo monta bajo el prefijo /server. Por lo tanto, la ruta /predict se convierte en /server/predict.

Health Check 

app.get(
    "/",
    (req, res) => {

    res.json({
        status: "OK"
    });

});

Esta ruta permite verificar de forma sencilla que el servidor funciona. Cuando un cliente llama a la dirección raíz, el backend devuelve un objeto JSON que indica que el servidor está operativo.

Inicio del servidor 

app.listen(
    3000,
    () => {

    console.log(
        "Server running on port 3000"
    );

});

El servidor escucha en el puerto 3000. Todas las solicitudes enviadas a este puerto pueden ser gestionadas por Express.

07

Arquitectura completa del sistema

La arquitectura completa se basa en la comunicación mediante varias etapas. Todo comienza con el frontend o dashboard, que contiene los datos necesarios para realizar la predicción. Envía una solicitud HTTP POST al endpoint /server/predict. Express recibe la solicitud y recupera las propiedades model, x1 y x2. Después de la validación, la ruta llama al servicio runCommerce(). Este servicio utiliza el módulo child_process de Node.js para iniciar el programa Python. Node.js envía los datos al programa Python en formato JSON a través de stdin. El script Python lee los datos, identifica el modelo solicitado y selecciona el archivo PKL correspondiente utilizando el diccionario file_map. El modelo SVR se vuelve a cargar utilizando pickle.load(). Las variables x1 y x2 se recuperan y se pasan al modelo mediante predict(). El modelo produce un valor predicho. Python convierte entonces este valor en JSON y lo escribe en stdout. Node.js recupera el contenido de stdout, analiza el JSON mediante JSON.parse() y devuelve el resultado a la ruta Express. Finalmente, Express envía la respuesta JSON al frontend. Esta arquitectura permite utilizar un modelo real de Machine Learning desarrollado en Python manteniendo al mismo tiempo un backend Web moderno basado en Node.js y Express.

Función de las tecnologías

Cada tecnología utilizada en esta arquitectura tiene una responsabilidad específica. Python y Scikit-learn se utilizan para la parte de Machine Learning. SVR es el algoritmo de regresión utilizado para aprender la relación entre las variables de entrada y los valores objetivo. Pickle permite guardar los modelos entrenados y volver a cargarlos durante las predicciones. Node.js es el entorno de ejecución del backend JavaScript. Express se utiliza para crear la API REST y gestionar las solicitudes HTTP. El módulo child_process permite que Node.js ejecute Python y se comunique con él. JSON es el formato de intercambio de datos entre ambos entornos. Finalmente, el frontend o dashboard utiliza la API para enviar las variables de entrada y mostrar el resultado de la predicción.

Conclusión

Este sistema representa una arquitectura completa de Machine Learning integrada en una aplicación Web. Los datos se utilizan para entrenar dos modelos SVR independientes y los modelos entrenados se guardan posteriormente en archivos PKL. Un script Python especializado vuelve a cargar el modelo solicitado y produce una predicción basada en las variables recibidas. Node.js actúa como puerta de enlace entre la aplicación Web y Python mediante el módulo child_process y la función spawn(). Express proporciona los endpoints HTTP que permiten al frontend comunicarse con el sistema. El formato JSON garantiza la comunicación entre los diferentes componentes. Por lo tanto, toda la cadena puede representarse como: Datos → Entrenamiento SVR → Archivo PKL → Python → Node.js → Express → Predicción → Dashboard. Esta organización permite utilizar modelos reales de Machine Learning desarrollados en Python dentro de una aplicación Web moderna, manteniendo al mismo tiempo una arquitectura modular y escalable.
