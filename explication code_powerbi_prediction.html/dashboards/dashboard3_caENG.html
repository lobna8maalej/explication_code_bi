1. Bank Dashboard Overview

This banking dashboard was developed from an accounting file containing the data required for financial analysis.

The project implements a complete data processing pipeline, from the source accounting file to visualization in Power BI and the integration of a Machine Learning model designed to perform predictions.

Particular attention was paid to data quality. The accounting file contained several anomalies requiring a data cleaning phase, identification of missing and outlier values, as well as transformations adapted to the data structure.

2. Data Source — Accounting File

The initial source of the project is an accounting file containing the data used to build the banking analyses.

Before integration into the ETL process, the structure of the file was analyzed in order to identify the various data quality issues that could affect the analyses and predictive models.

Issues Encountered

  • Missing values
  • Outlier values
  • Data inconsistencies
  • Data formats requiring transformation
  • Column structure requiring adaptation

3. Cleaning and Transformation with Python

Python is used to prepare the data before its integration into the ETL pipeline.

This step makes it possible to analyze the quality of the accounting file, identify anomalies and transform the data in order to obtain a structure that can be used in the following steps.

3.1 Identification of Missing Values

The data is analyzed in order to identify incomplete or missing fields. The processing is carried out according to the nature of the data and its importance for the analysis.

3.2 Identification of Outlier Values

Unusual values are also identified in order to prevent them from affecting the dashboard indicators or Machine Learning results.

3.3 Data Transformation

After identifying the issues, the data is transformed to comply with the structure required for integration into the Staging Area and the Data Warehouse.

3.4 Objective of Python Data Preparation

The objective of this step is to produce clean, consistent and structured data that can be used both for business intelligence analysis and predictive modeling.

4. Staging Area and Processing with Talend

Once the data has been cleaned and transformed with Python, it is integrated into a Staging Area using Talend.

This step provides an intermediate area before the final loading of the data into the Data Warehouse.

Structure Adaptation

Some transformations are performed according to the errors and structural issues encountered during data integration.

7. Machine Learning — Prediction

After preparing and analyzing the data, a Machine Learning component is integrated into the project.

The model uses the prepared data to produce a predictive value based on the input variables.

7.1 Variables Used

The Python prediction script receives two input variables:

  • ca_tnd — revenue in TND
  • ca_eur — revenue in EUR

7.2 Model Loading

The previously trained Machine Learning model is saved in a file called EXPORT.pkl.

The Python script loads this model using the pickle library.

7.3 Python File — ca.py 

 
import sys 
import json 
import pickle 
import os 
 
mode = sys.argv[1] 
ca_tnd = float(sys.argv[2]) 
ca_eur = float(sys.argv[3]) 
 
BASE_DIR = os.path.dirname(os.path.abspath(**file**)) 
model_path = os.path.join(BASE_DIR, "EXPORT.pkl") 
 
model = pickle.load(open(model_path, "rb")) 
 
prediction = model.predict([[ca_tnd, ca_eur]]) 
 
result = { 
"mode": mode, 
"ca_tnd": ca_tnd, 
"ca_eur": ca_eur, 
"prediction": float(prediction[0]) 
} 
 
print(json.dumps(result))

7.4 Explanation of the ca.py File

  1. Importing libraries: Python uses sys, json, pickle and os to manage parameters, the model and communication.
  2. Retrieving parameters: the values mode, ca_tnd and ca_eur are retrieved from the arguments passed to the script.
  3. Numeric conversion: the revenue values are converted into decimal numbers using float().
  4. Model location: os.path is used to build the path to the EXPORT.pkl file.
  5. Model loading: pickle.load() restores the trained Machine Learning model.
  6. Prediction: model.predict() receives the two variables ca_tnd and ca_eur and generates the prediction.
  7. Creating the response: the result is organized in a Python object containing the mode, input values and prediction.
  8. JSON communication: json.dumps() converts the result into JSON so that it can be retrieved by Node.js.

8. Python Integration with Node.js

Node.js acts as an intermediary between the application and the Python script.

The child_process module and the spawn() function allow Node.js to execute the Python program and retrieve its result.

8.1 CaService.js Service 

 
const { spawn } = require("child_process"); 
 
function runPython(file, args = []) { 
 
return new Promise((resolve, reject) => { 
 
const py = spawn("python", ["-u", file, ...args]); 
 
let output = ""; 
 
py.stdout.on("data", (data) => { 
  output += data.toString(); 
}); 
 
py.stderr.on("data", (err) => { 
  console.error(err.toString()); 
}); 
 
py.on("close", (code) => { 
 
  if (code !== 0) { 
    return reject("Python error code " + code); 
  } 
 
  try { 
    resolve(JSON.parse(output.trim())); 
  } catch (e) { 
    reject("JSON parse error"); 
  } 
 
}); 
 
}); 
 
} 
 
module.exports = runPython;

8.2 Service Operation

  1. Node.js receives the path of the Python file.
  2. The required parameters are passed to the script.
  3. spawn() starts the Python process.
  4. Node.js retrieves the data produced by stdout.
  5. Python errors are retrieved using stderr.
  6. The JSON result is parsed using JSON.parse().
  7. The final result is returned to the Express controller.

9. Node.js / Express API

Express exposes an API route allowing the application to send the data required by the prediction system.

9.1 CARoute.js Route 

 
const express = require("express"); 
const router = express.Router(); 
const path = require("path"); 
const runPython = require("../service/CaService"); 
 
router.use(express.json()); 
 
router.post("/", async (req, res) => { 
 
try { 
 
const { mode, ca_tnd, ca_eur } = req.body; 
 
console.log("REQUEST BODY:", req.body); 
 
if (ca_tnd == null || ca_eur == null) { 
 
  return res.status(400).json({ 
    error: "ca_tnd and ca_eur are required" 
  }); 
 
} 
 
const result = await runPython( 
  path.join(__dirname, "../../python/ca.py"), 
  [ 
    mode || "export", 
    String(ca_tnd), 
    String(ca_eur) 
  ] 
); 
 
return res.status(200).json(result); 
 
} catch (error) { 
 
console.error("SERVER ERROR:", error); 
 
return res.status(500).json({ 
  error: error.toString() 
}); 
 
} 
 
}); 
 
module.exports = router;

9.2 Route Explanation

The route uses the POST method to receive the data sent by the application.

The server then retrieves mode, ca_tnd and ca_eur from req.body.

A validation checks that the two required revenue values are present.

The runPython() service is then called to execute ca.py with the received parameters.

Finally, the prediction result is returned to the client as a JSON response.

12. Project Results

This project makes it possible to transform an accounting file containing raw and potentially inconsistent data into structured and usable data.

The combination of Python, Talend, the Data Warehouse and Power BI makes it possible to build a complete business intelligence analysis pipeline.

The addition of Machine Learning also makes it possible to go beyond descriptive analysis by integrating a predictive dimension.

Finally, the use of Node.js and Express makes it possible to integrate the Python model into an application accessible through a REST API.
