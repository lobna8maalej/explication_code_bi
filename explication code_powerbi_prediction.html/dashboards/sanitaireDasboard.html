```
🏥 SANITAIRE Analytics Dashboard — Documentation technique

Cette documentation explique en détail le fonctionnement du composant CasaDashboard.jsx, sa liaison avec sanitaireSlice.js, son fichier CasaDashboard.css, ainsi que l'utilisation de Redux Toolkit, Axios, Recharts et Power BI.

Le composant constitue une interface d'analyse permettant d'afficher un rapport Power BI, de récupérer les données sanitaires depuis le store Redux et de représenter les valeurs et la prédiction sous forme de graphique en barres.

```
```

1. Présentation générale du projet

Le composant CasaDashboard.jsx représente l'interface principale du Dashboard consacré aux données SANITAIRE.

Il utilise React pour construire l'interface, Redux Toolkit pour récupérer et gérer les données globales, Axios pour communiquer avec le backend et Recharts pour créer un graphique de type BarChart.

Le Dashboard contient également un rapport Power BI intégré directement dans la page grâce à un élément iframe.

Lors du chargement du composant, l'action fetchSanitaireData() est exécutée afin de récupérer les informations disponibles depuis l'API.

``` CasaDashboard.jsx ↓ useEffect() ↓ dispatch(fetchSanitaireData()) ↓ sanitaireSlice.js ↓ Axios ↓ GET /sanitaire ↓ Backend ↓ Redux Store ↓ data / loading / error ↓ CasaDashboard.jsx ↓ Informations + BarChart ↓ CasaDashboard.css ↓ Interface finale ```
```

```

29. État fulfilled

state.loading = false;
```

})

```
fulfilled signifie que la requête a réussi.

Le chargement est alors terminé :

Les données reçues sont ensuite enregistrées dans :
```

```
state.error = action.payload;
```

})
```

rejected est déclenché lorsque la récupération des données échoue.

Le chargement est arrêté :

L'erreur est ensuite enregistrée :

Le composant React peut alors afficher cette erreur.
```

```
69. Ce que fait réellement CasaDashboard.jsx

Le composant CasaDashboard.jsx joue principalement le rôle de couche de présentation et d'orchestration.

Il ne contient pas directement la logique interne de la requête HTTP.

Il demande la récupération des données grâce à :

Le slice Redux s'occupe ensuite de communiquer avec le backend grâce à Axios.

Le composant récupère ensuite le résultat avec :

Il utilise finalement les données pour afficher le modèle, la prédiction, le graphique et le rapport Power BI.
```

```
75. Résumé final à retenir

React construit l'interface → useEffect déclenche fetchSanitaireData() → Redux Toolkit gère l'état → createAsyncThunk lance l'opération asynchrone → Axios communique avec le backend → /sanitaire retourne les données → Redux stocke data, loading et error → useSelector récupère ces informations → React affiche le modèle et la prédiction → chartData prépare les données → Recharts construit le BarChart → Power BI affiche le rapport analytique → CasaDashboard.css contrôle la présentation.

Le composant CasaDashboard.jsx constitue donc l'interface principale du Dashboard SANITAIRE.

Il déclenche la récupération des données grâce à dispatch(fetchSanitaireData()) et récupère l'état Redux avec : 

useSelector((state) => state.sanitaire)

Le fichier sanitaireSlice.js est responsable de la logique de récupération des données. Il utilise createAsyncThunk et Axios pour envoyer une requête GET vers : 

http://localhost:3000/sanitaire

Le slice gère ensuite les trois états de la requête : pending, fulfilled et rejected.

Lorsque les données sont disponibles, elles sont stockées dans state.sanitaire.data. Le composant récupère alors le modèle, les valeurs et la prédiction.

Les valeurs sont ensuite transformées dans chartData afin de construire un graphique BarChart avec Recharts.

Le graphique compare trois éléments : Value 1, Value 2 et Prediction.

En parallèle, le rapport Power BI est intégré dans un iframe, ce qui permet d'afficher le rapport décisionnel directement dans l'application React.

Enfin, CasaDashboard.css est responsable de la présentation visuelle du Dashboard, tandis que sanitaireSlice.js assure la gestion des données et de l'état Redux.
```
