# 47 — Gestión de datos inmobiliarios con Redux Toolkit y React

En esta parte del proyecto, se ha desarrollado un sistema de gestión de datos inmobiliarios utilizando varias tecnologías frontend complementarias, entre ellas React, Redux Toolkit, Axios, Chart.js y Power BI. El objetivo principal de esta funcionalidad es permitir al usuario visualizar un dashboard inmobiliario que contiene un informe de Power BI, un gráfico que representa los precios inmobiliarios y una funcionalidad que permite insertar datos inmobiliarios en el backend. La arquitectura se basa en una separación clara entre la gestión de datos y su visualización. Redux Toolkit se utiliza para centralizar el estado relacionado con la inserción de datos inmobiliarios, mientras que React es responsable de la interfaz de usuario y de las interacciones. Axios gestiona la comunicación HTTP entre el frontend y el backend Node.js/Express. Cuando un usuario hace clic en el botón "Insertar datos", la función handleInsert() prepara un array que contiene varios bienes inmobiliarios y luego ejecuta la acción de Redux insertImmobilier(). Esta acción se crea con createAsyncThunk() y envía una solicitud HTTP POST a http://localhost:3000/insert. El backend recibe los datos y los procesa. Redux Toolkit gestiona automáticamente los diferentes estados de la operación asíncrona mediante pending, fulfilled y rejected. Cuando comienza la inserción, la propiedad loading pasa a true. Cuando la inserción se realiza correctamente, Redux recupera el estado, el mensaje y el número de filas procesadas devueltos por el backend. En caso de error, el mensaje correspondiente se almacena en error. El componente React utiliza posteriormente useSelector() para recuperar esta información del store de Redux y mostrar el resultado al usuario. Al mismo tiempo, Chart.js se utiliza para representar gráficamente los precios de dos bienes inmobiliarios, una casa y un apartamento, mientras que un iframe permite integrar un informe de Power BI directamente en la interfaz. Esta arquitectura combina, por tanto, Business Intelligence con Power BI, visualización gráfica con Chart.js, gestión del estado con Redux Toolkit y comunicación con el backend mediante Axios en una misma página.

# 48 — Importación de Redux Toolkit y Axios

El archivo Redux comienza importando dos funcionalidades esenciales de Redux Toolkit: createSlice y createAsyncThunk. createSlice se utiliza para crear una parte específica del store de Redux dedicada a la gestión de los datos inmobiliarios. Permite definir el nombre del slice, su estado inicial y la lógica asociada a las diferentes acciones. createAsyncThunk se utiliza para crear una acción asíncrona capaz de realizar una operación que requiere tiempo, como una solicitud HTTP a un servidor backend. El código también importa Axios mediante import axios from "axios". Axios es una biblioteca de JavaScript utilizada para enviar solicitudes HTTP. En este proyecto, Axios se utiliza para enviar datos inmobiliarios desde el frontend React hacia el backend Node.js/Express. La combinación de Redux Toolkit y Axios permite, por tanto, crear una comunicación organizada entre la interfaz de usuario y la API backend.

# 49 — Creación de la acción asíncrona insertImmobilier

La acción principal del archivo Redux es insertImmobilier. Se crea utilizando createAsyncThunk(). El primer parámetro, "immobilier/insertImmobilier", corresponde al tipo de acción de Redux y permite identificar esta operación dentro de la aplicación. El segundo parámetro es una función asíncrona que recibe los datos inmobiliarios en la variable data. La función utiliza posteriormente un bloque try/catch para gestionar correctamente una comunicación exitosa o fallida con el servidor. Dentro del bloque try, Axios utiliza axios.post("http://localhost:3000/insert", data) para enviar una solicitud HTTP POST al backend. La variable data contiene la información inmobiliaria preparada en el componente React. Cuando el servidor responde, la respuesta se almacena en la variable res. res.data contiene la información devuelta por el backend. Este valor se devuelve posteriormente mediante return res.data. Se convierte automáticamente en el payload de la acción fulfilled cuando la operación tiene éxito. En el bloque catch, si Axios encuentra un error, el código utiliza rejectWithValue() para transmitir el error al reducer de Redux. La expresión err.response.data permite recuperar la información del error enviada por el backend. Esta organización permite gestionar correctamente la comunicación entre el frontend y el backend.

# 50 — Creación del slice inmobiliario

A continuación, el código crea el slice de Redux utilizando createSlice(). El slice se denomina "immobilier" mediante la propiedad name. Representa una parte del store global dedicada a la funcionalidad inmobiliaria. El estado inicial contiene varias propiedades: status, message, rows, loading y error. La propiedad status se establece inicialmente en null y se utilizará para recibir el estado devuelto por el backend después de la inserción. message contiene inicialmente una cadena vacía y se utilizará para mostrar el mensaje devuelto por el servidor. rows se inicializa en cero y representa el número de filas procesadas o insertadas. La propiedad loading se establece inicialmente en false, lo que significa que ninguna operación de inserción está en curso cuando se inicia la aplicación. Finalmente, error se inicializa en null para poder almacenar un posible error. Por lo tanto, el slice centraliza toda la información necesaria para supervisar la operación de inserción.

# 51 — Gestión del estado Pending

Cuando el usuario hace clic en el botón de inserción, la acción insertImmobilier se envía a Redux mediante dispatch(). Redux Toolkit activa automáticamente el estado pending al inicio de la operación asíncrona. El código .addCase(insertImmobilier.pending, (state) => { ... }) define lo que debe ocurrir mientras la operación está cargando. La propiedad state.loading se establece entonces en true. Esto indica a la interfaz React que una inserción está actualmente en curso. El código también establece state.error = null, lo que elimina un error anterior antes de iniciar una nueva operación. En el componente React, el valor loading se utiliza para desactivar temporalmente el botón y cambiar su texto. Por lo tanto, durante la inserción, el usuario ve "Insertando..." en lugar de "Insertar datos". Esta lógica también evita que el usuario haga clic varias veces en el botón durante la misma operación.

# 52 — Gestión del estado Fulfilled

Cuando la solicitud POST al backend tiene éxito, Redux Toolkit activa automáticamente el estado fulfilled. El código recupera entonces la información devuelta por el servidor mediante action.payload. La primera instrucción es state.loading = false, lo que indica que la inserción ha finalizado. A continuación, el código recupera el estado devuelto por el backend mediante state.status = action.payload.status. El mensaje devuelto por el servidor se almacena en state.message = action.payload.message. Finalmente, el número de filas procesadas se almacena mediante state.rows = action.payload.rows. Gracias a esta lógica, el frontend puede mostrar con precisión el resultado de la operación. Por ejemplo, si el backend devuelve un estado de éxito, un mensaje que confirma la inserción y el número de filas insertadas, esta información queda disponible en el store de Redux. React la recupera posteriormente mediante useSelector() para mostrarla al usuario.

# 53 — Gestión del estado Rejected

Cuando la solicitud de Axios falla, Redux Toolkit activa el estado rejected. Esta situación puede producirse si el servidor backend está detenido, si la dirección de la API es incorrecta, si aparece un error del servidor o si otro error impide la inserción. En esta situación, el código vuelve a establecer state.loading en false, porque la operación ha terminado aunque haya fallado. El error se recupera posteriormente mediante action.payload.message y se almacena en state.error. El componente React puede entonces mostrar este error en la interfaz mediante la condición {error && ...}. Esta gestión permite, por tanto, informar claramente al usuario cuando no se puede realizar una inserción. Todo el ciclo de la operación asíncrona es gestionado por Redux Toolkit: pending al inicio, fulfilled en caso de éxito y rejected en caso de error.

# 54 — Exportación del reducer

Al final del archivo Redux, el código utiliza export default immobilierSlice.reducer. Esta instrucción exporta el reducer creado por createSlice(). Este reducer deberá añadirse posteriormente al store principal de Redux de la aplicación. Una vez registrado en el store, estará disponible para el componente React mediante useSelector(), y las acciones podrán ejecutarse mediante useDispatch(). Esta organización permite, por tanto, centralizar toda la lógica de estado relacionada con la inserción de datos inmobiliarios en el slice immobilier.

# 55 — Importación de las funcionalidades de React

El componente ImmobilierDashboard comienza importando React, así como las herramientas necesarias de Redux. useDispatch permite al componente enviar acciones a Redux, mientras que useSelector permite recuperar los datos presentes en el store. El componente también importa la acción insertImmobilier desde el archivo Redux immobilierSlice. Esta acción se utilizará cuando el usuario haga clic en el botón de inserción. El archivo CSS ImmobilierDashboard.css también se importa para separar la lógica de presentación de la lógica JavaScript.

# 56 — Importación y configuración de Chart.js

El componente también utiliza la biblioteca Chart.js con el componente React Bar proporcionado por react-chartjs-2. Esta biblioteca permite representar los datos inmobiliarios en forma de gráfico. Se importan varios elementos de Chart.js: CategoryScale para el eje que contiene las categorías, LinearScale para el eje numérico, BarElement para las barras del gráfico, Title para la gestión del título, Tooltip para mostrar información al pasar el cursor y Legend para la leyenda. Estos elementos se registran posteriormente mediante ChartJS.register(). Este paso es necesario para que Chart.js pueda utilizar correctamente estos componentes en el gráfico. El proyecto puede, por tanto, crear un gráfico de barras que muestre los precios asociados a diferentes tipos de bienes inmobiliarios.

# 57 — Creación del componente ImmobilierDashboard

La función ImmobilierDashboard() representa la página principal del dashboard inmobiliario. Combina varias funcionalidades: mostrar el informe de Power BI, el gráfico de precios inmobiliarios, el botón de inserción y los resultados devueltos por el backend. Por tanto, el componente actúa como capa de presentación. Recibe información desde Redux y la transforma en elementos visibles en la interfaz. El usuario puede así consultar la información inmobiliaria e iniciar una operación de inserción sin tener que comunicarse directamente con la API backend.

# 58 — Uso de useDispatch

El código utiliza const dispatch = useDispatch() para obtener la función utilizada para enviar acciones de Redux. Esta función se utiliza posteriormente en handleInsert() mediante la instrucción dispatch(insertImmobilier(data)). Esto significa que React prepara los datos y luego solicita a Redux que ejecute la acción asíncrona de inserción. El componente no realiza directamente la solicitud de Axios. La comunicación con el backend está centralizada en el slice de Redux. Esta separación hace que el código esté más organizado y facilita el mantenimiento de la aplicación.

# 59 — Recuperación del estado con useSelector

El componente recupera posteriormente la información del slice inmobiliario mediante useSelector(). La instrucción const { status, message, rows, loading, error } = useSelector((state) => state.immobilier) extrae varias propiedades del store de Redux. status contiene el estado de la operación, message contiene el mensaje devuelto por el backend, rows contiene el número de filas procesadas, loading indica si la inserción está en curso y error contiene un posible error. Gracias a useSelector(), el componente React recibe automáticamente la información cuando estos valores cambian en Redux y puede actualizar la interfaz en consecuencia.

# 60 — Creación de la función handleInsert

La función handleInsert() se ejecuta cuando el usuario hace clic en el botón "Insertar datos". Comienza creando una constante llamada data. Esta constante contiene un array de dos objetos que representan dos bienes inmobiliarios. El primer objeto corresponde a una Casa con una superficie de 120 m², un precio de 200000 y una fuente llamada AROUS. El segundo objeto corresponde a un Apartamento con una superficie de 80 m², un precio de 150000 y una fuente llamada GEMMA. Cada objeto también posee un identificador idImmobilier. Después de preparar este array, la función llama a dispatch(insertImmobilier(data)). Redux recibe los datos y activa el proceso asíncrono. Axios envía posteriormente los datos al backend mediante la solicitud POST definida en el slice. Esta función representa, por tanto, el punto de partida de toda la operación de inserción desde la interfaz de usuario.

# 61 — Preparación de los datos del gráfico

El gráfico se prepara utilizando la constante chartData. Esta constante contiene la información necesaria para que Chart.js construya el gráfico de barras. La propiedad labels contiene las categorías mostradas en el eje horizontal: Casa y Apartamento. La propiedad datasets contiene las series de datos del gráfico. Se define una serie llamada Precio Inmobiliario que contiene los valores 200000 y 150000. Estos valores corresponden a los precios de la casa y del apartamento definidos anteriormente en los datos de ejemplo. El gráfico permite, por tanto, comparar visualmente los precios de los dos tipos de bienes inmobiliarios.

# 63 — Visualización del estado de carga

El componente utiliza la propiedad loading para determinar si la inserción está actualmente en curso. El botón tiene la propiedad disabled={loading}. Cuando loading es true, el botón se desactiva para evitar múltiples inserciones simultáneas. Su texto también cambia mediante una expresión condicional: {loading ? "Insertion..." : "Insert data"}. De esta manera, el usuario puede comprender inmediatamente que la operación está en curso. Cuando Redux pasa al estado fulfilled o rejected, loading vuelve a ser false y el botón vuelve a estar disponible. Esta pequeña lógica mejora la experiencia del usuario y permite seguir visualmente el procesamiento de la solicitud.

# 64 — Visualización del resultado de la inserción

Después de una inserción exitosa, el componente comprueba si status existe mediante la condición {status && (...)}. Si esta condición es verdadera, se muestra un párrafo con la clase CSS success. Su contenido combina el mensaje devuelto por el backend y el número de filas procesadas. La expresión {message} ({rows} rows) permite mostrar información como el mensaje de éxito acompañado del número de filas insertadas. Los valores mostrados no están escritos directamente dentro del componente: proceden del backend, se han almacenado en Redux y posteriormente React los recupera mediante useSelector(). Esta cadena muestra claramente el recorrido de la información desde el servidor hasta la interfaz de usuario.

# 65 — Visualización de errores

El componente también permite mostrar errores mediante {error && (...)}. Si existe un error en el estado de Redux, se muestra un párrafo con la clase error que contiene el valor de la variable error. Esta información procede del bloque catch del thunk de Redux. Cuando se produce un error, rejectWithValue() transmite la información al reducer rejected, que la almacena en state.error. React recupera posteriormente este valor mediante useSelector(). El usuario puede así ser informado directamente en la interfaz cuando un error impide la inserción de los datos inmobiliarios.

El gráfico se muestra utilizando el componente Bar proporcionado por react-chartjs-2. La instrucción <Bar data={chartData} /> transmite a Chart.js los datos preparados anteriormente. Chart.js utiliza entonces las labels para mostrar las categorías y los valores del dataset para construir las barras. En este caso, el gráfico representa los precios de dos categorías inmobiliarias: Casa y Apartamento. # 68 — Comunicación completa entre React, Redux, Axios y Backend

El proceso completo comienza cuando el usuario abre el Dashboard Inmobiliario. React muestra el componente ImmobilierDashboard junto con el informe de Power BI y el gráfico de Chart.js. Cuando el usuario hace clic en el "Insertar datos", la función handleInsert() crea el array que contiene la información inmobiliaria. A continuación, llama a dispatch(insertImmobilier(data)). Redux Toolkit activa entonces el estado pending y la propiedad loading pasa a true. El thunk insertImmobilier utiliza Axios para enviar una solicitud HTTP POST a /insert. El backend recibe los datos, los procesa y devuelve una respuesta. Si la respuesta es correcta, Redux activa fulfilled, desactiva la carga y almacena el estado, el mensaje y el número de filas en el store. Si se produce un error, Redux activa rejected y almacena el mensaje de error. Gracias a useSelector(), React recupera automáticamente los nuevos valores y actualiza la interfaz. El botón vuelve a su estado normal y se muestra el resultado o el error. Esta comunicación forma, por tanto, una cadena completa entre el usuario, React, Redux Toolkit, Axios, el backend y finalmente el retorno de la información a la interfaz.

# 72 — Ciclo completo de inserción de datos

El ciclo comienza cuando el usuario hace clic en el botón "Insertar datos". La función handleInsert() prepara dos objetos inmobiliarios y los agrupa en un array. El array se pasa posteriormente a insertImmobilier(data) mediante dispatch(). Redux Toolkit activa el estado pending, lo que activa el indicador de carga y desactiva el botón. El thunk utiliza posteriormente Axios para enviar los datos a la API backend mediante una solicitud POST. El servidor recibe los datos y los procesa. Si la operación tiene éxito, la respuesta del servidor se convierte en el payload de fulfilled. Redux recupera entonces el estado, el mensaje y el número de filas. La carga se desactiva y el mensaje de éxito se hace visible en la interfaz. Si la operación falla, el bloque catch transmite el error a Redux mediante rejectWithValue(). El reducer rejected almacena este error y React lo muestra al usuario. El ciclo completo permite, por tanto, supervisar con precisión el estado de la operación desde su inicio hasta su resultado final.
