# 47 — Gestion des données Immobilier avec Redux Toolkit et React

Dans cette partie du projet, un système de gestion des données immobilières a été développé en utilisant plusieurs technologies frontend complémentaires, notamment React, Redux Toolkit, Axios, Chart.js et Power BI. L'objectif principal de cette fonctionnalité est de permettre à l'utilisateur d'afficher un dashboard immobilier contenant un rapport Power BI, un graphique représentant les prix immobiliers et une fonctionnalité permettant d'insérer des données immobilières dans le backend. L'architecture repose sur une séparation claire entre la gestion des données et leur affichage. Redux Toolkit est utilisé pour centraliser l'état relatif à l'insertion des données immobilières, tandis que React est responsable de l'interface utilisateur et des interactions. Axios assure la communication HTTP entre le frontend et le backend Node.js/Express. Lorsqu'un utilisateur clique sur le bouton « Insérer données », la fonction handleInsert() prépare un tableau contenant plusieurs biens immobiliers, puis déclenche l'action Redux insertImmobilier(). Cette action est créée avec createAsyncThunk() et envoie une requête HTTP POST vers l'adresse http://localhost:3000/insert. Le backend reçoit alors les données et effectue leur traitement. Redux Toolkit gère ensuite automatiquement les différents états de l'opération asynchrone avec pending, fulfilled et rejected. Lorsque l'insertion commence, la propriété loading devient vraie. Lorsque l'insertion réussit, Redux récupère le statut, le message et le nombre de lignes traitées retournés par le backend. En cas d'erreur, le message correspondant est enregistré dans error. Le composant React utilise ensuite useSelector() pour récupérer ces informations depuis le store Redux et afficher le résultat à l'utilisateur. En parallèle, Chart.js permet de présenter graphiquement les prix de deux biens immobiliers, une maison et un appartement, tandis qu'une iframe permet d'intégrer un rapport Power BI directement dans l'interface. Cette architecture permet donc de réunir dans une même page la Business Intelligence avec Power BI, la visualisation graphique avec Chart.js, la gestion d'état avec Redux Toolkit et la communication avec le backend grâce à Axios.

# 48 — Importation de Redux Toolkit et Axios

Le fichier Redux commence par l'importation de deux fonctionnalités essentielles de Redux Toolkit : createSlice et createAsyncThunk. createSlice permet de créer une partie spécifique du store Redux destinée à gérer les données immobilières. Il permet de définir le nom du slice, son état initial ainsi que les traitements associés aux différentes actions. createAsyncThunk est utilisé pour créer une action asynchrone capable d'effectuer une opération qui nécessite du temps, comme une requête HTTP vers un serveur backend. Le code importe également Axios avec import axios from "axios". Axios est une bibliothèque JavaScript permettant d'envoyer des requêtes HTTP. Dans ce projet, Axios est utilisé pour envoyer les données immobilières du frontend React vers le backend Node.js/Express. L'association de Redux Toolkit et Axios permet donc de créer une communication organisée entre l'interface utilisateur et l'API backend.

# 49 — Création de l'action asynchrone insertImmobilier

L'action principale du fichier Redux est insertImmobilier. Elle est créée avec createAsyncThunk(). Le premier paramètre "immobilier/insertImmobilier" correspond au type de l'action Redux et permet d'identifier cette opération dans l'application. Le deuxième paramètre est une fonction asynchrone qui reçoit les données immobilières dans la variable data. La fonction utilise ensuite un bloc try/catch afin de gérer correctement le succès ou l'échec de la communication avec le serveur. Dans le bloc try, Axios utilise axios.post("http://localhost:3000/insert", data) pour envoyer une requête HTTP POST vers le backend. La variable data contient les informations immobilières préparées dans le composant React. Lorsque le serveur répond, la réponse est enregistrée dans la variable res. res.data contient les informations retournées par le backend. Cette valeur est ensuite retournée par la fonction avec return res.data. Elle devient automatiquement le payload de l'action fulfilled lorsque l'opération réussit. Dans le bloc catch, si Axios rencontre une erreur, le code utilise rejectWithValue() pour transmettre l'erreur au reducer Redux. L'expression err.response.data permet de récupérer les informations d'erreur envoyées par le backend. Cette organisation permet donc de gérer proprement la communication entre le frontend et le backend.

# 50 — Création du slice Immobilier

Le code crée ensuite le slice Redux avec createSlice(). Le slice est nommé "immobilier" grâce à la propriété name. Il représente une partie du store global consacrée à la fonctionnalité immobilière. L'état initial contient plusieurs propriétés : status, message, rows, loading et error. La propriété status est initialement définie à null et servira à recevoir le statut retourné par le backend après l'insertion. message contient initialement une chaîne vide et sera utilisée pour afficher le message retourné par le serveur. rows est initialisé à zéro et représente le nombre de lignes traitées ou insérées. La propriété loading est initialement à false, ce qui signifie qu'aucune opération d'insertion n'est en cours au démarrage. Enfin, error est initialisée à null afin de pouvoir stocker une éventuelle erreur. Le slice centralise donc toutes les informations nécessaires au suivi de l'opération d'insertion.

# 51 — Gestion de l'état pending

Lorsque l'utilisateur clique sur le bouton d'insertion, l'action insertImmobilier est envoyée à Redux avec dispatch(). Redux Toolkit déclenche automatiquement l'état pending au début de l'opération asynchrone. Le code .addCase(insertImmobilier.pending, (state) => { ... }) permet de définir ce qui doit se produire pendant le chargement. La propriété state.loading est alors mise à true. Cela indique à l'interface React qu'une insertion est actuellement en cours. Le code met également state.error = null, ce qui permet de supprimer une ancienne erreur avant de commencer une nouvelle opération. Dans le composant React, la valeur loading est utilisée pour désactiver temporairement le bouton et modifier son texte. Ainsi, pendant l'insertion, l'utilisateur voit « Insertion... » au lieu de « Insérer données ». Cette logique évite également que l'utilisateur clique plusieurs fois sur le bouton pendant la même opération.

# 52 — Gestion de l'état fulfilled

Lorsque la requête POST vers le backend réussit, Redux Toolkit déclenche automatiquement l'état fulfilled. Le code récupère alors les informations retournées par le serveur grâce à action.payload. La première instruction est state.loading = false, ce qui indique que l'insertion est terminée. Le code récupère ensuite le statut retourné par le backend avec state.status = action.payload.status. Le message retourné par le serveur est stocké dans state.message = action.payload.message. Enfin, le nombre de lignes traitées est enregistré avec state.rows = action.payload.rows. Grâce à cette logique, le frontend peut afficher précisément le résultat de l'opération. Par exemple, si le backend retourne un statut de succès, un message confirmant l'insertion et le nombre de lignes insérées, ces informations deviennent disponibles dans le store Redux. React les récupère ensuite avec useSelector() afin de les présenter à l'utilisateur.

# 53 — Gestion de l'état rejected

Lorsque la requête Axios échoue, Redux Toolkit déclenche l'état rejected. Cette situation peut se produire si le serveur backend est arrêté, si l'adresse de l'API est incorrecte, si une erreur serveur apparaît ou si une autre erreur empêche l'insertion. Dans cette situation, le code remet state.loading à false, car l'opération est terminée même si elle a échoué. L'erreur est ensuite récupérée avec action.payload.message et enregistrée dans state.error. Le composant React peut alors afficher cette erreur dans l'interface grâce à la condition {error && ...}. Cette gestion permet donc d'informer clairement l'utilisateur lorsqu'une insertion ne peut pas être effectuée. Le cycle de l'opération asynchrone est ainsi entièrement pris en charge par Redux Toolkit : pending au démarrage, fulfilled en cas de succès et rejected en cas d'erreur.

# 54 — Exportation du reducer

À la fin du fichier Redux, le code utilise export default immobilierSlice.reducer. Cette instruction permet d'exporter le reducer créé par createSlice(). Ce reducer devra ensuite être ajouté au store Redux principal de l'application. Une fois enregistré dans le store, il devient accessible au composant React grâce à useSelector() et les actions peuvent être déclenchées grâce à useDispatch().
