Visão Geral

Este módulo apresenta uma arquitetura para integrar dados ou modelos de Machine Learning em uma aplicação Web desenvolvida com Node.js e Express, utilizando MySQL como sistema de armazenamento dos resultados. Neste projeto de parafarmácia, são gerados dois arquivos Python no formato PKL: biodream.pkl e bonheur.pkl. Esses arquivos representam objetos que são salvos utilizando a biblioteca Python pickle. O backend Node.js utiliza então o Express para disponibilizar uma API acessível pelo frontend. Quando uma requisição é enviada para /parapharma, o Express chama uma rota específica. Essa rota utiliza o serviço parapharmaservice.js para produzir valores reais e valores previstos. Os resultados são então armazenados no banco de dados MySQL, especialmente na tabela gb_model1. O objetivo dessa arquitetura é, portanto, separar as diferentes responsabilidades: os modelos e o processamento são tratados no lado Python, o Node.js gerencia a lógica do backend e a comunicação com a API, o Express organiza as rotas HTTP, o MySQL armazena os resultados e o frontend pode utilizar esses dados para exibir gráficos, indicadores ou dashboards.

Geração dos Arquivos PKL

A primeira parte do projeto diz respeito ao armazenamento de objetos em arquivos .pkl. O módulo Python utiliza a biblioteca pickle. Essa biblioteca permite serializar um objeto Python, ou seja, transformar o objeto em um formato que pode ser armazenado em um arquivo e carregado novamente posteriormente. No código fornecido, é criada uma função chamada save_pickle() para centralizar essa operação de armazenamento. A função recebe dois parâmetros: o objeto que será salvo e o nome do arquivo. O arquivo é aberto utilizando o modo wb, que significa "write binary", e então pickle.dump() salva o objeto dentro do arquivo. O programa cria então dois objetos: data_biodream e data_bonheur. O primeiro contém um score de 0.92 e o tipo "biodream_model", enquanto o segundo contém um score de 0.88 e o tipo "bonheur_model". Esses objetos são então salvos nos arquivos biodream.pkl e bonheur.pkl. É importante especificar que, no código fornecido, esses arquivos PKL atualmente contêm dicionários Python de demonstração, e não um modelo de Machine Learning treinado com uma biblioteca como Scikit-learn. Entretanto, a arquitetura pode utilizar a mesma lógica com um modelo real previamente treinado.

Servidor Node.js com Express

A segunda parte do sistema diz respeito ao backend Node.js. Node.js é o ambiente de execução JavaScript utilizado no lado do servidor. Express é utilizado como framework para criar a API. O servidor primeiro importa o Express utilizando require("express") e depois cria uma aplicação com express(). A instrução app.use(express.json()) permite que o servidor processe requisições que contêm dados no formato JSON. Em seguida, as rotas do módulo de parafarmácia são importadas a partir de ./Routes/parapharmaRoute. A linha app.use("/parapharma", parapharmaRoutes) associa essas rotas ao prefixo /parapharma. Finalmente, o servidor fica escutando na porta 3000. Isso significa que a API pode ser acessada através de http://localhost:3000 e que a rota principal do módulo está disponível através de GET /parapharma.

04

Serviço de Previsão

O arquivo parapharmaservice.js contém a função trainModels(). Essa função representa a camada de serviço do backend. Sua função é preparar os dados e produzir as previsões que serão posteriormente enviadas para a rota Express. O array X contém os valores de entrada 1, 2, 3, 4 e 5. O array y contém os valores reais 100, 200, 300, 400 e 500. O método map() percorre cada valor de X e aplica a regra v * 100. O resultado é armazenado no array predictions. Portanto, para 1 a previsão é 100, para 2 é 200, para 3 é 300, para 4 é 400 e para 5 é 500. A função então retorna um objeto contendo success e um objeto data contendo X, y e predictions. É importante especificar que essa função atualmente não realiza um treinamento real de Machine Learning. Ela simula uma previsão utilizando uma fórmula matemática simples. Em uma versão avançada, essa função poderia chamar um modelo real previamente treinado ou um serviço Python responsável por realizar a previsão.

const X = [

1,

2,

3,

4,

5

];

100,

400,

500

];

const predictions =

X.map(v => v * 100);

return {

success: true,

data: {

X,

y,

predictions

}

};

}

trainModels

};

Os arquivos biodream.pkl e bonheur.pkl também são atualmente objetos Python salvos, e não modelos treinados. Entretanto, essa arquitetura pode servir como base para integrar posteriormente um modelo preditivo real.

Rota Express e Processamento dos Resultados

O arquivo parapharmaRoute.js funciona como ponto de coordenação entre o serviço de previsão e o banco de dados MySQL. A rota utiliza router.get("/"), o que significa que, quando um cliente chama GET /parapharma, essa função é executada. O primeiro passo é abrir uma conexão MySQL utilizando getConnection(). O segundo passo é chamar trainModels(). O resultado retornado contém os valores reais e as previsões. O código recupera então result.data.y na variável real e result.data.predictions na variável pred. Em seguida, Math.min() determina o número de elementos compartilhados pelos dois arrays. Um loop for percorre então os valores e utiliza connection.execute() para inserir cada par valor real / previsão na tabela gb_model1. Após a inserção, o Express retorna uma resposta JSON contendo uma mensagem de sucesso, o número de linhas inseridas e os valores reais associados às suas previsões. A rota representa, portanto, a conexão entre o serviço de cálculo e o banco de dados.

📄 parapharmaRoute.js 
const express = require("express");

const router = express.Router();

const {
getConnection
} = require("../DBMysql/parapharmadb");

const {
trainModels
} = require("../service/parapharmaservice");

router.get("/", async (req, res) => {

let connection;

try {

connection =
await getConnection();

const result =
await trainModels();

const real =
result.data.y;

const pred =
result.data.predictions;

const length =
Math.min(
real.length,
pred.length
);

for (

let i = 0;

i < length;

i++

) {

await connection.execute(

    `INSERT INTO gb_model1
    (real_value, prediction)
    VALUES (?, ?)`,

    [
        real[i],
        pred[i]
    ]

);

}

res.status(200).json({

message:
    "Modelo treinado e salvo",

rowsInserted:
    length,

data:
    real.map((r, i) => ({

        real: r,

        prediction:
            pred[i]

    }))

});

} catch (err) {

res.status(500).json({

error:
    err.message

});

} finally {

if (connection) {

await connection.end();

}

}

});

module.exports = router;

Arquitetura Completa

A arquitetura completa funciona como uma cadeia de processamento. O frontend ou dashboard chama a API Node.js através do endpoint /parapharma. O Express recebe essa requisição e executa a rota definida em parapharmaRoute.js. A rota abre uma conexão com o MySQL e depois chama trainModels(). O serviço prepara os dados X e y e calcula as previsões. Os valores reais e previstos são então recuperados pela rota. Para cada observação, o Node.js executa uma consulta SQL para armazenar o valor real e a previsão em gb_model1. Depois que todas as linhas são armazenadas, o Express retorna uma resposta JSON para o frontend. O dashboard pode então recuperar esses dados da API e exibi-los como gráficos ou indicadores. Os arquivos biodream.pkl e bonheur.pkl pertencem à camada Python responsável por salvar objetos e podem posteriormente ser utilizados como base para integrar modelos preditivos reais.

Explicação para uma Apresentação Comercial

Durante uma apresentação comercial, não é necessário apresentar cada linha de código ao cliente. O principal objetivo é explicar como o sistema funciona e qual valor ele oferece. Você pode explicar que o módulo de parafarmácia utiliza uma arquitetura dividida em várias camadas. Os dados e modelos são preparados no lado Python e podem ser salvos como arquivos PKL. Nesta versão, dois objetos são salvos: biodream.pkl e bonheur.pkl. O backend Node.js utiliza então o Express para disponibilizar uma API. Quando o frontend solicita os resultados através de /parapharma, o Express executa a rota correspondente. Essa rota chama o serviço trainModels(), que prepara os dados e calcula as previsões. Os resultados são então comparados com os valores reais e armazenados no MySQL na tabela gb_model1. Depois que o processamento é concluído, a API retorna os dados ao frontend no formato JSON. O dashboard pode então utilizar essas informações para criar gráficos e indicadores que ajudam a visualizar o desempenho do modelo. A principal vantagem dessa arquitetura é a separação das responsabilidades: Python é utilizado para o modelo e o processamento, Node.js e Express gerenciam a comunicação do backend, MySQL armazena os resultados e o frontend fornece a visualização. Essa organização permite que o projeto evolua gradualmente para um sistema preditivo real, substituindo a simulação atual por um modelo de Machine Learning realmente treinado.

Conclusão

Este módulo apresenta uma arquitetura completa para conectar a preparação dos modelos, o backend, a API e o banco de dados. Os arquivos PKL permitem salvar objetos Python, enquanto Node.js e Express fornecem acesso a essa funcionalidade a partir de uma aplicação Web. Em uma versão futura, o cálculo atualmente simulado dentro de trainModels() pode ser substituído por um modelo real de Machine Learning treinado com dados reais. Os arquivos PKL poderão então conter os modelos treinados, e o backend poderá recuperar as previsões e apresentá-las diretamente na aplicação Web.
