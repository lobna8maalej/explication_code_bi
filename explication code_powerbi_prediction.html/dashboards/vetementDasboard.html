👕 Vetement ML Dashboard — Documentation technique

Cette documentation explique en détail le fonctionnement du composant VetementDashboard.jsx, sa communication avec le backend grâce à Fetch API, la structure du fichier vetementSlice.js, ainsi que l'utilisation de React, Redux Toolkit, Recharts, ScatterChart, Power BI et du système de Machine Learning.

Le Dashboard Vêtement permet d'envoyer automatiquement des données concernant un produit vestimentaire vers le backend.

Les données envoyées sont :

  • Prix_C1 = 150
  • Prix_C2 = 180
  • numbers = 15
  • Target = 1

La requête est envoyée avec la méthode HTTP POST vers : 

http://localhost:3000/vetement

Le backend traite ensuite ces données et retourne une réponse JSON. Cette réponse est stockée dans la variable d'état items.

Les données retournées sont ensuite utilisées pour construire un Scatter Plot avec Recharts.

En parallèle, un rapport Power BI est affiché directement dans le Dashboard grâce à une iframe.

1. Présentation générale du projet

Le composant VetementDashboard.jsx représente l'interface React du Dashboard consacré aux données de vêtements.

Son objectif est d'envoyer automatiquement des données au backend afin de récupérer une réponse provenant du système de traitement et de Machine Learning.

Le composant affiche ensuite les données reçues sous forme de Scatter Plot.

Il contient également un rapport Power BI intégré avec une iframe.

39. Présentation du fichier vetementSlice.js

Le fichier vetementSlice.js utilise Redux Toolkit afin de définir une logique Redux destinée aux données Vêtement.

40. Importation de Redux Toolkit 

import {
    createSlice,
    createAsyncThunk
} from "@reduxjs/toolkit";

createSlice permet de créer la structure Redux du module Vêtement.

createAsyncThunk permet de gérer une opération asynchrone, ici la récupération des données depuis le backend.

41. Importation d'Axios 

import axios from "axios";

Axios est utilisé dans le Slice pour communiquer avec le backend.

42. Création de fetchVetementData 

export const fetchVetementData = createAsyncThunk(
    "vetement/fetch",
    async (_, thunkAPI) => {
        ...
    }
);

Cette fonction crée une action Redux asynchrone appelée : 

vetement/fetch

Elle permet de récupérer les données du endpoint /vetement.

43. Requête GET avec Axios 

const res = await axios.get(
    "http://localhost:3000/vetement"
);

Axios envoie ici une requête HTTP GET.

Le backend retourne ensuite les données disponibles pour le module Vêtement.

44. Retour de res.data 

return res.data;

Cette instruction retourne les données reçues du backend vers le système Redux.

La réponse peut notamment avoir une structure de type : 

{
    message: "...",
    size: ...,
    data: [...]
}

La structure exacte dépend de la réponse fournie par le backend.

45. Gestion des erreurs dans le Slice 

catch (error) {
    return thunkAPI.rejectWithValue(
        error.response?.data?.error ||
        error.message
    );
}

Si Axios rencontre une erreur, le Slice utilise rejectWithValue() afin de transmettre un message d'erreur personnalisé à Redux.

L'opérateur ?. permet de vérifier que les propriétés intermédiaires existent avant d'y accéder.

        items: null,

    },
    ...
});

Cette instruction crée le Slice Redux appelé vetement.

    items: null,

Propriété Valeur initiale Rôle

48. extraReducers 

extraReducers: (builder) => {
    builder
        ...
}

extraReducers permet au Slice de réagir aux différents états de l'action asynchrone fetchVetementData.

Trois états principaux sont gérés :

  • pending
  • fulfilled
  • rejected

49. État pending 

.addCase(
    fetchVetementData.pending,
    (state) => {
        state.loading = true;
        state.error = null;
    }
)

Lorsque la requête commence, Redux positionne : 

loading = true

L'erreur précédente est également supprimée : 

error = null

50. État fulfilled 

.addCase(
    fetchVetementData.fulfilled,
    (state, action) => {
        state.loading = false;
        state.items = action.payload;
    }
)

Lorsque la requête réussit :

  • loading devient false
  • items reçoit les données retournées par l'action asynchrone. 
Requête réussie
      ↓
fulfilled
      ↓
loading = false
      ↓
items = action.payload

51. État rejected 

.addCase(
    fetchVetementData.rejected,
    (state, action) => {
        state.loading = false;
        state.error = action.payload;
    }
)

Si la requête échoue : 

loading = false

et le message d'erreur est stocké dans : 

error = action.payload

54. Point important : Fetch et Redux ne sont pas utilisés ensemble dans ce composant

Dans le code fourni, VetementDashboard.jsx utilise directement Fetch API avec useState.

Il n'utilise pas useDispatch() ni useSelector().

Le fichier vetementSlice.js possède cependant sa propre logique Redux avec fetchVetementData() et Axios.

Il faut donc distinguer les deux flux : 

FLUX ACTUEL DU DASHBOARD

VetementDashboard.jsx
        ↓
useEffect()
        ↓
Fetch POST
        ↓
/vetement
        ↓
Backend
        ↓
setItems()
        ↓
items
        ↓
ScatterChart


FLUX REDUX DU SLICE

fetchVetementData()
        ↓
Axios GET
        ↓
/vetement
        ↓
Redux
        ↓
items / loading / error

55. Pourquoi cette distinction est importante ?

Cette distinction permet de comprendre précisément l'architecture actuelle du projet.

Le Dashboard utilise actuellement un état local React : 

const [items, setItems] = useState(null);

tandis que le Slice Redux possède son propre état : 

{
    items: null,
    loading: false,
    error: null
}

Il existe donc actuellement deux mécanismes de gestion des données Vêtement.
