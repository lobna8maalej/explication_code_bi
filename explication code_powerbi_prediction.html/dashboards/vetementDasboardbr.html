👕 Vetement ML Dashboard — Documentação técnica

Esta documentação explica em detalhes o funcionamento do componente VetementDashboard.jsx, sua comunicação com o backend por meio da Fetch API, a estrutura do arquivo vetementSlice.js, bem como o uso de React, Redux Toolkit, Recharts, ScatterChart, Power BI e do sistema de Machine Learning.

O Dashboard de Roupas permite enviar automaticamente dados relacionados a um produto de vestuário para o backend.

Os dados enviados são:

  • Prix_C1 = 150
  • Prix_C2 = 180
  • numbers = 15
  • Target = 1

A requisição é enviada usando o método HTTP POST para: 

http://localhost:3000/vetement

O backend processa esses dados e retorna uma resposta JSON. Essa resposta é armazenada na variável de estado items.

Os dados retornados são então usados para construir um Scatter Plot com Recharts.

Paralelamente, um relatório do Power BI é exibido diretamente no Dashboard por meio de uma iframe.

1. Apresentação geral do projeto

O componente VetementDashboard.jsx representa a interface React do Dashboard dedicado aos dados de roupas.

Seu objetivo é enviar automaticamente dados ao backend para obter uma resposta do sistema de processamento e de Machine Learning.

O componente então exibe os dados recebidos na forma de um Scatter Plot.

Ele também contém um relatório do Power BI integrado por meio de uma iframe.

39. Apresentação do arquivo vetementSlice.js

O arquivo vetementSlice.js usa Redux Toolkit para definir uma lógica Redux destinada aos dados de Roupas.

Ele contém, entre outras, a seguinte ação assíncrona: 

fetchVetementData

Essa ação usa Axios para realizar uma requisição GET ao backend.

40. Importação do Redux Toolkit 

import {
    createSlice,
    createAsyncThunk
} from "@reduxjs/toolkit";

createSlice permite criar a estrutura Redux do módulo de Roupas.

createAsyncThunk permite gerenciar uma operação assíncrona, neste caso a recuperação de dados do backend.

41. Importação do Axios 

import axios from "axios";

Axios é usado no Slice para se comunicar com o backend.

42. Criação de fetchVetementData 

export const fetchVetementData = createAsyncThunk(
    "vetement/fetch",
    async (_, thunkAPI) => {
        ...
    }
);

Esta função cria uma ação Redux assíncrona chamada: 

vetement/fetch

Ela permite recuperar os dados do endpoint /vetement.

43. Requisição GET com Axios 

const res = await axios.get(
    "http://localhost:3000/vetement"
);

Axios envia aqui uma requisição HTTP GET.

O backend então retorna os dados disponíveis para o módulo de Roupas.

44. Retorno de res.data 

return res.data;

Esta instrução retorna os dados recebidos do backend para o sistema Redux.

A resposta pode ter, por exemplo, uma estrutura como: 

{
    message: "...",
    size: ...,
    data: [...]
}

A estrutura exata depende da resposta fornecida pelo backend.

45. Gerenciamento de erros no Slice 

catch (error) {
    return thunkAPI.rejectWithValue(
        error.response?.data?.error ||
        error.message
    );
}

Se o Axios encontrar um erro, o Slice usa rejectWithValue() para transmitir uma mensagem de erro personalizada ao Redux.

O operador ?. permite verificar se as propriedades intermediárias existem antes de acessá-las.

46. Criação do Slice 

const vetementSlice = createSlice({
    name: "vetement",
    initialState: {
        items: null,
        loading: false,
        error: null,
    },
    ...
});

Esta instrução cria o Slice Redux chamado vetement.

47. InitialState 

initialState: {
    items: null,
    loading: false,
    error: null,
}
Propriedade Valor inicial Função
items null Conterá os dados recuperados.
loading false Indica se a requisição está em andamento.
error null Contém um possível erro.

48. extraReducers 

extraReducers: (builder) => {
    builder
        ...
}

extraReducers permite que o Slice reaja aos diferentes estados da ação assíncrona fetchVetementData.

Três estados principais são gerenciados:

  • pending
  • fulfilled
  • rejected

49. Estado pending 

.addCase(
    fetchVetementData.pending,
    (state) => {
        state.loading = true;
        state.error = null;
    }
)

Quando a requisição começa, o Redux define: 

loading = true

O erro anterior também é removido: 

error = null

50. Estado fulfilled 

.addCase(
    fetchVetementData.fulfilled,
    (state, action) => {
        state.loading = false;
        state.items = action.payload;
    }
)

Quando a requisição é bem-sucedida:

  • loading se torna false
  • items recebe os dados retornados pela ação assíncrona. 
Requisição bem-sucedida
      ↓
fulfilled
      ↓
loading = false
      ↓
items = action.payload

51. Estado rejected 

.addCase(
    fetchVetementData.rejected,
    (state, action) => {
        state.loading = false;
        state.error = action.payload;
    }
)

Se a requisição falhar: 

loading = false

e a mensagem de erro é armazenada em: 

error = action.payload

53. Diferença entre VetementDashboard.jsx e vetementSlice.js

Arquivo Tecnologia Função

54. Ponto importante: Fetch e Redux não são usados juntos neste componente

No código fornecido, VetementDashboard.jsx usa diretamente a Fetch API com useState.

Ele não usa useDispatch() nem useSelector().

No entanto, vetementSlice.js possui sua própria lógica Redux com fetchVetementData() e Axios.

É preciso, portanto, distinguir os dois fluxos: 

FLUXO ATUAL DO DASHBOARD

VetementDashboard.jsx
        ↓
useEffect()
        ↓
Fetch POST
        ↓
/vetement
        ↓
Backend
        ↓
setItems()
        ↓
items
        ↓
ScatterChart


FLUXO REDUX DO SLICE

fetchVetementData()
        ↓
Axios GET
        ↓
/vetement
        ↓
Redux
        ↓
items / loading / error

55. Por que essa distinção é importante?

Essa distinção permite compreender com precisão a arquitetura atual do projeto.

Atualmente, o Dashboard usa um estado local do React: 

const [items, setItems] = useState(null);

enquanto o Slice Redux possui seu próprio estado: 

{
    items: null,
    loading: false,
    error: null
}

Portanto, atualmente existem dois mecanismos de gerenciamento dos dados de Roupas.
