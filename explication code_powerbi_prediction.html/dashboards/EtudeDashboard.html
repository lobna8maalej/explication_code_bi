📊 Dashboard Étude avec Redux Toolkit et React

Explication détaillée du fonctionnement du fichier Redux etudeSlice.js et du composant React EtudeDashboard.jsx.

76 Présentation générale

Cette partie du projet met en place un dashboard consacré à l'étude des données à l'étranger en utilisant plusieurs technologies frontend complémentaires, notamment React, Redux Toolkit, Axios et Recharts. L'objectif principal est de récupérer automatiquement les données depuis le backend, de les stocker dans le store Redux, de gérer les différents états de la requête, puis de présenter les résultats dans une interface React sous forme de liste et de graphique. Le composant React EtudeDashboard communique avec le backend grâce à l'action asynchrone fetchEtudeData. Cette action est créée avec createAsyncThunk et utilise Axios pour envoyer une requête HTTP GET vers l'adresse http://localhost:3000/etude/dashboard. Le backend retourne les données sous forme JSON et le code récupère précisément la propriété data de la réponse. Ces informations sont ensuite envoyées vers Redux, qui les stocke dans la propriété items du state global. Le composant React récupère ensuite les données avec useSelector. Le hook useEffect permet de lancer automatiquement l'action de récupération lorsque la page est chargée. Les données récupérées sont ensuite transformées avec map() afin de créer un tableau adapté à Recharts. Chaque élément contient un nom correspondant au mode, une valeur réelle et une valeur de prédiction. Le composant affiche également le dashboard Power BI grâce à une balise iframe. Enfin, Recharts est utilisé pour construire un graphique de type histogramme permettant de visualiser les prédictions. Cette architecture permet donc de séparer clairement la gestion des données, assurée par Redux Toolkit, de la présentation et de l'interaction, assurées par React.

77 Importation de Redux Toolkit et Axios

Le fichier Redux commence par l'importation de createSlice et createAsyncThunk depuis Redux Toolkit. La fonction createSlice permet de créer une partie du store Redux dédiée aux données de l'étude. Elle permet de définir le nom du slice, l'état initial et les traitements associés aux différentes situations de la requête asynchrone. La fonction createAsyncThunk permet quant à elle de créer une action asynchrone capable de communiquer avec le backend. Le code importe également axios, qui est utilisé comme client HTTP pour effectuer la requête vers l'API Node.js/Express. 

import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";
import axios from "axios";

Ces importations constituent donc la base de la communication entre le frontend React, le store Redux et le backend.

78 Création de l'action asynchrone fetchEtudeData

L'action principale du fichier Redux est fetchEtudeData. Elle est créée avec createAsyncThunk. Cette fonction permet d'effectuer une opération asynchrone tout en laissant Redux Toolkit gérer automatiquement les états pending, fulfilled et rejected. Le premier argument, "etude/fetchEtudeData", correspond au type de l'action Redux. Il permet d'identifier cette opération dans l'application. Le deuxième argument est une fonction asynchrone qui sera exécutée lorsque l'action sera appelée depuis le composant React. 

export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        try {
            const response = await axios.get(
                "http://localhost:3000/etude/dashboard"
            );

            return response.data.data;

        } catch (error) {
            return thunkAPI.rejectWithValue(error.message);
        }
    }
);

Le symbole _ représente ici le premier argument de la fonction, mais il n'est pas utilisé car cette action ne nécessite aucune donnée envoyée par le composant. Le deuxième paramètre thunkAPI permet notamment d'utiliser rejectWithValue afin de transmettre une erreur personnalisée vers le state Redux.

79 Requête Axios vers le backend

À l'intérieur de la fonction asynchrone, Axios effectue une requête HTTP de type GET vers la route /etude/dashboard. L'utilisation du mot-clé await permet d'attendre la réponse du serveur avant de poursuivre l'exécution. Lorsque le backend répond, Axios place la réponse dans l'objet response. Les données retournées par le serveur sont accessibles grâce à response.data. Dans ce projet, la réponse contient elle-même une propriété data. Le code récupère donc response.data.data, qui correspond au tableau contenant les données nécessaires au dashboard. 

const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

return response.data.data;

Le return est particulièrement important, car la valeur retournée devient le payload de l'action lorsque la requête se termine correctement.

80 Gestion des erreurs avec try / catch

La requête est placée dans une structure try / catch. Le bloc try contient la requête Axios et son traitement normal. Si la requête échoue, par exemple lorsque le serveur backend est arrêté, lorsque l'URL est incorrecte ou lorsqu'une erreur réseau survient, l'exécution passe dans le bloc catch. Le code récupère alors le message de l'erreur grâce à error.message et utilise thunkAPI.rejectWithValue() pour transmettre cette information vers Redux. Le composant React pourra ensuite récupérer cette erreur grâce à la propriété error. 

catch (error) {
    return thunkAPI.rejectWithValue(error.message);
}

81 Création du etudeSlice

Le code crée ensuite le slice Redux consacré à l'étude avec createSlice. La propriété name définit le nom de cette partie du store. Dans ce cas, le nom est etude. Cette identification permet d'accéder aux données avec state.etude dans le composant React. 

const etudeSlice = createSlice({
    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    reducers: {},

    extraReducers: (builder) => {
        // ...
    }
});

L'utilisation de extraReducers est adaptée ici parce que l'action fetchEtudeData a été créée avec createAsyncThunk. Les états générés automatiquement par cette action sont donc traités dans cette section.

82 Définition du initialState

Le initialState représente l'état initial du module étude. La propriété items est initialisée avec un tableau vide car aucune donnée n'a encore été récupérée. La propriété loading est initialisée à false, ce qui signifie qu'aucune requête n'est actuellement en cours. Enfin, la propriété error est initialisée à null, car aucune erreur n'a encore été rencontrée. Ces trois propriétés permettent au composant React de connaître l'état actuel de la récupération des données. 

initialState: {
    items: [],
    loading: false,
    error: null
}

83 Gestion de l'état pending

Lorsque le composant React exécute dispatch(fetchEtudeData()), Redux Toolkit déclenche automatiquement l'état pending. Cet état signifie que la requête est en cours. Le code met alors state.loading à true et remet la propriété error à null. Grâce à cette information, React peut afficher un message de chargement à l'utilisateur pendant que le backend traite la demande. 

.addCase(fetchEtudeData.pending, (state) => {
    state.loading = true;
    state.error = null;
})

84 Gestion de l'état fulfilled

Lorsque la requête Axios se termine correctement, Redux Toolkit déclenche l'état fulfilled. Cela signifie que le backend a répondu correctement et que les données ont été récupérées. Le code met loading à false puisque le chargement est terminé. Ensuite, action.payload contient les données retournées par fetchEtudeData. Ces données sont directement enregistrées dans state.items. Elles deviennent donc disponibles dans le store Redux. 

.addCase(fetchEtudeData.fulfilled, (state, action) => {
    state.loading = false;
    state.items = action.payload;
})

Cette étape est essentielle car elle fait passer les données du backend vers le store Redux. Le composant React pourra ensuite les récupérer avec useSelector.

85 Gestion de l'état rejected

Si une erreur se produit pendant la requête, Redux Toolkit déclenche l'état rejected. Le code remet d'abord loading à false, car la requête est terminée, puis récupère le message d'erreur grâce à action.payload. Celui-ci correspond à la valeur envoyée par rejectWithValue dans le bloc catch. L'erreur est ensuite enregistrée dans state.error. Le composant React peut ainsi afficher cette erreur à l'utilisateur. 

.addCase(fetchEtudeData.rejected, (state, action) => {
    state.loading = false;
    state.error = action.payload;
})

86 Exportation du reducer

À la fin du fichier Redux, le reducer du slice est exporté avec export default etudeSlice.reducer. Ce reducer pourra ensuite être ajouté au store Redux principal de l'application. Il représente la logique responsable de la modification de l'état etude. 

export default etudeSlice.reducer;

87 Importation des fonctionnalités React

Le fichier React commence par importer React ainsi que le hook useEffect. Il importe également useDispatch et useSelector depuis React Redux. Le composant importe ensuite l'action fetchEtudeData depuis le fichier Redux. Enfin, plusieurs composants de Recharts sont importés afin de construire le graphique de visualisation. 

import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchEtudeData } from "../redux/etudeSlice";

88 Utilisation de useDispatch

Dans le composant EtudeDashboard, le hook useDispatch permet d'obtenir la fonction dispatch. Cette fonction est utilisée pour envoyer une action vers le store Redux. Dans notre cas, elle permet de lancer l'action fetchEtudeData(). React ne réalise donc pas directement la requête Axios. Il demande à Redux de réaliser cette opération. 

const dispatch = useDispatch();

89 Utilisation de useSelector

Le hook useSelector permet au composant React de récupérer les données présentes dans le store Redux. Le code accède à state.etude et extrait directement les propriétés items, loading et error. Ainsi, le composant connaît les données disponibles, sait si une requête est en cours et peut également connaître le message d'erreur éventuel. 

const { items, loading, error } =
    useSelector(state => state.etude);

90 Récupération automatique avec useEffect

Le hook useEffect est utilisé afin de lancer automatiquement la récupération des données lorsque le composant est chargé. À l'intérieur du hook, le code appelle dispatch(fetchEtudeData()). Cela déclenche l'action Redux et donc la requête Axios vers le backend. L'utilisateur n'a pas besoin de cliquer sur un bouton pour récupérer les données. Le chargement est donc automatique lorsque la page du dashboard est ouverte. 

useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

91 Transformation des données avec map()

Après avoir récupéré les données depuis Redux, le composant crée une nouvelle variable appelée chartData. Cette variable est construite grâce à la méthode JavaScript map(). La méthode map permet de parcourir chaque élément du tableau items et de créer un nouvel objet adapté à Recharts. Pour chaque élément, la propriété name reçoit la valeur de item.mode, la propriété Value reçoit la valeur réelle item.value et la propriété Prediction reçoit la prédiction. L'opérateur ?? permet de fournir la valeur 0 lorsque la prédiction est null ou undefined. 

const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

Cette transformation permet d'obtenir exactement la structure de données attendue par le composant BarChart.

92 Intégration du dashboard Power BI

Le composant React intègre également un rapport Power BI grâce à une balise iframe. Cette technique permet d'afficher un contenu externe directement dans la page Web. L'attribut src contient l'adresse du rapport Power BI publié. L'utilisateur peut ainsi consulter le dashboard Power BI directement depuis l'interface React. La propriété allowFullScreen autorise également l'affichage en plein écran lorsque cette fonction est disponible. 

<iframe
    className="etude-iframe"
    title="etude A L'Etranger"
    src="URL_DU_RAPPORT_POWER_BI"
    allowFullScreen
/>

Cette intégration permet de réunir dans une même page les visualisations Power BI et les données dynamiques provenant du backend.

93 Gestion de loading et error

Le composant React utilise les propriétés loading et error récupérées depuis Redux afin d'informer l'utilisateur de l'état de la requête. Lorsque loading est vrai, le composant affiche un message Loading.... Lorsque error contient une valeur, le message d'erreur est affiché. Cette logique rend l'interface plus claire et permet à l'utilisateur de comprendre ce qui se passe pendant la récupération des données. 

{loading && (
    <p className="etude-loading">
        Loading...
    </p>
)}

{error && (
    <p className="etude-error">
        {error}
    </p>
)}

94 Affichage des données sous forme de liste

Le composant affiche ensuite les données récupérées sous forme de liste HTML. La méthode map() est utilisée pour parcourir le tableau items. Pour chaque élément, un élément li est créé. La propriété key permet à React d'identifier chaque élément de manière unique pendant le rendu. Pour chaque ligne, le composant affiche le mode, la valeur réelle et la prédiction. L'opérateur ?? permet d'afficher N/A lorsqu'aucune prédiction n'est disponible. 

<ul className="etude-list">

    {items.map((item, i) => (
        <li key={i}>
            Mode: {item.mode}
            | Value: {item.value}
            | Prediction: {item.prediction ?? "N/A"}
        </li>
    ))}

</ul>

95 Création du graphique avec Recharts

La bibliothèque Recharts est utilisée pour transformer les données en représentation graphique. Le composant ResponsiveContainer permet au graphique de s'adapter automatiquement à la largeur disponible. Le composant BarChart reçoit le tableau chartData. Les composants XAxis et YAxis représentent respectivement les axes horizontal et vertical. CartesianGrid ajoute une grille afin de faciliter la lecture du graphique. Tooltip affiche les informations lorsque l'utilisateur passe la souris sur une barre et Legend permet d'afficher la légende. Enfin, le composant Bar utilise la propriété dataKey="Prediction" afin de représenter graphiquement les prédictions. 

<ResponsiveContainer width="100%" height={350}>

    <BarChart data={chartData}>

        <CartesianGrid strokeDasharray="3 3" />

        <XAxis dataKey="name" />

        <YAxis />

        <Tooltip />

        <Legend />

        <Bar
            dataKey="Prediction"
            fill="#6366f1"
        />

    </BarChart>

</ResponsiveContainer>

96 Fonctionnement global Redux et React

Le fonctionnement commence lorsque l'utilisateur ouvre la page EtudeDashboard. React monte le composant et exécute le hook useEffect. Celui-ci déclenche dispatch(fetchEtudeData()). Redux Toolkit lance alors l'action asynchrone créée avec createAsyncThunk. L'état pending est automatiquement déclenché et la propriété loading devient true. Axios envoie ensuite une requête GET vers le backend. Le backend traite la demande et retourne les données du dashboard. Si la requête réussit, Redux déclenche fulfilled, remet loading à false et place les données dans state.items. Le composant React récupère alors ces données grâce à useSelector. Elles sont utilisées pour construire la liste et le tableau chartData. Ce dernier est transmis à Recharts afin de construire le graphique. Si une erreur survient, l'état rejected est déclenché, l'erreur est enregistrée dans Redux et React peut afficher le message correspondant.

97 Architecture frontend complète

Cette fonctionnalité illustre une architecture frontend organisée dans laquelle chaque technologie possède un rôle précis. React est responsable de l'interface utilisateur et du rendu des composants. Redux Toolkit est utilisé pour centraliser les données de l'étude dans le store global. createAsyncThunk simplifie la gestion de l'opération asynchrone. Axios assure la communication HTTP entre le frontend et le backend. useEffect permet de déclencher automatiquement la récupération des données. useDispatch permet à React d'envoyer l'action Redux et useSelector permet de récupérer les résultats depuis le store. La méthode map() permet de transformer les données reçues pour les adapter au graphique. Enfin, Recharts permet de créer une visualisation graphique interactive et Power BI fournit une visualisation décisionnelle intégrée dans la même page. Cette séparation des responsabilités rend le code plus organisé, plus maintenable et plus facile à faire évoluer.

98 Conclusion

Le dashboard Étude constitue une chaîne complète de récupération, de gestion et de visualisation des données. Le processus commence dans React avec useEffect, qui déclenche l'action Redux fetchEtudeData. Cette action utilise createAsyncThunk et Axios pour communiquer avec le backend. Redux Toolkit gère ensuite automatiquement les trois étapes principales de la requête : pending pendant le chargement, fulfilled lorsque les données sont récupérées avec succès et rejected lorsqu'une erreur se produit. Les données reçues sont stockées dans state.etude.items puis récupérées dans React grâce à useSelector. Le composant transforme ensuite les informations avec map() afin de créer les données nécessaires à Recharts. Les résultats sont affichés sous forme de liste et de graphique, tandis que Power BI est intégré grâce à une iframe. L'ensemble forme donc une architecture frontend complète dans laquelle le backend fournit les données, Redux Toolkit les centralise et React les présente à l'utilisateur. Cette organisation permet de construire un dashboard dynamique capable d'afficher à la fois les données réelles et les résultats de prédiction dans une interface moderne.
