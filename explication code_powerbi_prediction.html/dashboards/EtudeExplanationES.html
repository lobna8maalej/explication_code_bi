🌍 Dashboard de Estudios en el extranjero — Explicación del código

Documentación técnica del funcionamiento de React, Redux Toolkit, Axios, Recharts y Power BI para la recuperación, visualización y representación de datos relacionados con los estudios en el extranjero.

# 109 — Presentación del Dashboard de Estudios

El Dashboard de Estudios en el extranjero constituye una interfaz frontend desarrollada con React que permite mostrar y analizar datos relacionados con los estudios en el extranjero. Esta funcionalidad utiliza varias tecnologías complementarias: React para construir la interfaz de usuario, Redux Toolkit para centralizar y gestionar el estado de los datos, Axios para comunicarse con el backend, Recharts para representar gráficamente los datos, y Power BI para integrar un informe de Business Intelligence directamente en la página. A diferencia de un formulario de entrada clásico, el Dashboard de Estudios recupera automáticamente los datos desde el backend cuando se carga el componente. Por lo tanto, el usuario puede consultar directamente la información disponible, los valores asociados a los diferentes modos de estudio y los valores de predicción. El dashboard combina así varios niveles de visualización: el informe de Power BI, la lista de datos recuperados, y el gráfico comparativo generado con Recharts.

# 110 — Importación de React y useEffect

El archivo EtudeDashboard.jsx comienza importando React y el hook useEffect: 


import React, { useEffect } from "react";

React se utiliza para crear el componente de interfaz de usuario. El hook useEffect permite ejecutar una operación después de la renderización del componente. En este dashboard, useEffect desempeña un papel importante, ya que permite iniciar automáticamente la recuperación de los datos cuando se carga la página. Por lo tanto, el usuario no necesita hacer clic en un botón para activar la recuperación de los datos.

# 111 — Importación de useDispatch y useSelector

El componente importa posteriormente dos hooks desde react-redux: 


import { useDispatch, useSelector } from "react-redux";

useDispatch() permite al componente React enviar una acción a Redux. En nuestra aplicación, se utilizará para activar la acción asíncrona fetchEtudeData(). useSelector(), por el contrario, permite leer la información presente en el store de Redux. El componente podrá así recuperar: items para los datos, loading para conocer el estado de carga, y error para recuperar un posible error. Estos dos hooks permiten establecer la comunicación entre el componente React y el store de Redux.

# 112 — Importación de fetchEtudeData

El componente importa posteriormente la acción asíncrona fetchEtudeData desde el archivo Redux: 


import { fetchEtudeData } from "../redux/etudeSlice";

Esta función está definida en el archivo etudeSlice.js. Se crea mediante createAsyncThunk() y tiene como objetivo comunicarse con el backend para recuperar los datos del Dashboard de Estudios. Por lo tanto, el componente React no realiza directamente la solicitud Axios. La lógica de comunicación con el servidor está centralizada en el slice de Redux. Esta separación permite hacer que la arquitectura sea más clara y fácil de mantener.

CartesianGrid añade una cuadrícula para mejorar la lectura del gráfico. Legend muestra la leyenda de las series. Finalmente, ResponsiveContainer permite que el gráfico se adapte automáticamente al ancho disponible.

El archivo JSX contiene la estructura y el comportamiento del dashboard, mientras que EtudeDashboard.css contiene las reglas que permiten controlar los colores, las dimensiones, los espacios, los bordes, las tarjetas y la capacidad de respuesta. Esta separación mejora la legibilidad y facilita las futuras modificaciones de la interfaz.

# 116 — Inicialización de useDispatch

El código utiliza: 


const dispatch = useDispatch();

Esta instrucción obtiene la función dispatch proporcionada por Redux. Permite al componente enviar una acción al store. En nuestro caso, esta función se utilizará para activar:

Esta instrucción solicita a Redux ejecutar la acción asíncrona responsable de recuperar los datos de Estudios.

# 117 — Recuperación del estado Etude con useSelector

El componente recupera posteriormente los datos del store de Redux: 


const { items, loading, error } =
    useSelector(state => state.etude);

useSelector() permite acceder a la parte etude del store de Redux. Se extraen tres propiedades. items contiene los datos recuperados desde el backend. loading indica si la solicitud está actualmente en curso. error contiene un posible error. Cuando Redux modifica uno de estos valores, React recibe automáticamente la información del cambio y el componente vuelve a ejecutarse para actualizar la interfaz.

# 118 — Recuperación automática con useEffect

El dashboard utiliza el hook useEffect: 


useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

Esta lógica permite activar automáticamente la recuperación de los datos después de cargar el componente. Cuando el usuario abre el Dashboard de Estudios, React ejecuta el useEffect. Este llama a: dispatch(fetchEtudeData()). Redux Toolkit inicia entonces el ciclo asíncrono de la acción. Posteriormente, el backend es contactado mediante Axios. El array de dependencias contiene dispatch para respetar las reglas de gestión de dependencias del hook.

# 119 — Transformación de los datos para Recharts

Los datos recibidos desde Redux se transforman para que sean compatibles con Recharts: 


const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

El método map() recorre cada elemento del array items. Para cada elemento se crea un nuevo objeto. La propiedad name recibe item.mode. Representa el modo de estudio y se utilizará como categoría en el eje horizontal. La propiedad Value recibe item.value. Representa el valor real asociado al modo de estudio. Finalmente, la propiedad Prediction recibe item.prediction. El operador ?? permite utilizar 0 cuando el valor de predicción está ausente o es null.

# 123 — Gestión del estado Loading

El componente comprueba la propiedad loading: 


{loading && (

Si loading es true, se muestra el mensaje Loading.... Esta información permite al usuario comprender que los datos se están recuperando actualmente. Cuando Redux recibe la respuesta del backend, loading pasa a ser false y el mensaje desaparece automáticamente. Esta lógica mejora la experiencia del usuario durante el tiempo de carga.

# 124 — Gestión de errores

El componente también prevé la visualización de los errores: 


{error && (

Si la propiedad error contiene un valor, este se muestra en la interfaz. Este valor procede del slice de Redux. Puede corresponder, por ejemplo, a un error de red, un error del backend o un error producido por Axios. De esta manera, el usuario recibe directamente una indicación cuando un problema impide recuperar los datos.

# 132 — Creación del archivo etudeSlice.js

La gestión de los datos está centralizada en el archivo etudeSlice.js. Este archivo utiliza Redux Toolkit y Axios: 


import { createSlice, createAsyncThunk }
from "@reduxjs/toolkit";

import axios from "axios";

createAsyncThunk permite crear una acción asíncrona. createSlice permite crear la parte del store dedicada a los datos de Estudios. Axios, por su parte, permite comunicarse con el backend.

# 133 — Creación de fetchEtudeData

La acción asíncrona principal es: 


export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        ...
    }
);

fetchEtudeData es responsable de recuperar los datos de Estudios. El primer parámetro: "etude/fetchEtudeData" representa el tipo Redux de la acción. El símbolo _ indica que no se necesita ningún argumento específico para ejecutar esta acción. El parámetro thunkAPI proporciona herramientas de Redux Toolkit que permiten, entre otras cosas, gestionar los errores.

# 134 — Solicitud Axios al backend

Dentro del thunk, Axios envía una solicitud GET: 


const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

El método GET permite al frontend solicitar los datos al servidor. El endpoint utilizado es: /etude/dashboard. El backend recibe la solicitud y devuelve los datos necesarios para el dashboard. La palabra clave await permite esperar la respuesta del servidor antes de continuar con la ejecución.

# 135 — Retorno de los datos del backend

Después de la respuesta de Axios, el código utiliza: 


return response.data.data;

response contiene la respuesta completa proporcionada por Axios. response.data corresponde al cuerpo de la respuesta HTTP. Finalmente, response.data.data recupera el array de datos contenido en la propiedad data de la respuesta del backend. Este valor se convierte posteriormente en el payload de la acción Redux cuando esta se ejecuta correctamente.

# 136 — Gestión de errores de Axios

El thunk también contiene un bloque try/catch: 


try {

    const response = await axios.get(
        "http://localhost:3000/etude/dashboard"
    );

    return response.data.data;

} catch (error) {

    return thunkAPI.rejectWithValue(
        error.message
    );

}

Si la solicitud tiene éxito, los datos son devueltos. Si se produce un error, el programa pasa al bloque catch. La instrucción: rejectWithValue(error.message) transmite el mensaje de error al reducer rejected. Este enfoque permite posteriormente al componente React mostrar el problema al usuario.

# 137 — Creación del slice Etude

El slice de Redux se crea mediante: 


const etudeSlice = createSlice({

    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    ...
});

La propiedad name identifica el slice con el nombre etude. El initialState define los valores iniciales del estado. items comienza con un array vacío porque todavía no se han recuperado datos. loading comienza en false porque no hay ninguna solicitud en curso al inicio. error comienza en null porque inicialmente no existe ningún error.

# 138 — Estado pending

Cuando comienza fetchEtudeData(), Redux Toolkit activa automáticamente el estado pending: 


.addCase(
    fetchEtudeData.pending,
    (state) => {

        state.loading = true;
        state.error = null;

    }
)

loading pasa a ser true. El componente React puede entonces mostrar el mensaje Loading.... El error anterior también se elimina mediante state.error = null. El sistema está así preparado para recibir una nueva respuesta del backend.

# 139 — Estado fulfilled

Cuando la solicitud tiene éxito, Redux Toolkit activa el estado fulfilled: 


.addCase(
    fetchEtudeData.fulfilled,
    (state, action) => {

        state.loading = false;

        state.items = action.payload;

    }
)

loading vuelve a ser false porque la solicitud ha terminado. Los datos devueltos por el thunk están disponibles en action.payload. Posteriormente se almacenan en: state.items. El componente React recibe automáticamente los nuevos datos mediante useSelector().

# 140 — Estado rejected

Cuando la solicitud falla, Redux Toolkit activa el estado rejected: 


.addCase(
    fetchEtudeData.rejected,
    (state, action) => {

        state.loading = false;

        state.error = action.payload;

    }
)

loading vuelve a ser false porque la solicitud ha terminado. El mensaje de error transmitido por rejectWithValue() se recupera mediante action.payload. Posteriormente se almacena en: state.error. React puede entonces mostrar este error en la interfaz.

# 141 — Exportación del reducer

Al final del archivo Redux, el reducer se exporta: 


export default etudeSlice.reducer;

Este reducer debe registrarse posteriormente en el store principal de Redux. Una vez registrado, el componente React puede acceder al estado mediante: 


useSelector(state => state.etude);

De esta manera se establece el vínculo entre el store de Redux y el componente EtudeDashboard.

# 142 — Ciclo completo de Redux

El funcionamiento de Redux Toolkit se basa en tres estados principales:

⏳ Pending

La solicitud comienza. loading = true.

✅ Fulfilled

La solicitud tiene éxito. Los datos se almacenan en items.

❌ Rejected

La solicitud falla. El error se almacena en error.

# 143 — Recorrido completo de los datos

El recorrido completo comienza cuando el usuario abre la página Etude Dashboard. React carga el componente EtudeDashboard. A continuación se ejecuta el hook useEffect(). Este activa: dispatch(fetchEtudeData()). Redux Toolkit pasa entonces al estado pending. El thunk utiliza Axios para enviar una solicitud GET a: http://localhost:3000/etude/dashboard. El backend procesa la solicitud y devuelve una respuesta JSON. Si la respuesta tiene éxito, el thunk devuelve response.data.data. Redux activa posteriormente fulfilled y almacena los datos en state.items. React recupera estos datos mediante useSelector(). Los datos se transforman posteriormente en chartData. Finalmente, Recharts utiliza este array para construir el gráfico.

# 145 — Papel de React

React constituye la capa de interfaz de usuario. Es responsable de mostrar el Dashboard, el título, la lista de datos, los mensajes de carga y error, así como el gráfico. React también permite reaccionar automáticamente a las modificaciones del estado de Redux. Cuando items se actualiza, el componente vuelve a ejecutarse y los nuevos datos aparecen automáticamente en la interfaz.

# 146 — Papel de Redux Toolkit

Redux Toolkit centraliza la gestión de los datos de Estudios. El slice etude contiene: items, loading, y error. También gestiona los diferentes estados de la acción asíncrona: pending, fulfilled, y rejected. Esta organización evita colocar toda la lógica de comunicación con el backend directamente dentro del componente React.

# 147 — Papel de Axios

Axios es responsable de la comunicación HTTP entre el frontend y el backend. En esta funcionalidad, Axios utiliza una solicitud GET: http://localhost:3000/etude/dashboard. A continuación, recibe la respuesta del servidor. El thunk de Redux recupera los datos mediante: response.data.data. Axios constituye, por lo tanto, el puente de comunicación entre la aplicación React/Redux y la API del backend.

# 148 — Papel de Recharts

Recharts se utiliza para transformar los datos recuperados en una representación gráfica. Los datos se preparan en chartData. Posteriormente, Recharts utiliza: BarChart, Bar, XAxis, YAxis, Tooltip, Legend, y ResponsiveContainer. Esta biblioteca permite transformar los datos numéricos en una visualización fácil de comprender.

# 149 — Papel de Power BI

Power BI aporta la dimensión de Business Intelligence al Dashboard de Estudios. El informe se integra directamente en React mediante un iframe. Esta integración permite combinar dos enfoques complementarios. Power BI proporciona visualizaciones y análisis avanzados para la toma de decisiones. React proporciona una interfaz personalizada capaz de recuperar los datos del backend, mostrar las predicciones y generar gráficos adicionales con Recharts. El dashboard se convierte así en una interfaz híbrida que combina desarrollo web, análisis de datos y Business Intelligence.

# 150 — Arquitectura completa

La arquitectura de esta funcionalidad puede resumirse en varias capas. El frontend React contiene el componente EtudeDashboard. El slice de Redux contiene la lógica de recuperación de los datos. createAsyncThunk coordina la operación asíncrona. Axios se comunica con la API. El backend Node.js / Express procesa la solicitud y devuelve los datos. Redux almacena posteriormente los resultados. React recupera los datos mediante useSelector(). Los datos se transforman en chartData. Recharts genera la visualización gráfica. Paralelamente, Power BI proporciona el informe de análisis integrado. Esta separación de responsabilidades hace que la aplicación sea más organizada, escalable y fácil de mantener.

# 151 — Conclusión

El Dashboard de Estudios en el extranjero representa una funcionalidad completa que combina desarrollo frontend, gestión del estado, comunicación con el backend, visualización de datos, predicción y Business Intelligence. React construye la interfaz de usuario. useEffect activa automáticamente la recuperación de los datos. Redux Toolkit centraliza el estado y gestiona el ciclo asíncrono. createAsyncThunk facilita la creación de la acción de recuperación. Axios se comunica con el backend mediante una solicitud HTTP GET. Node.js / Express proporciona los datos solicitados por el frontend. Recharts transforma los datos en una visualización gráfica. Finalmente, Power BI aporta una capa de Business Intelligence directamente integrada en la aplicación. En conjunto, todo esto forma una arquitectura moderna que permite conectar los datos del backend, la gestión del estado con Redux, la interfaz React, la predicción, la visualización gráfica y el análisis de decisiones mediante Power BI.
