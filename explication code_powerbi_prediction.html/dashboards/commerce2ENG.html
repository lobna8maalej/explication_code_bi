01

General Overview

This module implements a prediction architecture designed for the commerce domain and allows results to be compared or estimated for two brands: Carrefour and Aziza. The architecture relies on several technologies that communicate with each other. The first part is developed in Python and uses the Scikit-learn library together with the SVR algorithm, or Support Vector Regression. Two independent Machine Learning models are trained using the same input variables X, but with two different sets of target values: one set for Carrefour and another for Aziza. Once trained, the models are serialized using the pickle library and saved as carrefour.pkl and aziza.pkl files. The second part of the system concerns the Python script responsible for receiving data from Node.js. This script reads a JSON object sent through standard input, identifies the requested model, loads the corresponding PKL file, retrieves the x1 and x2 variables, and then uses the SVR model's predict() method to produce a prediction. The third part is developed in Node.js. The backend uses the native child_process module to launch Python from Node.js. The runCommerce() function prepares the path to the Python interpreter, locates the prediction script, starts the Python process, and sends the data to it in JSON format. The result produced by Python is retrieved from stdout, converted from JSON into a JavaScript object, and then returned to the backend. Finally, Express exposes a REST API with a test route /train and a POST route /predict. The frontend or dashboard can therefore send the model name together with the input variables and automatically receive the prediction calculated by the actual Machine Learning model.

02

SVR Model Training

The first step of the system consists of creating the Machine Learning models. The Python code imports SVR from sklearn.svm. SVR stands for Support Vector Regression and is a version of the Support Vector Machines method adapted to regression problems. Unlike a simple mathematical formula manually coded, the SVR model is trained using input data and target values. In this project, the X array contains four observations and two variables for each observation. The first observation contains the values 10 and 1, the second 20 and 2, the third 30 and 3, and the fourth 40 and 4. These two variables represent the features used by the model to learn the relationship with the target variable. For Carrefour, the y_carrefour array contains the values 120, 240, 360, and 480. A first SVR() object is created and the fit() method is called with X and y_carrefour. The model therefore learns a relationship between the two input variables and Carrefour's target values. The model is then saved in the carrefour.pkl file. The same principle is applied to Aziza. The y_aziza array contains the values 100, 200, 300, and 400. A second SVR model is created, trained using the same X variables but with Aziza's target values, and then saved as aziza.pkl. We therefore obtain two independent models capable of producing different predictions from the same input variables.

Importing SVR 

from sklearn.svm import SVR

This instruction imports the SVR class from the sklearn.svm module. It allows a regression model based on Support Vector Machines to be created. The model can then be trained using the fit() method and used to produce predictions with predict().

Importing Pickle 

import pickle

The pickle library is used to serialize the trained model. After training, the SVR model exists as a Python object in memory. Pickle allows this object to be transformed into a file so that it can be saved and reloaded later without having to train the model for every prediction.

This method is particularly useful for building reliable paths to PKL files.

03

Python Prediction Script

After training and saving the models, a second Python script is used to perform predictions. Its role is particularly important because it acts as the bridge between Node.js and the Python Machine Learning models. The script imports sys, json, pickle, and os. It begins by reading the data sent by Node.js using sys.stdin.read(). This data is sent in JSON format and converted into a Python object using json.loads(). The script then retrieves the model name using data.get("model", "carrefour"). If no model is provided, Carrefour becomes the default model. A file_map dictionary is then used to associate the logical model name with the corresponding PKL file. If the received name does not exist in this dictionary, the program raises an error. When the model is valid, the PKL file path is built automatically and the file is opened in binary mode. pickle.load() then reloads the trained SVR model. A security check uses hasattr(model, "predict") to verify that the loaded object actually has a prediction method. The x1 and x2 variables are then retrieved from the received data and converted into decimal numbers using float(). The model is finally called with model.predict([[x1, x2]]). The double list is necessary because Scikit-learn generally expects a structure representing one or more observations with their features. The result is retrieved and converted to a float. Finally, the script produces a JSON object containing success, the model name, and the prediction. If an error occurs at any stage, the except block also returns JSON, but with success: false and the error message.

Reading Node.js Data 

data = json.loads( 
    sys.stdin.read() 
)

sys.stdin.read() allows the Python script to read the data sent by the Node.js process. Since Node.js sends the information in JSON format, json.loads() transforms this JSON string into a Python dictionary that can be used by the program.

Model Selection 

model_name = data.get( 
    "model", 
    "carrefour" 
).lower()

This instruction retrieves the requested model name. The get() method uses Carrefour as the default value if the model property is not provided. The lower() method converts the text to lowercase in order to avoid certain issues related to uppercase letters.

Model / PKL File Mapping 

file_map = { 
    "carrefour": "carrefour.pkl", 
    "aziza": "aziza.pkl" 
}

The file_map dictionary maps the name sent by the frontend to the physical file containing the model. If model = carrefour, the program loads carrefour.pkl. If model = aziza, it loads aziza.pkl. This organization avoids directly constructing a file name from uncontrolled user input.

Loading the Model 

with open( 
    model_path, 
    "rb" 
) as f: 
 
    model = pickle.load(f)

The PKL file is opened using the rb mode, which means binary reading. pickle.load() reconstructs the Python object previously saved. The trained SVR model is therefore restored in memory and can immediately be used to perform a prediction.

Model Validation 

if not hasattr( 
    model, 
    "predict" 
): 
 
    raise Exception( 
        "Invalid ML model loaded" 
    )

This validation ensures that the loaded object actually has a predict() method. Since the system expects a Machine Learning model capable of producing a prediction, this verification prevents the process from continuing with an incompatible object.

Retrieving the Variables 

x1 = float( 
    data["x1"] 
) 
 
x2 = float( 
    data["x2"] 
)

The two variables sent by Node.js are retrieved from the JSON object. The float() function converts the values into decimal numbers so that they can be properly used by the SVR model.

Producing the Prediction 

prediction = model.predict( 
    [[x1, x2]] 
)[0]

This instruction represents the main Machine Learning step. The SVR model receives the two input variables and uses the parameters learned during training to calculate a prediction. The predict() method returns an array containing the result. The [0] index retrieves the first prediction.

JSON Response 

print(json.dumps({ 
    "success": True, 
    "model": model_name, 
    "prediction": float(prediction) 
}))

The result is converted into JSON using json.dumps(). This format is essential because Node.js can easily retrieve the response from the standard output of the Python process and then convert it into a JavaScript object. In case of success, the response contains the status, model name, and predicted value.

04

Node.js Service and Communication with Python

The server.js service-side file acts as the gateway between the Node.js backend and the Python program. The child_process module provided by Node.js allows an external process to be launched. Here, the spawn() function is used to start the Python interpreter. The runCommerce() function returns a Promise, allowing the Express route to use await and wait for the Python processing to finish. The service first builds the path to the Python interpreter located in the .venv virtual environment. It then builds the path to the commerce2.py script. Before launching Python, the code uses fs.existsSync() to verify that the interpreter and the script actually exist. This step is particularly useful for diagnosing path errors. When both files are available, spawn() launches Python with the prediction script. Node.js then sends the data to the Python process using python.stdin.write(). The data is converted into JSON using JSON.stringify(). Python reads this data using sys.stdin.read(). During execution, Node.js listens to stdout to retrieve the result produced by Python and also listens to stderr to retrieve possible error messages. When Python finishes, the close event is triggered. The code then checks the process exit code. If the code is different from zero, it means that the Python process terminated with an error. If the result is empty, another error is returned. Finally, if Python produced a response, JSON.parse() transforms the JSON text into a JavaScript object. This object is then returned using resolve(). The service therefore provides real communication between the JavaScript environment and the Python Machine Learning model.

Express Prediction Route

The serverRoutes.js file defines the endpoints accessible by the frontend. It creates an Express router using express.Router(), and then imports the runCommerce() service. A first GET route called /train serves as a test route. It does not actually train the models; it simply returns a message indicating that Carrefour and Aziza are ready. The actual training is performed by the Python model creation script. The second route, POST /predict, is the main prediction route. It retrieves the information sent in req.body, including the model name, x1, and x2. A validation checks that x1 and x2 are present. If a value is missing, the API returns an HTTP 400 response. When the data is valid, the route calls runCommerce() with the received information. The Node.js service then launches the Python script, loads the corresponding PKL model, and calculates the prediction. Once the response is received, Express returns it directly to the client using res.status(200).json(result). The frontend can therefore call this API and directly receive the result from the Machine Learning model.

Main Node.js / Express Server

The main backend file initializes the Express application and connects the prediction routes. Express is imported and an application instance is created using express(). The express.json() middleware is enabled so that the server can receive and parse JSON data sent by the frontend. The serverRoutes file is then imported and mounted using the /server prefix. This means that all routes defined in serverRoutes are accessible from this base path. Therefore, the route router.post("/predict") becomes the complete endpoint POST /server/predict. The server also contains a root route GET / that returns { status: "OK" }. This route can be used as a Health Check to verify that the backend has started correctly. Finally, app.listen(3000) starts the server on port 3000. The backend can then receive requests from the frontend and trigger Python predictions.

Complete System Architecture

The complete architecture is based on communication through several stages. Everything starts with the frontend or dashboard, which contains the data required for the prediction. It sends an HTTP POST request to the /server/predict endpoint. Express receives the request and retrieves the model, x1, and x2 properties. After validation, the route calls the runCommerce() service. This service uses the Node.js child_process module to launch the Python program. Node.js sends the data to the Python program in JSON format through stdin. The Python script reads the data, identifies the requested model, and selects the corresponding PKL file using the file_map dictionary. The SVR model is then reloaded using pickle.load(). The x1 and x2 variables are retrieved and passed to the model using predict(). The model produces a predicted value. Python then converts this value into JSON and writes it to stdout. Node.js retrieves the stdout content, parses the JSON using JSON.parse(), and returns the result to the Express route. Express finally sends the JSON response to the frontend. This architecture therefore makes it possible to use a real Machine Learning model developed in Python while maintaining a modern Web backend based on Node.js and Express.

Example of Operation

To understand how the system works in practice, imagine that a user selects the Carrefour model and provides the values x1 = 30 and x2 = 3. The frontend then sends a POST request to /server/predict with a JSON object containing the model and the two variables. Express receives the request and verifies that x1 and x2 are present. The route then calls runCommerce(). Node.js launches the Python script commerce2.py using spawn() and sends the JSON data to it. Python reads the JSON, identifies carrefour as the requested model, selects carrefour.pkl, and then reloads the SVR model using pickle.load(). The values 30 and 3 are then passed to model.predict([[30, 3]]). The model uses the parameters learned during training to produce an estimate. Python then converts the result into JSON and writes it to stdout. Node.js retrieves this result, uses JSON.parse() to convert it into a JavaScript object, and then passes it to Express. Express finally returns this result to the frontend. The dashboard can then display the predicted value to the user. If the requested model were aziza, the same flow would be used, but the script would load aziza.pkl and use the SVR model trained on Aziza data.

    "x1": 30,

}

The response produced by Python and then returned by Express has a structure similar to: 

{ 
    "success": true,

    "prediction": 360 
}

The exact prediction value depends on the trained SVR model and its parameters. The example above is only intended to illustrate the response structure.

Explanation to Give During a Sales Presentation

During a sales presentation, it is preferable not to explain every line of code to the client, but rather clearly present the value of the system and its architecture. You can explain that the project implements a prediction solution designed for the commerce domain. Two independent Machine Learning models have been developed to represent two different brands: Carrefour and Aziza. The models are trained in Python using the SVR algorithm, which is designed for regression problems. Once training is completed, each model is saved in a PKL file so that it can be quickly reused without having to retrain it for every request. The application's backend is developed with Node.js and Express. The frontend can send the model name together with the variables required for the prediction through a REST API. Node.js then communicates directly with Python using the child_process module. The Python script reloads the corresponding model, performs the prediction using the predict() method, and returns the result in JSON format. Node.js receives this response and passes it to the frontend. This architecture therefore makes it possible to combine the power of Python Machine Learning libraries with a modern Web architecture based on Node.js and Express. The system is also scalable: new models can be added, new variables can be integrated, and the dashboard can use the predictions to build indicators, charts, and decision-support tools.

Conclusion

This system represents a complete Machine Learning architecture integrated into a Web application. The data is used to train two independent SVR models, and the trained models are then saved in PKL files. A specialized Python script subsequently reloads the requested model and produces a prediction based on the received variables. Node.js acts as the gateway between the Web application and Python through the child_process module and the spawn() function. Express provides the HTTP endpoints that allow the frontend to communicate with the system. JSON format ensures communication between the different components. The overall chain can therefore be represented as: Data → SVR Training → PKL File → Python → Node.js → Express → Prediction → Dashboard. This organization makes it possible to use real Python Machine Learning models in a modern Web application while maintaining a modular and scalable architecture.
