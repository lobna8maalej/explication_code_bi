📊 Kantra ML Dashboard — Technical Documentation

This documentation explains in detail how the kantraSlice.js file, the PredictionForm.jsx component, and their connection with the kantra.css file work.

The architecture uses React, Redux Toolkit, Axios, Recharts, Power BI, and a backend responsible for performing Machine Learning predictions.

1. General Overview of the Project

The PredictionForm.jsx component is the user interface of the Machine Learning Dashboard dedicated to Kantra.

It allows the user to enter two values, A and B, and then start a prediction.

The prediction is sent to the backend through Redux Toolkit and Axios. Once the result is received, it is added to a history.

The component then displays the latest entered values, the obtained prediction, and a chart representing the prediction history.

The Dashboard also contains an integrated Power BI report using an iframe element.

PredictionForm.jsx ↓ User enters A and B ↓ handlePredict() ↓ dispatch(fetchPrediction({ a, b })) ↓ kantraSlice.js ↓ Axios POST /kantra ↓ Backend ↓ Machine Learning ↓ Result ↓ Redux history ↓ PredictionForm.jsx ↓ KPI + chart ↓ kantra.css ↓ Final interface

3. Imports in kantraSlice.js

The kantraSlice.js file starts by importing two important functions from Redux Toolkit: createSlice and createAsyncThunk. 

import {
createSlice,
createAsyncThunk
} from "@reduxjs/toolkit";

createSlice is used to create a section of the Redux store with its initial state and reducers.

createAsyncThunk is used to manage an asynchronous operation, here the prediction request to the backend.

The file also imports Axios: 

import axios from "axios";

Axios is used to perform the HTTP POST request to the backend.

4. Creating fetchPrediction

The fetchPrediction function is created using createAsyncThunk. 

export const fetchPrediction = createAsyncThunk(
"kantra/fetchPrediction",
async ({ a, b }, { rejectWithValue }) => {
    ...
}
);

The first argument: 

"kantra/fetchPrediction"

corresponds to the Redux action identifier.

The asynchronous function receives an object containing two parameters: a and b.

These two values correspond to the inputs provided by the user.

5. Axios Request to the Backend

Inside fetchPrediction, Axios sends a POST request: 

const res = await axios.post(
"http://localhost:3000/kantra",
{ a, b }
);

The URL used is: 

http://localhost:3000/kantra

The backend therefore receives an object containing: 

{
a,
b
}

The server can then use these two values to perform the prediction with the Machine Learning model.

6. Preserving the Input Values

After the backend response, the code returns: 

return {
...res.data,
a,
b
};

The ... operator retrieves the properties contained in res.data.

The code also adds the original values a and b.

This makes it possible to preserve both the input values and the obtained prediction in Redux.

Example: 
{
a: 100,
b: 200,
prediction: 350.25
}

The history can therefore identify which values produced which prediction.

7. Error Handling in fetchPrediction

The Axios request is placed inside a try/catch block. 

try {
...
} catch (err) {
return rejectWithValue(
err.response?.data || "Server error"
);
}

If the backend returns an error, the code retrieves err.response.data when available.

If no response is available, the message "Server error" is used.

rejectWithValue then allows this error to be passed to the rejected reducer.

8. Creating the kantraSlice

The code then creates the Redux slice: 

const kantraSlice = createSlice({
name: "kantra",
...
});

The property: 

name: "kantra"

identifies this section of the Redux store.

The React component can therefore access this state with: 

s.kantra

9. initialState

The initial state of the slice is: 

initialState: {
history: [],
loading: false,
error: null,
}

It contains three properties.

  • history: contains the prediction history.
  • loading: indicates whether a prediction is currently being processed.
  • error: contains a possible error.

10. The resetKantra Reducer

The slice contains a reducer called resetKantra. 

reducers: {
resetKantra: (state) => {
    state.history = [];
},
},

Its role is to completely clear the prediction history.

When this action is called, the history array becomes empty again.

11. fetchPrediction.pending

When the user starts a prediction, createAsyncThunk first triggers the pending state. 

.addCase(fetchPrediction.pending, (state) => {
state.loading = true;
state.error = null;
})

loading becomes true.

The previous error is also cleared using: 

state.error = null;

12. fetchPrediction.fulfilled

When the backend successfully returns a prediction, Redux moves to the fulfilled state. 

.addCase(fetchPrediction.fulfilled, (state, action) => {
state.loading = false;

state.history.unshift({
    a: action.payload.a,
    b: action.payload.b,
    prediction: action.payload.prediction,
    time: new Date().toLocaleTimeString(),
});
})

Loading is stopped: 

state.loading = false;

Then, a new object is added to the beginning of history using: 

state.history.unshift(...)

Using unshift() therefore places the new prediction in the first position.

13. History Contents

Each history item contains four pieces of information: 

{
a: action.payload.a,
b: action.payload.b,
prediction: action.payload.prediction,
time: new Date().toLocaleTimeString()
}
Property Meaning
a First input value.
b Second input value.
prediction Result produced by the model.
time Time when the prediction was performed.

14. fetchPrediction.rejected

If the request fails, Redux moves to the rejected state. 

.addCase(fetchPrediction.rejected, (state, action) => {
state.loading = false;
state.error = action.payload;
})

Loading is stopped and the error is stored in: 

state.error

The React component can then retrieve this error using useSelector.

15. Exporting the Reducer

At the end of the file, the reducer is exported: 

export default kantraSlice.reducer;

It can then be integrated into the Redux store of the application.

The resetKantra action is also exported: 

export {
resetKantra
};

24. handlePredict Function

The handlePredict function is executed when the user clicks the Predict button. 

const handlePredict = () => {
if (!a || !b) return;

dispatch(
    fetchPrediction({
        a: Number(a),
        b: Number(b)
    })
);
};

The first condition: 

if (!a || !b) return;

prevents the request from being sent if one of the two values is missing.

Then, Number(a) and Number(b) convert the entered values into numbers.

The Redux action is then dispatched with: 

dispatch(fetchPrediction({
a: Number(a),
b: Number(b)
}));

const last = history[0];

50. Final Summary to Remember

React builds the interface → Redux Toolkit manages the state → Axios communicates with the backend → Machine Learning produces the prediction → Redux stores the history → Recharts visualizes the results → Power BI displays the report → CSS controls the presentation.

The kantraSlice.js file is responsible for Redux logic. It defines the asynchronous action fetchPrediction, communicates with the backend using Axios, and manages the pending, fulfilled, and rejected states.

The PredictionForm.jsx component is the user interface. It allows the user to enter A and B, send a prediction request, display the latest result, keep the history in Redux, and represent predictions in a chart.

The kantra.css file is responsible for the visual appearance. The connection with React is made through: 

import "./kantra.css";

and then through the different className attributes used in the JSX.

Therefore, business logic, data management, display, and visual presentation are separated into specialized files and technologies.
