🌍 Dashboard Estudos no Exterior — Explicação do código

Documentação técnica do funcionamento de React, Redux Toolkit, Axios, Recharts e Power BI para a recuperação, exibição e visualização de dados relacionados aos estudos no exterior.

# 109 — Apresentação do Dashboard Estudos no Exterior

O Dashboard Estudos no Exterior constitui uma interface frontend desenvolvida com React, permitindo exibir e analisar dados relacionados aos estudos no exterior. Essa funcionalidade utiliza várias tecnologias complementares: React para construir a interface do usuário, Redux Toolkit para centralizar e gerenciar o estado dos dados, Axios para se comunicar com o backend, Recharts para representar graficamente os dados, e Power BI para integrar um relatório de Business Intelligence diretamente na página. Diferentemente de um formulário de entrada de dados tradicional, o Dashboard Estudos recupera automaticamente os dados do backend quando o componente é carregado. Dessa forma, o usuário pode consultar diretamente as informações disponíveis, os valores associados aos diferentes modos de estudo e os valores de previsão. O dashboard combina, assim, vários níveis de visualização: o relatório do Power BI, a lista de dados recuperados, e o gráfico comparativo gerado com Recharts.

# 110 — Importação do React e useEffect

O arquivo EtudeDashboard.jsx começa importando o React e o hook useEffect: 


import React, { useEffect } from "react";

React é utilizado para criar o componente da interface do usuário. O hook useEffect, por sua vez, permite executar uma operação após a renderização do componente. Neste dashboard, useEffect desempenha um papel importante, pois permite iniciar automaticamente a recuperação dos dados quando a página é carregada. Dessa forma, o usuário não precisa clicar em um botão para iniciar a recuperação dos dados.

# 111 — Importação de useDispatch e useSelector

O componente importa em seguida dois hooks de react-redux: 


import { useDispatch, useSelector } from "react-redux";

useDispatch() permite que o componente React envie uma ação para o Redux. Em nossa aplicação, ele será utilizado para executar a ação assíncrona fetchEtudeData(). useSelector(), por outro lado, permite ler as informações presentes no store Redux. O componente poderá, assim, recuperar: items para os dados, loading para conhecer o estado do carregamento, e error para recuperar um possível erro. Esses dois hooks permitem estabelecer a comunicação entre o componente React e o store Redux.

# 112 — Importação de fetchEtudeData

O componente importa em seguida a ação assíncrona fetchEtudeData do arquivo Redux: 


import { fetchEtudeData } from "../redux/etudeSlice";

Essa função é definida no arquivo etudeSlice.js. Ela é criada com createAsyncThunk() e tem como objetivo se comunicar com o backend para recuperar os dados do Dashboard Estudos. O componente React não executa diretamente a requisição Axios. A lógica de comunicação com o servidor é centralizada no slice Redux. Essa separação torna a arquitetura mais clara e mais fácil de manter.

# 116 — Inicialização do useDispatch

O código utiliza: 


const dispatch = useDispatch();

Essa instrução recupera a função dispatch fornecida pelo Redux. Ela permite que o componente envie uma ação para o store. Neste caso, essa função será utilizada para executar:

Essa instrução solicita ao Redux que execute a ação assíncrona responsável pela recuperação dos dados Estudos.

# 117 — Recuperação do state Etude com useSelector

O componente recupera em seguida os dados do store Redux: 


const { items, loading, error } =
    useSelector(state => state.etude);

useSelector() permite acessar a parte etude do store Redux. Três propriedades são extraídas. items contém os dados recuperados do backend. loading indica se a requisição está atualmente em andamento. error contém um possível erro. Quando o Redux modifica uma dessas informações, o React é automaticamente informado sobre a mudança e o componente é executado novamente para atualizar a interface.

# 118 — Recuperação automática com useEffect

O dashboard utiliza o hook useEffect: 


useEffect(() => {
    dispatch(fetchEtudeData());
}, [dispatch]);

Essa lógica permite iniciar automaticamente a recuperação dos dados após o carregamento do componente. Quando o usuário abre o Dashboard Estudos, o React executa o useEffect. Ele chama: dispatch(fetchEtudeData()). O Redux Toolkit inicia então o ciclo assíncrono da ação. O backend é posteriormente contatado através do Axios. O array de dependências contém dispatch para respeitar as regras de gerenciamento das dependências do hook.

# 119 — Transformação dos dados para o Recharts

Os dados recebidos do Redux são transformados para serem compatíveis com o Recharts: 


const chartData = items.map(item => ({
    name: item.mode,
    Value: item.value,
    Prediction: item.prediction ?? 0
}));

O método map() percorre cada elemento do array items. Para cada elemento, um novo objeto é criado. A propriedade name recebe item.mode. Ela representa o modo de estudo e será utilizada como categoria no eixo horizontal. A propriedade Value recebe item.value. Ela representa o valor real associado ao modo de estudo. Finalmente, a propriedade Prediction recebe item.prediction. O operador ?? permite utilizar 0 quando o valor da previsão estiver ausente ou for null.

# 132 — Criação do arquivo etudeSlice.js

O gerenciamento dos dados é centralizado no arquivo etudeSlice.js. Esse arquivo utiliza Redux Toolkit e Axios: 


import { createSlice, createAsyncThunk }
from "@reduxjs/toolkit";

import axios from "axios";

createAsyncThunk permite criar uma ação assíncrona. createSlice permite criar a parte do store dedicada aos dados Estudos. Axios, por sua vez, permite se comunicar com o backend.

# 133 — Criação de fetchEtudeData

A principal ação assíncrona é: 


export const fetchEtudeData = createAsyncThunk(
    "etude/fetchEtudeData",
    async (_, thunkAPI) => {
        ...
    }
);

fetchEtudeData é responsável por recuperar os dados Estudos. O primeiro parâmetro: "etude/fetchEtudeData" representa o tipo Redux da ação. O símbolo _ indica que nenhum argumento específico é necessário para iniciar essa ação. O parâmetro thunkAPI fornece ferramentas do Redux Toolkit que permitem, entre outras coisas, gerenciar erros.

# 134 — Requisição Axios para o backend

Dentro do thunk, o Axios envia uma requisição GET: 


const response = await axios.get(
    "http://localhost:3000/etude/dashboard"
);

O método GET permite que o frontend solicite os dados ao servidor. O endpoint utilizado é: /etude/dashboard. O backend recebe a requisição e retorna os dados necessários para o dashboard. A palavra-chave await permite aguardar a resposta do servidor antes de continuar a execução.

# 135 — Retorno dos dados do backend

Após a resposta do Axios, o código utiliza: 


return response.data.data;

response contém a resposta completa fornecida pelo Axios. response.data corresponde ao corpo da resposta HTTP. Finalmente, response.data.data recupera o array de dados contido na propriedade data da resposta do backend. Esse valor se torna então o payload da ação Redux quando ela é concluída com sucesso.

# 136 — Gerenciamento dos erros do Axios

O thunk também contém um bloco try/catch: 


try {

    const response = await axios.get(
        "http://localhost:3000/etude/dashboard"
    );

    return response.data.data;

} catch (error) {

    return thunkAPI.rejectWithValue(
        error.message
    );

}

Se a requisição for bem-sucedida, os dados são retornados. Se ocorrer um erro, o programa passa para o bloco catch. A instrução: rejectWithValue(error.message) transmite a mensagem de erro para o reducer rejected. Essa abordagem permite que o componente React exiba posteriormente o problema para o usuário.

# 137 — Criação do slice Etude

O slice Redux é criado com: 


const etudeSlice = createSlice({

    name: "etude",

    initialState: {
        items: [],
        loading: false,
        error: null
    },

    ...
});

A propriedade name identifica o slice com o nome etude. O initialState define os valores iniciais do state. items começa com um array vazio, pois nenhum dado foi recuperado ainda. loading começa como false, pois nenhuma requisição está em andamento no início. error começa como null, pois inicialmente não existe nenhum erro.

# 138 — Estado pending

Quando fetchEtudeData() começa, o Redux Toolkit ativa automaticamente o estado pending: 


.addCase(
    fetchEtudeData.pending,
    (state) => {

        state.loading = true;
        state.error = null;

    }
)

loading passa a ser true. O componente React pode então exibir a mensagem Loading.... O erro anterior também é removido com state.error = null. O sistema está, portanto, pronto para receber uma nova resposta do backend.

# 139 — Estado fulfilled

Quando a requisição é bem-sucedida, o Redux Toolkit ativa o estado fulfilled: 


.addCase(
    fetchEtudeData.fulfilled,
    (state, action) => {

        state.loading = false;

        state.items = action.payload;

    }
)

loading volta a ser false, pois a requisição terminou. Os dados retornados pelo thunk estão disponíveis em action.payload. Eles são então armazenados em: state.items. O componente React recebe automaticamente os novos dados através de useSelector().

# 140 — Estado rejected

Quando a requisição falha, o Redux Toolkit ativa o estado rejected: 


.addCase(
    fetchEtudeData.rejected,
    (state, action) => {

        state.loading = false;

        state.error = action.payload;

    }
)

loading volta a ser false, pois a requisição terminou. A mensagem de erro transmitida por rejectWithValue() é recuperada através de action.payload. Ela é então armazenada em: state.error. O React pode então exibir esse erro na interface.

# 141 — Exportação do reducer

No final do arquivo Redux, o reducer é exportado: 


export default etudeSlice.reducer;

Esse reducer deve então ser registrado no store Redux principal. Depois de registrado, o componente React pode acessar o state com: 


useSelector(state => state.etude);

Assim, a conexão entre o store Redux e o componente EtudeDashboard é estabelecida.

# 142 — Ciclo completo do Redux

O funcionamento do Redux Toolkit é baseado em três estados principais:

⏳ Pending

A requisição começa. loading = true.

✅ Fulfilled

A requisição é bem-sucedida. Os dados são armazenados em items.

❌ Rejected

A requisição falha. O erro é armazenado em error.

# 143 — Fluxo completo dos dados

O fluxo completo começa quando o usuário abre a página Etude Dashboard. O React carrega o componente EtudeDashboard. O hook useEffect() é então executado. Ele dispara: dispatch(fetchEtudeData()). O Redux Toolkit passa então para o estado pending. O thunk utiliza Axios para enviar uma requisição GET para: http://localhost:3000/etude/dashboard. O backend processa a requisição e retorna uma resposta JSON. Se a resposta for bem-sucedida, o thunk retorna response.data.data. O Redux ativa então fulfilled e armazena os dados em state.items. O React recupera esses dados através de useSelector(). Os dados são então transformados em chartData. Finalmente, o Recharts utiliza esse array para construir o gráfico.

# 145 — Papel do React

React constitui a camada da interface do usuário. Ele é responsável pela exibição do Dashboard, do título, da lista de dados, das mensagens de carregamento e erro, assim como do gráfico. O React também permite reagir automaticamente às alterações do state Redux. Quando items é atualizado, o componente é executado novamente e os novos dados aparecem automaticamente na interface.

# 146 — Papel do Redux Toolkit

O Redux Toolkit centraliza o gerenciamento dos dados Estudos. O slice etude contém: items, loading, e error. Ele também gerencia os diferentes estados da ação assíncrona: pending, fulfilled, e rejected. Essa organização evita colocar toda a lógica de comunicação com o backend diretamente no componente React.

# 147 — Papel do Axios

Axios é responsável pela comunicação HTTP entre o frontend e o backend. Nesta funcionalidade, o Axios utiliza uma requisição GET: http://localhost:3000/etude/dashboard. Ele recebe então a resposta do servidor. O thunk Redux recupera os dados através de: response.data.data. Portanto, o Axios funciona como uma ponte de comunicação entre a aplicação React/Redux e a API do backend.

# 148 — Papel do Recharts

Recharts é utilizado para transformar os dados recuperados em uma representação gráfica. Os dados são preparados em chartData. O Recharts utiliza então: BarChart, Bar, XAxis, YAxis, Tooltip, Legend, e ResponsiveContainer. Essa biblioteca permite transformar os dados numéricos em uma visualização fácil de compreender.

# 149 — Papel do Power BI

O Power BI adiciona a dimensão de Business Intelligence ao Dashboard Estudos. O relatório é integrado diretamente ao React através de um iframe. Essa integração permite combinar duas abordagens complementares. O Power BI fornece visualizações e análises avançadas para apoio à tomada de decisão. O React, por sua vez, fornece uma interface personalizada capaz de recuperar os dados do backend, exibir as previsões e produzir gráficos adicionais com Recharts. O dashboard torna-se, assim, uma interface híbrida que combina desenvolvimento web, análise de dados e Business Intelligence.

# 150 — Arquitetura completa

A arquitetura dessa funcionalidade pode ser resumida em várias camadas. O frontend React contém o componente EtudeDashboard. O slice Redux contém a lógica de recuperação dos dados. createAsyncThunk coordena a operação assíncrona. Axios se comunica com a API. O backend Node.js / Express processa a requisição e retorna os dados. O Redux armazena então os resultados. O React recupera os dados através de useSelector(). Os dados são transformados em chartData. O Recharts produz a visualização gráfica. Paralelamente, o Power BI fornece o relatório de Business Intelligence integrado. Essa separação de responsabilidades torna a aplicação mais organizada, escalável e fácil de manter.

# 151 — Conclusão

O Dashboard Estudos no Exterior representa uma funcionalidade completa que combina desenvolvimento frontend, gerenciamento de estado, comunicação com o backend, visualização de dados, previsão e Business Intelligence. React constrói a interface do usuário. useEffect inicia automaticamente a recuperação dos dados. Redux Toolkit centraliza o estado e gerencia o ciclo assíncrono. createAsyncThunk facilita a criação da ação de recuperação. Axios se comunica com o backend através de uma requisição HTTP GET. Node.js / Express fornece os dados solicitados pelo frontend. Recharts transforma os dados em uma visualização gráfica. Finalmente, Power BI adiciona uma camada de Business Intelligence diretamente integrada à aplicação. O conjunto forma, portanto, uma arquitetura moderna capaz de conectar os dados do backend, o gerenciamento de estado Redux, a interface React, a previsão, a visualização gráfica e a análise de Business Intelligence com Power BI.
