📡 Radio Analytics Dashboard — Documentation technique

Cette documentation explique en détail le fonctionnement du composant RadioDashboard.jsx, sa liaison avec radioSlice.js, son fichier RadioDashboard.css, ainsi que l'utilisation de Redux Toolkit, Axios à travers le slice, Recharts et Power BI.

Le composant constitue une interface d'analyse permettant d'afficher un rapport Power BI, de récupérer des informations depuis le store Redux et de représenter certaines données sous forme de graphique Scatter Plot.

1. Présentation générale du projet

Le composant RadioDashboard.jsx représente l'interface principale du Dashboard consacré aux données RADIO.

Il utilise React pour construire l'interface, Redux Toolkit pour récupérer et gérer les données globales, et Recharts pour créer un graphique de type Scatter Plot.

Le Dashboard contient également un rapport Power BI intégré directement dans la page grâce à un élément iframe.

Lors du chargement du composant, l'action fetchRadio() est exécutée afin de récupérer les informations disponibles dans le store Redux.

``` RadioDashboard.jsx ↓ useEffect() ↓ dispatch(fetchRadio()) ↓ radioSlice.js ↓ Récupération des données ↓ Redux ↓ data / loading / error ↓ RadioDashboard.jsx ↓ Informations + Scatter Plot ↓ RadioDashboard.css ↓ Interface finale ```

53. Ce que fait réellement RadioDashboard.jsx

Le composant RadioDashboard.jsx joue principalement le rôle de couche de présentation et d'orchestration.

Il ne contient pas directement la logique interne de récupération des données de fetchRadio().

Il demande cette récupération grâce à : 

dispatch(fetchRadio());

puis il récupère le résultat depuis Redux avec : 

useSelector((state) => state.radio)

Il transforme ensuite certaines informations en données compatibles avec Recharts.

54. Résumé du fonctionnement de Redux

``` fetchRadio() ↓ Action Redux ↓ radioSlice.js ↓ Mise à jour de state.radio ↓ data / loading / error ↓ useSelector() ↓ RadioDashboard.jsx ↓ React re-render ↓ Nouvel affichage ```

Lorsque l'état Redux change, le composant qui utilise useSelector est automatiquement actualisé avec les nouvelles données.

55. Résumé final à retenir

React construit l'interface → useEffect déclenche fetchRadio() → Redux gère l'état → useSelector récupère data, loading et error → React affiche les informations → chartData prépare les données du graphique → Recharts construit le Scatter Plot → Power BI affiche le rapport analytique → RadioDashboard.css contrôle la présentation.

Le composant RadioDashboard.jsx constitue donc l'interface principale du Dashboard RADIO.

Il récupère les données depuis le store Redux à travers useSelector et déclenche leur récupération grâce à dispatch(fetchRadio()).

Le composant gère également les différents états de l'interface : chargement, erreur et disponibilité des données.

Lorsque les données sont disponibles, il affiche les informations message, columns et count.

Il prépare également chartData afin de construire un Scatter Plot avec Recharts. L'axe X utilise reputation_ranking et l'axe Y utilise tuition_fee.

En parallèle, le rapport Power BI est intégré dans un iframe, permettant d'afficher le Dashboard décisionnel directement dans l'application React.

Enfin, RadioDashboard.css est chargé de la présentation visuelle, tandis que radioSlice.js est responsable de la gestion Redux associée aux données RADIO.
