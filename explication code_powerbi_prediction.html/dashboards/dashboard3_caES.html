1. Descripción general del Dashboard Bancario

Este dashboard bancario fue desarrollado a partir de un archivo contable que contiene los datos necesarios para el análisis financiero.

El proyecto implementa un proceso completo de tratamiento de datos, desde el archivo contable de origen hasta la visualización en Power BI y la integración de un modelo de Machine Learning diseñado para realizar predicciones.

Se prestó especial atención a la calidad de los datos. El archivo contable contenía varias anomalías que requerían una fase de limpieza de datos, identificación de valores faltantes y valores atípicos, así como transformaciones adaptadas a la estructura de los datos.

2. Fuente de datos — Archivo contable

La fuente inicial del proyecto es un archivo contable que contiene los datos utilizados para construir los análisis bancarios.

Antes de su integración en el proceso ETL, se analizó la estructura del archivo con el fin de identificar los diferentes problemas de calidad de los datos que podrían afectar a los análisis y a los modelos predictivos.

Problemas encontrados

  • Valores faltantes
  • Valores atípicos
  • Inconsistencias en los datos
  • Formatos de datos que requieren transformación
  • Estructura de columnas que requiere adaptación

3. Limpieza y transformación con Python

Python se utiliza para preparar los datos antes de su integración en el proceso ETL.

Este paso permite analizar la calidad del archivo contable, identificar anomalías y transformar los datos para obtener una estructura que pueda utilizarse en las etapas siguientes.

3.1 Identificación de valores faltantes

Los datos se analizan con el fin de identificar campos incompletos o faltantes. El tratamiento se realiza según la naturaleza de los datos y su importancia para el análisis.

3.2 Identificación de valores atípicos

También se identifican los valores inusuales para evitar que afecten a los indicadores del dashboard o a los resultados del Machine Learning.

3.3 Transformación de los datos

Después de identificar los problemas, los datos se transforman para cumplir con la estructura necesaria para su integración en la Staging Area y en el Data Warehouse.

3.4 Objetivo de la preparación de datos con Python

El objetivo de esta etapa es producir datos limpios, coherentes y estructurados que puedan utilizarse tanto para el análisis de business intelligence como para la modelización predictiva.

Adaptación de la estructura

7. Machine Learning — Predicción

Después de preparar y analizar los datos, se integra un componente de Machine Learning en el proyecto.

El modelo utiliza los datos preparados para producir un valor predictivo basado en las variables de entrada.

7.1 Variables utilizadas

El script de predicción de Python recibe dos variables de entrada:

  • ca_tnd — ingresos en TND
  • ca_eur — ingresos en EUR

7.2 Carga del modelo

El modelo de Machine Learning previamente entrenado se guarda en un archivo llamado EXPORT.pkl.

El script de Python carga este modelo utilizando la biblioteca pickle.

7.3 Archivo Python — ca.py 

 
import sys 
import json 
import pickle 
import os 
 
mode = sys.argv[1] 
ca_tnd = float(sys.argv[2]) 
ca_eur = float(sys.argv[3]) 
 
BASE_DIR = os.path.dirname(os.path.abspath(**file**)) 
model_path = os.path.join(BASE_DIR, "EXPORT.pkl") 
 
model = pickle.load(open(model_path, "rb")) 
 
prediction = model.predict([[ca_tnd, ca_eur]]) 
 
result = { 
"mode": mode, 
"ca_tnd": ca_tnd, 
"ca_eur": ca_eur, 
"prediction": float(prediction[0]) 
} 
 
print(json.dumps(result))

7.4 Explicación del archivo ca.py

  1. Importación de bibliotecas: Python utiliza sys, json, pickle y os para gestionar los parámetros, el modelo y la comunicación.
  2. Recuperación de parámetros: los valores mode, ca_tnd y ca_eur se recuperan de los argumentos enviados al script.
  3. Conversión numérica: los valores de ingresos se convierten en números decimales mediante float().
  4. Ubicación del modelo: os.path se utiliza para construir la ruta al archivo EXPORT.pkl.
  5. Carga del modelo: pickle.load() restaura el modelo de Machine Learning entrenado.
  6. Predicción: model.predict() recibe las dos variables ca_tnd y ca_eur y genera la predicción.
  7. Creación de la respuesta: el resultado se organiza en un objeto Python que contiene el modo, los valores de entrada y la predicción.
  8. Comunicación JSON: json.dumps() convierte el resultado en JSON para que pueda ser recuperado por Node.js.

8. Integración de Python con Node.js

Node.js actúa como intermediario entre la aplicación y el script de Python.

El módulo child_process y la función spawn() permiten que Node.js ejecute el programa Python y recupere su resultado.

8.1 Servicio CaService.js 

 
const { spawn } = require("child_process"); 
 
function runPython(file, args = []) { 
 
return new Promise((resolve, reject) => { 
 
const py = spawn("python", ["-u", file, ...args]); 
 
let output = ""; 
 
py.stdout.on("data", (data) => { 
  output += data.toString(); 
}); 
 
py.stderr.on("data", (err) => { 
  console.error(err.toString()); 
}); 
 
py.on("close", (code) => { 
 
  if (code !== 0) { 
    return reject("Python error code " + code); 
  } 
 
  try { 
    resolve(JSON.parse(output.trim())); 
  } catch (e) { 
    reject("JSON parse error"); 
  } 
 
}); 
 
}); 
 
} 
 
module.exports = runPython;

8.2 Funcionamiento del servicio

  1. Node.js recibe la ruta del archivo Python.
  2. Los parámetros necesarios se envían al script.
  3. spawn() inicia el proceso de Python.
  4. Node.js recupera los datos producidos por stdout.
  5. Los errores de Python se recuperan mediante stderr.
  6. El resultado JSON se analiza mediante JSON.parse().
  7. El resultado final se devuelve al controlador Express.

9. API Node.js / Express

Express expone una ruta API que permite a la aplicación enviar los datos necesarios al sistema de predicción.

9.1 Ruta CARoute.js 

 
const express = require("express"); 
const router = express.Router(); 
const path = require("path"); 
const runPython = require("../service/CaService"); 
 
router.use(express.json()); 
 
router.post("/", async (req, res) => { 
 
try { 
 
const { mode, ca_tnd, ca_eur } = req.body; 
 
console.log("REQUEST BODY:", req.body); 
 
if (ca_tnd == null || ca_eur == null) { 
 
  return res.status(400).json({ 
    error: "ca_tnd and ca_eur are required" 
  }); 
 
} 
 
const result = await runPython( 
  path.join(__dirname, "../../python/ca.py"), 
  [ 
    mode || "export", 
    String(ca_tnd), 
    String(ca_eur) 
  ] 
); 
 
return res.status(200).json(result); 
 
} catch (error) { 
 
console.error("SERVER ERROR:", error); 
 
return res.status(500).json({ 
  error: error.toString() 
}); 
 
} 
 
}); 
 
module.exports = router;

9.2 Explicación de la ruta

La ruta utiliza el método POST para recibir los datos enviados por la aplicación.

El servidor recupera entonces mode, ca_tnd y ca_eur desde req.body.

Una validación comprueba que los dos valores de ingresos requeridos estén presentes.

A continuación, se llama al servicio runPython() para ejecutar ca.py con los parámetros recibidos.

Finalmente, el resultado de la predicción se devuelve al cliente como una respuesta JSON.

10. Servidor Express

El archivo principal del servidor inicializa Express, permite la recepción de datos JSON y registra la ruta de predicción. 

 
const express = require("express"); 
 
const app = express(); 
 
app.use(express.json()); 
 
const CARoute = require("./routes/CARoute"); 
 
app.use("/CA", CARoute); 
 
app.listen(3000, () => { 
 
console.log("SERVER STARTED"); 
 
});
